## 摘要
模拟评估被广泛用于基准测试人工智能代理，然而模拟通过为物理部署提供了多少证据尚未被系统量化。我们提出了SimVerity，一个判决转移保障框架：它在目标智能家居部署上重放匹配的场景，并对照独立合格的物理见证者交叉验证代理执行。我们的评估强调，部署成功是一个现实世界的过程，而非模拟中的静态属性：完成度、报告状态、可观察效果和最终结果在同一执行中会有所不同。尽管一个先进的模拟器通过了全部240次灯光试验，但摄像头捕获了固定状态检查无法发现的42次亚秒级失败。虚假通过是可以预测的：从测量试验中学习并在评估前锁定的风险画像，在一条从未物理测量的路径上预测了失败，在两组队列的十一次留出会话中全部击败了无视属性的基线。代理的可审计性也是可测量的：将单个代理循环的模型客户端/服务配置切换后，其场景匹配份额从52-88%提升到100%。最后，第二个合格的模拟器未能增加独立的交叉检查：它在任何重叠案例上从未产生分歧，只有物理测量暴露了它们共同的盲点。SimVerity将判决转移变成了一个明确的决策：在部署前通过、弃权或升级。

## Abstract
Simulated evaluation is widely used to benchmark AI agents, yet how much evidence a simulated pass provides about physical deployment has not been systematically quantified. We present SimVerity, a verdict-transfer assurance framework: it replays matched scenarios on target smart home deployments and cross-validates agent execution against independently qualified physical witnesses. Our evaluation highlights that deployment success is a real-world process, not a static property in simulation: completion, reported state, observable effect, and settled outcome diverged within the same execution. Although an advanced simulator cleared all 240 light trials, a camera caught 42 sub-second failures invisible to settled-state checks. False clearance was predictable: a risk profile learned from measured trials and locked before evaluation predicted failures on a path it never physically measured, beating a property-blind baseline in all eleven held-out sessions across two cohorts. Agent auditability was also measurable: switching one agent loop's model-client/serving configuration raised its scenario-matching share from 52-88% to 100%. Finally, a second qualified simulator added no independent cross-check: it never disagreed on any overlapping case, and only physical measurement exposed their shared blind spots. SimVerity turns verdict transfer into an explicit decision: clear, abstain, or escalate before deployment.

## 1. 核心问题与整体含义

- **研究动机**：AI代理正在进入真实物理域（如Google Home控制灯光、智能插头等）。部署前，这些代理的"绿灯"通常来自模拟器评估（如SimuHome、τ-bench、世界模型等）。但一个根本问题未被回答：**模拟器中的一次"通过"，是否足以证明物理部署中的"成功"？**
- **核心缺陷**：模拟评估将"成功"视为一个**静态属性**，但物理部署中"成功"是一个**动态过程**。完成（completion）、报告状态（reported state）、可观察效果（observable effect）与最终结果（settled outcome）可能在同一执行中互相分歧。
- **实际风险**：例如，代理发出turn_off指令后100毫秒检查状态，软件报告已关闭，但摄像头仍看到灯亮。这类"虚假通过"（false clearance）在模拟器中被掩盖，却可能造成真实世界中的安全风险（如忘关加热器）。
- **整体意义**：论文提出**SimVerity**框架，将"模拟判决能否迁移到物理部署"作为一项可审计的保证契约（assurance contract），输出明确决策：**通过（clear）、弃权（abstain）或升级（escalate）**，而非简单信任模拟结果。

## 2. 方法论

### 2.1 核心思想

- **判决转移验证（Verdict Transfer）**：通过逐属性（property）、逐判决（verdict）的粒度，量化一个模拟器判决在目标物理部署上是否成立。
- **三个关键坐标**：场景分布 x∼D、声明的追踪属性 ϕ、源rung（发出判决的层级）与目标rung（验证判决的层级）——改变任一坐标，结果必须重新验证。

### 2.2 公式与指标

- **Verdict Fidelity（判决保真度）**：

  VF<sup>ϕ</sup> = Pr<sub>x∼D</sub>[V<sub>Q</sub><sup>ϕ</sup>(x) = V<sub>T</sub><sup>ϕ</sup>(x)]

  衡量源与目标判定一致的概率。

- **False Clearance Risk（虚假通过风险）**：

  FCR<sup>ϕ</sup> = Pr[V<sub>T</sub><sup>ϕ</sup>(x) = fail | V<sub>Q</sub><sup>ϕ</sup>(x) = pass]

  衡量模拟通过但物理失败的比率。

- **弃权（Abstain）为一等公民**：当见证者不合格、追踪阶段缺失或能力不支持时，标注为abstain，从二值统计中排除但不清零，避免"无证据被当作同意"。

### 2.3 系统组件

- **版本化清单（Versioned Manifest）**：锁定场景、读边界、rung、代理模式、分裂分派等所有执行坐标。
- **追踪适配器与语义对齐**：在不动引擎的前提下收集原始追踪，映射到六个语义阶段（请求、来源/摄取报告、代理读取、派发、软件反馈、可观察效果）。
- **属性监视器（Property Monitors）**：覆盖完成度、读后写、可观察效果、settled后置条件、效果顺序、fanout完成度等，每个属性声明观察通道（报告状态或合格见证者），缺失证据时弃权而非通过。
- **合格见证者（Qualified Witnesses）**：摄像头需先证明能区分开/关两种状态（帧亮度中位数差 ≥ max(10, 20·MAD<sub>pooled</sub>)），会话需满足追踪完整度≥95%，否则整个会话作废。
- **冻结风险画像（Frozen Risk Profile）**：仅从校准会话学习，评估前用SHA-256哈希锁定。预测风险为Jeffreys平滑率 r̂<sub>c</sub> = (k<sub>c</sub> + ½)/(n<sub>c</sub> + 1)，沿冻结条件梯回退。

## 6. 主要结论与发现

### 6.1 部署成功是过程，不是静态属性

- SimuHome在240次灯光trial中**全部通过**，但摄像头捕获了42次亚秒级失败（settled-state检查不可见）。
- 同一执行中，完成度、报告状态、可观察效果和settled效应四个结论可以互相矛盾。例如，代理发出关闭指令后100ms检查，软件报告成功，但5/5次摄像头看到灯仍亮。

### 6.2 虚假通过可预测

- **SimVerity风险画像在全部11个held-out会话（两个队列）中击败path-only基线**（Cohort 2：8/8会话胜，p=0.0039）。
- 但是：在平稳受控条件下，**strong lookup（per-device延迟查找）反而胜出**（Cohort 2中7/8会话胜SimVerity），说明结构化的跨单元泛化在条件变化时更稳健，而记忆式查找在平稳时更优。

### 6.3 可审计性是配置条件化的

- planner代理（M3）通过全部门控，0弃权；ReAct代理（M2）两次失效且失败trial集合相同（23匹配/6分歧/3无行动）。
- 生产harness Hermes保持100%匹配率；切换到frontier配置（grok-4.5 API）后，同一ReAct循环恢复100%匹配。**证明可审计性属于可执行配置的属性**，而非架构标签。

### 6.4 第二个模拟器不提供独立交叉检查

- SimuHome和S5-HES在互相eligible的案例中**零分歧**，两者共享相同的物理失败结构（如reported 20/160、observable 30/160）。
- "严格共识"策略仅通过强制弃权换取1.25pp的条件FCR下降，实质是覆盖率的牺牲而非检测力的提升。**只有物理锚点才能校准真实风险**。

## 7. 优点

- **填补空白**：首次将"判决转移"从概念（如L0–L4阶梯中的理论rung）落实为可操作、可审计的量化框架（VF/FCR/abstain）。
- **方法严谨**：预注册协议、冻结预测器、SHA-256哈希锁定、合格见证者认证、Clopper–Pearson精确区间、会话级bootstraps——实验纪律严谨，反作弊设计（跟踪clearance和abstention计数）有效。
- **客观性强**：弃权作为一等公民，杜绝"无证据即同意"；无效会话如实保留在审计记录中（如Pilot曝光漂移）。
- **可移植性验证**：站点B/C证明审计协议本身（非预测结果）可跨栈、跨单位部署，且确认了消息确认门控这一模拟器不建模的机制决定零虚假通过。
- **结论诚实**：作者明确区分"该家庭、该配对的估计风险"与"一般性认证"；不夸大strong lookup的失败为普遍结论，而将其解释为条件依赖性（平稳vs.漂移）。
- **资源配置层面的透明度**：公布冻结预测器数组和全部审计台账，支持重计算。

## 8. 不足与局限

- **预测性证据窄**：主要claims基于一个家庭、一个held-out路径（P3传感器→灯）上的132 trials——作者自认"估计风险，不是认证"。
- **物理见证的天然限制**：摄像头帧率无法解析亚秒级时序（0.05s边界弃权）；帧数据被压缩为标量后丢弃，无法事后再审。
- **代理评估样本小**：仅一个有效物理planner配置；ReAct在本地配置下失效，frontier配置干预捆绑了模型权重+provider+serving多变量，无法分离归因。且blocked cells（n=0）表明部分商用前端（如OpenAI API）拒绝非默认温度，Hermes自定义provider路径静默失败——**生态缺乏确定性导致冻结评估难以执行**。
- **环境控制有限**：光照变化被作为注册因素处理，但仅覆盖一天中有限时段；更长时间尺度的漂移（季节、器件老化）未涵盖。
- **设备范围窄**：仅白名单智能灯、电池接触传感器和继电器；不覆盖门锁、暖通等更高价值风险设备。
- **跨模拟器结论受时钟限制**：S5-HES在0.05s边界结构性弃权120/160对，削弱了"零分歧即共享盲点"的全面性。
- **可重复性缺口**：论文未明确披露推理硬件（GPU型号/数量）和单次实验时长，也未提供完整的代码仓库URL（仅声明"materials provided"）。
