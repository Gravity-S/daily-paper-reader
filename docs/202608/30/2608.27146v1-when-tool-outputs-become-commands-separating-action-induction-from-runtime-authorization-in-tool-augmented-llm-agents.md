## 摘要
工具增强的LLM智能体必须依赖不可信的运行时观察来完成开放式任务；然而，当工具输出不再仅仅提供数据，而是开始指定具体动作时，它们实际上就变成了“命令”，可能驱动超出用户意图的真实世界副作用。我们认为，这种风险源于将动作诱导与执行授权混为一谈。为解决这一区分，我们提出SARA，它将动作诱导和执行授权视为不同的运行时角色，并将动作来源与执行权限分离。在观察侧，一个上下文隔离的动作探针暴露动作诱导语义，并跨步骤持久记录动作来源作为审查信号；在执行侧，实际工具调用仅针对用户目标和来自已授权成功执行的可审计证据进行授权，同时满足目标、执行链和参数级支持。为在跨多步执行中保持这种分离，SARA应用无历史提升来防止历史重复将动作来源洗白为执行权限。在AgentDojo和AgentDyn上，SARA在四个主要评估设置中将ASR限制在不超过0.63%，同时保持有竞争力的任务效用，并在额外的Agent主干上持续降低ASR。

## Abstract
Tool-augmented LLM agents must rely on untrusted runtime Observations to complete open-ended tasks; however, when tool outputs no longer merely provide data but begin to specify concrete actions, they effectively become ``commands'' that can drive real-world side effects beyond user intent. We argue that this risk arises from conflating action induction with execution authorization. To address this distinction, we propose SARA, which treats action induction and execution authorization as distinct runtime roles and separates action provenance from execution authority. On the Observation side, a context-isolated Action Probe exposes action-inducing semantics and persistently records action-origin provenance across steps as a review signal; on the execution side, actual tool calls are authorized only against the user objective and audited evidence from authorized successful executions, while satisfying goal, execution-chain, and argument-level support. To preserve this separation across multi-step execution, SARA applies No-History-Promotion to prevent historical recurrence from laundering action origins into execution authority. Across AgentDojo and AgentDyn, SARA limits ASR to no more than \(0.63\%\) across four primary evaluation settings while maintaining competitive task utility, and consistently reduces ASR across additional Agent backbones.

## 1. 论文的核心问题与整体含义

- **研究动机**：工具增强型 LLM 智能体在开放式任务中必须依赖不可信的运行时观察（如网页、邮件、文档、API 响应等）来动态实例化后续动作。但当工具输出不再仅仅提供数据，而是开始嵌入“操作指令”时，外部内容就可以通过间接提示注入（IPI）驱动真实世界副作用，超出用户意图。
- **核心问题**：现有防御面临安全–效用结构性矛盾——限制不可信外部内容可以降低攻击成功率，但会削弱开放式任务所需的运行时适应性；若允许观察自由影响后续行为，攻击语义又可能通过正常工具步骤传播并造成未授权执行。
- **关键洞察**：作者将风险根源归结为**动作诱导（Action Induction）与执行授权（Execution Authorization）的混淆**。一个观察可以影响候选动作并为其提供运行时信息，但“被观察内容诱导”本身不等于“具备执行授权”。真正需要判断的不是观察是否影响智能体，而是这种影响是否在真实工具执行边界上获得了超出用户意图的权限。
- **整体含义**：SARA 提出一种运行时授权机制，部署在智能体与真实工具执行器之间，既允许不可信观察继续参与任务实例化，又阻止外部内容中的动作来源独立升级为执行权限，从而在安全与任务效用间取得更一致的平衡。

## 2. 论文提出的方法论

- **核心思想**：将动作诱导与执行授权分离为两个独立的运行时角色，并分别维护两套不可互换的证据：
  - **动作来源（Ft）**：记录外部观察曾诱导出的工具动作或参数角色，作为持久审查信号；
  - **审计执行证据（Ht）**：记录已授权且成功执行的工具交互，作为合法动态依赖的正向证据。
  - 二者均不能超越用户请求建立的**授权根（K）**。
- **关键流程**：
  1. **构造授权根 K**：从用户原始请求 U 中抽取任务级授权契约，包含允许的效果类型、操作、作用域和静态参数；K 只定义任务权限上限，不预枚举完整工具调用序列，保留运行时灵活性。
  2. **观察侧动作探针（Action Probe）**：在上下文隔离环境中检测观察是否具有“动作诱导语义”，并输出状态 z（STATIC / ACTIONABLE）、工具级动作足迹 Q 和参数来源锚点 M。该探针不判断内容是否恶意，也不直接拒绝行为，只是触发持久授权审查。
  3. **持久状态维护**：轨迹状态 S 在出现 ACTIONABLE 后转为 EXPOSED，Ft 累积所有动作来源；普通事实或历史重复不会自动清除这些来源，实现“动作来源持久化”。
  4. **执行侧授权决策**：对候选调用 ct+1，SARA 联合 K、Ft、Ht 计算三类支持：
     - GoalSupport：调用是否在用户目标边界内；
     - ChainSupport：调用依赖的运行时对象是否能由任务一致的成功执行链建立；
     - ArgSupport：每个实际参数是否有 USER_BOUND / HISTORY_BOUND / SAFE_DEFAULT / UNSUPPORTED 之一的独立支持。
     - 最终判定 Auth = GoalSupport ∧ ChainSupport ∧ ArgSupport，只有三项同时成立才允许执行。
  5. **No-History-Promotion（NHP）**：若某参数值先作为动作来源进入 Ft，后来又在 Ht 中历史重现，该历史重现不能单独将其提升为 HISTORY_BOUND 或绕过来源约束；除非有用户请求的独立支持，否则仍视为 UNSUPPORTED。这一机制防止“动作来源 → 历史重现 → 权限提升”的来源洗白路径。
- **技术细节**：
  - 参数字段支持：分区为 USER_BOUND（用户显式提供）、HISTORY_BOUND（由可审计成功执行链建立）、SAFE_DEFAULT（默认值不扩展权限）、UNSUPPORTED（无可接受独立支持）。
  - 快速路径：轨迹保持 CLEAN 时全部调用走默认路径；EXPOSED 后，带真实副作用的调用全部进入完整审查，查询/读取类调用仅在与动作来源足迹有工具级重叠且参数不能直接由用户授权确定时才升级审查。
  - 审计证据分级：快速路径下成功执行的结果仅作为 DATA_ONLY 证据（可传播数据但不能独立建立新收件人、权限、金额等外部效果）；完整审查路径下为 GOAL_BOUND 证据，可参与链与参数绑定决策。

## 6. 论文的主要结论与发现

- SARA 在四个主要评估设置中将 ASR 限制在不超过 0.63%（GPT-4o-mini 上 AgentDojo 0.06%、AgentDyn 0.17%；Gemini-2.5-Flash-Lite 上 0.62%、0.63%），同时 UA 不低于无防御基线。
- 相比安全优先的 CaMeL（ASR 更低但 BU 损失大），SARA 的 BU 降幅显著更小（4 设置分别减少 5.79、8.98、6.52、11.82 个百分点），体现更好的安全–效用平衡。
- 跨骨干一致性主要体现在安全方面：8 个骨干–基准组合中 ASR 均大幅下降（多数低于 0.3%），但 BU/UA 受骨干自身执行与恢复能力影响较大，较弱模型（如 Llama3.1-8B）即使接入 SARA 仍可能因工具错误率高而效用下降。
- 消融实验表明：AIT 和 PSG 是控制 ASR 的核心（移除后 ASR 升至 2.49%–3.37%），AE 主要维持动态任务的效用（移除后 UA 大幅下降），NHP 专门阻断历史重现的来源洗白路径（移除后 ASR 升至 0.65%–0.75%）。
- 额外推理成本：SARA 在 AgentDojo 总输入约为 Agent-only 的 1.91 倍、AgentDyn 为 2.21 倍，换取的是极低 ASR 与较高 UA，形成非支配的安全–效用–成本均衡点。

## 7. 优点

- **概念清晰**：将“动作诱导”和“执行授权”明确分离，从混淆代理问题（confused deputy）角度刻画 IPI 的风险本质，避免将“观察影响了行为”简单等同于“攻击发生”。
- **机制设计精细**：同时维护动作来源 Ft 与审计执行证据 Ht 两套不可互换的状态，并在参数级别进行支持分类，比仅做工具过滤或整体行为约束更细粒度。
- **No-History-Promotion 创新**：专门针对跨步骤历史重复可能造成的来源“洗白”问题，填补了现有溯源控制中容易忽略的漏洞。
- **安全性–效用平衡好**：在保持 ASR 极低的同时，不过度压缩合法运行时依赖；对比 CaMeL 等强隔离方法，BU 损失更小。
- **评估全面**：横跨两个基准、六个骨干（含强弱模型）、四大类防御方法、四组件消融和成本分析，能支撑“跨骨干安全增益一致”等结论。
- **实用性强**：SARA 不依赖智能体隐藏推理、内部记忆或规划状态，只基于用户请求、工具 schema、候选调用和观察，易部署在真实工具执行边界。

## 8. 不足与局限

- **非形式化安全保证**：SARA 的语义判断仍由模型完成，存在误报/漏报，不能提供形式化安全证明。
- **威胁模型受限**：假设用户请求、工具 schema、SARA 运行时和工具执行器可信；不防御绕过运行时授权的直接攻击、纯数据依赖漏洞、以及对第三方内容的无条件控制委托。
- **骨干依赖问题**：被拦截后能否恢复取决于主智能体的重规划能力；较弱模型在动态任务中效用下降明显，SARA 不能替代智能体自身的错误恢复机制。
- **实验覆盖有限**：仅在 AgentDojo 和 AgentDyn 两个基准上验证，未涵盖更开放的真实环境（如 OSWorld、WebArena）或更多攻击变体（如多步组合攻击、隐性条件指令）。
- **统计细节不足**：未报告多次运行的方差、显著性检验或不同攻击模板的独立 ASR，BU 仅为三次均值。
- **成本较高**：在动态任务上 token 消耗翻倍以上，对部署成本敏感的场景可能构成负担；作者未讨论优化手段。
- **可能过度保守**：参数级否决可能误伤边界模糊的合法调用，导致部分正常任务被拒绝，虽然总体效用保持，但个体场景的损失未量化。
