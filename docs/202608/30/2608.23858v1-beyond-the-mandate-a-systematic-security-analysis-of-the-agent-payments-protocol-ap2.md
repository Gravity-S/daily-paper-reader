## 摘要
由Google推出的智能体支付协议（AP2）使大型语言模型驱动的购物智能体能够代表用户授权并执行支付。其签名的结账与支付授权在签名后保护交易数据的完整性。然而，在授权前塑造交易的智能体交互和外部输入（包括智能体间协议消息和模型上下文协议工具调用）不在该保护范围内。先前的工作发现了AP2 v0.1中的重放和提示注入攻击。AP2 v0.2解决了其中一些问题，但增加了需要重新分析的能力和部署假设。我们基于其角色、交易生命周期、部署架构和信任边界，对AP2 v0.2进行了系统性安全分析。我们将生命周期划分为五个阶段，并识别出五种部署架构。使用MAESTRO（多智能体环境、安全、威胁、风险、结果），我们对四个威胁行为者、十一个攻击面、十八种敌对能力和六个攻击者目标进行建模。由此产生的目录包含跨越五个攻击家族的48个威胁。我们使用人工智能漏洞评分系统（AIVSS）对这些威胁进行评分，识别出至少有一种架构中达到高等级（High band）的八个威胁。由于没有完整的公开AP2部署可用，我们构建了一个覆盖所有五种架构的测试平台，并开发了五个概念验证演示，涵盖所有八个高风险威胁及其缓解措施。我们还开发了一个部署感知扫描器，将适用的威胁映射到静态、跨角色一致性和对抗性检查。我们的分析表明，当授权前的上下文被操纵时，有效的授权签名本身并不能确保智能体介导的交易反映用户的意图。

## Abstract
The Agent Payments Protocol (AP2), introduced by Google, enables large language model (LLM)-driven shopping agents to authorize and execute payments on behalf of users. Its signed Checkout and Payment Mandates protect the integrity of transaction data after signing. Agent interactions and external inputs that shape a transaction before authorization remain outside that protection, including Agent-to-Agent Protocol (A2A) messages and Model Context Protocol (MCP) tool calls. Prior work identified replay and prompt-injection attacks in AP2 v0.1. AP2 v0.2 addresses some of these issues but adds capabilities and deployment assumptions that require renewed analysis. We present a systematic security analysis of AP2 v0.2 based on its roles, transaction lifecycle, deployment architectures, and trust boundaries. We divide the lifecycle into five phases and identify five deployment architectures. Using MAESTRO (Multi-Agent Environment, Security, Threat, Risk, Outcome), we model four threat actors, eleven attack surfaces, eighteen adversary capabilities, and six attacker goals. The resulting catalog contains 48 threats spanning five attack families. We score these threats with the Artificial Intelligence Vulnerability Scoring System (AIVSS), identifying eight that reach the High band in at least one architecture. Because no complete public AP2 deployment was available, we build a testbed spanning all five architectures and develop five proof-of-concept demonstrations covering all eight High-risk threats and their mitigations. We also develop a deployment-aware scanner that maps applicable threats to static, cross-role consistency, and adversarial checks. Our analysis shows that valid mandate signatures alone do not ensure that an agent-mediated transaction reflects the user's intent when its pre-authorization context is manipulated.

## 6. 主要结论与发现

- AP2 的**签名机制只能保护签名后的数据**，无法保护签名前的上下文；攻击者无需伪造签名或破坏密码学，仅通过上下文操纵即可使有效签名支持恶意交易。
- 部署架构对威胁具有**决定性影响**：同一威胁在一种架构中可能不存在，在另一种架构中存在，在第三种架构中被放大（例如共享 MCP 显著扩大语义操纵类威胁）。
- AIVSS 评分识别出 **8 个高风险威胁**，涵盖语义操纵、权威伪造、供应链颠覆、状态绑定失败、问责失败等五类攻击家族。
- AP2 的安全性**依赖于其支撑协议（A2A、MCP）与部署架构**，但这些协议和架构本身并未受 AP2 保护；AP2 的缓解措施无法“回溯”修复已经损坏的协议交换。
- 不同威胁类别需要不同的检测方法：推理层威胁（提示注入）需对抗性测试，供应链与配置类威胁需静态分析，跨角色差异需一致性比较。
- 提出的安全扫描器能够自动配置针对部署架构的威胁检查，并通过静态、跨角色一致性、对抗性探测三种互补层提高检测能力。

## 7. 优点

- **系统性与完整性**：首次覆盖 AP2 v0.2 的完整生命周期（五阶段）、五种部署架构、四类攻击者、十一个攻击面、六种目标，提供结构化威胁目录（48 个威胁）。
- **架构感知的风险评估**：针对每种架构分别计算 AIVSS 分数，清晰展示架构差异对风险的放大或抑制效果。
- **可验证性**：所有高风险威胁均通过测试平台上的 PoC 演示验证，并给出了具体缓解措施（AM1–AM5）。
- **多方法交叉评估**：使用 STRIDE-GPT 独立基线进行覆盖度比较，使用 8 名专家进行评分复现，使用消融实验验证扫描器分层，多角度增强了结果的可信度。
- **实用性**：开发的 AP2 安全扫描器为开发者提供部署前的安全审计能力，将抽象威胁模型转化为可操作的静态与运行时检查。
- **清晰的安全要求定义**：明确区分基线假设（BA1–BA3）与安全要求（SR1–SR8），避免将超出协议范围的问题纳入分析。

## 8. 不足与局限

- **缺少真实部署环境**：评估时没有完整的公开 AP2 生产或原型部署，只能使用自建测试平台；因此无法保证同样的失败在未来第三方实现中完全一致，实际误报/漏报率未知。
- **测试平台可控性**：PoC 在作者构建的测试环境中运行，与真实生产环境的组件差异可能导致攻击效果失真。
- **STRIDE-GPT 比较的潜在偏差**：输入使用了相同的生命周期和安全属性定义，可能高估一致覆盖率；每个架构只运行一次，无法测量生成结果的可变性。
- **评分的主观性**：AIVSS 的 AARS 因子赋值（0/0.5/1）依赖评分者判断，虽然专家复现一致性较高，但仍存在固有主观性。
- **未验证外部支付轨影响**：PoC 仅验证 AP2 层内的授权失败，未测量对这些授权失败是否会传导至卡组织、发卡行、收单机构或其他支付网络。
- **扫描器能力边界**：部分威胁（如 T-2，T-1 在 A3 上，T-3 在 A4 上）未被任何扫描器层检测到，表明扫描器并不能覆盖所有威胁。
- **性能与扩展性**：未报告扫描器在大型真实代码库上的运行时间或成本；LLM 驱动的 CDSE 与对抗层依赖商业模型（gpt-5.5），可能造成不可忽略的推理成本。
