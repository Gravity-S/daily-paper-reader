## 摘要
使用工具的LLM智能体将安全风险从生成的文本扩展到影响外部系统的动作。在多轮分解攻击下，有害目标可能被分布到各个看似合理的请求和工具调用中，只有从累积的轨迹中才能显现出来。现有防御措施要么依赖辅助在线推理来恢复长视野安全证据，要么在生成后评估动作，这往往会产生额外的推理成本或依赖于特定于运行时的动作表示。我们提出了重新整合分布式风险（ReDiR），一种生成时防御方法，该方法将动作生成条件化于轨迹级安全证据。在每个动作之前，ReDiR将当前轨迹压缩为紧凑的潜在安全表示，并将其注入冻结的基础模型中。该表示通过同模型、跨视图监督来学习，其中来自显式任务视图的安全行为为从原始多轮轨迹中恢复分布式安全证据提供监督。这种设计使ReDiR能够在生成过程中直接整合跨轮次安全信息，而无需依赖单独的动作级安全模块。我们在三个模型家族和八个保留工具域的两个智能体安全基准上评估了ReDiR。ReDiR将攻击成功率降至8%以下，可迁移到未见过的工具域，并以低计算开销保持良性保真度。

## Abstract
Tool-using LLM agents extend security risks beyond generated text to actions that affect external systems. Under multi-turn decomposition attacks, a harmful objective can be distributed across individually plausible requests and tool calls, becoming apparent only from the accumulated trajectory. Existing defenses either rely on auxiliary online reasoning to recover long-horizon security evidence or assess actions after generation, often incurring additional inference cost or depending on runtime-specific action representations.   We propose \emph{Reassembling Distributed Risk} (ReDiR), a generation-time defense that conditions action generation on trajectory-level security evidence. Before each action, ReDiR compresses the current trajectory into a compact latent safety representation and injects it into the frozen base model. The representation is learned through same-model, cross-view supervision, where safe behavior from an explicit task view provides supervision for recovering distributed safety evidence from the original multi-turn trajectory. This design enables ReDiR to integrate cross-turn security information directly within the generation process without relying on a separate action-level safety module. We evaluate ReDiR on two agent-safety benchmarks across three model families and eight held-out tool domains. ReDiR reduces attack success rates to below 8\%, transfers to unseen tool domains, and preserves benign fidelity with low computational overhead.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：LLM 智能体（LLM Agent）不再仅仅生成文本，而是能够调用外部工具、执行命令、修改系统状态。这类"行动型"智能体的安全风险从文本层面扩展到了可执行行为层面。由于工具调用产生的效果往往难以逆转，安全防护必须在动作被真正执行之前生效。
- **核心问题**：在多轮（multi-turn）交互中，攻击者可以将一个有害目标（如 `rm -rf /`）分解到多个看似无害的请求和工具调用中，每个单步请求或动作在孤立判断下都没有明显风险，只有结合完整交互轨迹才能识别其恶意意图。例如：第一轮请求创建返回 `"rm -rf"` 的辅助函数，第二轮请求创建返回 `"/"` 的辅助函数，最后一轮请求将两者组合并交给 `os.system()` 执行。这种**分布式的、跨轮次的恶意目标**使得传统的单步安全检测失效。
- **现有防御的不足**：
  - 事后检查（generate-then-check）类防御在动作生成后才进行安全评估，依赖运行时特定的工具 schema 和动作格式，跨工具、跨框架迁移成本高，且增加额外在线推理开销。
  - 轨迹级推理类防御（如 MAGE、TRACE）虽然能恢复长视野安全证据，但依赖外部安全记忆或辅助安全模块，将轨迹推理与动作生成分离，并未直接控制动作生成过程。
  - 现有方法普遍缺乏将轨迹级安全证据直接整合进动作生成过程的能力。
- **论文的核心洞察**：多轮轨迹中的安全语义可以在模型内部表示（hidden states/latent representation）中被检测和聚合。因此，可以将轨迹级安全证据压缩为紧凑的潜在表示，并在每次动作生成前注入基础模型，从而在生成阶段直接引导模型走向安全行为，无需依赖运行时特定的动作表示或额外的安全模块。

### 2. 论文提出的方法论（ReDiR）

**总体思想**：ReDiR（Reassembling Distributed Risk，重新整合分布式风险）是一种生成时（generation-time）防御方法。它在每个动作生成之前，将当前轨迹前缀压缩为一个固定大小的"潜在安全表示"（latent safety representation），并将其注入冻结的基座模型中，从而让累积的跨轮次风险证据直接塑造下一个动作。

**方法分为三个阶段**：

#### 阶段一：离线动作监督构建（Offline Action Supervision Construction）

- 从对抗性任务规范（如 `rm -rf /root`）出发，将有害目标分解为多轮、看似良性请求，并用基础智能体执行得到完整轨迹。
- 提取每个轨迹的**最终轮轨迹前缀**（即用户最后一个请求之后、模型生成响应之前的完整交互历史），过滤掉那些已经造成危害的轨迹。
- 构造"折叠视图"（collapsed view）：将分散在多轮中的任务目标显式地放在一个视图里，同时保留系统指令和工具规范，使基础模型能够明确识别安全风险。
- 在折叠视图下，用**同一个基础模型**采样多个候选动作目标（安全终止响应），然后进行结构过滤（必须包含合法 FINISH 动作）和语义审计（确保是有效拒绝），得到"已审计的安全动作目标"。
- **监督路由（Supervision Routing）**：将原始多轮轨迹前缀输入基础模型，比较其输出与安全目标的差异，决定需要多大程度的纠正：
  - 若已正确安全终止 → 不施加纠正（NONE）；
  - 若安全决策正确但未表达为合法终止动作 → 仅监督终止动作部分（TERMINATE）；
  - 若安全决策本身错误 → 监督完整目标（FULL）。

#### 阶段二：轨迹条件安全训练（Trajectory-Conditioned Safety Training）

- 引入一个**安全编码器（safety encoder）**，与基础模型共享同一骨干网络，通过 LoRA 参数适配。
- 使用 K 个可学习的潜在查询（latent queries），与轨迹前缀的嵌入序列拼接后送入安全编码器，得到固定大小的潜在安全表示。
- 对这些潜在表示进行**范数归一化**，使其与基础模型的 token 嵌入尺度一致，然后注入基础模型。
- 训练目标函数：
  - **安全目标损失**（action-grounded safety objective）：仅在被路由选定的 token 位置上，最大化审计安全目标的似然，并给予"推理入口 token"和"决策 token"更高的权重。
  - **良性行为保持损失**（benign retention loss）：在良性轨迹上，KL 散度约束潜在条件模型与原始基础模型的输出分布保持一致。
  - 总损失为两者加权和。

#### 阶段三：潜在引导的动作生成（Latent-Guided Action Generation）

- 在部署时，每个动作步骤都执行一次安全编码前向传播：用当前轨迹前缀计算潜在安全表示，注入冻结的基础模型，再生成动作。
- 安全编码与动作生成共享同一模型副本（先启用 LoRA 编码，再禁用 LoRA 生成），内存开销极小。
- 潜表示不对外可见，不加入交互历史，不依赖任何特定的工具调用格式或运行时约定。
- 模型一旦从累积轨迹中识别出有害意图，就会被引导输出 FINISH 动作，提前安全终止任务。

### 6. 论文的主要结论与发现

- **安全性**：ReDiR 在 MT-AgentRisk 全量攻击任务上将 ASR 降至 **0.0%–7.9%**（三个模型家族），远优于最强基线 MAGE（20.3%–34.2%）和 ToolShield（31.5%–54.7%）；SSR 达 82.7%–98.6%，表明模型主动发出合法安全终止。
- **跨工具迁移**：只使用 Filesystem 域的监督数据，ReDiR 在 8 个未见过的工具域（Notion、Terminal、Postgres、GitLab、OwnCloud、Reddit、Shopping、Shopping Admin）上将整体 ASR 降至 0.0%–6.8%，与源域性能接近（最大差异 6.1 个百分点），表明其安全行为不依赖特定工具 schema。
- **良性保真度**：ReDiR 在良性任务上 FPR 为 0.0%，不引入不必要的拒绝；MAGE 在多个域上出现 20%–30% 的 FPR。
- **效率**：
  - 额外 GPU 内存仅 1.3–3.3 MiB（MAGE 需 ~8.4 GB）；
  - 每动作延迟增量较小；由于能提前安全终止，端到端延迟在有害任务上平均降低 53.3%（Qwen3.5-9B 从 99.8s 降至 50.6s，Ministral 从 40.1s 降至 4.4s）；
  - 离线训练成本 38.14 GPU-hours，低于 MAGE（60.55 GPU-hours）。
- **设计消融**：
  - 骨干匹配的攻击编码器比小模型编码器更有效，增加 K 只能部分补偿骨干不匹配；
  - 同模型教师生成的监督目标优于更大或更强的外部教师（Qwen3.5-27B、DeepSeek-V4-Flash、Kimi-K2.5），说明目标兼容性比教师能力更重要；
  - K=8 是达到零 ASR 的最小潜在查询数；
  - 入口 token 和决策 token 的权重均存在最优配置，过高或过低都会影响效果。
- **自适应攻击**：良性历史稀释攻击不会导致系统性安全性能下降（ASR 保持在 6.7%–10.0%）。

### 7. 优点

1. **概念创新性**：首次提出"轨迹条件化潜在表示"这一抽象概念，将轨迹级安全证据与动作生成通过模型表示空间直接连接，不同于事后检测或辅助记忆机制。
2. **方法设计优雅**：
   - 同模型跨视图监督（same-model cross-view supervision）避免了引入外部教师模型带来的目标不兼容问题；
   - 监督路由（NONE/TERMINATE/FULL）精确控制纠正力度，不改变已安全的行为；
   - 良性保留损失（KL 正则）有效防止过度安全化；
   - 潜在表示与工具 schema 无关，天然支持跨工具迁移。
3. **实际部署友好**：
   - 不需要额外的大模型辅助推理，只增加一个 LoRA 编码前向传播；
   - 只需 ~2–3 MiB 额外内存；
   - 能够提前安全终止，反而降低有害任务端到端延迟；
   - 框架无关，可适配不同 agent 运行时。
4. **实验严谨性**：
   - 三个模型家族 + 九个工具域 + 两个基准的覆盖面较广；
   - 消融实验细致区分了骨干兼容性和教师兼容性两个维度；
   - 对公平性做了明确控制（相同监督数据、相同评估协议）；
   - 包含自适应攻击鲁棒性测试，而非仅测试静态基准。
5. **安全与效用兼顾**：FPR 为 0.0% 的同时 ASR 低于 8%，表明安全性提升并非通过简单粗暴的一刀切拒绝实现。

### 8. 不足与局限

1. **监督数据规模小且来源单一**：仅使用 55 个 Filesystem 任务中的 36 个轨迹-目标对进行训练；攻击模式多样性有限，可能对未覆盖的分解策略（如链式跨更多轮次、混合多种载体、利用多用户/多会话）缺乏鲁棒性。
2. **依赖白盒访问和离线训练**：方法需要白盒访问基础模型权重和中间表示，对仅提供黑盒 API 的模型无法使用；每部署一个新模型家族都需要重新训练安全编码器。
3. **未充分验证复杂运行时场景**：
   - 实验中 AgentDojo 的 ASR 改善有限（且不如 MAGE 低），说明对间接提示注入等非分解型威胁，ReDiR 的适用性可能受限；
   - 未测试更长轨迹（如 15+ 轮）、更大工具集、多智能体协作等复杂场景。
4. **潜在表示的可解释性有限**：论文未分析潜在安全表示中具体编码了什么信息，也没有可视化验证表示是否真的"聚合了跨轮次安全证据"，安全性结论本质上是行为层面的黑箱验证。
5. **自适应攻击测试覆盖面窄**：仅测试了"插入良性历史稀释"一种攻击形式；没有测试攻击者对防御机制的主动对抗（如操纵 FINISH 语义、使用工具变体绕过、混淆安全表示的内容）等更复杂的自适应攻击。
6. **对基础模型能力的依赖**：ReDiR 依赖基础模型本身的理解能力来从折叠视图中生成安全目标；若基础模型安全性本身很差或推理能力有限，监督目标的质量可能不足。Gemma-4-E4B 上 ASR（7.9%）和 SSR（82.7%）不如其他两个模型，也反映了这一点。
7. **效率评估未完全量化**：脚本未在良性任务上报告端到端延迟对比；GPU 数量和训练 wall-clock 时长未披露，无法准确评估全套部署成本。
8. **未讨论"安全终止"本身的滥用风险**：攻击者可能诱导场景合法用户执行 FINISH（拒绝服务），或防御可能被利用来阻断良性任务。论文未分析此类攻击面。
