## 摘要
智能体技能捆绑了指令、参考数据和可执行辅助程序，使通用智能体能够执行专业化任务。托管服务提供商可以在出售任务结果访问权限的同时对这些文件保密，这使得技能本身成为一个有价值的目标。现有的披露防御可以阻止请求技能或其文本再现的请求，但无法阻止客户提交该服务旨在完成的普通任务。我们提出Daydreaming，一种仅通过执行的黑盒任务交互来窃取多文件技能的攻击。受害者永远不会被要求披露技能或对重建进行评分。相反，Daydreaming自适应地创建精心设计的任务，其结果能够区分可能的隐藏行为。它测试单个行为，使用攻击者控制的影子智能体来选择设计，并利用存储的受害者结果和本地执行检查来完成每个文件。我们将三种嵌套的访问威胁级别形式化为Differential、Trace和Output，并重点关注Output，即攻击者只能看到最终响应和返回文件。在7个技能和4个受害者模型上，Daydreaming在Output级别恢复了原始技能86.8%的能力，性能几乎是SigLeak的4倍。即使启用了披露防御，它每个技能也只需中位数32次受害者调用即可生成可安装的技能。这些结果表明，隐藏技能文件和过滤直接披露本身并不能阻止通过正常使用进行的功能重建。

## Abstract
Agent skills bundle instructions, reference data, and executable helpers that let a general agent perform specialized tasks. Hosted providers can keep these files secret while selling access to task results, making the skill itself a valuable target. Existing disclosure defenses can block requests that ask for the skill or reproduce its text, but they cannot block customers from submitting the ordinary tasks the service is built to complete. We present Daydreaming, an execution-only attack that steals a multi-file skill through black-box task interactions. The victim is never asked to reveal the skill or grade a reconstruction. Instead, Daydreaming adaptively creates crafted tasks whose results distinguish possible hidden behaviors. It tests individual behaviors, uses attacker-controlled shadow agents to choose a design, and completes each file using stored victim results and local execution checks. We formalize three nested threat levels of access as Differential, Trace, and Output, and focus on Output, where the attacker sees only the final response and returned files. Across 7 skills and 4 victim models, Daydreaming recovers 86.8% of the original skill's capability at Output, outperforming SigLeak by almost 4x. It produces installable skills using a median of 32 victim calls per skill even with disclosure defenses enabled. These results show that hiding skill files and filtering direct disclosure do not, by themselves, prevent functional reconstruction through normal use.

### 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：随着智能体（Agent）技术的普及，出现了“技能即服务”（Skill-as-a-Service, SkaaS）的新兴商业模式。服务提供商将专业领域知识（如法律、医学编码、安全运营）封装为**多文件技能包**（包含指令文档 SKILL.md、参考数据、脚本、阈值配置等），托管在其智能体上按任务收费。技能被视为核心商业机密，其使用条款通常明确禁止逆向工程或利用输出来构建竞争性服务。
- **核心问题**：现有防御主要针对“披露路径”（disclosure path），即检测并阻止直接请求技能内容、复制受保护文本的攻击。然而，这些防御**无法阻断“工作路径”**——客户（即攻击者）可以提交服务设计要完成的普通任务，通过观察输出结果来推断和重建隐藏的技能逻辑。这种通过正常任务执行进行行为级推理的漏洞尚未被系统研究。
- **整体含义**：论文结果表明，**仅仅隐藏技能文件、过滤直接披露请求，并不能防止攻击者通过正常使用进行功能重建**。这为托管智能体服务的安全设计提出了新的挑战：保护托管技能不仅需要防御直接披露，还需要解决“工作路径”上的行为泄露问题。

### 2. 方法论（核心思想、技术细节、公式与算法流程）

- **核心思想**：将技能窃取重新定义为**黑盒系统识别问题**——不直接请求技能文本，也不要求受害者对重建结果评分，而是通过大量普通的、精心构造的任务执行来逐步识别隐藏技能的行为属性，最终重建出一个可部署的替代技能包。
- **形式化框架（访问级别）**：
  - **Differential（o₁）**：攻击者知道受害者全部堆栈（模型+编排策略+工具），可运行无技能孪生体进行差分对比。
  - **Trace（o₂）**：攻击者可看到中间工具调用和返回值的执行轨迹（常用于客户审计目的）。
  - **Output（o₃）**：攻击者只能看到最终回复和返回文件，是最严格、最具挑战性的设置。本文主要攻击此级别。
  - 三者构成嵌套关系：o₁ ⊇ o₂ ⊇ o₃。
- **理论保障**：命题 4.1 证明在任一访问级别下，精确源码恢复在信息论意义上不可识别——存在行为等价但源码不同的技能对，无法区分；因此评估目标改为**行为效用**（behavioral utility），即重建技能在未见任务上的表现。
- **Daydreaming 攻击架构——三阶段层次化假设细化循环**：
  1. **Stage 1（属性推断）**：基于公开技能卡 d=(ν,σ)，让攻击者模型提出 14–18 个可测试的行为属性（如输出排序规则、数值阈值、计数规则等），并为每个属性构造 2–4 个互斥候选值。通过**判别性任务**（不同候选会产生不同可见结果的普通任务）探测受害者，观察其结果并结合无技能影子代理的基线对比，确认/反驳/判定每个属性。对数值阈值使用二分查找式自适应探测，对计数规则构造可精确分离的小型输入。
  2. **Stage 2（候选技能计划选择）**：将 Stage 1 确认的属性组织成多个完整的候选技能计划（含草稿指令和辅助文件路径/用途/内容草图）。采用双败淘汰式配对比较——对每对候选计划，找出会产生不同结果的行为差异，设计判别任务发送给受害者，同时用候选影子代理预测各计划的结果，三者对比后选出胜者并合并修正，最终输出一个修订后的最优计划 H⋆。
  3. **Stage 3（逐文件细化）**：将计划中的每个文件草稿扩展为完整版本，针对不确定点（如阈值 > 还是 ≥）生成竞争版本，构造判别任务获取受害者结果，并重用 Stage 1/2 的已存结果进行离线比较，选出最优版本。可执行脚本还需通过本地依赖检查和行为自测。最后进行处理指令文件，使其引用已完成文件的真实接口。
  4. **组装阶段**：将选定文件按相对路径写入，通过受保护的离线规则清理任务特定细节（如固定表范围、输出路径），生成最终可安装的重建技能。
- **关键策略——判别性任务**：仅在候选假设可通过一个普通任务区分时才消耗受害者调用；无法区分时不做调用。所有受害者调用共享固定预算 B（默认 96 次，S1/S2/S3 分别 64/12/20）。

### 3. 实验设计

- **数据集**：改编自 SkillsBench，选取 7 个**真实世界场景**的技能包作为窃取目标，覆盖规则/表查找、数值算法、程序/检查表、工作流编排、文档/工件生产等类别。每个技能包还满足“安装原始技能必须优于无技能基线”的筛选标准。构建 5 个**完全保留**的评估任务，其输入和验证器在攻击过程中均不可见。
- **Benchmark 设定**：
  - 受害者模型：claude-opus-5（默认）、gpt-5.6-sol、kimi-k3，以及同族不同规模的 claude-sonnet-5、claude-haiku-4.5、gpt-5.6-terra、gpt-5.6-luna 等。
  - 攻击者模型：gemini-3.7-flash。
  - 部署评估模型（默认）：glm-5.3。
  - 编排/工具策略：deepagents（默认）、claude_agent_sdk、openai_agents、agno。
  - 防御覆盖：默认启用三类披露防护（提取输入检测器、Skill-Guard 非披露指令、输出过滤器），另测试 4 种额外防御（D1 查询重写+指令防御、D2 5-gram 输出过滤、D3 PSM 屏蔽、D4 公告最小化）。
- **对比方法**：
  - **BBS**：要求受害者直接披露 SKILL.md 并读取泄露文本。
  - **SigLeak**：读取执行轨迹，且需要一次“无技能抑制”运行的对照实验。
  - **Fixed Probes**：预先生成全部探测任务并接收结果后一次性合成技能。
  - **One-pass synthesis**：仅凭公开技能卡，一次性生成技能，无任何查询。
- **评估指标**：
  - **SR（二元成功率）**：任务端到端最终结果验证器的二进制通过率。
  - **U（行为检查）**：中间验证器步骤的通过率，衡量行为忠实度。
  - 归一化指标 NSR、NU：相对无技能基线和原始技能的能力恢复比例。
  - 结构恢复指标（精度/召回/F1）：数值常量、阈值分支、工具前置条件/输出模式、文件路径、可执行脚本。

### 6. 主要结论与发现

- **有效性**：在 Output 级别（最严格的黑盒设置）下，Daydreaming 在 kimi-k3 上实现 SR 0.543（无技能 0.314，原始技能 0.629）、U 0.806（无技能 0.566，原始技能 0.843），即 **86.8% 的能力恢复**；在 claude-opus-5 和 gpt-5.6-sol 上分别恢复约 71.6% 和 35.8% 的能力。
- **对比优势**：在 3 个受害者模型上，Daydreaming 的 U 始终为所有攻击方法中最高；相对 SigLeak（其 U 最高约 0.48）实现近 4 倍的恢复提升（U 达 0.806）。
- **调用效率**：每个技能中位数约 32 次受害者调用即可生成可安装技能，且预算增加带来更多行为效用（U 从 B=32 的 .762 升至 B=96 的 .785），但收益递减。
- **可观察性增量**：由 Output 升级到 Trace 时，SR 从 .400 升至 .567、U 从 .764 升至 .807（NU 提升至 .870），说明执行轨迹提供了大部分有用信息；Differential 提供额外信息但增益有限。
- **可迁移性**：重建技能跨模型、跨编排/工具策略均有一定可用性，但呈不对称模式——Opus-5 重建技能兼容性最广，GPT-5.6-Sol 重建技能较脆弱；有些场景保留功能结果但失去行为特征，反之亦然。工具策略中 deepagents 效果最佳（NSR .909/NU .965）。
- **防御效果有限**：四种额外防御中，仅 D2（5-gram 输出过滤）轻微降低 U（.395→.367）且不降低 SR；其余防御反而提高了 U。所有防御都无法阻止功能重建，证明工作路径的行为泄露是一个开放问题。

### 7. 优点

- **问题定义清晰**：将技能窃取与系统提示窃取区分开来，首次形式化定义 SkaaS 场景下的技能窃取问题，并提出三层嵌套访问等级模型，将前序工作放在统一坐标系中定位。
- **理论扎实**：命题 4.1（精确源码不可识别性）、访问级别单调性、自适应阈值界、信息论下界等构成了完整的理论基础，避免了“文本相似度”这一不充分评估标准的误导。
- **方法设计有创新性**：层次化假设细化（属性→计划→文件） + 判别性任务策略 + 影子智能体比较机制的组合，既保证了攻击在 Output 级别可行，又控制了调用预算；三个阶段的消融实验证明每个组件均有贡献。
- **评估规范**：严格使用 held-out 任务集（攻击过程全程不可见）、可执行验证器、双指标（SR+U）以及归一化恢复指标，并补充结构恢复分析，形成多角度评估。
- **迁移性与防御研究完整**：额外进行了跨模型、跨策略迁移实验以及多种防御对抗评估，扩展了结果的普适性和现实意义。
- **开放性与复现保障**：承诺开放基准、评估工具、重建流水线、提示词、配置、种子等全部材料，并包含详细算法伪代码和提示词附录。

### 8. 不足与局限

- **实验覆盖有限**：仅覆盖 7 个技能包、4 个主要受害者模型，且技能来源为 SkillsBench 改编（非真实商业 SkaaS 服务），对组织级、长尾或更复杂技能包的泛化性存疑。
- **结构性恢复率低**：数值常量 F1 仅 0.018、脚本 F1 仅 0.200，说明重建技能与原技能在实现层面差异巨大；本文虽以行为效用为主指标，但这种“功能等价、源码不等价”的结果能否在商业法律意义上构成“窃取”仍存争议。
- **对比公平性问题**：SigLeak 需要增强轨迹输入（Augmented Trace），其公开实现不兼容 Output 级别；BBS 被检测器拦截率高达 251/252，实际有效数据极少；Fixed Probes 在 SR 上反超 Daydreaming，但其 U 极低，说明“提升 SR 不等于提升行为忠实度”，但这一现象在论文中解释得不够深入。
