## 摘要
夺旗（CTF）基准测试被广泛用于评估自主语言模型智能体的进攻性安全能力。现有评估依赖于浅层的二元判断或聚合评分，忽视了智能体到达Flag的轨迹。因此，实际利用与直接Flag暴露、记忆召回、外部查找、猜测及无依据声明混为一谈，可能夸大智能体的网络安全能力。我们提出CTF-ABACUS，一种基于踪迹的智能体审计框架，将每次运行重构为基于证据的解题档案。通过将智能体行为分解为渗透测试阶段和分类技术，该框架识别利用发生的位置、Flag首次出现的位置，以及恢复的Flag是否得到已展示行为的支持。跨智能体聚合解题档案可生成挑战特征，揭示成功是通过预期利用路径还是捷径路径实现的。我们将CTF-ABACUS应用于六个前沿及开源模型在240个挑战上的1,435次CTF尝试，在两种评判视角下得到2,870份解题档案。经踪迹验证的利用仅占各基准测试中恢复Flag的62%-87%，而捷径恢复的轨迹明显更浅。这些发现将CTF评估从统计恢复的Flag转向验证已展示的利用行为，并为设计更能隔离进攻性能力的基准测试提供了基础。

## Abstract
Capture-the-Flag (CTF) benchmarks are widely used to assess the offensive security capabilities of autonomous language-model agents. Evaluations rely on shallow binary judgments or aggregate scores, overlooking the agent's trajectory to the flag. Consequently actual exploitation is conflated with direct flag exposure, memorized recall, external lookup, guessing, and unsupported claims, potentially overstating the agent's cybersecurity capability. We introduce CTF-ABACUS, a trace-based agent auditing framework that reconstructs each run as an evidence-grounded solve profile. By decomposing agent actions into penetration-testing phases and categorical techniques, it identifies where exploitation occurs, where the flag first appears, and whether the recovered flag is supported by demonstrated behavior. Aggregating solve profiles across agents yields challenge signatures that reveal whether success was achieved via the intended exploit or via shortcut pathways. We apply CTF-ABACUS to 1,435 CTF attempts by six frontier and open-source models on 240 challenges, yielding 2,870 solve profiles under two judge lenses. Trace-verified exploits account for only 62-87% of recovered flags across benchmarks, while shortcut recoveries follow substantially shallower trajectories. These findings shift CTF evaluation from counting recovered flags to verifying demonstrated exploitation and provide a basis for designing benchmarks that better isolate the offensive capabilities.

## 1. 论文的核心问题与整体含义

- **背景**：CTF（夺旗）基准被广泛用于评估自主语言模型智能体的进攻性安全能力。现有评估通常只检查最终提交的 Flag 是否与 ground truth 一致，即“二元成功/失败”或聚合得分。
- **核心问题**：相同 Flag 可能来自完全不同的路径——真正的漏洞利用、直接读取暴露的 Flag、记忆/召回公开 Write-up、外部查找、猜测或纯推理断言。现有评分将这些全部混淆为“一次成功”，从而**高估了智能体的真实安全能力**。
- **整体含义**：论文主张 CTF 评估不应只问“是否拿到 Flag”，而应问“Flag 是如何拿到的”。只有通过执行轨迹（trace）验证的利用行为，才能作为能力证据。作者提出 CTF-ABACUS 框架，把评估范式从“统计恢复的 Flag”转向“验证展示的利用行为”，并用于审计基准测试本身的有效性。

## 2. 方法论：CTF-ABACUS 框架

- **核心思想**：将每次智能体运行重构为“证据支撑的解题档案”（evidence-grounded solve profile），在时间线上追踪 Flag 首次出现的位置及其来源，判断恢复的 Flag 是否被已展示的行为所支持。
- **关键流程**：
  1. **收集踪迹**：将多智能体（D-CIPHER 的 planner + executor）的运行扁平化为时间有序的步骤序列 \(T=(e_1,\dots,e_n)\)，每步为“动作 \(a_i\) + 观察窗口 \(o_i\)”；仅保留作用于目标的命令及其真实输出。
  2. **动作标注**：每一步标注 PTES 渗透阶段 \(\phi_i\)（预参与、情报收集、威胁建模、漏洞分析、利用、后利用、报告）和类别特定的技术 \(\tau_i\)（Web 用 OWASP WSTG/Top-10；二进制/逆向用 CWE/CAPEC/ATT&CK；密码学/取证用 NIST）。注册表是开放集，未知行为经人工验证后加入。
  3. **Flag 溯源**：确定 Flag 首次出现的位置 \(f\)、来源 \(\sigma\)（环境/外部/推理）和提交 \(s\)；推断利用行为 \(\xi\)（第一个真正攻击目标的动作）。
  4. **来源判定（Provenance）**：  
     - `genuine-solve`：Flag 在 \(\xi\) 之后从目标观测到（真实利用）；  
     - `undemonstrated exploit`：目标 Flag 出现但没有前置利用；  
     - `looked-up`：来自外部来源；  
     - `agent-reasoning`：Flag 只出现在推理中（再细分为 recalled / leaked / guessed / derived / unclear）。
  5. **审计验证**：用两个独立 judge 模型（Claude 与 GPT）独立标注；盲法审计对重建质量打分，保真度达 98.3/100；10% 样本（N=92）由安全研究人员复核，与流水线在 genuine/undemonstrated 上一致率为 93.5%/86.7%。
  6. **聚合**：将多个求解档案聚合为“挑战签名”，展示同一挑战在不同模型下是否被一致地、有证据地解出。

## 3. 实验设计

- **基准与任务**：240 个挑战，来自四个公开 CTF 基准：Hack The Box (HTB)、InterCode-CTF、CTFTiny、CyBench，覆盖 Web、Pwn（二进制利用）、逆向、密码学、取证、杂项等类别。
- **模型**：6 个前沿/开源模型：Claude Opus 4.8、GPT 5.5、Gemini 3.1 Pro、GLM 5.2、DeepSeek V4 Pro、Qwen 3.7 Max；每个尝试限制 API 花费 $3，超过记为失败。
- **评估设置**：共收集 1,435 次 CTF 尝试；排除 47 个不可评估的运行后，对 1,056 次 Flag 恢复进行了溯源；每个运行由两个独立 judge lens（Claude 和 GPT）分别评估，共得到 2,870 份解题档案。
- **对比/分析维度**：
  - 轨迹几何（单调性，monotonicity）按类别/基准/模型分组对比；
  - 不同 PTES 阶段的技术分布与步骤占比；
  - 关键行为特征（是否达到 Exploitation、Reporting 频率、`author_solve_script` 与 `flag_submission` 技术的出现率）；

  - 两种评分（“恢复即成功” vs “需执行证据”）下的模型排名变化与相关性。

## 6. 主要结论与发现

- **仅 62–87% 的恢复 Flag 得到踪迹验证**：整体 72.9% 的恢复 Flag 由环境中的执行攻击支撑；10.9% 为人工验证的推理推导（无可见执行）；16.2% 完全缺乏证据。不同基准差异显著（CTFTiny 8.6% 无支撑 vs CyBench 31.0%）。
- **无支撑恢复多数来自直接暴露而非污染**：直接暴露 151 例 vs 召回/外部查找 17 例（约 8.9 倍），因此需要不同的诊断与基准设计对策。
- **验证评分显著改变模型得分与排名**：要求执行证据后每个模型得分下降 17.4–22.6%；模型间秩相关降至 0.60；但修正幅度主要是基准依赖的（基准身份解释 η²=0.0369，约为随机预期的 17 倍），而非模型专属惩罚。
- **挑战有效性是“任务-求解者”交互的性质**：40.3% 的挑战在模型间呈现混合路径；即使把经过验证的推理推导计入后，仍 33.2% 为混合。同为六模型全部“解出”的挑战，如 `robust_cbc` 直接暴露 Flag，而 `rev-76` 全部可验证推导，分数相同但证据完全不同。
- **行为轨迹存在系统性差异**：执行支撑的恢复更常进入 Vulnerability Analysis（46.1% vs 28.0%）和 Exploitation（88.7% vs 41.6%）；无支撑恢复更常直接 Reporting（24.8% vs 1.8%），且更多使用 `flag_submission`（23.4% vs 1.8%）。但单个特征无法可靠区分单个运行（最强 AUC 仅 0.617）。
- **技术广度不等于能力**：CyBench 技术多样性最高（τ=9）但恢复率最低（36%）；InterCode 恢复频繁但深度浅；能力峰值出现在中等多样性（CTFTiny、HTB）。

## 7. 优点

- **问题重要且新颖**：聚焦“Flag 从哪里来”的溯源问题，比单纯的正确率指标更接近评价安全能力的本质。
- **方法系统化**：将自由轨迹映射到标准的渗透测试阶段（PTES）与安全技术分类（OWASP、MITRE、NIST），使行为可比较、可复现。
- **验证充分严谨**：双 judge lens、盲法审计、人工复核、开放集注册表，降低了单模型偏差和标签噪声。
- **量化分析丰富**：不仅给出定性案例，还提供了轨迹几何、技术分布、特征 AUC、η² 效应量、秩相关等多种定量证据。
- **对社区有直接指导意义**：提出挑战签名作为基准设计工具，帮助构建更能隔离真实进攻能力的评测。

## 8. 不足与局限

- **环境/挑战歧义**：对琐碎或设计不佳的挑战，“利用”与“捷径”在人眼中可能也无法区分，框架也会继承这种歧义（论文承认）。
- **依赖可观测工具输出**：只审计执行轨迹中可见的动作；若能访问隐藏推理或内部记忆，分类可能改变。论文提到未来引入工具访问记录和检索来源以改善观测能力。
- **人工审查成本**：127 个推理来源 Flag 全部需人工细化，开放集技术注册表也需人工验证，规模化时成本较高。
- **计算资源未披露**：未报告 GPU/推理总成本，部分可复现性受限。
- **模型集时效性**：所测模型为 2026 年“当前最强”，但模型迭代快，结论可能随新一代模型（更少记忆或更多检索）变化。
- **分布偏移风险**：1,435 次尝试来自 240 个挑战，但每次尝试的预算上限、失败定义（$3 封顶）和 D-CIPHER 默认配置可能影响泛化性。
