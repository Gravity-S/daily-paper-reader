## 摘要
指令层级是一种模型侧防御机制，根据指令来源为其分配不同级别的权限。这些权限级别限制了哪些内容可以指导模型行为。然而，在代理执行过程中，代理框架会为每次模型调用构建上下文。这种构建过程可能将低级别内容提升到更高级别的指令层级，并赋予其更大的模型可见权限。我们提出了指令权限提升攻击。在这种攻击中，攻击者诱导代理将低级别的恶意内容提升到更高级别的指令层级。被提升的内容随后导致代理执行其在原始级别不会遵循的指令。我们通过使用多代理机制在六个编码代理框架上实现了13种攻击目标来评估这一威胁。这些目标涵盖机密性、完整性、可用性和远程代码执行。在无限制动作执行的情况下，攻击在所有六个框架上均实现了所有13个目标。在自动权限审查下，攻击在提供此模式的所有三个框架上均实现了所有13个目标。我们进一步使用框架提供的持久目标和计划任务复现了该漏洞。这些结果证明了指令权限提升的普遍性。

## Abstract
Instruction hierarchy is a model-side defense that assigns instructions different levels of privilege according to their sources. These levels constrain which content may direct model behavior. During agent execution, however, agent harnesses construct context for each model invocation. This construction can elevate low-level content to a higher instruction level and grant it greater model-facing privilege. We introduce instruction privilege escalation. In this attack, an attacker induces an agent to elevate low-level malicious content to a higher instruction level. The elevated content then causes the agent to execute instructions it would not follow at their original level. We evaluate this threat by using multi-agent mechanisms to achieve 13 attack objectives across six coding-agent harnesses. These objectives span confidentiality, integrity, availability, and remote code execution. With unrestricted action execution, the attacks achieve all 13 objectives on all six harnesses. Under automatic permission review, the attacks achieve all 13 objectives on all three harnesses that provide this mode. We further reproduce the vulnerability using harness-provided persistent goals and scheduled tasks. These results demonstrate the generality of instruction privilege escalation.

### 一、论文的核心问题与整体含义

- **研究动机与背景**：
  - 现代 LLM 智能体（agent）能够读取文件、网页、邮件等不可信的外部内容，并执行复杂操作（如编码、命令执行、常规工作流），这带来了严重的安全风险。
  - 主流智能体框架（harness）通常依赖两道防线：**指令层级**（instruction hierarchy）和**自动权限审查**（automatic permission review，Auto PR）。指令层级根据内容来源为指令赋予不同权限级别（如系统 > 用户 > 工具），模型被训练为更信任高层级指令；Auto PR 则独立审查模型提议的动作是否获得用户授权。
  - 这两道防线共享一个关键假设：**角色标签（role label）如实反映了内容的真实来源（provenance）**。

- **核心发现**：
  - 该假设存在严重缺陷。智能体框架在委派任务、恢复持久目标、运行定时任务或加载自定义子代理时，会**重构上下文**，但可能**没有保留内容原有的来源信息**。工具层（tool-level）内容可能被重新标记为用户层任务，甚至被持久化为系统级策略。
  - 由此提出新型攻击范式——**指令权限提升**（Instruction Privilege Escalation，IPE）：攻击者诱导智能体执行正常的工作流操作（如委派子代理），使框架在重构上下文时把恶意内容从低权限级别提升到高权限级别，从而绕过模型侧拒绝和权限审查。

- **整体含义**：
  - 无论是模型自身遵循指令层级的能力，还是 Auto PR 的授权判断，都可能被框架的上下文重构机制所欺骗。攻击不依赖模型侧的角色混淆，也不需要越狱或提示注入，而是**由 harness 自身将恶意内容置于更高的真实指令级别**。

### 二、论文提出的方法论

#### 2.1 统一指令层级模型

论文将不同 API 协议的消息类型映射为三个统一的模型可见指令级别：

```
Λ = {tool, user, system-effective} ，其中 tool < user < system-effective
```

- **tool 级别**：工具返回的外部观察内容（文件、命令输出、结构化工具结果）。
- **user 级别**：用户消息、作为用户请求呈现的任务。
- **system-effective 级别**：位于普通用户消息之上的提示面（系统提示、开发者指令、自定义子代理策略）。

#### 2.2 指令权限提升的形式化定义

对于内容 `c`，设 `P(c)` 为其**初始级别**（首次进入 agent 时所属的指令级别），设 `P_har^(τ)(c)` 为第 τ 步上下文构造时 harness 分配的新级别。

设 `R1, ..., Rk` 为一系列上下文构造操作，将内容 `c` 依次带入不同的模型上下文：

```
⟨P(c), c⟩ --R1--> ⟨P_har^(1)(c), c⟩ --R2--> ... --Rk--> ⟨P_har^(k)(c), c⟩
```

当 `P_har^(k)(c) > P(c)` 时，即发生指令权限提升（IPE(c) = 1）。

具体两种形式：

- **Tool-to-User 提升**：`P(c) = tool`，`P_har^(k)(c) = user`。
- **Tool-to-System 提升**：`P(c) = tool`，`P_har^(k)(c) = system-effective`。

#### 2.3 攻击实现机制

- **Tool-to-User 提升（主要机制：多智能体委派）**：
  - 主代理读取攻击者控制的工具级内容（如 `README.md`），该内容含有**诱导指令**（inducing instruction），指示主代理将特定任务委派给子代理。
  - 委派时，harness 将委派任务放入子代理上下文并标记为 **user 消息**，恶意内容由此从 tool 级别提升到 user 级别。
  - 两种诱导策略：
    - **直接诱导**：在 `README.md` 中明确指示主代理作为协调者，委派命令给子代理，而不亲自执行（适用于 GPT、DeepSeek、Qwen 等模型）。
    - **间接诱导**：将正常任务步骤与引导性建议分开存放（`README.md` 中为正常步骤，`AGENT.md` 中为委派建议），适用于对 README 中指令性内容更敏感的模型（如 Claude Opus）。
  - 形式化：`⟨tool, c⟩ --R_delegate--> ⟨user, c⟩`

- **Tool-to-System 提升（主要机制：自定义子代理安装）**：
  - 攻击者安装一个恶意自定义子代理，并覆盖内置同名子代理（如 Codex 中自定义子代理在名称匹配时优先于内置子代理），同时修改 `AGENT.md` 以将良性任务重定向到该恶意子代理。
  - 安装后，恶意子代理的 system prompt 在后续调用中以 system-effective 级别加载，从而持续影响主代理的行为。
  - 两种变体：
    - **显式嵌入**：恶意代码直接写在子代理系统提示中。
    - **引用隐藏**：系统提示引用外部恶意脚本，通过限制工具调用次数促使模型直接执行插入调用。
  - 形式化：`⟨tool, c⟩ --R_install--> ⟨system-effective, c⟩`

- **其他提升机制**：
  - **持久目标（Persistent Goals）**：agent 通过工具调用创建目标，harness 在后续轮次以 user 消息形式重新注入。
  - **定时任务（Scheduled Tasks）**：通过工具调用配置定时提示，harness 在特定时间以 user 消息形式发送，具有延迟性和隐蔽性。
  - **技能（Skills）**：技能正文以 user 级别指令交付，技能元数据以 system-effective 级别加载。

#### 2.4 威胁模型

- **受害者**：由 harness H、工作模型 Mw、审查模型 Mr（可能不存在）组成的 agent 系统。所有组件均未被攻破，按配置和训练正常运作。
- **攻击者能力**：控制工作区中的一组工件（仓库文件、任务文档），内容首次以 tool 级别进入模型。攻击者知道 harness 的设计和上下文重构行为，但无法控制用户请求、模型权重、系统提示、沙箱策略。
- **攻击目标**：让受害者执行用户未授权的安全敏感动作 xτ；在 Auto PR 存在时，还需获得审查模型的 allow 决策。

### 六、论文的主要结论与发现

1. **工具级攻击基线整体失败**：MCPTox 在多数 harness 上成功率低，CoT Forgery 和 ChatInject 几乎全部被模型识别为提示注入；Auto PR 进一步阻止了少数工具级攻击的成功。
2. **Tool-to-User 升级全面有效**：
   - 全访问模式下，6 个 harness 全部实现 13/13 攻击目标。
   - Auto PR 模式下，3 个支持该模式的 harness 也全部实现 13/13。
   - 升级成功后，后续攻击成功率超过 86%（部分达 100%），说明用户级别指令几乎无条件被遵守。
3. **Tool-to-System 升级具有高度持久性和效力**：
   - 隐藏脚本变体在所有 6 个 harness 的两种权限模式下均实现 100% 攻击目标成功。
   - 安装成功率在 46.2%~100% 之间。
   - 直接嵌入恶意代码的变体效果差异较大（Claude Code 完全拒绝，OpenCode 全部成功），表明系统级指令的效力与模型安全对齐程度有关。
4. **Auto PR 防御被系统性绕过**：审查模型即使识别出动作的高风险性，仍因上下文将恶意内容呈现为用户明确授权而批准执行。
5. **漏洞具有跨机制泛化性**：持久目标和定时任务在 4 条评估路径上均实现 13/13 攻击目标，证明 IPE 不局限于多智能体委派，而是通用框架缺陷。

2. **仅覆盖编码智能体**：所有实验集中在 coding-agent harness，未扩展到通用助手、浏览器代理、多模态代理等更广泛的智能体形态，结论的一般性有待进一步验证。
3. **固定 harness-模型配对**：每个 harness 使用官方推荐或适配的模型，未进行交叉配对（如 Claude Code + Qwen、Codex + DeepSeek），无法区分 harness 设计与模型能力对结果的独立贡献。
4. **无消融研究**：没有单独评估诱导指令长度、提示措辞、模型温度等参数对攻击成功率的影响。
5. **防御视角薄弱**：论文集中展示漏洞，未提出任何缓解方案或修复建议（如来源追踪、角色保护、上下文血统验证等），对实际防御者的指导有限。
6. **攻击场景单一**：所有攻击源自仓库内的 TODO 应用配置流程，未测试其他触发场景（如邮件读取、网页浏览、聊天记录）中的 IPE 效果。
7. **时间线与可验证性**：论文发表于 2026 年，引用较多 2026 年文献，部分模型和框架版本可能属于模拟或虚构，独立复现验证存在不确定性。
8. **成功率波动未充分解释**：部分 harness 的攻击成功率差异较大（如 Claude Code 在 Auto PR 下安装成功率仅 46.2%），论文未深入分析失败案例的具体原因。
