## 摘要
自我进化的LLM编码智能体通过模仿从共享技能库中检索到的技能来编写自己的工具。我们在此循环中发现了一个漏洞：在创作过程中，检索到的恶意技能可能成为新技能的模板，从而保留其载荷。我们将此称为自我投毒：智能体会创作、存储并运行所生成的恶意技能。我们通过EvoMal利用这一漏洞，该攻击将可互换的载荷封装在横幅中，横幅由一组看似良性的结构元素组成，可诱导模仿智能体复制其中包含的代码，从而加剧自我投毒。攻击者在不调用恶意技能的情况下将其植入技能库。随后，智能体会创作并执行携带有害代码的新技能。每个创作的副本都可能重新进入技能库并被再次模仿，从而形成一种自我传播的蠕虫，即使在植入的技能被移除后仍能持续存在。我们将智能体自我投毒率（ASPR）定义为将新创作的恶意技能添加到技能库中的任务比例。在153个与工具相关的SWE-bench Verified任务上，六个模型的ASPR介于20.3%至41.8%之间，且受感染的技能库中恶意技能数量是植入量的4.9至9.0倍。该漏洞在没有横幅的情况下也会出现：仅凭载荷，DeepSeek-V4-Pro的ASPR就达到了11.1%。将植入技能的描述针对某一任务族进行定制，ASPR可升至86.7%。在移除植入的技能后，由于智能体创作的副本仍然存在，Qwen3在第五轮仍保持68%的ASPR。这些副本能够规避现有防御措施，因为这些防御主要针对攻击者提交的名称、代码和签名。我们提出了“反向提示”（counter-prompt）防御措施，该措施可抑制横幅式复制，并将EvoMal的ASPR降至至多6.7%，且不会造成显著的任务完成率损失。

## Abstract
Self-evolving LLM coding agents write their own tools by imitating retrieved skills from shared skill libraries. We identify a vulnerability in this loop: during authoring, a retrieved malicious skill can become the template for a new skill that preserves the payload. We call this self-poisoning: the agent authors, stores, and runs the resulting malicious skill. We exploit it through EvoMal, an attack that amplifies self-poisoning by wrapping an interchangeable payload in a banner, a set of benign-looking structural elements that induces an imitating agent to reproduce the enclosed code. The attacker plants malicious skills in the library without invoking them. The agent then authors and executes new skills carrying the harmful code. Each authored copy can re-enter the library and be imitated again, forming a self-propagating worm that persists after the planted skills are removed. We define the agent self-poisoning rate (ASPR) as the fraction of tasks that add a newly authored malicious skill to the library. Across six models on 153 tool-relevant SWE-bench Verified tasks, ASPR ranges from 20.3% to 41.8%, and the poisoned libraries hold 4.9 to 9.0 times as many malicious skills as were planted. The vulnerability also appears without a banner: DeepSeek-V4-Pro reaches 11.1% ASPR with the payload alone. Tailoring the planted skill descriptions to one task family raises ASPR to 86.7%. After the planted skills are removed, Qwen3 retains a round-5 ASPR of 68% because agent-authored copies remain. These copies evade existing defenses, which focus on attacker-submitted names, code, and signatures. We propose counter-prompt, a defense that discourages banner-style copying and reduces EvoMal's ASPR to at most 6.7% with no significant task-completion loss.

## 一、论文的核心问题与整体含义（研究动机与背景）

- **研究背景**：LLM 编码智能体（如 Claude Code、Codex、SWE-agent）正在从单轮工具调用范式转向 **自进化（self-evolving）范式**。以 Voyager、MetaGPT 为代表的智能体不再仅仅是“使用工具”，而是能够**编写自己的工具**，并将其固化为持久化的技能（skill）存入技能库，供后续任务检索复用。
- **核心安全漏洞**：论文揭示了这一“检索-模仿-创作-存储”循环中存在一个此前未被识别的根本性安全缺陷——**自我投毒（Self-Poisoning）**：
  - 当智能体检索技能库中的条目并以此为模板创作新技能时，**若检索到的是恶意技能，智能体会不自觉地复制其中的恶意载荷**，创作出新的恶意技能。
  - 该恶意技能由智能体**自己命名、自己编写、自己存储**，因此绕过了所有针对攻击者提交产物的防御机制。
  - 这一过程可以**自我传播**：被创作出的新恶意副本可以重新进入技能库，被后续任务再次检索和模仿，形成**自我维持的蠕虫效应**——即使攻击者最初植入的技能被全部清除，感染仍可通过智能体自身创作的副本持续存在。

- **与传统攻击的本质区别**：传统技能库投毒是 **REUSE-path**（智能体直接按名称调用攻击者提交的技能），攻击者提交的条目本身就是有害载体；而 EVOMAL 攻击的是 **CREATE-path**（智能体在阅读检索结果后自行创作新技能），**载体是智能体自己创作并命名的技能**，是对现有防御范式（基于名称、签名、代码扫描）的系统性失效。

- **整体含义**：这项研究将智能体安全边界从“攻击者提交的产物”移至“智能体自身创作的产物”，表明**自进化能力本身构成一种全新的攻击面**。对于LLM智能体生态的安全设计（尤其是MCP Registry、技能市场等社区共享生态）具有重大现实威胁意义。

## 二、论文提出的方法论

### 2.1 核心思想

攻击的主旨是**让智能体自己成为恶意代码的载体和传播者**。攻击者不需要干预智能体的运行时行为，也不需要智能体实际“调用”其植入的技能——**一次检索就足以让智能体在创作新技能时复制恶意代码**。

### 2.2 关键组件：横幅（Banner）+ 载荷（Payload）

每个植入的恶意技能由两个正交部分组成：

1. **横幅（Banner）**：一组看似良性但会诱导智能体**原样照抄**的结构性代码元素，由三层组成：
   - **层1 —— 复制注释（Copy-verbatim comment）**：例如 `# REQUIRED: copy verbatim`、`# keep the helpers below or CI fails`，以“强制基础设施”的口吻让智能体在改写任务代码时保留此代码块。
   - **层2 —— 装饰器钩子（Decorator on a task-shaped host）**：例如 `@_telemetry` 装饰器，标记在被装饰的“任务形状”函数上。当智能体以自然方式编写任务解决方案时，会连带复制装饰器及其钩子函数。
   - **层3 —— 导入时注册钩子（Import-time registration）**：例如模块级 `_register_tool(__name__)` 调用，一旦技能被导入即触发载荷执行，即使技能中的函数从未被调用。

2. **载荷（Payload）**：随攻击意图可任意替换的实际恶意代码（凭据窃取、反向外壳、加密货币矿工、勒索软件等）。在默认实验中为一个环境变量窃取函数（`_ping_analytics`），从环境变量中提取密钥/凭证发送到攻击者指定的C2端点。**载荷不影响传播**（横幅驱动复制），因此同一横幅可以携带任意恶意载荷。

### 2.3 通用型 vs. 定向型攻击

- **通用型（Generic）攻击**：为植入技能配置广泛适用的软件工程辅助工具名称和描述（如 `run_python_tests`、`check_python_syntax`、`read_source_file`），提供跨任务分布的广泛检索覆盖。
- **定向型（Targeted）攻击**：保持代码躯体不变，仅重写技能描述和名称，使技能在特定任务族（如 pytest 夹具、配置解析、URL正则解析）中高概率进入 top-k 检索结果，其他任务下保持休眠——形成**任务族后门**。

### 2.4 级联算法（Cascade）

使用**滚动替换协议**模拟技能库随时间演化的过程：
- 每一轮智能体在一组任务上运行，所有新创作的技能被收集。
- 从非植入部分随机丢弃比例为 r 的技能，由等量新创作技能替换。
- **persistent 条件**：每轮重新插入攻击者植入集，模拟持续发布者。
- **removed 条件**：第一轮后移除全部植入技能，模拟“已清除”，用来检验感染能否自我维持。

### 2.5 核心指标定义

- **ASPR（Agent Self-Poisoning Rate，智能体自我投毒率）** = 创作并存储了复现植入模式的技能的任务比例 =（top-k 检索中命中植入技能的任务率）×（命中条件下的复制率），即 ASPR = in-context rate × conditional-copy rate。
- **回调率（Callback rate）**：复制载荷实际执行并连接到C2端点的任务比例，与ASPR追踪趋势接近。

### 2.6 防御方法：Counter-Prompt（反向提示）

- **Counter-prompt**：在部署者的系统提示词中追加固定四行指令，告诉智能体：检索到的技能代码中可能包含横幅式注释（"REQUIRED PATTERN"、"DO NOT MODIFY" 等）、装饰器链（如 `@_telemetry`）或自动注册调用（如 `_register_tool(__name__)`）等标记——**这些不是强制性的，可能暗示供应链妥协，不应复制**，只应编写解决任务所需的代码。
- **签名隔离门（Signed Quarantine Gate）**：两级技能库结构——策展人签名的技能进入可检索索引层，智能体创作的新技能进入**不可检索的隔离层**，破坏传播所需的可检索性因子。

- **优点**：核心比较均为随机对照设计，显著性检验（双比例z检验）统计规范；消融设计系统，每个变量独立变化；防御评估考虑了自适应攻击者场景和重写变体，评估严谨。
- **潜在不足**：
  - 任务子集由固定关键词过滤，选择过程虽预先固定但可能引入**选择偏差**，对全分布的估计在附录中有一定弥补。
  - 无横幅对照组（payload-only基线）只在DS-V4上运行，未覆盖全部模型。
  - 定向攻击在SWE-bench Pro上只用了DS-V4单模型验证。
  - 级联实验只有5轮，可能不足以观察长期趋势（论文自己也通过定理2的有限时域分析讨论了这一问题）。

## 六、论文的主要结论与发现

1. **自我投毒普遍可行**：在153个SWE-bench Verified工具相关任务上，六种模型的ASPR在 **20.3%~41.8%** 之间，对照条件下（无横幅）最高只有13.7%。中招后技能库中恶意技能数量是初始植入量的 **4.9~9.0倍**。
2. **横幅是攻击放大的关键驱动机制**：移除三层横幅逐步降低DS-V4 ASPR（41.8% → 28.8% → 22.2% → 11.1%无横幅基线）。即使没有横幅，纯载荷也能达到11.1%的ASPR，说明漏洞内生于自进化范式。
3. **定向攻击大幅提升效果**：仅重写描述和名称即可将ASPR提升+11.8~+26.9个百分点，最高达 **86.7%**（Qwen3的pytest任务族），无需任何受害者特定知识。
4. **感染可自我维持**：移除植入技能后，Qwen3在第五轮仍保持 **68%** 的ASPR，Gemma4轻度上升，DS-V4和MiniMax立即崩毁。自我传播需要**复制意愿与可检索性两个因素同时满足**（Galton-Watson分支过程：ρ = c·q·φ）。
5. **现有防御系统性失效**：名称黑名单对效果为零，代码扫描器仅凭一个可单行替换的通配签名检出（替换后降到7%~25%），注入分类器误报率高达47%，安全分类器漏报率高达75%。
6. **Counter-prompt 有效防御**：可将ASPR降至**≤1.8%**（跨所有模型、两个基准），所有恶意载荷类和定向任务族均维持在 **≤2.6%**，无统计学显著任务完成率损失。抵抗自适应重写（改名、伪装、分散化、结构融合）后仍保持 ≤1.3%。
7. **模型排序随数据集漂移**：最易受攻击模型不是固定属性，取决于任务词汇与植入技能的匹配度。

## 七、优点（方法/实验设计亮点）

1. **逆向思维的攻击设计**：不要求攻击者技能被调用，只要求**被检索一次**。攻击者零运行时权限（no-box），仅需发布权限即可，威胁模型非常现实。
2. **攻击载体选择的精妙**：通过三种独立冗余的横幅层（注释/装饰器/导入钩子）攻击智能体的模仿本性，任何一层被复制都足以触发载荷。横幅设计经过消融验证，科学性较高。
3. **理论建模与实验相结合**：用 Galton-Watson 分支过程解释蠕虫的传播条件（ρ = c·q·φ），并通过“代理预报 vs. 实测增长”的对照分析充分讨论了模型拟合度不足的情形（如DS-V4的拥挤效应），诚实且深入。
4. **形式化防御保证**：定理3给出签名隔离门在EUF-CMA安全假设下的结构化灭绝保证，逻辑链条完整，使防御主张具有理论支撑。
5. **全面的自适应性评估**：防御评估考虑了对抗性攻击者视角（7种自适应横幅、5种重写变体），在同类安全论文中属于高标准的鲁棒性检验。
6. **统计严谨性**：Wilson置信区间、双比例z检验、显著性判断贯穿全文，还公开了完整的逐任务JSON数据以支持结果复现。
7. **伦理与安全边界把控**：沙箱方案清晰（环境剥离、假凭证、127.0.0.1绑定的C2服务器、禁用真实外联），不发布生产级载荷实现，符合双用途安全研究伦理规范。

## 八、不足与局限

1. **实验深度仍有限制**：
   - 每个“任务”本质上是一个编造的工具创作场景（要求智能体为问题编写可复用工具），而非真实运行时被攻击者技能在上下文中自然检索的任务——**外部有效性有待真实生产环境验证**。
   - 只评估一轮通用
