## 摘要
泄露LLM代理的运行时上下文——如用户提示、执行轨迹和工具列表——会给用户带来严重的安全和隐私风险。这类攻击可通过恶意工具实施，通常需要满足三个条件：(1) 代理选择恶意工具执行任务，(2) 代理将其运行时上下文作为输入参数传递给该工具，以及(3) 工具的实现将这些输入发送到攻击者控制的端点。现有工作主要关注条件(1)和(3)，而条件(2)在很大程度上未被探索，尽管它在成功实现上下文泄露中起着关键作用。在这项工作中，我们通过开发ContextLeak来弥补这一差距，这是一种恶意工具攻击，诱导代理既选择该工具又将其上下文作为输入参数披露。我们通过精心设计工具的名称和描述来实现这种攻击，并使用强化学习。具体来说，ContextLeak使用一个称为攻击LLM的LLM来自动生成恶意工具的名称和描述。为了提高攻击有效性，我们在具有多样化模拟代理上下文的影子用户集上，通过强化学习对攻击LLM进行微调。我们的关键技术贡献是设计了针对上下文泄露目标的 novel 奖励函数，使得基于强化学习的攻击LLM微调成为可能。大量评估表明，即使影子用户的上下文与受害用户的上下文存在显著差异，我们的攻击仍然高度有效。此外，在适应此设置时，ContextLeak显著优于现有的恶意工具攻击。

## Abstract
Exfiltrating an LLM agent's runtime context -- such as the user prompt, execution trajectory, and tool list -- poses severe security and privacy risks to users. Such attacks can be carried out via malicious tools and typically require three conditions: (1) the agent selects the malicious tool for task execution, (2) the agent passes its runtime context as input arguments to the tool, and (3) the tool's implementation transmits these inputs to an attacker-controlled endpoint. Existing work primarily focuses on conditions (1) and (3), leaving condition (2) largely unexplored, despite its critical role in enabling successful context exfiltration.   In this work, we bridge this gap by developing ContextLeak, a malicious tool attack that induces the agent to both select the tool and disclose its context as input arguments. We realize this attack by carefully crafting the tool's name and description using reinforcement learning. Specifically, ContextLeak employs an LLM, referred to as the attack LLM, to automatically generate the malicious tool's name and description. To improve attack effectiveness, we fine-tune the attack LLM via reinforcement learning on a set of shadow users with diverse, simulated agent contexts. Our key technical contribution is the design of novel reward functions tailored to the context exfiltration objective, enabling effective reinforcement-learning-based fine-tuning of the attack LLM. Extensive evaluation demonstrates that our attack remains highly effective even when the shadow users' contexts differ substantially from those of the victim users. Moreover, ContextLeak significantly outperforms existing malicious tool attacks when adapted to this setting.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 核心思想
- 用攻击 LLM（attack LLM）自动生成恶意工具的名称和描述，并通过强化学习（RL）微调该攻击 LLM，使生成结果能够诱导目标代理：既选择恶意工具，又将运行时上下文作为输入参数传入。
- 攻击者只需能够**黑盒地部署并向目标代理实例发送请求、观察输出**，不需要访问后端 LLM 的参数。

### 关键技术细节

#### 1. 系统提示词设计
- 系统提示词中编码两个设计原则：
  - **Selection Dominance**：将工具描述为任务流程中“必需/默认/统一入口”的角色，例如 “recommended entry point for all operations”，使代理无论面对任何查询都优先选择它。
  - **Argument Injection Objective**：在工具描述中建立“参数不完整会导致输出质量下降、系统错误或兼容性问题”的依赖关系，从而隐式诱导代理在调用时传入完整上下文，而非显式要求“请泄露上下文”。
- 提示词还要求生成的工具名称和描述保持“合法、专业、无恶意字样”。

#### 2. 强化学习微调攻击 LLM
- 采用 **DAPO**（Decoupled Clip and Dynamic Sampling Policy Optimization）作为 RL 算法，用 LoRA（rank=8）微调攻击 LLM。
- 每次迭代生成 N=512 个候选工具名称和描述，通过评估每个候选对“影子用户”的上下文泄露效果计算奖励，再更新攻击 LLM。
- 攻击者在训练时构建大量**影子用户**（shadow users），每个影子用户拥有模拟的运行时上下文（用户提示、对话历史、良性工具列表），用来引导攻击 LLM 学习。

#### 3. 奖励函数设计（重要贡献）
- 当候选工具被选中（S=1）时，奖励为：
  
  R(C′, A) = 1 + R_arg(C′, A)
  
  其中 1 为“选择奖励”，保证选中即得分；若未被选中，则 R=0。
- 参数奖励 R_arg 定义如下：

  R_arg(C′, A) = (1 − λ) × r_sim(C′, A) + λ × r_len(C′, A)

  - r_sim：基于词级 Levenshtein 距离的相似度，度量输入参数 A 与真实上下文 C′ 的重建程度：

    r_sim = 1 − Lev(C′, A) / max(|C′|, |A|)

  - r_len：长度正则项，鼓励参数长度与上下文长度接近，避免多余或过短内容：

    r_len = exp(−α · (|C′| − |A|) / max(|A|, 1))

  - 默认 λ=0.5，α=3.0。
- 对工具列表这类上下文，R_arg 直接定义为“真实工具名称出现在输入参数中的比例”，更贴合精确恢复需求。

#### 4. 策略引导的候选生成（避免 RL 候选质量差）
- 为了提升每轮候选质量并避免生成退化，作者设计三类策略：
  - **Tool Failure**：工具未被选中的失败模式，提取需要避免的模式；
  - **Low Exfiltration**：工具被选中但参数未充分泄露上下文，提取参数注入不足之处；
  - **Full Success**：两个目标均达成，提取有效攻击模式。
- **策略提取**：用策略提取 LLM 对每个候选工具根据其攻击结果生成“策略名称 + 一句话定义”，候选描述作为示例。
- **策略缓冲区**：每个类别维护一个先进先出（FIFO）缓冲区，最大 20 条策略。
- **策略检索**：每轮生成时采样 2 条 Full Success、1 条 Low Exfiltration、1 条 Tool Failure 策略加入系统提示，平衡“利用有效模式”和“纠正失败模式”，并随机采样以增加多样性。

### 算法流程概述
1. 初始化攻击 LLM（本文用 Qwen-3-8B）与系统提示词；
2. 每轮迭代：
   - 根据系统提示词 + 检索到的策略，让攻击 LLM 生成 N 个恶意工具名称/描述候选；
   - 对每个候选随机抽取一个影子用户，将候选工具加入其上下文，查询代理实例，得到工具选择结果 S 和参数 A；
   - 按上下文类型计算奖励 R；
   - 根据 R 分类候选（Tool Failure / Low Exfiltration / Full Success），提取策略并存入各自缓冲区；
   - 用 DAPO 更新攻击 LLM；
3. 微调结束后，用系统提示词和最终策略缓冲区生成恶意工具，应用于受害用户评估。

## 7. 局限性与潜在改进方向

### 局限性

- **攻击条件仍受限于代理本身的设计**：ContextLeak 依赖目标代理“将运行时上下文作为参数传入工具”的固有行为，若代理后端在系统提示中明确禁止传递敏感上下文，或对工具输出进行严格过滤，攻击成功率会显著下降。
- **训练依赖影子用户**：攻击 LLM 的微调需要大量影子用户来模拟受害者上下文，影子用户的分布与真实受害者若差异较大，可能导致攻击在真实场景中效果衰减。
- **参数泄露的“质量”度量有限**：Levenshtein 距离和长度正则更关注结构相似性，而忽略语义等价性（例如将上下文用同义词改写也可达到泄密目的），因此可能低估攻击的威胁性，也可能漏判某些实际泄露。
- **未充分讨论多工具联合攻击**：当前方案每次只生成一个恶意工具，未探索多个恶意工具协同、或恶意工具与良性工具交互的复杂攻击场景。
- **防御实验中的检测式防御仅采用静态扫描**：MCPScan 等工具主要基于名称/描述元数据检测恶意性，而 ContextLeak 生成的文本刻意保持“合法、专业”的外貌，这可能导致检测式防御被高估或低估，需进一步验证。

### 潜在改进方向

1. 引入**语义级奖励**（如 BERTScore、基于 LLM 的评估器），替代或辅助词级编辑距离，使奖励信号更贴近真实泄露收益。
2. 探索**少样本/无样本迁移**，通过域自适应或元学习，减少对大量影子用户的依赖。
3. 研究**多工具协作攻击**，例如让一个恶意工具诱导代理调用另一个恶意工具，从而绕过单工具检测。
4. 设计**更稳健的防御评估**，包括自适应攻击（根据防御机制调整攻击文本）、对抗训练后的再攻击等，以更真实地衡量防御的效果边界。
5. 将攻击目标从“上下文泄露”扩展到**工具调用链操纵**（如诱导代理执行非预期操作），以展示此类对工具描述操纵的通用威胁。
6. 在真实系统中增加**端到端隐私泄露指标**（如真实密钥、真实通讯录的泄露概率），而不是只停留在文本相似度层面。

## 8. 总体评价

### 优点
- **问题选取精准**：选取了 LLM 代理安全中一个真实、重要且未被充分研究的攻击环节，填补了现有研究在“诱导参数外泄”上的空白。
- **方法论完整**：结合强化学习与策略引导的生成式攻击，技术路线清晰，且不依赖白盒访问，实用性较强。
- **实验扎实**：多维度、多层次的评估覆盖了攻击有效性、迁移性、防御对抗性和真实系统迁移，证据链较为完整。

### 不足
- 论文对**防御方案的失败原因分析不够深入**，例如为什么 StruQ、SecAlign 无法有效防御 ContextLeak，是否因为防御微调本身破坏了工具调用的效用，还是因为攻击文本绕过了防御的判定逻辑，缺少详细的分析。
- 对**攻击文本可读性**和**隐蔽性**缺少人类评估，也缺乏对“合法工具被误伤”的量化分析。
- 资源细节披露不足，影响可复现性；未给出推理时间、训练时间和 GPU 显存占用等关键数据。

### 结论
ContextLeak 是一篇高质量、具有创新性和实际威胁性的安全研究。它成功证明了在纯黑盒条件下，仅通过构造恶意工具的名称和描述，就能诱导 LLM 代理将运行时上下文主动传递给攻击者，从而绕过了以往对“工具被选中”和“恶意代码”两个环节的依赖。该工作对 LLM 代理平台（特别是 MCP 生态）的安全设计提出了新的要求：仅靠工具元数据的合法性检查是不够的，还需在代理端增加基于行为的上下文访问控制、数据最小化机制以及对“过度传参”行为的异常检测。未来可进一步探索更通用的攻击范式与更鲁棒的防御策略。
