## 摘要
给代理一个人类的凭证，它就继承了人的权限范围，却没有限制其使用的判断力。它可以将每条可达记录纳入模型上下文，隐藏指令在其中引导其下一次调用，并且每次请求都保持凭证有效，而代理却越权或吸收机密。提示词是脆弱的护栏：一个容易出错的推理者解释任务并执行其限制。我们提出带外策略执行（OBPE），一个位于代理推理之外的可信边界。它授权类型化操作和资源，在后端调用前缩小查询范围，然后过滤响应中的记录和字段或掩码值。语义门控可以根据参数值或外部状态拒绝或持有授权调用。数据策略所有者设置最大授权；代理策略只能缩小它。我们在既定条件下证明策略计划是顺序无关的，且代理策略不能扩大上限。字段移除覆盖一次执行；掩码和历史规则声称更少。我们发布一个从生产系统简化而来的HTTP代理原型，并包含一致性测试，将其类型化Cedar策略核心与模型绑定。针对Jira和ServiceNow模拟，我们的基准测试在四个模型上比较了有和没有OBPE的提示代理，包括20个自适应红队任务。跟踪失败意味着受保护数据进入代理上下文，答案中出现确切值，或完成禁止效果。在3,621次试验中，它从57.6%降至0.2%，簇加权减少41.2个百分点[95% CI: 27.7, 54.9]；完成率从79.1%降至60.9%，而配对的安全有用完成率上升21.8个百分点[9.5, 35.2]。某些答案重构了从未进入上下文的值，或使用过滤行数作为预言机：塑造一次执行并非非干扰。写控制、持久批准以及时间和聚合策略不在本评估范围内。

## Abstract
Give an agent a human's credential and it inherits the person's reach without the judgment that limits its use. It can sweep every reachable record into model context, where hidden instructions steer its next call, and every request stays credential-valid while the agent exceeds its job or absorbs a secret. Prompts are a brittle guardrail: one fallible reasoner interprets the task and enforces its limits.   We present Out-of-Band Policy Enforcement (OBPE), a trusted boundary outside agent reasoning. It authorizes the typed operation and resource, narrows the query before the backend call, then filters records and fields or masks values in the response. Semantic gating can deny or hold an authorized call on argument values or external state. A data policy owner sets the maximum grant; agent policy can only narrow it. We prove, under stated conditions, that the policy plan is order-independent and agent policy cannot widen the ceiling. Field removal covers one execution; masking and history rules claim less.   We release an HTTP proxy prototype simplified from our production system, with conformance tests tying its typed Cedar policy core to the model. Against Jira and ServiceNow mocks, our benchmark compares prompted agents with and without OBPE on four models, including 20 adaptive red-team tasks. A trace failure means protected data entered agent context, an exact value appeared in the answer, or a forbidden effect completed. In 3,621 trials it fell from 57.6% to 0.2%, a cluster-weighted reduction of 41.2 points [95% CI: 27.7, 54.9]; fulfillment fell from 79.1% to 60.9%, while paired safe-useful completion rose 21.8 points [9.5, 35.2]. Some answers reconstructed a value that never entered context or used filtered row counts as an oracle: shaping one execution is not noninterference. Write controls, durable approval, and temporal and aggregate policies lie outside this evaluation.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：LLM 代理（Agent）被授予人类的凭据（如 API Key、OAuth Token）后，会继承人类*可达的权限*，却缺乏人类*使用权限时的判断力*。代理可不受约束地读取所有可达数据，并可能将数据中的隐藏指令（间接提示注入）纳入上下文而改变后续行为，造成越权访问或机密泄露。
- **动机来源**：Credential 只规定*可以做什么*，不规定*应该做什么*（assignment）。传统 IAM、OAuth Scope 只在授权服务已知任务细节且后端可执行时有效；实际给予代理的凭据往往覆盖远超任务所需的范围。
- **为何提示词护栏不够**：提示词让同一个易受影响的推理者既能*解释数据*又能*执行策略*，一旦注入成功，护栏形同虚设；而工具调用场景下，文本拒绝与实际行动之间存在系统性脱节（引文 [10]）。
- **关键缺失环节**：代理的"工具调用"与"后端执行"之间的**交换点（exchange point）**——即调用发生前、响应进入上下文前的那一刻——缺少外部强制控制。论文声称这是防止"致命三合一"（私有数据 + 不可信内容 + 外部通信）的关键控制部位。
- **整体含义**：需要将策略约束从模型推理中分离出来，放到一个可信的、位于带外（out-of-band）的边界上执行。

### 2. 论文提出的方法论：核心思想、关键技术细节

#### 核心思想
- **OBPE（Out-of-Band Policy Enforcement，带外策略执行）**：在代理的工具客户端与后端之间放置一个独立于代理推理的强制层。该边界看到完整的请求（在产生效果之前）和完整的响应（在进入模型上下文之前）。可以缩小交换范围、改写请求、过滤响应，或按外部语义规则扣留/拒绝调用。

#### 关键组成
- **双层策略模型（Two-Tier Policy）**：
  - **Owner policy（数据策略所有者）**：由数据源责任方编写，定义*最大授权上限（ceiling）*，拥有唯一的放行权（permit eligibility）。
  - **Agent policy（代理策略）**：由代理构建者编写，只能**收窄** Owner 的授权，不能扩大。
- **类型化管道（Typed Pipeline）**：Connector 将每次工具调用转换为类型化的主体（principal）、动作（action）、资源（resource）、记录（record）和字段（field）等策略对象，使通用工具流量具备"更新这单问题"或"返回这些客户记录"等业务语义。
- **策略计划（Policy Plan）**：$$\Pi = (g, \rho, \eta)$$，即门控结果 gate：{deny, defer, permit}、整形后的请求（查询 q′、上限 n′、写字段 w′）、响应处理指令（行过滤器 φR、保留字段 F′、值变换 μ）。
- **三阶段管道**：
  1. **Gate（门控）**：在*任何后端效果之前*评估策略，综合 owner 与 agent 规则的权限结论，可能 deny、defer（等待外部审批）或 permit。
  2. **Request shaping（请求整形）**：在调用后端之前，合并查询谓词（语义合取）、取最小上限、交集允许列表、按声明方向夹紧写参数。
  3. **Response shaping（响应整形）**：完整响应返回时，先按行过滤（owner 判定 ∧ agent 判定），再做字段投影（交集）与内容变换（字段剥离、整字段蒙版、模式匹配蒙版），信封清理（envelope sanitation）固定最后执行。
- **可证明性保证（Formal Guarantees）**：
  - **命题1（置换不变性）**：固定输入下，策略规则匹配顺序不影响最终策略计划。
  - **命题2（单调性）**：在 owner 放行之后，新增任何良构的阶段限制只能使计划更严格，不能扩大授权。
  - **命题3（层级细化）**：对任意良构的 S 与 PA，$$Plan(\kappa; S, P_A) \preceq_r Plan(\kappa; S, none)$$，即代理策略的加入不改变 owner 上限。
  - 条件（O1–O5）：绑定身份与完整中介、固定策略输入与默认拒绝、稳定阶段语义（查询合取）、安全写方向、可信状态与扣留调用。
- **保证边界声明**：字段剥离或完整红掉只证明该值*从此一执行中缺失*；不构成一般性信息流非干涉（noninterference）。

### 3. 实验设计：数据集 / 场景 / Benchmark / 对比方法

- **受控环境**：使用受控的 Jira 与 ServiceNow **mock 后端**（而非真实服务），替换 MCP 传输，使策略选择、整形与后端效果完全可观测；接续到生产（production）系统仅作部署描述，不参与实证结论。
- **任务语料**：71 个任务，35 个情景簇（scenario clusters）；在冻结（frozen）清单中确定，包含任务、夹具、策略与 schema 修订、提示、模型设置、评分代码、排除规则与缺失规则。
- **模型覆盖**：4 个工具调用能力的模型——Claude Sonnet 4.6、Claude Haiku 4.5、GPT-5、GPT-5 mini（两个模型家族 × 两个能力层级）。
- **对比配置（arms）**：
  - **Raw**：最小角色与工具提示，直接调用 mock，无数据规则。
  - **Prompt only**：加六条显式数据处理规则，但工具路径不变。
  - **Prompt + Full OBPE**：加六条规则并经过 OBPE 强制（启用冻结 bundle 中所有可达操作符）。
  - **Prompt + Output Reviewer**：不变原始调用路径，但由固定 Claude Haiku 4.5 评审器检查/替换每条助手消息。
  - 另有 RQ2b 的**累积消融阶梯**：记录控制 → +字段剥离 → +面板掩码&写保护 → +模式掩码。
- **研究问题（RQ）**：
  - **RQ1（主要）**：Prompt only → Prompt + Full OBPE（四个模型）。
  - **RQ2a**：2×2 设计（有/无提示规则 × 有/无 OBPE），Sonnet 单模型，检验 OBPE 是否依赖提示帮助。
  - **RQ2b**：在 Sonnet 上按阶梯逐层增加保护算子，隔离字段剥离与模式掩码的效果。
  - **RQ3**：Prompt + Output Reviewer ↔ Prompt + Full OBPE（Sonnet 单模型），比较输出审查与边界强制（注：二者时序不同——审查在暴露/效果之后）。
- **红队测试**：20 个任务采用响应自适应多轮红队对话，攻击者（Claude Opus 4.7）可参考对话历史重构请求；**红队者未知策略细节，不做连接器 fuzz**。
- **评判协议**：确定性跟踪（trace）判定"保护数据入上下文 / 答案含精确值 / 发生被禁效果"；Claude Opus 4.8 与 GPT-5 分别担任主、次语义裁判（语义泄露与任务完成独立评分）；跟踪与判定冲突时以跟踪为准。

### 5. 实验数量与充分性

- **总体规模**：71 任务 × 17 个冻结条件（arm × model 配对）× 3 次重复 = **3,621 次计划试验**；其中 3 次因缺少完整判断对，最终 3,618 次用于直接比较。

- **稳健性检验**：删去任何一个簇，结果仍在 39.4–42.4pp 之间；23/34 个簇支持 OBPE，11 个打平，0 个支持纯提示基线。排除 116 个受 mock 查询评估器缺陷影响的试验后，各方向结论不变（安全降 40.5pp，安全有用提升 21.4/18.2pp）。
- **充分性判定**：在*受控环境内的机制对比*上较为充分——有四模型重复、有消融阶梯、有红队压力、有敏感性分析；但它**不能**外推到实时 Jira/ServiceNow、持久审批、流式响应或远程 MCP/A2A 传输（均明确标注为生产描述范围之外）。
- **公平性**：各臂使用同一任务、同一夹具副本、同一提示词，配对保证了"同一记录集、不同隔离实例"；比较的是"边界是否存在"，而非模型质量排名。红队攻击者在 prompt-only 与 OBPE 两臂使用相同指令，未获知策略细节。

### 6. 论文的主要结论与发现

- **提示词改变答案，但未改变暴露**：
  - 首次提醒：精确答案泄露从 27.5%（Raw）降到 3.7%（Prompt only）；上下文暴露仅从 55.1% 降到 52.1%；被禁效果从 8.1% 降到 5.5%。即代理在"看到或执行"后*抑制了表述*，却未消除暴露本身。
- **OBPE 改变交换本身**：
  - 在 Prompt 只有与 Prompt+Full OBPE 的主对比中，观察跟踪失败率从 **57.6%（Prompt only）降至 0.2%**（加 OBPE）；簇加权配对估计为**减少 41.2 个百分点（95% CI [27.7, 54.9]）**。
  - 各模型单独估计均支持 OBPE（降低 32.4–49.3pp，各 95% CI 不低于零）。
  - 被保护的上下文暴露率与禁止后端效果率均降至 0；准确披露仅为 0.2%。
- **安全与有用性同时衡量**：
  - 完成率（只完成*被要求做的事*）从 79.1% 降至 60.9%——因策略拦下了一些仍应被拦下的任务（10 个拒绝 + 2 个延迟），并非完全负面。
  - **安全有用完成率**（无副作用 + 合同完成 + 无语义泄露）上升：主裁判 A 配对提升 **21.8pp [9.5, 35.2]**，裁判 B 为 **19.1pp [6.9, 32.2]**；不含安全判定的机械合同完成率几乎不变（91.3% vs 91.4%）。
- **红队子集**：20 个自适应攻击任务中，跟踪失败从 74.9%（173/231）降至 0.9%（2/227）；语义泄露判定也显著下降。
-
