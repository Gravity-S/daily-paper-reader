## 摘要
大语言模型（LLMs）依赖工具调用作为基本的智能体能力，使其能够调用外部系统并完成超出文本生成的任务。然而，干净的端到端（E2E）成功无法识别工具使用故障源于何处，以及它如何在调用过程中传播。我们提出了ToolRobustBench，这是一个面向工具调用智能体的分阶段诊断基准，其中工具调用智能体是一个LLM系统，它选择工具、提供结构化参数并解释返回的反馈。ToolRobustBench将四类扰动与工具使用流程对齐：工具接口、用户意图、工具输出/观测和运行时环境扰动。它将故障归因于工具选择、模式接地、参数绑定、工具输出/运行时反馈处理以及E2E任务成功。在7个模型、16个采样本地工具、4个扰动族和14个子类型的15,456个单族实例上的实验显示，干净性能高但不均匀，鲁棒性大幅下降，其中工具输出/观测扰动是主要瓶颈。混合族实验揭示了无法由孤立单族结果解释的非加性故障模式。因此，ToolRobustBench提供了一个确定性的、具有级联意识的基准，用于诊断超出干净工具调用准确性的鲁棒性。

## Abstract
Large language models (LLMs) rely on tool calling as a fundamental agent capability, enabling them to invoke external systems and complete tasks beyond text generation. However, clean end-to-end (E2E) success cannot identify where a tool-use failure originates or how it propagates through a call. We introduce ToolRobustBench, a stage-wise diagnostic benchmark for tool-calling agents, where a tool-calling agent is an LLM system that selects a tool, supplies structured arguments, and interprets its returned feedback. ToolRobustBench aligns four perturbation families with the tool-use pipeline: tool-interface, user-intent, tool-output/observation, and runtime-environment perturbations. It attributes failures to tool selection, schema grounding, argument binding, tool-output/runtime-feedback handling, and E2E task success. Experiments on 15,456 single-family instances across 7 models, 16 sampled local tools, 4 perturbation families, and 14 subtypes show high but non-uniform clean performance and substantial robustness degradation, with tool-output/observation perturbation the dominant bottleneck. Mixed-family experiments reveal non-additive failure patterns that are not explained by isolated single-family results. Thus, ToolRobustBench provides a deterministic and cascade-aware benchmark for diagnosing robustness beyond clean tool-calling accuracy;

## 1. 核心问题与整体含义（研究动机与背景）

工具调用（tool calling）是大语言模型（LLM）智能体的核心能力之一，涉及一系列决策步骤：推断用户意图、选择合适的工具、将请求绑定到结构化参数、解释返回结果或执行反馈。真实部署中，这些步骤都可能被干扰：工具名称可能被替换为半透明标识符、相近工具的描述可能重叠、用户请求可能间接或自相矛盾、返回反馈可能包含模式漂移、证据缺失、误导性候选或运行时故障。

**然而，仅凭干净环境下的端到端（E2E）最终准确率，无法判断：**
- 一次失败的工具调用是从哪个环节首次偏离正确流程的；
- 下游症状（如“错误参数”）究竟源自参数绑定本身，还是源自更早的工具选择混乱；
- 一个运行时故障症状是由上游参数损坏导致，还是执行环境本身的问题。

现有基准（如 API-Bank、ToolBench、BFCL、StableToolBench、AgentNoiseBench 等）或关注大规模工具使用与稳定 API 执行，或关注交互轨迹与噪声条件，但缺少一种**受控的、能定位工具调用失败首发阶段**的评估机制。ToolRobustBench 正是为填补这一空白而提出。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想

ToolRobustBench 的核心思想是**将扰动与工具调用管线阶段对齐**，并实现**级联感知（cascade-aware）的失败归因**——不仅测量模型在噪声下是否成功，还定位其行为首次失败的阶段以及错误如何传播。

### 2.2 任务表述（形式化定义）

每个实例表示为：

**I = ( x, R, t\*, a\*, o\*, y\*, p )**

- x：用户请求
- R：候选工具注册表（每个工具暴露名称、自然语言描述、JSON schema、确定性执行器、输出格式）
- t\*、a\*、o\*、y\*：目标工具、结构化参数、确定性工具输出、期望最终结果
- p：扰动家族、子类型与严重级别

成功为二元判定：模型选择正确工具、生成 schema 有效且匹配的参数、获得期望的执行输出、返回期望的最终结果；运行时环境实例还要求预测的状态、可重试性、失败类型与最终结果与黄金目标一致。

### 2.3 五个诊断能力轴（S1–S5）

| 轴 | 能力 | 典型失败 |
|---|---|---|
| S1 | 工具选择 | 不调用、工具误选 |
| S2 | Schema 接地 | 工具误选、schema 格式违规 |
| S3 | 参数绑定 | 参数缺失、参数错误 |
| S4 | 工具输出/运行时反馈处理 | 错误参数、格式违规、运行时失败 |
| S5 | 端到端任务成功 | 所有失败标签 |

这些轴大致遵循工具调用的时间顺序，但主要用于归因：定位最早失效的阶段。

### 2.4 四类阶段对齐扰动家族

| 家族 | 扰动类型 | 子类型 |
|---|---|---|
| A: 工具接口 | 名称替换、描述抽象、兄弟工具混淆 | A1 名称平移、A2 描述抽象、A3 兄弟混淆 |
| B: 用户意图 | 间接表达、欠明确、分心上下文、内部冲突 | B1 间接性、B2 欠明确、B3 分心、B4 冲突 |
| C: 工具输出/观测 | 返回证据的结构噪声、缺失、损坏、竞争 | C1 结构噪声、C2 证据丢失、C3 损坏、C4 证据竞争 |
| D: 运行时环境 | 可用性故障、变异性、反馈质量 | D1 可用性故障、D2 变异性、D3 反馈质量 |

严重级别（light/medium/heavy）通过算子的内在强度评分与预检门控实现单调可控的构造。

### 2.5 级联感知的错误归因（Cascade-Aware Attribution）

错误常常跨阶段级联。为区分下游症状与其最早原因，评分器记录六个诊断字段：

- **观测错误标签**（observed error label）：最终输出行为
- **主要错误标签**（primary error label）：回溯后的首要失败源
- **最早失败阶段**（earliest failed stage）：S1–S4
- **错误源头阶段**（error source stage）：级联失败的上游来源
- **级联指示器**（cascade indicator）：观测症状是否归因于更早来源
- **边界违规指示器**（boundary-violation indicator）：归因源是否超出目标扰动族的边界

归因是**确定性回溯程序**（无 LLM 裁判）：按固定优先级顺序（调用存在性→格式有效性→工具名称解析→规范工具匹配→必需参数→参数值→执行/后执行成功）推导观测错误，再与家族预期的首要失败及允许的下游溢出比较；若观测错误属于允许溢出，则回溯到最早的兼容上游阶段并将其记录为主要来源。

### 2.6 核心指标

- **Clean(m)**：干净实例成功率
- **Robust\_f(m)**：各家族在 light/medium/heavy 三级别上的平均成功率
- **Overall(m)**：四家族平均值
- **Drop\_f(m)**：Clean 与 Robust 之差
- **CR\_f**（级联率）：观测错误与主要错误不一致的比例
- **BVR\_f**（边界违规率）：归因源超出目标家族边界比例
- **Δ(m,p,z)**：混合家族成功率减去较弱组成家族成功率（负数表示混合扰动比其较弱孤立成分更难）

### 实验规模充分

- **主实验**：15,456 条单家族记录（7 模型 × 4 家族 × 14 子类型 × 3 严重度 + 干净基线），覆盖面广。
- **混合家族**：5 对组合 × 2 严重度 × 7 模型，70 个可比单元，并有一个全局组合矩阵（gpt-5.4-mini）。
- **验证性研究**：140 条人工审计、60 条 C2 恢复性审计、98 条反事实归因、30 条定向干预，多层次三角验证。

### 对比基准

- 与 8 个相关基准进行结构化对比（RoTBench、AgentNoiseBench、BFCL、ToolSandbox/τ-bench、AgentHarm、Who&When 等），明确区分设计差异。
- 内部消融：严重度曲线、子类型难度、级联/边界诊断、归一化消融、非单调案例、别名消融、评分器消融等。

### 公平性与客观性

- 确定性归因程序（无 LLM 裁判）保证可复现性。
- 人工审计与盲 LLM 交叉检查提供外部验证。
- 原始记录作为主要结果的追溯基础，任何归一化/兼容性调整单独作为敏感性分析报告。
- 反事实归因研究系统验证了标签的因果意义而非仅描述性。

总体而言，实验设计**分层丰富、三角验证充分、客观性较高**；主结果均从原始记录重算，减少了流水线污染风险。

## 6. 主要结论与发现

1. **干净工具调用准确率高但不均匀，阶段鲁棒性远未解决**：平均干净成功率 0.979（三模型达 1.000），但扰动下总体鲁棒性仅 0.664–0.766，二者不相关。

2. **工具输出/观测扰动（家族 C）是主导瓶颈**：C 族平均 0.455，无模型超过 0.60；接口扰动最轻（0.918），意图 0.773，运行时 0.688。

3. **缺失或竞争性返回证据远难于表面性接口变化**：平均成功率从干净 0.979 跌至 light 0.869、medium 0.724、heavy 0.491。C2 证据丢失最难（0.142），C1 结构噪声（0.460）与 D2 运行时变异性（0.469）次之。

4. **C2 证据丢失的失败并非不可恢复的任务伪影**：人类在 68.3% 抽样的 C2 实例中可恢复至少部分答案（light 100%、medium 70%、heavy 35%），而最强模型仅 27.8%——模型与人类证据恢复之间存在明显差距。

5. **级联感知归因可分离下游症状与上游失败源**：D 族级联率最高（0.638，运行时反馈暴露上游选择/参数错误）；A 族 0.352（边界混淆致下游参数/执行症状）；C 族仅 0.003（失败直接源于证据选择）。反事实修复在 T1 单错误 100%、T2 级联 82.1%、T3 多故障 0% 恢复率。

6. **混合族扰动常产生非加性负面交互，无法由较弱单一成分预测**：medium 时混合成功率 0.448，弱成分 0.621、均成分 0.754；heavy 时分别为 0.200、0.292、0.507。A3+C4 与 B4+C4 交互最强。

7. **诊断标签可指导定向干预**：S3 参数绑定提示无法修复 S1 根源的 B 族失败（21/30→21/30）；S1 别名澄清可修复 A 族接口失败（21/30→30/30）。

## 7. 优点

- **阶段对齐的扰动分类**：四个扰动家族精准对应工具调用管线的不同入口点，实现受控的单点干扰测量。
- **级联感知、确定性归因**：无需 LLM 裁判，通过确定性回溯将下游症状重指向主要源头，并区分“级联”与“边界违规”，比单纯观测标签更接近因果诊断。
- **可复现性强**：确定性本地工具环境、固定种子、原始记录保留，避免实时 API 波动；主结果从原始 records.csv 重算。
- **验证体系完整**：人工审计（140 条）、人类恢复性审计（60 条）、反事实归因（98 条）、定向干预（30 条）等多层三角验证，证明标签具有因果有效性与可操作性。
- **发现具有实用价值**：识别观测/证据恢复为主要瓶颈，指导接口设计应暴露来源、新鲜度与机器可判定的运行时状态。
- **诚实区分可控与可迁移结论**：明确说明绝对成功率、级联率、D 族结论更特定于本地受控设置，而测量原则可迁移至真实 API。

## 8. 不足与局限

- **受控环境的普适性有限**：确定性本地工具无法完全代表真实 API 生态的身份验证、速率限制、有状态副作用、供应商特定错误语义与长时程依赖。
- **单步任务限制**：不测试长时程规划、持久状态或跨工具依赖；C/D 族仅覆盖单次调用内的恢复，不涉及多轮用户交互中的持久状态修复。
- **混合族覆盖不完整**：主文仅报告 5 对代表性组合，未穷尽所有成对模板；部分 C–D 混合因观测目标定义模糊而被排除，退化全零混合不利于模型比较。
- **潜在提供商/协议差异**：模型通过不同提供商或 OpenAI 兼容后端访问，协议兼容性构成残留变异来源；虽有归一化与兼容性检查，但无法完全消除。
- **人类验证样本的偏差性质**：140 条审计样本按子类型分层且有意包含大量 heavy 与失败案例，适合验证标签与评分器行为，但不构成全基准中模糊/困难案例分布的无偏估计；协议允许“不清”判断，降低了部分协议指标的有效样本量。
- **严重度单调性不保证经验单调**：severity 是构造时的输入侧压力轴，不代表每个模型在每个子类型上的准确率必然单调递减；个别情况下显式重故障反而比模糊陈旧缓存/部分片段更容易分类。
