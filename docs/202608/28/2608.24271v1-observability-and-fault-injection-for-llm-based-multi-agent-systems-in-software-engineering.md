## 摘要
基于大语言模型的多智能体系统在软件工程任务中的应用日益广泛，但在受控故障下对其进行检查、调试和评估仍然困难。我们提出了llmmas-otel，一个轻量级且与框架无关的工具，它将基于OpenTelemetry的分布式追踪与故障注入相结合，用于软件工程工作流中的基于LLM的多智能体系统。该工具通过跨工作流阶段、智能体步骤、智能体间通信、工具调用和LLM调用的轨迹对齐遥测来检测智能体执行，并在选定的交互点支持有针对性的故障注入。这使得以可重复的方式比较基线执行和故障执行，并通过对齐的轨迹和运行工件检查效果成为可能。我们描述了该工具在最小演示工作流和用于软件开发的实际基于LLM的多智能体系统上的动机、架构、实现、当前能力和初步验证。

## Abstract
Large Language Model-based multi-agent systems are increasingly explored for software engineering tasks, but they remain difficult to inspect, debug, and evaluate under controlled failures. We present llmmas-otel, a lightweight and framework-agnostic tool that combines OpenTelemetry-based distributed tracing with fault injection for LLM-based multi-agent systems in software engineering workflows. The tool instruments agent executions with trace-aligned telemetry across workflow phases, agent steps, inter-agent communication, tool calls, and LLM invocations, and supports targeted fault injection at selected interaction points. This makes it possible to compare baseline and faulty executions in a reproducible way and inspect the effects through aligned traces and run artifacts. We describe the motivation, architecture, implementation, current capabilities, and initial validation of the tool on a minimal demo workflow and a real LLM-based multi-agent system for software development.

## 1. 论文的核心问题与整体含义

- 研究背景：基于大语言模型的多智能体系统（LLM-MAS）越来越多地被用于软件工程任务（如规划、编码、审查、测试），但这类系统在实际运行中失败频繁、原因隐蔽，最终输出错误往往源自较早阶段的约束遗漏、智能体交接问题、工具错误或模型响应偏差。
- 核心痛点：这类系统是多步骤、跨智能体、且具有随机性的分布式执行过程，简单日志或最终成功率不足以支撑深入调试、归因和正常/故障执行的对比。
- 该论文的整体含义：提出一个轻量级、框架无关的工具 **llmmas-otel**，将 OpenTelemetry 分布式追踪与故障注入结合，为 LLM-MAS 在软件工程中的受控实验、压力测试和调试提供可复用的基础设施。

## 2. 论文提出的方法论

- 核心思想：不重新发明 agent 框架，而是“包装”现有 LLM-MAS。用户只需在少量关键边界处标记插桩点，工具负责 span 创建、上下文传播和遥测导出。
- 输入输出：输入为现有 LLM-MAS + 任务 + 可选故障规范；输出为结构化且有注释的分布式追踪（traces）和离线消息记录，使基线运行与故障运行保持结构对齐。
- 使用步骤：
  1. 标记工作流边界，如任务开始、阶段切换、agent 步骤、A2A 通信、工具调用、LLM 调用；
  2. 先执行一次基线运行，获得基准 trace 和消息记录；
  3. 可选地配置故障规则，重新执行同一任务，得到用于对比的故障运行。
- 追踪模型：基于 OpenTelemetry 的 span 层次结构：
  - session span：一次完整任务运行；
  - segment span：工作流阶段；
  - agent-step span：具体智能体步骤；
  - a2a_send / a2a_receive span：智能体间通信；
  - tool call span：工具调用；
  - llm_call span：模型调用。
- 属性设计：定义统一的 span 属性词汇表（如 session.id、segment.name/order、agent.id、step.index、source/target agent、message.channel、tool.name、request.model、fault.injected 等），保证跨运行和跨工作流的可比性。
- 故障注入层：在 LLM 调用、工具调用、A2A send/receive 边界评估配置规则，支持的故障包括：
  - A2A send：delay、drop、truncate；
  - A2A receive：delay、drop；
  - Tool call：delay、not_installed、timeout、malformed_response；
  - LLM call：delay、rate_limit、timeout、network_error、malformed_response。
- 对齐设计：注入故障不改变 span 结构，只是在对应 span 上附加 fault 相关属性。这样基线 trace 和故障 trace 可以在同一结构下逐 span 对比。
- 效果指标：提出 **amplification** = 额外端到端运行时间 / 注入延迟。接近 1 表示近似线性开销，大于 1 表示局部扰动被放大。

## 3. 实验设计

- 目标系统 1：最小演示工作流 Planner → Coder，包含两阶段、两个 agent 步骤、一次 A2A 交接、两次 LLM 调用。
- 目标系统 2：ChatDev，一个更真实的、基于聊天的软件工程多智能体系统，覆盖设计、编码、测试三个生命周期阶段。

## 6. 论文的主要结论与发现

- llmmas-otel 能对 LLM-MAS 进行结构化、可复现的追踪记录，并通过 trace 对齐方式比较基线与受控故障执行。
- 在最小 demo 中，注入LLM延迟的整体放大倍数接近 1（均值 1.053），而 A2A 延迟的放大倍数更高（均值 1.295），说明通信边界扰动比孤立 LLM 调用更强地影响下游执行。
- 在 ChatDev 中，注入单次 LLM delay 的平均放大倍数达 48.1（中位数 13.9），A2A delay 的平均放大倍数达 59.2（中位数 6.6）。
- 这说明在消息密集、多阶段工作流中，局部小延迟可能被显著放大；而 llmmas-otel 能通过 trace 对齐使这种放大效应可量化、可观察。
- 作者总结认为，该工具为软件工程领域 LLM-MAS 的可观测性、可控压力测试和故障诊断提供了实用基础。

## 7. 优点

- 框架无关且轻量：不要求替换已有 MAS 框架，只需要少量插桩标记。
- 统一 trace 模型：一致的 span 层次和属性定义，使不同运行、不同工作流之间可以系统化比较。
- 可观测性与故障注入深度耦合：故障注入记录在原始操作 span 上，保持基线与故障运行的结构对齐。
- 配置驱动、可扩展：新增故障类型和 hook 不需要修改宿主工作流代码，重新配置即可复用。
- 针对软件工程场景设计：覆盖 A2A、工具调用、LLM 调用等关键交互边界，直接服务于 SE 工作流。
- 工具开源，并提供 demo、ChatDev 插桩和说明，便于复现与二次开发。

## 8. 不足与局限

- 故障注入面有限：仅覆盖 A2A、LLM 调用和工具调用；workflow 级、memory 相关和协调类故障尚未支持（作者在 future work 中承认）。
- 验证范围较窄：只实验了 delay 类故障；未覆盖论文中列出的其他故障类型。
- 缺乏与其他工具的系统性对比：没有与 AEGIS、AgenTracer 等最相关工作在相同条件下进行实证比较，因此难以评估相对优势。
