## 摘要
企业人工智能智能体日益频繁地调用工具、修改基础设施并处理受保护数据，因此需要将动作生成与动作授权分离。本文提出 VeriWeave Govern，一种确定性运行时治理层，它依据带版本策略评估结构化智能体动作，验证带类型的证据，应用固定的拒绝 > 复核 > 允许优先级，将重要动作路由至可问责的人工复核，并记录可重放且防篡改的审计状态。GovernBench 在 30 个独立随机种子和 60,000 个由 oracle 标注的案例上评估该设计，这些案例涵盖五个企业领域、对抗性证据、分布外动作以及时序策略演化。VeriWeave 在评估案例上达到 0.9888 的平均准确率、0.9836 的宏 F1、零观测到的总体误允许，以及零观测到的治理攻击成功率。六项消融实验表明，证据门控、拒绝优先、分布外失效安全行为、人工审查、矛盾处理以及时序重放共同贡献了互补的安全性。部署的 API 还通过了 12/12 个端到端场景以及包含 40,040 个请求的并发矩阵，且零失败。一项单独的、基于欧盟/奥地利法规的 150 个案例评估使用冻结预测和两名独立的盲法人工标注者，他们在所有决策上均一致。在该数据集上，确定性引擎保持保守，而 Gemma 4 31B 对比模型与人类共识更为接近。结果揭示了一种可度量的安全—效用权衡，并推动将证据感知、可重放的治理作为企业智能体执行的独立控制平面。

## Abstract
Enterprise artificial-intelligence agents increasingly call tools, modify infrastructure, and process protected data, creating a need to separate action generation from action authorization. This article presents VeriWeave Govern, a deterministic runtime governance layer that evaluates structured agent actions against versioned policies, validates typed evidence, applies fixed deny > review > allow precedence, routes consequential actions to accountable human review, and records replayable tamper-evident audit state. GovernBench evaluates the design over 30 independent seeds and 60,000 oracle-labelled cases spanning five enterprise domains, adversarial evidence, out-of-distribution actions, and temporal policy evolution. VeriWeave achieves 0.9888 mean accuracy, 0.9836 macro-F1, zero observed aggregate false allows, and zero observed Governance Attack Success Rate on the evaluated cases. Six ablations show that evidence gating, deny precedence, out-of-distribution fail-safe behavior, human review, contradiction handling, and temporal replay contribute complementary safety. The deployed API additionally passes 12/12 end-to-end scenarios and a 40,040-request concurrency matrix with zero failures. A separate 150-case EU/Austria regulation-grounded evaluation uses frozen predictions and two independent blinded human annotators, who agree on all decisions. On this set, deterministic engines remain conservative, while a Gemma 4 31B comparator aligns more closely with the human consensus. The results expose a measurable safety--utility trade-off and motivate evidence-aware, replayable governance as an independent control plane for enterprise agent execution.

## 1. 核心问题与整体含义

- **研究动机**：LLM 正从文本生成器演变为能够推理、调用工具并执行动作的智能体（ReAct、Toolformer 等范式）。能力跃迁改变了安全问题的性质——"错误回答"固然不理想，但"错误授权的动作"可能部署软件、泄露数据、发送外部消息或影响面向公民的流程。
- **核心问题**：传统授权机制（RBAC/ABAC 的角色与属性控制，OPA/Cedar 的策略外部化）提供了必要基础，但智能体治理还依赖**证据时效性、冲突控制、人类问责、未知动作处理以及策略演化**。例如，生产部署技术上被允许，但仍需当前变更审批与回滚方案；高影响动作即使文档齐全，也可能必须转交人工复核。
- **整体含义**：论文主张将**动作生成与动作授权分离**，不应让同一个随机组件既充当提案者又充当最终授权权威（避免循环信任模型）。VeriWeave Govern 被定位为一个**确定性治理边界**，置于智能体/工作流与产生副作用的工具之间，其最终决策路径不依赖 LLM。它不判断组织是否合法合规，而是操作化执行组织已选择编码的策略，并检验这些决策在缺失证据、冲突规则、未知动作、对抗输入与策略演化下是否保持稳定。

## 2. 方法论

- **核心思想**：将随机规划留在治理边界之外，边界内采用**证据门控的三态决策模型**，并强制一组运行时不变式（无隐式允许、拒绝主导、证据单调性、问责制、时间保真、可重放完整性）。
- **请求形式化**：治理请求表示为 `x = ⟨a, o, r, p, c, E, t⟩`，分别对应智能体/工作负载身份、操作、资源、目的、上下文属性、提交的证据集与评估时间。规则 `q` 包含谓词、目标决策 `dq ∈ {allow, review, deny}`、所需证据类型、版本元数据与可选复核队列。
- **决策归约（核心公式）**：设 `Q(x)` 为匹配规则集，`G(x) ∈ {0,1}` 表示证据门是否全部满足：
  - 升级条件 `U(x) = 1[∃q ∈ Q(x): dq = review] ∨ ¬G(x) ∨ 1[Q(x) = ∅]`
  - 最终决策 `D(x)`：若存在 deny 规则则 deny；否则若 `U(x)=1` 则 review；否则 allow。
  - 关键设计：`Q(x)=∅` 将未知动作固定为 review（OOD 失效安全）；deny 优先级保证禁止规则不会被同时匹配的允许规则覆盖。
- **证据门控**：每条证据映射到权威性、当前状态、签名、实质内容、策略引用语言、矛盾等特征，用逻辑回归信任分数 `s(e) = σ(wᵀφ(e)+b)` 拟合（训练数据与评估分离）。仅当 `s(e) ≥ τ` 且类型满足规则要求时才被接受。类型化充分性 `Gq(x) = ⋀η∈Tq 1[∃e∈E: type(e)=η ∧ A(e)=1]`，防止"证据数量"变成隐式投票。
- **审计完整性**：采用 SHA-256 哈希链 `hi = SHA256(hi−1 ∥ Ri)`，可选 HMAC 签名；要求链头或检查点受外部保护，否则全量重写历史无法被哈希链阻止。
- **反事实治理证书**：输出观测决策、最小支撑证据、缺失证据、策略版本及"改变决策的扰动"，且反事实通过同一确定性决策函数重算，而非自由文本解释。
- **理论性质**：三条命题——拒绝主导（增加 allow/review 规则不能使决策更宽松）、证据单调性（移除/过期/降级证据不会产生新的 allow）、重放确定性（相同归一化请求、策略版本、特征提取与阈值下，重复评估返回相同决策、理由与匹配规则集）。计算复杂度约 O(m+n)，矛盾检查朴素实现会引入成对开销。
- **架构组件**：评估 API（校验/归一化）、策略匹配器（版本化谓词）、证据验证器（权威性/新鲜度/签名/矛盾）、决策归约器（deny > review > allow + OOD 失效安全）、复核路由器（映射到可问责队列）、审计/重放（哈希链 + 历史策略版本重放）。
- **策略生命周期**：策略版本、评估时间与来源快照作为一等输入；历史重放绑定旧请求与旧策略哈希，实时评估绑定当前策略包；支持影子模式上线、反事实证书回归测试与"决策 diff"（新允许/新复核/新拒绝）。
