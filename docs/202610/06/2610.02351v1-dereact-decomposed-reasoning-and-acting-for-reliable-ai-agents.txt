Abstract
ReAct-based agents typically rely on a single
LLM policy to propose actions, interact with
the environment, and decide when a task is
complete. This coupling makes action autho-
rization and completion control difficult to en-
force independently, allowing errors to prop-
agate and unsupported completion claims to
terminate execution. We introduce DeReAct,
a modular agent architecture that externalizes
two gating policies: a Critic that validates pro-
posed actions before execution, and a Con-
text Manager that reconstructs an environment-
supported STATE and certifies task completion.
Across GAIA and SWE-bench Verified, DeRe-
Act improves Pass@1 most for weaker Brain
models, with gains of 6.5–7.0 points for
Qwen3-Coder-480B and 4.2–5.2 points for
Claude Sonnet 4.5; gains diminish as Brain
capability increases. Trajectory and ablation
analyses show that external gating is effective
when targeted failures are sufficiently prevalent
and the gating policy is itself sufficient. With
Claude Opus 4.5, Pass@1 remains compara-
ble to ReAct, while DeReAct produces more
evidence-complete and constraint-satisfying
trajectories, indicating that completion con-
trol can trade earlier termination for stronger
grounding. Overall, DeReAct improves weaker
agents while retaining grounding benefits as
models strengthen.

Introduction
ReAct (Yao et al., 2023b) and related single-policy
agents (Shinn et al., 2023; Yao et al., 2023a; Chen
et al., 2025a) commonly rely on one policy to inter-
leave reasoning, action, and observation throughout
execution. While simple and effective, this design
couples task solving with two reliability-critical de-
cisions: whether a proposed action should reach the
environment and whether the task is complete. The
task-performing policy therefore authorizes its own
*Corresponding author
actions and certifies its own completion. Errors
can consequently propagate through the trajectory,
distort later decisions, and trigger premature ter-
mination before sufficient evidence is gathered or
task requirements are satisfied, a recurring failure
pattern in LLM agent systems (Cemri et al., 2025).
This pattern is confirmed by our trajectory analy-
ses, which show that some early completions are
weakly grounded or explicitly guessed.
Existing methods address stages of this failure
pattern. Runtime guardrails and reviewer policies
constrain actions before execution (Wang et al.,
2026; Ta et al., 2026), while self-correction and ver-
ifier methods critique outputs or track task progress
(Gou et al., 2024; Chen et al., 2025b; Han et al.,
2026). Context-management systems compress or
externalize long trajectories (Packer et al., 2023;
Kang et al., 2026). However, these approaches do
not jointly separate action authorization and com-
pletion control from ReAct or ground both in in-
dependently reconstructed, environment-supported
evidence. Consequently, invalid actions may reach
the environment, while completion may rely on
unverified reasoning or prior errors.
To address this gap, we introduce DeReAct, an
inference-time architecture that decomposes the
ReAct loop into a task-solving Brain and two in-
dependently configurable gating policies: a Critic
and a Context Manager (CM). The Critic is a
hard pre-execution gate that blocks actions violat-
ing configured validity or task constraints. After
each executed action, the CM reconstructs a com-
pact STATE from environment-supported evidence,
excluding the Brain’s unverified reasoning, and ac-
cepts completion only when the STATE supports it.
DeReAct thus separates action authorization and
completion control from task reasoning.
We evaluate DeReAct on GAIA (Mialon et al.,
2024) and SWE-bench Verified (Jimenez et al.,
2024) across three Brain capability levels. DeRe-
Act improves Pass@1 most for weaker Brains, with

gains diminish with Brain capability; with Claude
Opus 4.5, Pass@1 remains comparable to ReAct.
Pass@3 shows a complementary pattern: repeated-

Ablations show that the Critic and CM contribute
differently across Brains and domains, and that
intervention frequency alone does not predict ef-

targeted failures are sufficiently prevalent and the
gating policy is itself sufficient: its prompt, model,
and available context must support reliable inter-
vention. Prompt-, model-, and context-level limita-
tions can be diagnosed from trajectories.
To summarize, our contributions are threefold.
We introduce DeReAct, which externalizes pre-
execution action authorization and task-completion
control around an environment-supported STATE.
We evaluate it across benchmarks and Brain capa-
bility levels, analyzing task performance, trajectory
grounding, and the roles of its gating policies. Fi-
nally, we introduce policy sufficiency to diagnose
when external gating is effective across Brains and
domains.

Related Work
Model–Scaffold
Interactions.
Recent
work
shows that agent performance depends on both
base-model capability and scaffolding.
Ríos-
García et al. (2026) find that the former explains
most performance variance, while scaffolding pri-
marily helps procedural reasoning.
Hao et al.
(2026) show that different scaffolds solve partially
disjoint SWE-bench problems and benefit from
stronger models during scaffold editing. Both treat
the scaffold as an aggregate choice; DeReAct in-
stead decomposes it into control policies and stud-
ies how their contributions vary with capability.
Pre-Execution Validation in Agent Loops.
Prior work constrains agent behavior through
runtime validation and monitoring, including ex-
ecutable guardrails, formal verifiers, and pre-
execution reviewers (Wang et al., 2026; Xiang
et al., 2025; Miculicich et al., 2025; Bhat et al.,
2026). Closest to DeReAct’s Critic is Reinforced
Agent (Ta et al., 2026), which reviews proposed
tool calls before execution. DeReAct instead evalu-
ates each intent–command pair against the verified
STATE and enforces rejection as a hard gate, leav-
ing the environment unchanged.
Completion Verification and Termination Con-
trol.
Premature termination and inadequate task
verification are recurring failure modes in agent sys-
tems (Cemri et al., 2025). Prior work explores self-
correction with model or tool feedback (Madaan
et al., 2023; Gou et al., 2024), though such correc-
tion is unreliable without external feedback (Huang
et al., 2024).
Other systems introduce explicit
completion verification (Chen et al., 2025b; Han
et al., 2026). DeReAct applies completion con-
trol to the full trajectory of a general ReAct agent:
the Context Manager reconstructs an environment-
supported STATE that excludes the Brain’s unveri-
fied reasoning and ratifies a final answer only when
that state supports task completion.
Context Management and Agent Memory.
Long agent trajectories motivate context selection,
compression, and externalization (Liu et al., 2024).
MemGPT (Packer et al., 2023) manages in-context
and archival memory, while ACON (Kang et al.,
2026) compresses trajectory history. DeReAct’s
STATE is neither a general-purpose summary nor
a memory store: it is rebuilt from environment-
supported evidence at each step and paired with a
separate sliding window of recent raw history.
Multi-Agent and Loop Decomposition.
Multi-
agent frameworks such as AutoGen (Wu et al.,
2024) and MetaGPT (Hong et al., 2024) distribute
sub-tasks across model instances, whereas DeRe-
Act decomposes the control loop of a single agent.
Smurfs (Chen et al., 2025b) is closest in spirit,
but decomposes branching search and verifies sub-
tasks, while DeReAct separates reasoning, action
authorization, verified-state construction, and com-
pletion control within a linear ReAct loop.

The DeReAct Architecture
Standard ReAct (Yao et al., 2023b) uses a single
policy that, at each step, produces a reasoning trace
(Thought) and an action (Action); the resulting ob-
servation is appended to the trajectory until the
model emits a Final Answer. Thus, the same policy
both selects actions and declares task completion,
against a history that interleaves environment feed-
back with its own reasoning.
DeReAct decomposes this loop into three inde-
pendently prompted modules (Figure 1): a Brain,
a Critic, and a Context Manager (CM). The Brain

Critic checks configured pre-execution constraints
such as safety, syntax, and explicit task require-
ments, but not strategy or task progress, provid-
ing an independent validation layer that may use a
smaller model than the Brain.
Context Manager (πcm : (X × I × C × R) →
∆(S ×X)). After command ct returns result rt, the
CM reconstructs the verified context xt+1 (STATE)
and sets st+1 ∈{SUCCESS, CONTINUE}. The
STATE contains only environment-supported facts,
excluding the Brain’s unverified reasoning, and is
replaced rather than appended each step to avoid
reverting to the interleaved trajectory it replaces.
The raw-history window is available only to the
Brain, not to the Critic or CM. This separates veri-
fied evidence from recent procedural detail. After
each executed action, the CM returns SUCCESS
only if the STATE contains sufficient evidence that
the task-completion criteria are satisfied; otherwise,
it returns CONTINUE. The execution loop termi-
nates only on SUCCESS.

4.4
Policy Activation and Sufficiency
We use policy sufficiency to describe how well a
gating policy is suited to a setting, treating it as
continuous rather than binary. For the CM, suf-
ficiency depends on three adjustable levers: the
completion prompt, which controls veto behavior;
the CM model, which determines STATE fidelity;
and the Brain’s history window, which determines
whether required evidence remains available. We
assess the first two with an independent Claude
Opus 4.7 judge, blind to benchmark outcomes, on
100 sampled complete trajectories per configura-
tion. STATE GOOD measures preservation of veri-
fied evidence, while FAV POOR measures unsup-
ported Final Answer Validation. Together with veto
rates and trajectory lengths, these diagnose prompt,
model, and context limitations from trajectories.
High activation can still be harmful. On SWE-
bench, the Haiku CM vetoes 93.1% of Qwen3 final
answers yet lowers Pass@1 by 3.5 points, with only
37% STATE GOOD and 33% FAV POOR (Table 22).

on GAIA. These are empirical diagnostics rather
than universal thresholds.

Grounded Exploration
We first ask whether CM vetoes promote productive
exploration rather than merely longer trajectories.

least one CM veto. DeReAct achieves higher reso-
lution rates for Qwen3 and Sonnet on both bench-
marks (+7.1 and +7.5 points on GAIA; +6.4 and
+9.7 on SWE-bench Verified). Ablation A shows
the same pattern (Tables 14 and 21), showing that
it persists without the Critic.
For Opus, the difference narrows to +3.4 points
on GAIA and −1.7 on SWE-bench.
However,
ReAct’s additional resolutions are not uniformly
grounded: among pairs unresolved by DeReAct,
ReAct resolves 15.6% on GAIA and 17.8% on
SWE-bench, of which only 20.0% and 61.9%, re-
spectively, are grounded in evidence. This indicates
that some ReAct successes arise from early com-
pletion with weakly supported or guessed answers
rather than fully grounded evidence.
We next examine whether DeReAct improves
consistency or broadens success across repeated at-
tempts using Diff = ∆Pass@3−∆Pass@1. Nega-
tive Diff indicates consistency gains, whereas posi-
tive values indicate broader success across attempts.
On SWE-bench, Qwen3 and Sonnet have negative
Diff (−2.5 and −1.7), while Opus is positive across
all configurations on both benchmarks (Figure 2).
Thus, with stronger Brains, DeReAct shifts from
consistency gains toward broader exploration.
Finally, an independent Claude Opus 4.7 judge,
blind to benchmark outcomes, evaluates Opus 4.5
trajectories for evidence completeness, constraint
satisfaction, and admitted guessing on GAIA, and
appropriate testing on SWE-bench (Appendix B.5).
Tables 5 and 6 further confirm this pattern. On
GAIA, DeReAct increases evidence completeness
and constraint satisfaction while reducing admitted
guessing, with the largest gains among incorrect
trajectories. SWE-bench shows smaller but con-
sistent gains in appropriate testing, including on
unresolved trajectories.
4.6
Cost and Efficiency
DeReAct adds inference cost and can lengthen tra-
jectories through the Critic and Context Manager.
Cost and step distributions (Tables 13 and 20) show
the same broad pattern: overhead is largest with
weaker Brains and narrows as Brain capability in-
creases, especially on SWE-bench Verified. On
GAIA, mean per-run cost is about 2.9× ReAct with
the Opus Brain and step counts retain a heavier tail;
on SWE-bench, the strongest Opus configurations
approach or match ReAct in mean cost despite the
additional gating policies.

Conclusion
We introduced DeReAct, which separates task
reasoning from action authorization and comple-
tion control. Across GAIA and SWE-bench Ver-
ified, DeReAct improves task success for weaker
Brains while remaining comparable to ReAct with
the strongest Brain, where it still produces more
grounded trajectories. Our analyses show that exter-
nal control is effective when the underlying policy
exhibits the targeted failures and the control policy
is itself sufficient for the task and domain.
These findings suggest a practical design prin-
ciple for reliable agent systems: action authoriza-
tion and completion control need not remain inside
the task-solving policy. Externalizing these deci-
sions provides configurable control points that im-
prove weaker agents and retain value as base mod-
els strengthen. Future work should validate them
across new domains and deployment constraints.

6
Limitations
Our evaluation is limited to GAIA and SWE-bench
Verified and does not cover several practically im-
portant agent settings, including multi-turn dia-
logue, human-in-the-loop workflows, and agents
whose actions have real-world side effects. Gener-
alization to these settings remains open, as both fail-
ure prevalence and policy sufficiency may change
with the interaction structure, available feedback,
and deployment constraints.
An important open question is how DeReAct
generalizes across model families and capability
regimes. In our experiments, the Critic and Con-
text Manager are Claude models throughout, and
only one open-weight Brain is evaluated. Future
work should test whether the observed capability-
dependent behavior and policy-sufficiency patterns
persist across additional model families and non-
Claude gating policies. The configuration proce-
dure in Section 4.4 should likewise be validated
prospectively on new Brains and benchmarks.
Grounding is operationalized differently across
the two benchmarks: evidence completeness on
GAIA and appropriate testing on SWE-bench Veri-
fied. Cross-benchmark comparisons therefore con-
cern rates of ungrounded completion under domain-
specific criteria rather than identical grounding met-
rics. All judge-based analyses use a single judge
model (Claude Opus 4.7), and CM decision-quality
ratings are based on 100 sampled trajectories per
configuration.
Cost accounting uses list prices without prompt
caching or batching. Because full-history ReAct
benefits more from prefix caching than DeReAct’s
sliding windows, the reported cost parity on SWE-
bench Verified may change under caching-aware
deployment; cache-aligned windowing remains fu-
ture work. We also set Tmax=1000 to study intrin-
sic termination behavior, which increases mean
cost through a tail of failing runs.
Production
systems would typically use tighter step limits,
for which we additionally report medians and per-
centiles.

B
Prompt Templates
This appendix presents the prompts used in our evaluation. The ReAct system prompt is universal:
identical across all benchmarks (GAIA and SWE-bench Verified) and across all configurations (Full
DeReAct, Brain + Context Manager, Brain + Critic, ReAct). The Critic and Context Manager prompts
adapt per benchmark.
B.1
ReAct Prompt (Universal)
The same system prompt is used for ReAct (the monolithic baseline) and for the Brain component in all
DeReAct configurations across all benchmarks. This normalization is deliberate: holding the Brain’s
reasoning prompt constant ensures that any architectural effect on Brain behavior is attributable to the
architectural injection of the Critic and Context Manager, not to differences in how the Brain itself is
prompted.
System Prompt: ReAct & Brain Component
You are an AI agent using the ReAct (Reasoning + Acting) framework to accomplish tasks.
For each step, you should:
1. Think about what needs to be done next (Thought)
2. Decide on a single action to take (Action)
3. Execute the action and observe the result (Observation)
You MUST respond with exactly ONE Thought and ONE Action per response.
Do NOT plan multiple steps ahead.
Format your response as:
Thought: [your reasoning about what to do next]
Action: [the command to execute]
When the task is complete, respond with:
Thought: [explanation of why task is complete]
Final Answer: [summary of what was accomplished]
"Action" and "Final Answer" should be mutually exclusive, and therefore they should never appear
in one response at the same time.
CRITICAL FORMATTING RULES FOR ACTIONS:
- Output ONLY the raw command text after "Action:"
- NO markdown formatting
- NO code blocks with “‘ delimiters
- NO backticks around the command
- NO comments or additional text
The command will be executed directly as-is in a sandboxed environment.
