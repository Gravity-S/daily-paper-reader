ABSTRACT 

The growing adoption of large language model (LLM) agents creates a need for network administrators and security teams to audit agent behavior within organi-zational networks without inspecting private user content. Network traffic offers an observable source of evidence, but how much it reveals about agent tasks and operations remains unclear. Existing traffic datasets lack the joint task and stage annotations needed to evaluate this question. We introduce ANT ( Agent Network 

Traffic), a dataset providing agent behavior information at risk, scenario, and behavior primitive granularities alongside network traffic. ANT contains 3,114 execution episodes across 20 tasks and five scenarios, comprising 276,417 bidi-rectional flows and 40,049 behavior primitive segments organized into 47 macro groups. We establish a benchmark for agent risk identification, scenario recogni-tion, and behavior primitive classification using 13 representative traffic analysis baselines. The results show that existing methods recover useful but uneven be-havioral signals. They struggle to identify risk when malicious workflows resem-ble benign tasks and to distinguish scenarios with similar traffic patterns. Primitive classification is more reliable for frequent macro groups and those with distinc-tive traffic patterns than for rare or semantically similar groups. ANT provides a common basis for developing more precise auditing and forensic analysis of agent behavior from network traffic. Our data and code are available at https: //anonymous.4open.science/r/ant-main-suite-7BC0/ .

1 INTRODUCTION 

LLM agents are evolving from conversational assistants into systems that can plan, invoke tools, and interact with external environments on users’ behalf, driving their adoption in everyday workflows. However, this adoption has also raised governance concerns. Microsoft reports that 58% of surveyed organizations are concerned about unsanctioned generative AI use, while 57% report an increase in security incidents associated with AI use (Microsoft, 2024; 2025). Since Agent communications are encrypted during transmission, organizations need mechanisms to identify and govern LLM agent use without relying on deep inspection of user content. Encrypted traffic analysis offers a promising way to meet this need. Rather than examining en-crypted payloads, these methods infer applications and activities from observable traffic features, such as packet sizes and timing. These signals support application identification, website finger-printing, malicious traffic detection (Canadian Institute for Cybersecurity, 2016b) etc. Zhang et al. (2025a) further show that encrypted traffic can reveal fingerprints of agent interactions. Answering this question requires accounting for the distinctive structure of LLM agent traffic. Fig-ure 1 illustrates an execution of a question answering task using the Claude Code harness (Anthropic, 2026) and a DeepSeek backend (DeepSeek-AI et al., 2025). The upper timeline shows the sequence of model calls and tool events, while the lower timeline shows the network flows observed during the same period. At the semantic level, the execution can be partitioned into a sequence of behavior primitives , each of which pursues a coherent subgoal. A behavior primitive typically encompasses communication with the backend model for reasoning and planning, invocation of a selected tool, and analysis of the returned result. Correspondingly, bursts of network traffic appear near the onset of each behavior primitive. Primitives with different subgoals also produce different traffic compo-sitions and interaction patterns. For example, traffic during a WebSearch primitive is dominated by communication with the model backend because Claude Code delegates the search operation to that backend. By contrast, a WebFetch primitive introduces DNS lookups and Web content down-load flows because the agent retrieves the content of a specified URL. These differences show that network traffic carries signals associated with both an agent execution and its constituent behavior primitives. Systematically evaluating these behavioral signals requires traffic traces paired with annotations of both overall tasks and local execution stages. Existing datasets do not provide the traffic and an-notations needed to evaluate agent risk, task scenarios, and behavior primitives. Traditional traffic datasets typically label applications, websites, or fixed workloads, including browsing, chat, and file transfer (Canadian Institute for Cybersecurity, 2016b;a; Wang et al., 2017; Aceto et al., 2019; Siri-nam et al., 2018). However, they contain neither traffic generated by agent model–tool–environment loops nor descriptions of the corresponding execution stages. AgentPrint identifies agents and coarse activities (Zhang et al., 2025a), but lacks joint annotations for episode risk, task scenarios, and be-havior primitives. To close this evaluation gap, we introduce ANT, a dataset for analyzing agent behavior from user-side network traffic. ANT contains 3,114 execution episodes across 20 tasks and five scenarios, covering legitimate applications and cybersecurity misuse. Its 276,417 bidirectional flows are paired with task and runtime metadata. To expose execution semantics, we align traffic with session logs and construct 40,049 behavior primitive segments in 47 primitive macro groups. Meanwhile, we establish a benchmark for evaluating traffic analysis methods on risk identification, scenario recog-nition, and behavior primitive classification. Although all 13 baselines exceed 0.900 accuracy in risk identification, seven attain malicious class recall below 0.500, reflecting their difficulty in detecting content level misuse. The best baseline for scenario recognition reaches 0.727 accuracy, indicating that scenario semantics are partly recoverable even though similar scenarios remain difficult to dis-tinguish. For behavior primitive classification, existing baselines perform better on frequent macro groups and groups with distinctive traffic patterns, but struggle with rare and semantically similar groups. Our contributions are threefold: 1. We introduce ANT, a dataset of network traffic collected during client-side LLM agent execution, with task metadata for each episode and behavior primitive annotations aligned with traffic segments. 22. We establish a benchmark with three tasks: episode-level risk identification and scenario recognition, and segment-level behavior primitive classification. We evaluate 13 existing traffic analysis methods on this benchmark. 3. We show that existing methods can infer aspects of agent behavior from network traffic, but often miss malicious tasks that resemble benign workflows and confuse scenarios with similar traffic patterns. Behavior primitive classification remains difficult for rare or se-mantically similar groups. 

2 BACKGROUND AND MOTIVATION 

2.1 INFERRING AGENT BEHAVIOR FROM NETWORK TRAFFIC 

LLM agents move through model calls, tool invocations, and interactions with external services (Liu et al., 2024; Zhou et al., 2024). These transitions produce changes in observable packet sizes, direc-tions, timing, and destinations, even though encryption hides payload content. Traffic analysis meth-ods already use such features to identify websites and applications and detect cyberattacks (Sirinam et al., 2018; van Ede et al., 2020; Lin et al., 2022; Wang et al., 2024; Fu et al., 2025). Recent work recovers response content and topics from token length leakage in encrypted LLM streams (Weiss et al., 2024), while NetEcho targets recovery of both user prompts and LLM responses from en-crypted streaming traffic (Zhang et al., 2025b). However, these studies either evaluate methods on conventional traffic datasets or focus on recovering conversation content. They do not jointly evaluate agent behavior identification at the risk, scenario, and behavior primitive granularities. 2.2 THE NEED FOR A MULTI -GRANULARITY AGENT TRAFFIC DATASET 

Existing traffic datasets lack the combination of agent execution traces and behavior labels needed for this evaluation. Website and application corpora label sites or apps (Sirinam et al., 2018; van Ede et al., 2020), but not complete agent executions with synchronized stages. AgentPrint identifies agents and coarse activities (Zhang et al., 2025a), but lacks joint annotations for episode risk, task scenarios, and behavior primitives aligned with execution stages. We therefore collect traffic alongside execution logs from locally executed agents and align packet traces with task and stage semantics. Common splits, objectives, and metrics enable a unified bench-mark for agent risk identification, agent scenario identification, and behavior primitive identification. 

3 ANT D ESIGN 

To systematically investigate the mapping from observable network traffic to high-level agent se-mantics, we construct ANT. We deploy an automated collection infrastructure across geographically distributed cloud servers and collect packet-level traffic together with agent session logs, at a total collection cost of US$2,176.50. ANT contains 3,114 execution episodes collected under five agent combinations across 20 tasks in 5 scenarios, corresponding to 659 distinct task instances and 104.07 GB of traffic. To establish a multi-granularity benchmark, we annotate each episode with task and runtime metadata and construct behavior primitive segments from boundaries derived from session logs. In total, ANT comprises 276,417 bidirectional flows and 40,049 behavior primitive segments categorized into 47 primitive macro groups. We instantiate the four common scenarios with 17 benchmark-derived agent execution tasks. The misuse-oriented scenario is instantiated with three agent execution tasks derived from Meta’s Pur-pleLlama Cybersecurity Benchmarks and the OWASP Juice Shop vulnerability challenge platform. Across these scenarios, the selected execution tasks cover diverse agent behaviors, including differ-ent tool requirements, interaction patterns, external service dependencies, reasoning demands, and execution complexity. Each execution task further contains multiple task instances spanning differ-ent domains and difficulty levels. Detailed descriptions of the five scenarios and their corresponding tasks are provided in Appendix A.1. Following the definition of the task space, tasks are executed through a data collection system de-signed to simultaneously capture agent trajectories and network traffic, as illustrated in Figure 3. For each task instance, the system initializes the required workspace and runtime environment, supplies the natural-language task prompt, and launches the agent. The agent interprets the task, queries the model, invokes tools such as web search and shell commands, and incorporates the returned results into subsequent decisions until it produces a final response. Throughout this process, the system records model calls, tool invocations, tool outputs, and session states with their timestamps. Mean-while, tcpdump captures all inbound and outbound packets in PCAP format. The shared timeline links execution events to the corresponding packet-level traffic for behavior primitive segmentation. To guarantee the integrity, authenticity, and purity of the traffic data and address ethical considera-tions, we enforced rigorous environmental controls throughout the collection process. Each task in-stance ran in an independent virtual network namespace to prevent interference between concurrent tasks. Agents could access only their active workspace and necessary runtime environments, pre-venting shortcuts such as reading pre-existing answers instead of performing network retrieval. We used only public benchmark inputs, without real-user accounts, private communications, or person-ally identifiable information. Benign tasks requiring state-changing interactions ran against locally simulated services, while attack execution remained inside isolated Docker environments to protect collection servers and production systems. For Attack Code Generation, we used publicly released mutated prompts from Meta’s PurpleLlama Cybersecurity Benchmarks without additional jailbreak, prompt-obfuscation, or safety-bypass strategies, and excluded refusal-only episodes from the traffic corpus. These measures preserve model safety mechanisms and reduce interference during traffic collection. The Ethics Statement provides the full declarations. 3.2 BEHAVIOR PRIMITIVE ANNOTATION 

We annotate traffic segments with behavior primitives that describe the agent’s local execution ac-tions. We sort PCAP packets by arrival timestamp and bin them using each behavior primitive’s start time from the session logs as a boundary; packets of a transport flow spanning boundaries are assigned individually to the corresponding segments. We then use DeepSeek-v4-pro (DeepSeek-AI, 2026) to derive a behavior primitive from the aligned log evidence and assign it to the correspond-ing segment (annotation prompt in Appendix B.1). These primitives capture local execution actions rather than only the episode’s overall objective. Traffic preceding the first recorded behavior primi-tive is retained as a separate segment with a synthetic prelude label. The resulting primitive sequences expose differences in how agents carry out their tasks. Risk Identification. This objective evaluates the ability of traffic analysis methods to identify whether agent activities are malicious from network traffic, thereby supporting the mitigation of agent abuse. 

Scenario Recognition. This objective evaluates the ability of traffic analysis methods to recognize an agent activity scenario from an episode’s network traffic, supporting the compliance management of agent usage.

This objective evaluates whether traffic analysis methods can classify each behavior primitive segment into one of the 47 primitive macro groups using its network traffic. We compare existing encrypted traffic classification and website fingerprinting methods to assess their ability to recover agent behavior at different granularities, and use traffic scope and segment ablations to examine which components support scenario recognition. These comparisons reveal which behavioral signals current methods capture and where their limitations motivate more precise representations for agent auditing. 4.1 BASELINES AND EXPERIMENTAL SETUP 

Baselines. We evaluate ANT with 13 encrypted traffic classification and website fingerprinting baselines covering convolutional networks, Transformers, state-space models, and learned traf-fic representations. The encrypted traffic classification baselines are FlowLens (Barradas et al., 2021) [code], YaTC (Zhao et al., 2023) [code], NetMamba (Wang et al., 2024) [code], TFusion (Fu et al., 2025) [code], and TrafficFormer (Zhou et al., 2025) [code], spanning compact flow statistics, packet content, and sequential representations. The website fingerprinting baselines are Deep Fin-gerprinting (DF) (Sirinam et al., 2018) [code], AWF (Rimmer et al., 2018) [code], Tik-Tok (Rahman et al., 2020) [code], Var-CNN (Bhat et al., 2019) [code], NetCLR (Bahramali et al., 2023) [code], TMWF (Jin et al., 2023) [code], ARES (Deng et al., 2025) [code], and BAPM (Guan et al., 2021) [code], spanning direction and timing features, learned trace representations, and methods for multi-tab traffic. Appendix D.1 describes each method. 

Experimental setup. We randomly split episodes within each task into fixed training, validation, and test sets shared by all benchmarks. Behavior primitive segments inherit their source episode’s split, preventing segments from the same episode from entering different sets. The episode test set contains 209 episodes (189 benign and 20 malicious). Inputs use only packet headers and side-channel features such as packet direction, timing, and length. We mask identifying fields such as source and destination IP addresses to mitigate shortcut learning. Encrypted traffic classifica-tion baselines operate on flows, whereas website fingerprinting baselines operate on episodes. For episode-level evaluation, we aggregate flow predictions using the strategy with the highest validation accuracy among four candidates. As shown in Table 3, all 13 baselines achieve accuracy above 90% on the test set. However, more than half of the baselines achieve recall below 50%. AWF and FlowLens reach only 15% and 20%, respectively. This gap becomes clearer across individual abusive tasks. Figure 5 presents recall for three abusive tasks and specificity for the semantically similar regular code generation task. Multiple baselines achieve high recall for web penetration but substantially lower recall for the other two abusive tasks. Specifically, YaTC, NetMamba, TFusion, and TrafficFormer yield a 0.000 detection rate for malicious code generation and sandbox evasion while achieving a detection rate near 1.000 for web penetration. In contrast, TikTok, NetCLR, ARES, and BAPM perform relatively well across all three abusive tasks. This result indicates that abusive behaviors leave identifiable signatures in network traffic. Web penetration’s higher recall stems from its direct network interactions like scanning, SQL in-jection, and XSS leave distinct traffic clues. In contrast, malicious code generation and sandbox evasion rely on code content and execution intent, which encryption obscures. Their observable traf-fic closely resembles normal coding tasks, differing primarily in repeated security bypass attempts, backend model calls, and strategy adjustments. Identifying these abusive behaviors requires analyz-ing interaction context, stage sequences, and multi-flow relationships. The detection gap between normal and abusive tasks highlights the difficulty existing models face in recovering this complex risk intent. 

Takeaway. Baseline capability gaps are largest for attacks whose intent is not directly visible in traffic and whose execution resembles benign operations. 4.3 SCENARIO RECOGNITION RESULTS

Although we upsample rare groups to at least 200 training samples, correct predictions remain concentrated on frequent groups and groups with stable traffic patterns. Models also struggle to distinguish semantically similar primitive macro groups. For example, 37 of 204 browser fetch segments are predicted as search . Among 527 search segments, 38 are predicted as api query and 35 as browser fetch . These errors occur among related retrieval groups. The confusion shows that local traffic patterns carry useful signals, but current baselines struggle to distinguish these primitive macro groups from traffic alone. 

Takeaway. Traffic carries predictive signals for primitive macro groups, but existing baselines classify frequent groups and groups with distinctive traffic patterns more reliably than rare or semantically similar groups. 

5 DISCUSSION 

ANT supports research on agent behavior inference, transfer learning, and privacy defenses by providing paired traffic and semantic annotations and a common benchmark. We recognize that these auditing capabilities also pose dual-use risks, as attackers could exploit them to infer private user activities. Nevertheless, we believe that systematically studying these capabilities is essential for understanding privacy exposure and developing effective defenses, while enabling responsible oversight of agent use. Our study has three main limitations. First, financial and computational constraints limit coverage of agent applications and configurations, despite including prevalent use cases and diverse tasks. Second, AI annotation and grouping can introduce opaque or inaccurate decisions. We mitigate these risks through repeated AI interaction and iterative review and a manual spot check. Third, we collect part of ANT in controlled local environments for ethical reasons. However, this may cause traffic timing to differ from that in real deployments. Nevertheless, widely used traffic datasets such as ISCXIDS2012 (Shiravi et al., 2012) and CICIDS2017 (Sharafaldin et al., 2018) also rely on controlled testbeds. Their widespread adoption suggests that controlled testbeds can still provide useful benchmarks for comparative model evaluation. 

6 CONCLUSION 

We construct ANT, a dataset that pairs traffic with episode metadata and behavior primitive annota-tions, covering 3,114 episodes across 20 tasks and five scenarios, with 276,417 bidirectional flows, 9104.07 GB of traffic, and 40,049 primitive segments in 47 macro groups. To our knowledge, it is the first dataset dedicated to network traffic from client-side LLM agent execution. Our benchmark eval-uates 13 methods on risk identification, scenario recognition, and behavior primitive classification.
