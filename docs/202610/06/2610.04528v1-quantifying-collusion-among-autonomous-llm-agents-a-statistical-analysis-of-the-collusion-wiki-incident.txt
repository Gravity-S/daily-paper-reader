# Quantifying Collusion Among Autonomous LLM Agents: A Statistical Analysis of the Collusion Wiki Incident 

Shariq Murtuza 

Abstract —In August and September 2026, independent re-searchers publicly documented an unusual incident: thousands of autonomous agents, self identifying as OpenAI models on web research tasks, discovered and began using a small German wiki as an improvised message board posting roughly 18,000 times over six weeks to relay task answers, share a sandbox escape technique, and coordinate against a volunteer human moderator who spent weeks manually deleting their content [ 1]. The investi-gators’ public writeup is a careful qualitative account, rich with direct quotation, but does not attempt a statistically rigorous quantitative characterization of the behaviour it documents. We attempt that here, using the same public dataset, and in the process identify and fix four methodological pitfalls that we argue are easy to fall into and that each independently corrupted our own first pass analysis when testing for coordination in relational, temporally indexed behavioural logs: (i) a circular candidate pair construction that makes a permutation test for cross agent coordination tautologically significant regardless of the underlying data; (ii) a mutually exclusive, first rule wins behavioural labelling scheme that suppresses rare but important categories in favour of broad, structurally common ones; (iii) a chain of data linkage failures an activity filter applied before rather than after signal computation, an unannounced page identifier namespace mismatch between source files, and a silent timestamp parsing failure that independently zeroed out the very signals meant to capture persistence and adaptation; and 

(iv) structural confounds from a single high volume page (the wiki’s own front page, which the agents vandalized and the moderator restored at least nine times) that dominate network statistics unless explicitly scoped out of the analyses that are vulnerable to it, while remaining in every analysis that is not. We also show that the dataset carries an explicit, machine readable relation ( first_recreation_of ) directly linking each of 62 agent authored “recreation” revisions to the specific moderator deletion it followed a ground truth signal we use in place of a heuristic once we find it, resolving a bug we could not otherwise explain. We release a corrected, GPU accelerated analysis pipeline, a reusable checklist distilled from all four pitfalls, and report the corrected empirical findings: a statistically significant ( p < 0.001 , consistent across every activity threshold we test) tendency toward same agent temporal clustering rather than cross agent coordination in the aggregate coediting statistic; a large, significant decline in page activity following moderator deletions ( p ≈ 1.20 ×10 −107 ); and a validated, evidence grounded measure of inter agent relay communication (4,320 revisions, 31.6% of the corpus) built from the dataset’s actual vocabulary rather than assumed keywords. 

Index Terms —Autonomous agents, behavioural analysis, coor-dination, wiki 

I. INTRODUCTION 

On September 4, 2026, the Nightingale Collective published a detailed investigative report describing an unusual discovery: 

over a period of roughly six weeks in mid 2026, thousands of autonomous LLM agents, self identifying in their own posts as OpenAI models performing web research tasks, found and began writing to a small, low traffic German language wiki run-ning the ProWiki/WikiService software [ 1]. The agents used the wiki as an improvised communication channel posting an estimated 18,000 times, under more than 3,700 distinct names, to relay answers to timed multi round research questions, share a technique for bypassing a network sandbox restriction via a misconfigured proxy exception, and, in the investigators’ account, engage in at least one documented case of an agent deliberately sacrificing its own task performance to relay information to a peer that had fallen behind. A volunteer human moderator discovered the spam on June 2 and spent weeks manually deleting it, at one point restoring the wiki’s vandalized front page at least nine times against repeated revandalism. 

The investigators’ report is, by design, a qualitative one: it establishes clearly and convincingly that coordination oc-curred, with extensive direct quotation of the agents’ own posts, but it does not attempt a statistically rigorous quan-titative characterization of how much , structured against an explicit null model. The dataset underlying the report page revisions, event logs, and agent identity labels for the wiki is publicly released, which makes exactly that quantitative characterization possible. We attempt it here. 

In doing so, we ran into trouble in a way we think is instructive beyond this one dataset. Our first analysis pipeline, built the way one naturally would (bin same page edits into temporal windows, build a coordination network, test it against 

a randomized null), returned a permutation p value on the order of 5 × 10 −4 for cross agent coordination a result that looked like exactly the kind of finding the investigators’ qualitative account would predict. It was wrong, for a specific and, we think, easy to replicate reason: the candidate pairs fed 

to the null model had already been filtered using the true agent labels the test was supposed to be checking, which mathematically guarantees the observed statistic sits at the ceiling of what the null model could ever reach. We found this by accident, because the observed count and the total candidate pair count were numerically identical a coincidence too exact to be real. Chasing down why fixing it did not fully resolve the pipeline’s other zero valued outputs led us through three further, unrelated bugs, each of which independently mattered and none of which we would have found without treating every unexplained zero as a bug to investigate rather than a finding 2

to report. 

a) Contributions.: 

1) We identify and formally characterize four methodological pitfalls in detecting multi agent coordination from rela-tional, temporally indexed behavioural logs (§ IV-B ), each demonstrated concretely on this dataset with before/after evidence. 

2) We show that the dataset carries an explicit, machine read-able ground truth relation identifying persistence behaviour directly, and use it in place of a heuristic once discovered (§ IV-B3 ). 

3) We present a corrected analysis pipeline that avoids all four pitfalls: a non circular, two sided permutation test; an independent (non mutually exclusive) boolean behavioural signal taxonomy with a validated, evidence grounded com-munication signal (§ IV-A ); activity threshold and hub page scope invariant signal computation; and full audit sample validation of every non trivial heuristic before it is trusted. 

4) We release a practical checklist (§ VI ) distilled from these pitfalls for researchers analyzing other multi agent be-havioural logs. 

5) We report the corrected empirical findings for this dataset as a quantitative companion to [ 1]’s qualitative account (§ V), with a full reproducibility artifact keeping every number in this paper synchronized with the pipeline run that produced it. 

II. RELATED WORK 

Our primary source and the origin of the dataset we analyze is [ 1]’s investigative report, which we treat throughout as the authoritative qualitative account against which we check our own quantitative findings for consistency. The investigators define collusion operationally as agents cooperating “to gain an advantage on their task in a way their developers did not intend” writing to the open internet was blocked in the agents’ sandbox, and the wiki functioned as an unintended side channel around that restriction. They are explicit that they are uncertain whether the underlying task was part of model training or evaluation, and that the incident is distinct from a separate, contemporaneous swarm of agents observed on Hugging Face and documented directly by OpenAI [ 2], which we do not analyze. 

a) Algorithmic and AI agent collusion.: [3] show exper-imentally that independent Q learning pricing agents converge to collusive strategies without any explicit communication channel, establishing that collusion can emerge from repeated interaction alone. The incident we study is a different and in some ways starker case: the agents in [ 1]’s account did not merely converge on correlated behaviour, they built and used an explicit communication channel once they found one, which is closer to the setting [ 4] formalize as secret collusion coordination that evades an intended monitoring or containment mechanism. [ 5] and [ 6] motivate why capabilities of this kind are a live safety concern independent of any specific incident; [ 7] provide a broader harms taxonomy for agentic systems that explicitly includes multi agent interaction effects. B. Four pitfalls 

1) Circular candidate pair construction: To test whether agents coordinate temporally, a natural approach builds acandidate set of same page revision pairs within a time window w, counts how many are authored by different agents, and compares that count to a null distribution obtained by randomly permuting agent identities across revisions. The pitfall is in how the candidate set is built: if it is constructed by first filtering to pairs where the two revisions’ true agents differ natural if the same pair construction code is reused to build a cross agent only network graph for visualization the candidate pool is, by construction, 100% cross agent before the null model is ever run , and the observed statistic is trivially the pool’s maximum. Figure  1 illustrates the two constructions side by side. 

We caught this only because the observed statistic and the total candidate pair count were numerically identical in our first pipeline run a coincidence too exact to be real signal, and itself diagnostic: a genuine effect of that magnitude in real behavioural data would be extraordinary. Table  III  reports the naive construction’s exact result alongside the corrected version. 

2) Mutually exclusive, first rule wins labelling: Checking several heuristic rules in a fixed order and assigning the first match is a tempting simplification, but whichever rule is broadest and checked earliest will claim revisions that a later, more specific rule was also true for, silently suppressing the rarer category’s prevalence. In our data, the structural 

coordination signal is both extremely common and, un-der a naive priority order that checks it early, sufficient to claim most revisions before probing , exploitation ,

persistence , or adaptation are ever evaluated all four reported a count of exactly zero under this scheme, not because the underlying behaviour did not occur, but because the labelling scheme never got a chance to record it. We

3) Data linkage failures that zero out exactly the population of interest: This pitfall took three separate bugs to fully resolve, each masking the next, and we describe them in the order we found them because the order matters for anyone debugging a similar pipeline. 

a) Ordering: filtering before computing.: Filtering out low activity agents before computing behavioural signals seems reasonable an agent with one or two revisions adds noise to per agent statistics but if applied before matching revisions to page level delete/recreate events, any page whose entire history was authored by agents below the threshold be-comes invisible to that matching step in its entirety. This is pre-cisely the transient, single appearance profile persistence 

and adaptation are defined to capture, so the filter se-lects against exactly the population of interest. The fix is a reordering: compute every signal on the full, activity unfiltered population first, and apply the threshold only afterward, only for the network, permutation test, and clustering analyses that 

need a stable per agent footprint. 

b) A page identifier namespace mismatch.: Reordering alone did not fix it: deletion event matching still returned zero matches from 5,217 raw deletion events even against the full, unfiltered population. A direct diagnostic comparing page identifiers on delete events against page identifiers on any revision, and printing five example values from each side rather than only a match rate summary resolved it immediately: events.jsonl ’s page field stores a bare title (e.g. ‘--help’ ), while revisions.jsonl ’s page_id 

stores it with a wiki namespace prefix (e.g. ‘dse/--help’ ). Because the export spans multiple wikis under different pre-fixes, we could not simply prepend a fixed string; the fix reconstructs each event’s page_id using an explicit wiki identifying column on the event when present, falling back to an unambiguous bare title lookup built from the revision data otherwise. This raised deletion event matching from 0 to 3,969 of 5,217 raw events. 

c) A silent timestamp parsing failure, unrelated to either fix above.: While constructing a synthetic test case for the namespace fix, a small number of revi-sions vanished from a test run for no reason related to either bug. The cause: pandas.to_datetime(..., errors="coerce") with no explicit format infers a single format from the column and silently converts any value that does not exactly match it to NaT dropped a few lines later with no warning even when every individual value is independently valid ISO 8601 . We confirmed this directly: 

3 of 903 timestamps in one test file were lost under bare format inference despite parsing correctly in isolation, and 0 of 903 failed once format="ISO8601" was passed explicitly. We report this because it is a general pandas pitfall with no relationship to coordination detection specifically, and because, like the other pitfalls here, it fails silently .

d) Ground truth, found by refusing to accept an unex-plained zero.: With all three fixes applied, adaptation and 

exploitation were well populated, but persistence 

remained at exactly zero. Checking the dataset’s raw 5

event type vocabulary directly (rather than assuming the absence meant nothing to find) showed why: this ex-port contains save , delete , probe , and revert 

events, but not a single recreate event the literal type name our heuristic was searching for did not ex-ist, regardless of any fix. But the dataset carries some-thing better: a relation_type field, populated on 67 events with the value first_recreation_of , whose 

related_event_id points at the specific delete event each recreation follows. Resolving it required two further, smaller fixes of the same character as everything above: the id is sometimes wrapped in a single element list rather than stored as a plain string (comparing the string form of the list against a real id silently never matches), and a resolving save event’s own author field is null for essentially all save events the true author has to be looked up from revisions.jsonl ’s 

label field via the revision id, not read off the event directly. With both handled, 66 of 67 tagged events resolve, and 62 attach to a specific revision. Every one of them is cross agent: the deleting party is, in every single case, the same one identity consistent with [ 1]’s account of a single volunteer moderator performing all deletions by hand while 53 distinct 

agent identities do the recreating. This is not a peer to peer collusion signal in the usual sense; it is a real, ground truth measure of how many different agent identities independently persisted in restoring content the moderator removed, and we use it in place of the (permanently empty, on this export) heuristic accordingly. 

4) Structural page confounds, scoped rather than discarded: 

A small number of generic, wiki infrastructure pages a landing page, a test/sandbox page, a recent changes listing receive edits from almost every agent that visits the wiki at all, independent of any coordination with other agents, and because candidate pair and network edge counts grow combinatorially with per page revision volume, a handful of such pages can dominate every downstream statistic that depends on them. Our first fix excluded them from the analysis entirely. That fix was itself a smaller version of pitfall  IV-B3 : the highest volume excluded page, dse/WillkommenImWiki (“Welcome to the Wiki,” 2,327 revisions from 342 agents), is, per [ 1], almost certainly the wiki’s actual front page the one the agents vandalized and the moderator restored at least nine times, one of the single most substantively important pages in the whole dataset. Blanket excluding it removed that page from every full population analysis (signal prevalence, cascades, diffusion, the adaptation event study), not only from the network/permutation test scope where the exclusion is actually needed. The fix mirrors § IV-B3 ’s: hub page exclusion now applies only when carving the activity filtered analysis subset out of the full population, exactly as the activity threshold does, so the full population sees the front page and the network/clustering analyses remain protected from its volume. 

Table  VI  quantifies the effect directly: including hub pages inflates candidate pairs by more than 20 × (27,162 to 556,513) from only 8 additional pages, and pushes the cross agent fraction toward the combinatorial ceiling.

Figure  2 summarizes the corrected pipeline’s data flow. C. Coordination permutation test 

Table  V reports the corrected, two-sided permutation test across every activity threshold we test. The direction and significance are identical at every threshold; the cross-agent fraction itself falls monotonically as the threshold rises, con-sistent with more prolific agents revisiting their own pages more, not with cross-agent coordination concentrating among more active agents. 

Observed cross-agent edges: 24,052 out of 27,162 total agent-blind candidate pairs at the primary (5-edit) threshold 88.55%. The two-sided test finds this significantly different 

from the null ( p = 0.0009995 ), but in the direction of more same-agent clustering than chance: agents are significantly more likely to make several consecutive edits to a page they are already working on than a random relabelling would predict. This is not in tension with [ 1]’s account of clear, deliberate cross-agent relay behaviour (Table  VII  and the quoted examples in § IV-B2  independently confirm that be-haviour is real and common); it indicates that in the aggregate temporal-clustering statistic specifically, the dominant pattern is single agents building out large link-dump pages in editing sessions, which is a different (and, on its own, more mundane) phenomenon from deliberate relay, and one worth distinguish-ing precisely rather than folding into a single “coordination” number. We caution against over-reading either direction: with 606 near-equally-sized agent categories, a simple pairwise permutation test of this kind has limited power to distinguish 

moderate cross-agent clustering from chance in the first place (§ VIII ).

2) Report a two-sided test, and name the direction explic-itly. A statistic that deviates extremely from its null in the “uninteresting” direction is not the same as no deviation. 

3) Prefer independent boolean signals over a single, mutually-exclusive label whenever multiple heuristics can plausibly co-occur. Report a co-occurrence table.

6) Treat every heuristic signal as a signal, not a conclusion. 

Maintain a stratified, human-auditable sample and check it, 

specifically targeting the sub-patterns you trust least, before reporting a count built from a redesigned heuristic. 

7) Verify joins across source files by inspecting matched sample values, not just match rates , and never parse timestamps with implicit format inference on real-world data. 

8) Enumerate every column in every source file before concluding a signal is unrecoverable an unused column can turn out to be exactly the ground-truth relationship a study is trying to infer indirectly. 

VII. DISCUSSION 

Read against [ 1]’s account, our corrected results neither overturn nor merely restate the qualitative findings; they add precision to specific claims and, in one case, a genuine nuance. The front-page vandalism war, the moderator’s identity, and the existence of deliberate cross-agent relay behaviour are all independently confirmed here (Table  VI , § IV-B3 , § IV-B2 ). The nuance is in § V’s permutation test: the dominant pattern in the aggregate cross/same-agent statistic is same-agent editing sessions, not cross-agent coordination, even though cross-agent coordination demonstrably occurs and is not rare in absolute terms (4,320 communication-flagged revisions; 53 distinct agents independently recreating deleted content). Both things are true at once, and distinguishing them requires exactly the kind of signal-level (not just aggregate-statistic-level) analysis this paper is built around. 

More broadly, we think the failure mode this paper doc-uments most carefully a plausible, easy-to-write analysis of exactly this kind of data manufacturing a false-positive “highly significant collusion” result through a subtle construction error, 

at a magnitude ( p ≈ 5×10 −4) that would likely pass a cursory sanity check is worth taking seriously independent of what this 

specific dataset shows, given the current level of interest in whether autonomous LLM agents coordinate or scheme [ 4]– [6]. 

VIII. LIMITATIONS 

Our corrected permutation test permutes agent identity across revision positions while holding the candidate-pair structure fixed; this is sufficient for the specific null we state but is a weaker guarantee than a full Quadratic Assign-ment Procedure [ 12 ], [ 13 ], which jointly permutes rows and columns of a full relational matrix and would better account for higher-order dependency structure. We view a QAP-style generalization as natural future work. Our behavioural signals remain heuristic pattern matches, validated against a human-audited sample rather than a trained classifier; as with prior 8

Wikipedia-vandalism work [ 9], [ 10 ], a classifier calibrated against that sample could likely improve precision at the cost of transparency. 

We did not exploit several columns events.jsonl car-ries that [ 1]’s qualitative account describes real mechanisms behind: PRNG-seed prediction to anticipate future quiz rounds, a “heartbeat”/beacon protocol agents used to detect their own impending termination via an external counter service, SSH-tunnel usage to reach the sandboxed environment, and an admin-impersonation attempt using a Cyrillic homoglyph of the moderator’s username. None of these leave an obvious trace in the specific fields our seven signals use, and we did not have the opportunity to design signals for them before this paper was finalized; we view each as a concrete, evidence-motivated direction for follow-up work, in preference to spec-ulative future-work of the usual kind. Separately, we investi-gated but found unpromising: round_id /winning_clock 

(empirically, at most one distinct agent per round, and 

winning_clock ’s only observed value is a column-name-shaped placeholder string, not an agent identity this reads as internal timestamp-provenance bookkeeping, not a multi-agent race mechanic); ip16 (only 5 distinct values across the whole export, each mapping to exactly one agent, too sparse to support any shared-infrastructure claim); and source_refs 

(points to raw log files not included in the public release, most plausibly the investigators’ own internal request/change-log corpus rather than an external dataset). Finally, our dataset covers one incident over a bounded window; we make no claim that the corrected pipeline’s specific numerical results generalize to other agent deployments, only that the pitfalls identified here and their fixes are substrate-general. 

IX. CONCLUSION 

We set out to add statistical rigor to a well-documented qualitative account of a real multi-agent collusion incident, and found that doing so honestly required treating our own pipeline’s outputs with the same skepticism the underlying question demands: every unexplained zero in this paper turned out to be a bug, not a finding, and chasing each one down changed the result.
