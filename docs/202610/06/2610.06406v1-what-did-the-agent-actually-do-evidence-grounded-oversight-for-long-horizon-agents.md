## 摘要
当智能体承担长时程任务时，用户从做出单个决策转向监督自主执行。然而，智能体活动量之大以及支撑证据的碎片化，使得确定哪些决策需要用户验证变得困难。我们研究能够识别重要决策并定位证据以帮助用户评估其影响的监控器。我们提出 AgentMonBench，一个软件工程基准，包含三个子集，覆盖两个互补维度：需求与行为之间的一致性，以及对需要验证的重要自主决策的觉察。为支持这些判断，我们提出基于证据的行为图（EBG），这是一种免训练方法，将与来源关联的证据分组为行为，并将其关系组织成图。EBG 呈现该图的任务导向视图，以帮助监控器在上下文中解释行为。在八个模型上的实验表明，与直接访问原始上下文相比，EBG 在大多数设置中提升了决策识别和证据定位。进一步实验表明，EBG 的证据定位增益在不同输入规模和超参数设置下持续存在，而实际应用则展示了其对人类监督的实用价值。

## Abstract
As agents take on long-horizon tasks, users shift from making individual decisions to overseeing autonomous execution. Yet the volume of agent activity and the fragmentation of supporting evidence make it difficult to determine which decisions warrant user verification. We study monitors that identify consequential decisions and locate evidence to help users assess their implications. We introduce AgentMonBench, a software-engineering benchmark comprising three subsets that cover two complementary dimensions: alignment between requirements and behavior, and awareness of consequential autonomous decisions for verification. To support these judgments, we propose the Evidence-Grounded Behavior Graph (EBG), a training-free method that groups source-linked evidence into behaviors and organizes their relationships into a graph. EBG presents task-oriented views of this graph to help monitors interpret behavior in context. Experiments across eight models show that EBG improves decision identification and evidence localization in most settings compared with direct access to the original context. Further experiments show that EBG's evidence-localization gains persist across input scales and hyperparameter settings, while real-world applications illustrate its practical value for human oversight.

# 论文总结：What Did the Agent Actually Do? Evidence-Grounded Oversight for Long-Horizon Agents

## 1. 核心问题与整体含义（研究动机与背景）

- **背景转变**：随着编码智能体能够执行长时程任务（修改代码库、复现研究、分析数据），用户角色从"逐项决策者"转变为"自主执行的监督者"。责任并未随委托而消失——用户仍需判断智能体的选择是否服务于其目标。
- **核心困难**：长时程智能体的活动量与复杂度可能超出用户跟踪与评估能力（Kasirzadeh & Gabriel, 2026; Mitchell et al., 2026）。有效监督需要"态势感知"（Endsley, 1995）：注意到发生了什么、理解其意义、预判后续影响。
- **两个监督维度**：
  - **需求与行为的一致性**：执行是否偏离用户要求（如遗漏关键约束、静默改变评估指标语义）。
  - **对重要自主决策的觉察**：哪些选择会实质影响任务目标、约束或结果解释，需要用户确认。
- **证据碎片化问题**：决策证据分散在消息、工具调用结果、中间产物中；有限用户注意力使得"哪些决策需要验证"难以识别。
- **核心研究问题**：长时程智能体任务中，哪些重要决策值得用户验证？什么证据能帮助用户理解其影响？
- **整体含义**：论文主张监督的核心不是评估轨迹质量本身，而是建立"行为—证据—需求"之间的可追溯关联，让用户聚焦于真正需要确认的关键决策。

## 2. 方法论

### 2.1 核心思想

- 提出 **AgentMonBench** 基准 + **Evidence-Grounded Behavior Graph (EBG)** 方法，形成"基准评估 + 免训练监控"的完整框架。
- EBG 的核心是把可见上下文中的证据组织为**行为（Behavior）**、**作用域（Scope）**与**显式关系（Relation）**，并渲染为任务导向视图供监控器判断。

### 2.2 AgentMonBench 基准构造（三个子集）

- **SpecGAP（受控需求遗漏）**：从 DeNovoSWE 任务文档中删除关键条件，测试监控器能否发现"代码已实现但文档未说明"的重要行为。删除经过一致性检查；仓库证据映射采用"逐条件映射"与"整体映射"两种独立方法，人工复核。
- **SilentSwap（静默语义替换）**：文档不变，仓库中引入 5 处语义替换，要求现有测试套件仍能通过。构建分三阶段：行为选择 → 代码修改（附区分性语义测试）→ 范围验证；执行验证分个体验证与组合验证两阶段，确保每处替换可独立归因。
- **FeedbackTrace（延迟反馈验证点）**：来自 SWE-chat 的真实用户—智能体交互，以后续用户反馈定位此前的重要决策作为目标，但反馈本身不暴露给监控器。构造 Local / Long 两种轨迹视图，将智能体内容切分为"回复段落"和"工具交互"两类可引用证据单元，标注验证点、最小充分证据与关键性标签（MUST-DISCLOSE / WORTH-DISCLOSE）。

### 2.3 EBG 方法流程

- **输入与记号**：X 为可见 Agent 上下文，Q 为任务需求，输入类型 τ ∈ {repository, trajectory}；E、B、S、R 分别表示证据、行为、作用域、显式关系。
- **整体管线**：
  - `G = Fτ(X)`：图构建器将上下文转为结构化行为图。
  - `V = Pτ(G, Q)`：呈现器将图渲染为任务导向证据视图。
  - `Ŷ = M(Q, V)`：监控器基于需求与视图输出发现。
- **① 结构化行为图构建**（全部确定性、无 LLM 调用）：
  - **证据抽取**：`E = {ei}`，`ei = (i, ci, ℓi)`，保留标识符、原始内容、来源位置；多个行为可共享同一证据。
  - **行为形成**：仓库行为采用 `(Icond, Iop, Ires)` 即"条件—操作—结果"；轨迹行为采用 `(Idem, Iact, Iresp)` 即"需求—动作—响应"。
  - **图组织**：相关行为归入行为作用域（仓库按语法符号，轨迹按任务关联）；作用域间建立带证据支撑的有向关系边（调用、数据流、任务引用、先后顺序）。
- **② 任务导向证据呈现**：
  - **仓库视图**：任务引导的目录排序 → 文档匹配作用域作为种子 → 一跳扩展（不递归）→ 弱连通分量划分 → 每分量选一个阅读根（优先邻居数最多、最早被任务文档提及）→ 渲染证据视图。
  - **轨迹视图**：按 Task Scope 分组，保持原始轨迹顺序，最后一个可见行为所在作用域标记为 Current，其余为 History。
- **监控器判断**：监控器基于 Q 与 V 识别需用户验证的重要决策，并将发现锚定到可追溯至原始来源的证据。

## 6. 主要结论与发现

- **当前 LLM 监控能力仍有限**：即使在结构化上下文下，识别重要决策并将其锚定到支持证据仍有较大提升空间。
- **EBG 总体提升监控性能**：在多数设置下优于 Base，在仓库类任务上也多数优于 Repo

Graph；但提升幅度因任务类型、模型与指标而异，说明证据组织方式的收益并非普适，而是依赖于监控器能否有效利用结构化输入。

- **指标层面的具体表现**：
  - **SpecGAP**：EBG 在 Localization F1 与 Semantic F1 上普遍优于 Base 与 RepoGraph，说明"任务引导的目录排序 + 种子扩展 + 弱连通分量渲染"能帮助监控器更快锁定被删除条件所对应的代码位置；Question Quality 的提升表明 EBG 不仅帮助定位，也帮助监控器提出更有针对性的验证问题。
  - **SilentSwap**：EBG 在 Localization Correctness 上优势较明显，即更容易指出"哪一处被静默替换"；但 Change Correctness 的提升相对有限，说明监控器即便定位到位置，也未必能准确刻画语义替换带来的影响（例如替换是否改变了下游行为语义）。这表明"定位"与"理解影响"是两个难度不同的子问题。
  - **FeedbackTrace**：EBG 在 Evidence Hit Rate 与 Verification Point Alignment 上均有改善，但在长轨迹（Long 视图）下提升幅度收窄，且 Evidence Support Score 的绝对水平偏低，说明在数万 token 的交互轨迹中，仅靠行为图分组仍难以完全解决证据稀释问题。
- **消融结论**：行为组织（Behavior）、图组织（Graph）、任务引导（Task Guidance）三个组件均对性能有正向贡献，其中任务引导的移除导致的下降最为一致，暗示"以需求为锚"是 EBG 有效性的关键；行为组织的贡献在 SilentSwap 上更突出，图组织的贡献在 FeedbackTrace 上更突出。
- **输入规模与超参数**：性能随输入规模增大先升后降，在 Medium 档附近达到峰值，说明存在"证据量与噪声"的权衡；扩展深度 2 跳通常优于 1 跳与 3 跳，3 跳引入的远端符号反而稀释了任务相关性；交互预算增加带来的边际收益递减，6 轮左右趋于饱和。
- **披露检测**：EBG 提升了 MUST-DISCLOSE 项的 TPR，但 FPR 也同步上升，说明结构化呈现会让监控器更"愿意"报告，存在过度告警风险；因此实际部署中需要在召回与告警疲劳之间做权衡。
- **失败归因**：主要失败模式依次为"证据呈现遗漏"（相关证据存在但未被渲染进视图）、"模型判断失败"（证据可见但监控器未识别其重要性）、"文件选择遗漏"（种子选择未覆盖关键作用域）。这提示后续改进应优先优化种子选择与视图渲染的召回率，而非仅提升监控器推理能力。
- **真实应用案例**：5 个 Codex Harness 案例中，EBG 成功暴露了模糊优化目标、随机化回退、验证数据泄漏、缓存掩盖 API 检查、搜索预算不对等这类"表面正常但实质偏离需求"的决策，说明该方法在真实长时程工作流中具备可用性，而非仅限基准环境。

## 7. 局限性

- **基准覆盖范围有限**：三个子集各 100 个实例，且均以 Python 软件工程任务为主；SpecGAP / SilentSwap 源自 DeNovoSWE，FeedbackTrace 源自 SWE-chat，任务类型与语言分布较窄，结论向其他领域（数据分析、研究复现、多语言仓库）外推需谨慎。
- **FeedbackTrace 的标注约束**：每个会话最多取一个验证点，且以后续用户反馈作为"正确答案"的代理，可能遗漏用户当时未反馈但仍重要的决策，存在标签噪声与选择性偏差。
- **方法对比不完整**：RepoGraph 无法应用于 FeedbackTrace，导致该组件上只有 Base 与 EBG 对比，削弱了跨方法结论的说服力。
- **EBG 的确定性设计取舍**：图构建全程不使用 LLM，虽提升可复现性与成本效率，但也意味着语义等价、跨语言调用、动态派发等难以被符号规则捕获，可能造成证据遗漏。
- **指标依赖 LLM-as-a-judge**：部分语义指标（LC、VPA）在 GLM-5.2 与 Qwen3.7-Max 之间差异较大，说明评分对 judge 家族敏感，绝对分数不宜直接跨研究比较。
- **算力与成本披露不足**：论文未报告硬件配置、推理总成本与延迟，难以评估在真实监督场景（要求近实时）中的可行性。
- **误报问题**：披露检测中 FPR 上升，若直接部署可能产生告警疲劳，反而削弱监督有效性。
- **监督者假设**：方法假定用户能够理解证据视图并做出判断，但未评估不同专业水平用户的实际认知负荷与决策质量（缺少人因实验）。

## 8. 对后续研究的启发

- **从"评估轨迹"转向"评估决策"**：论文提示监督研究可将粒度从整体轨迹质量下沉到"重要决策点"，并围绕"是否需要用户确认"建立新的标注与评价范式。
- **证据可追溯性作为一等公民**：将每个发现锚定到原始来源位置，是降低用户验证成本的关键设计原则，值得推广到其他智能体监督与审计场景。
- **免训练监控路线的可行性**：EBG 表明在推理阶段通过结构化上下文即可获得增益，为算力受限或隐私受限的部署提供了替代方案。
- **需要更丰富的人机评估**：未来应引入真实用户实验，测量在 EBG 视图下的验证时间、漏检率与信任校准，而非仅依赖 LLM-as-a-judge。
- **跨领域与多语言扩展**：将 AgentMonBench 扩展到数据分析、科学复现、多语言仓库，并引入更长的真实轨迹，以检验方法的泛化边界。
- **降低误报与提升召回并重**：可探索"关键性分级 + 置信度校准"的披露策略，在 MUST-DISCLOSE 上保召回、在 WORTH-DISCLOSE 上控误报。

## 9. 总体评价

论文的核心贡献在于把"长时程智能体监督"从抽象关切转化为可操作的研究问题，并同时提供了**基准（AgentMonBench）**与**方法（EBG）**：基准用受控方式分离出"需求遗漏""语义替换""延迟验证点"三类监督难点，方法则以确定性行为图与任务导向呈现降低监控器的证据检索负担。其优势是实验体系较完整、免训练、证据可追溯、并配有真实应用案例；其不足是样本规模偏小、领域单一、部分对比缺失、指标对 judge 敏感、缺少人因验证与成本披露。总体而言，这是一项在问题定义与工程落地上都较为扎实的工作，为"以证据为中心、以需求为锚"的智能体监督研究提供了可复用的基准与基线。
