## 摘要
多智能体 LLM 系统通过智能体之间的信息交换来协调任务执行。当协调失效时，执行轨迹中的相似表征可能反映信息传递、使用或验证方式上的不同问题。通信拓扑刻画了智能体如何交换信息，并为区分协调失效模式提供了结构线索。将这些线索用于诊断，需要建立拓扑与失效模式之间的关系，并从缺乏显式拓扑标签的执行轨迹中恢复相关结构。我们分析了通信拓扑与失效模式之间的关系，并提出了 MAScope，一个用于拓扑条件化诊断的两阶段框架。其轨迹结构提取器 TSE 通过将交互图建立在消息证据之上，从异构执行轨迹中恢复通信拓扑。拓扑条件化评判器 TC-Judge 随后利用轨迹、预测拓扑、从单独标注轨迹估计得到的经验失效先验，以及拓扑特定失效模式的简短描述，对故障进行分类。在固定编排结构下，恢复出的拓扑可在不同执行之间复用。实验结果表明，通信拓扑与故障类型之间存在统计显著关联，$χ^2 = 409.9$，$p = 1.2 \times 10^{-70}$。在 \num{851} 条 MAST-clean 轨迹上，真实拓扑上下文将 gpt-mini 的 Macro-F1 从 $0.173$ 提升至 $0.350$。在使用预测拓扑时，该流水线达到 $0.346$，接近仅使用轨迹的 gpt-5.4 基线 $0.372$。对于固定编排结构下的 \num{1000} 条轨迹，包含一次拓扑提取在内的预计流水线成本约为重复进行 gpt-5.4 诊断成本的 $6\%$。这些结果表明，拓扑条件化上下文可改善故障诊断，并支持更低成本的部署。

## Abstract
Multi-agent LLM systems coordinate task execution through exchanges of information among agents. When coordination breaks down, similar symptoms in execution traces can reflect different problems in how information is passed, used, or verified. Communication topology captures how agents exchange information and provides structural cues for distinguishing coordination failure modes. Using these cues for diagnosis requires establishing how topology relates to failure patterns and recovering the relevant structure from execution traces that lack explicit topology labels. We analyze the relationship between communication topology and failure patterns and introduce MAScope, a two-stage framework for topology-conditioned diagnosis. Its Trace Structural Extractor TSE recovers communication topology from heterogeneous execution traces by grounding an interaction graph in message evidence. The Topology-Conditioned Judge TC-Judge then classifies failures using the trace, predicted topology, an empirical failure prior estimated from separate labeled traces, and a short description of topology-specific failure patterns. Under a fixed orchestration structure, the recovered topology can be reused across executions. Experimental results show a statistically significant association between communication topology and failure type, with $χ^2 = 409.9$ and $p = 1.2 \times 10^{-70}$. On the \num{851} MAST-clean traces, ground-truth topology context raises gpt-mini's Macro-F1 from $0.173$ to $0.350$. With predicted topology, the pipeline achieves $0.346$, approaching the trace-only gpt-5.4 baseline of $0.372$. For \num{1000} traces under a fixed orchestration structure, the projected pipeline cost, including one topology extraction, is approximately $6\%$ of repeated gpt-5.4 diagnosis cost. These results show that topology-conditioned context improves failure diagnosis and supports lower-cost deployment.

## 1. 核心问题与研究动机

- **背景**：LLM 多智能体系统（如 AutoGen、MetaGPT、ChatDev）通过智能体之间的信息交换来分工协作。任务成功不仅取决于单个智能体的能力，更取决于它们之间的协调方式。
- **核心痛点**：当协调失效时，执行轨迹中呈现的**表面症状往往相似**，但根因可能完全不同——可能是信息没有被传递、被使用了却没有验证、或者验证责任无人认领。仅凭轨迹文本难以区分这些失效模式。
- **关键洞察**：通信拓扑（谁与谁交换信息、以何种结构交换）蕴含了协调责任与信息流的结构线索，是区分故障模式的天然"坐标系"。然而现有诊断方法（MAST、Who&When、A2P 等）几乎只依赖执行轨迹，**未显式引入通信拓扑**；同时，异构框架的原生日志通常不记录显式拓扑标签，拓扑恢复本身是一个未被充分探索的问题。
- **研究问题**：(1) 拓扑与故障模式之间是否存在可验证的统计关联？(2) 能否从异构、无显式标签的执行轨迹中可靠恢复拓扑？(3) 拓扑条件化能否提升故障诊断性能并降低部署成本？

## 2. 方法论：MAScope 两阶段框架

### 2.1 核心思想

- **分离拓扑与故障标签**：拓扑 τ 在固定编排下跨大量执行保持不变（如一个部署好的 LangGraph 流水线运行数千次），而故障标签 y 每次执行都不同。因此将诊断拆分为两个变化频率不同的阶段：**一次拓扑提取 + 每次执行的低成本诊断**。
- **拓扑作为结构化先验**：用拓扑标签、该拓扑下的经验故障先验、以及拓扑特定失效模式描述，为低成本判断模型提供显式结构上下文，使其不必从原始轨迹中"重新发现"协作结构。

### 2.2 阶段一：TSE（Trace Structural Extractor）

从异构轨迹 T 中恢复规范化关系图 G(T) 与拓扑标签 τ̂，四个处理阶段：

1. **压缩与匿名化**：将轨迹解析为带说话人标记的消息流，参与者名替换为占位符 P01、P02…；用命名共指、交互动词、共享通道标记等对句子级片段打分，选出约 4k token 的证据视图，每个片段保留稳定标识符 Ei 供引用。
2. **关系抽取**：LLM 返回至多 24 条交互候选关系，每条属于五类之一——`control`（控制）、`use`（使用）、`feedback`（反馈）、`pool_read`（共享池读取）、`independent`（独立），并引用一到两个证据片段 Ei。
3. **验证与修复**：规则校验器检查 JSON 模式、方向、同一消息内接地、命名对端与命名存储；若拒绝率超阈值或共享通道标记伴随稀疏图，触发一次有界 LLM 修复调用；再用窄上下文正则补充恢复隐式池读取。
4. **拓扑标签分配**：将关系聚合为节点间关系表，交由结构标注 LLM 输出四类 Guo 拓扑之一或弃权；确定性门控按优先级裁决——命名生产者的 `pool_read` 最高，其次独立/相互活动、持续委托链、单向信息流。最终返回 G(T) 与 τ̂，每条关系与标签均链接到证据片段。

- 通过薄格式适配器支持 LangGraph、AutoGen、CrewAI、ChatDev、MetaGPT、Magentic、Simple Chain 共 7 种框架。

### 2.3 阶段二：TC-Judge（Topology-Conditioned Judge）

- 输入：原始轨迹 T、预测拓扑 τ̂、该拓扑的经验先验 π_τ(c) = N_{τ,c} / N_τ（14 个 MAST 故障码各自的发生率，用 400 条探索切片估计一次后冻结，与评估集不相交）、以及一段简短的拓扑失效签名描述。
- 输出：单次结构化 JSON 调用产生 14 位二进制故障向量 ŷ ∈ {0,1}^14，每个 MAST 码独立判定。
- **软先验校准指令**：要求判断器独立核查每个码与轨迹证据，而非直接套用频率。
- **零样本设计理由**：MAST-clean 中部分故障码正例不足 20 条，若监督训练会让模型学到框架指纹等捷径；因此保持模型参数固定，仅通过提示中的聚合频率与结构签名注入拓扑知识。

## 6. 主要结论与发现

- **拓扑与故障显著相关**：χ² = 409.9，dof = 39，p = 1.2×10⁻⁷⁰。标准化 Pearson 残差显示各拓扑有特征性失效模式：
  - **分层式**：信息损失（2.4 信息隐瞒、2.5 忽略输入），上游事实在单向路径中丢失。
  - **集中式**：验证错位（3.1–3.3），中心节点的全局验证标准与工作者逐渐脱节。
  - **去中心式**：协调停滞（2.1 角色违规），对等节点陷入互相等待或角色混淆。
  - **共享消息池**：语义漂移（2.2、2.3、2.6），黑板累积歧义上下文，后续读者静默重新解释早期意图。
  - 该关联在三个语料中定性一致。
- **拓扑恢复可行**：MAST-clean 上 TSE 恢复 798/851，准确率 **93.8%**（弃权 4 条），错误集中在 ChatDev（分层链被误判为集中式）；LG-Ctrl 上 312/408，**76.5%**，远高于 25% 平衡随机水平，共享消息池最难（56.9%）。
- **拓扑条件化显著提升诊断**：gpt-mini 从 M0 的 0.173 升至 M4 的 0.350（相对 +102%），达到仅轨迹 gpt-5.4 基线 0.372 的 94%；gpt-5.4 从 0.372 升至 0.399（+7.3%）。M4 也分别超过 MAST-Judge 0.219 和 0.036。
- **预测拓扑几乎无损**：端到端 gpt-mini 流水线达 0.346，与真实拓扑的 0.350 仅差 Δ = −0.004。
- **监督方法跨框架脆弱**：Flat-GBM 从 0.490 降至 0.226（保留 46%），Neural-Trace 从 0.296 降至 0.127（保留 43%），说明强分布内拟合不能可靠迁移。
- **成本优势**：固定编排下 1000 条轨迹的总成本约为重复 gpt-5.4 诊断的 6%（含一次拓扑提取），复用摊薄后优势随部署量增大。
- **机制解释**：拓扑帮助 gpt-mini 更大的原因在于，弱模型难以从原始轨迹自行推断协作结构，显式提供标签、先验与签名后可将注意力集中于核查轨迹证据。

## 7. 优点

- **视角新颖且可验证**

- **问题拆解干净**：识别出拓扑（低频、跨执行稳定）与故障标签（高频、逐次变化）的变化频率差异，据此设计"一次提取 + 多次复用"的两阶段架构，使方法论创新与工程成本收益形成闭环。
- **证据可追溯**：TSE 的每条关系与每个拓扑标签都链接到证据片段标识符 Ei，诊断结论因此可人工复核，缓解了 LLM 标注"不可审计"的常见批评。
- **消融设计严格**：M0–M4 采用同模型、同提示脚手架、同输出空间的递进式配对，能干净地隔离"标签 / 先验 / 失效签名"三类拓扑信息的边际贡献，而非只报告一个笼统的"加了拓扑更好"。
- **混淆控制意识强**：专门构造 LG-Ctrl 固定框架身份（状态模式、日志格式、智能体标识不变，仅改图边与迭代模式），以排除"拓扑增益其实来自框架指纹"这一最危险的替代解释。
- **防泄漏与防捷径**：经验先验在与评估集不相交的 400 条探索切片上估计一次后冻结；因部分故障码正例不足 20 条而坚持零样本、不微调参数，明确规避小样本监督下的捷径学习。
- **诚实的负面结果报告**：主动披露监督方法在 LOFO 下的性能崩塌（Flat-GBM 保留 46%、Neural-Trace 保留 43%），以及共享消息池拓扑恢复仅 56.9% 的困难，未选择性呈现有利结果。
- **成本论证具体**：给出可核对的美元级估算（8.73 vs 0.52、10.26 vs 0.63），使"低成本诊断"的主张具备可复现的量化依据。

## 8. 局限与不足

- **算力与资源披露缺失**：论文未说明 GPU 型号、数量、训练/推理时长或总算力开销；仅有的美元估算属于 API 调用费用，不能替代算力资源披露，影响可复现性评估。
- **拓扑与框架在 MAST-clean 中高度共线**：每个框架仅对应一种拓扑，导致 LOFO 的跨框架评估同时引入框架偏移与拓扑偏移，**无法把泛化失败单独归因于其中之一**，削弱了"跨框架脆弱性"结论的机制清晰度。
- **主评估集规模有限**：851 条轨迹、14 个故障码，部分码正例不足 20 条，Macro-F1 的尾部类别估计方差大，点估计的置信区间未报告，模型间小幅差距（如 gpt-5.4 的 +7.3%）的稳健性存疑。
- **Inject-Mix 分数不可跨语料比较**：故障标签由注入派生，其分布与真实故障的自然分布不同，只能在语料内部作相对比较，不能与 MAST-clean 的绝对分数并列解读。
- **拓扑标签体系较粗**：四类 Guo 拓扑（分层、集中、去中心、共享消息池）是离散分类，可能掩盖混合拓扑、动态拓扑切换（同一执行中拓扑随轮次变化）以及带权/带时延的细粒度结构差异；弃权机制虽存在，但弃权样本的分布与影响未充分分析。
- **拓扑恢复的错误结构未深挖**：ChatDev 的分层链被误判为集中式、共享消息池仅 56.9% 准确，论文报告了错误率但未给出系统性的错误归因（是证据片段选择、关系抽取还是标签裁决环节导致）。
- **零样本设计的另一面**：坚持零样本虽规避了小样本捷径，但也放弃了利用少量标注做轻量校准的可能；先验频率以固定提示注入，模型对先验的敏感度（是否过度依赖频率）仅用"软先验校准指令"约束，缺乏定量敏感性分析。
- **成本估算未含 TSE 失败/修复开销的分布**：有界 LLM 修复调用与正则补全的触发频率、以及拓扑误判导致的诊断损失，未纳入端到端成本-精度联合分析。
- **真实部署验证缺位**：实验均在离线轨迹上完成，未展示在线系统中拓扑恢复与诊断的延迟、吞吐与漂移（拓扑变更后先验失效）表现。

## 9. 对后续研究的启发

- **把"结构"作为一等公民引入 LLM 系统诊断**：本文示范了将协作结构显式建模为条件变量的收益，这一思路可迁移到其他多智能体属性——如预算分配结构、工具权限结构、记忆共享范围——检验它们与失效模式的统计关联。
- **变化频率分层是通用工程范式**：低频结构 + 高频事件的拆分，可推广到日志异常检测、工作流监控等场景，形成"结构缓存 + 事件判定"的通用低成本架构。
- **需要更强的跨框架/跨拓扑解耦实验**：后续工作应构造"框架 × 拓扑"的交叉设计（而非共线设计），才能真正分离框架指纹与拓扑效应，并据此判断监督方法崩塌的根因。
- **细粒度拓扑与动态拓扑是明显缺口**：带权边、时序边、运行中拓扑切换的表示与恢复，以及混合拓扑的标签体系，是自然延伸方向。
- **小样本故障码的评估方法学待改进**：应报告分层置信区间、采用对尾部更稳健的聚合方式，或引入分层重采样，以避免 Macro-F1 在正例稀少时的不稳定。
- **先验的注入方式值得系统研究**：频率先验、失效签名、反例提示三者的相对贡献与交互效应，以及在拓扑漂移时先验如何自适应更新，都是可深入的问题。
- **从诊断走向修复**：既然拓扑条件化能定位特征性失效模式（如集中式的验证错位、共享池的语义漂移），下一步可探索拓扑层面的干预建议（改边、改迭代模式、增设验证角色）并验证其因果效果。

## 10. 总体评价

本文的核心贡献不在于提出更强的诊断模型，而在于**重新定义了诊断问题的输入空间**：把通信拓扑从隐含背景变为显式条件变量，并证明这一变量既与故障模式统计显著相关，又能从异构、无标签的轨迹中以可接受精度恢复，还能以极低成本转化为诊断性能增益。其方法论的优雅之处在于抓住了拓扑与故障标签之间的变化频率不对称，从而把"昂贵推理"压缩为"一次性结构提取 + 廉价逐次判定"。

从证据强度看，拓扑—故障的关联检验（χ² = 409.9，p = 1.2×10⁻⁷⁰）与三语料定性一致性构成了较扎实的实证基础；M0/M4 的严格配对使增益归因相对可信；预测拓扑与真实拓扑仅差 Δ = −0.004，说明端到端可用性成立。同时，论文对监督方法跨框架崩塌的诚实报告，反而强化了"显式结构先验优于隐式分布拟合"这一论点的说服力。

主要保留意见集中在三点：一是 MAST-clean 中框架与拓扑共线，使跨框架结论的归因不够干净；二是主评估集规模偏小、尾部故障码正例过少，小幅增益的稳健性需更强统计支撑；三是算力披露缺失、真实在线部署验证缺位。总体而言，这是一篇问题意识清晰、方法设计克制、成本论证具体、且对自身局限有自觉的工作；其最大价值可能不在于 MAScope 这一具体实现，而在于"拓扑条件化诊断"这一可被后续工作继承和扩展的问题范式。
