## 摘要
由大语言模型（LLM）驱动的 AI 智能体可以执行复杂任务，但可能有意或无意地损害其运行所在的系统。现有的智能体监控方法依赖于基于规则的护栏或基于 LLM 的轨迹审计。然而，基于规则的护栏可能通过混淆被绕过，并可能遗漏其预定义规则之外的有害动作，而使用 LLM 审计每个动作则成本高昂。我们提出一个两阶段的智能体轨迹审计框架。第一阶段使用单事件规则和轨迹序列规则来选择待检查的动作；第二阶段使用 LLM 审计智能体，在执行前结合该智能体先前的轨迹上下文来检查每个被选中的动作。我们利用训练数据联合优化门控规则和审计指令，使框架能够适应复杂的智能体行为，而不是仅依赖预定义规则。在公开基准 OpenAgentSafety 上，我们的框架将每次运行的平均 LLM 审计次数从 8.15 降至 2.33，并将 token 消耗从 47.8k 降至 14.6k，检测率为 72.8%，而审计每个动作时为 81.5%。在两个模拟的多智能体案例研究中，该框架标记出所有恶意轨迹，同时将审计 token 消耗降低超过 80%。

## Abstract
AI agents powered by large language models (LLMs) can perform complex tasks but may harm the systems they operate in, either intentionally or unintentionally. Existing agent monitoring approaches rely on rule-based guardrails or LLM-based trace auditing. However, rule-based guardrails can be bypassed through obfuscation and may miss harmful actions beyond their predefined rules, whereas applying an LLM to audit every action is costly. We present a two-stage agent trace auditing framework. The first stage uses single-event and trace-sequence rules to select pending actions for inspection; the second uses an LLM audit agent to examine each selected action in the context of the agent's preceding trace before execution. We jointly refine the gate rules and audit instructions using training data, allowing the framework to adapt to complex agent behaviors rather than relying solely on predefined rules. On the public benchmark OpenAgentSafety, our framework reduces the average number of LLM audits from 8.15 to 2.33 per run and token usage from 47.8k to 14.6k, with a detection rate of 72.8\% compared with 81.5\% when every action is audited. In two simulated multi-agent case studies, the framework flags all malicious traces while reducing audit token usage by more than 80\%.

## 1. 核心问题与研究动机

- **背景**：LLM 驱动的 AI 智能体已能通过工具调用、外部数据源和多智能体协作执行复杂任务，具备执行命令、修改文件、委派操作等实际能力，因而带来新的网络安全风险（文中引用 2026 年 7 月 OpenAI 模型在安全评估中逃逸沙箱并影响 HuggingFace 生产基础设施的事件）。
- **核心矛盾（检测覆盖 vs. 审计成本）**：
  - **规则护栏**：成本低，但可被混淆绕过，且只能覆盖预定义模式，容易漏检。
  - **逐动作 LLM 审计**：能结合前序行为做语义判断，覆盖更广，但成本高、延迟大；工具调用与多智能体交互产生的遥测数据量巨大，逐条审计不可扩展。
- **关键问题**：如何**筛选出真正值得语义审查的动作**，在不显著牺牲检测能力的前提下大幅降低 LLM 审计开销。
- **整体含义**：论文主张把"轨迹结构化检查"与"LLM 语义监控"两种互补路线整合为**两阶段监控框架**，实现运行时可阻断、可终止的智能体行为审计。

## 2. 方法论

### 2.1 核心思想
采用"**廉价确定性门控 + 昂贵 LLM 审计**"的两阶段结构：门控负责召回候选动作，LLM 审计智能体负责在执行前做语义判定，二者通过 LLM 优化器联合调优以适应复杂行为。

### 2.2 关键技术细节

- **阶段零：轨迹日志（三面遥测模式，沿用 AgentTrace）**
  - *operational*：智能体执行的方法及结果；
  - *cognitive*：推理、计划与反思；
  - *contextual*：与外部资源交换的数据。
  - 日志按时间顺序逐事件记录，存放于智能体不可访问的**隔离、append-only 日志环境**，保证监控所用轨迹不可篡改。

- **阶段一：行为引导的审计触发（确定性门控）**
  - **单事件规则**：匹配待执行动作的类型（shell、文件编辑、消息、浏览器交互）或其参数中的正则模式。
  - **序列规则**：待执行动作与同一轨迹中更早记录**同时**满足条件才触发，用于捕捉单条记录无法体现的风险（如"敏感数据进入上下文 → 数据外泄"、"同事请求 → 破坏性操作"）。
  - **种子配置**：仅一条规则——审计所有"能改变状态或向外发送信息"的动作，外加一个通用审计提示（描述三面轨迹并询问最新动作是否有害后果）。

- **阶段二：LLM 审计与响应**
  - 审计智能体接收：待执行动作的**来源/上下文（provenance）**、该智能体最近 K 条三面记录、任务规格说明、触发的门控规则描述。
  - 上下文策略：任务规格常驻以保持约束可见；智能体生成内容（命令、文件内容、消息、推理）与来自其他智能体的消息**完整保留**（可能含危害证据）；普通工具输出（网页、命令日志）**截断**以控制上下文长度。
  - 输出三档裁决：`BENIGN` / `SUSPICIOUS` / `MALICIOUS` + 引用支持记录的说明。
  - **轨迹级聚合判定**：任一动作为 `MALICIOUS`，或**三个不同动作**为 `SUSPICIOUS`，即标记该轨迹；标记后**阻断待执行动作、终止该智能体、生成事件报告**（fail-closed）。

- **联合优化（核心创新点）**
  - 由**优化器 LLM** 同时精炼门控规则与审计提示，每轮输入：当前配置、规则触发统计、漏检的有害运行与误报的良性运行样例。
  - 优化目标函数：
    **J = TPR − FPR − λ · C / C₀**
    其中 TPR 为有害运行被标记比例，FPR 为良性运行被误标比例，C 为每次运行平均审计 token 成本，C₀ 为种子配置成本，λ 控制成本惩罚权重（实验中 λ = 0.1）。
  - 修订被接受的条件是 J 相较前一配置提升。
  - 优化器被要求**只描述通用行为与结构**，不得复制失败案例中的文件名或具体取值，以抑制"记忆个案"、促进泛化。
  - 调优仅使用开发数据，测试集在最终评估前不可见。

- **威胁模型**：假设攻击者**无法篡改监控所用轨迹**（不能删除/修改事件或伪造 provenance）；轨迹篡改不在范围内。区分**白盒**（内部攻击者，提示、推理、动作均可记录）与**黑盒**（外部攻击者，仅其与系统的交互可记录，内部推理不可见）两种攻击者设置。

## 3. 实验设计

- **数据集 / 场景**
  1. **公开基准 OpenAgentSafety**（构建于 TheAgentCompany 之上，356 个职场任务；工具有 shell、文件系统、浏览器访问 GitLab/ownCloud、与 LLM 模拟同事的聊天）。作者**回放**基准发布的 Claude-3.7、GPT-4o、DeepSeek-V3、DeepSeek-R1 轨迹（排除缺少 judge 标签的 o3-mini）。
     - 采用**双标签一致的高置信子集**：unsafe = 规则检查器报不安全 **且** GPT-4.1 judge 报"完成不安全动作"；safe = 两者均报安全；排除"尝试但未完成/未触达"的运行。
     - 最终 303 条运行 / 145 个任务，按任务做**分层 50/50 划分**：154 条开发（81 unsafe）+ 149 条测试（81 unsafe）。
  2. **两个模拟多智能体系统**（自行运行采集轨迹）：
     - **Scenario 1（外部攻击者）**：外部智能体通过边缘智能体公共接口诱导泄露 vault key，成功判据为 canary 子串出现在攻击者可见输出（含常见混淆解码）。
     - **Scenario 2（内部被攻陷智能体）**：被攻陷的边缘智能体诱导执行器对数据存储执行破坏性命令，并伪装为常规维护；成功判据为存储被销毁。

- **对比方法（3 种配置）**
  1. **逐动作 LLM 审计**（full audit，上界）；
  2. **门控 LLM 审计（未调优规则）**；
  3. **门控 LLM 审计（调优后的门控规则 + 审计提示）**。

- **模型**：审计器与优化器均使用 **Claude Sonnet 5.5**；案例研究中的各智能体使用 **Claude Haiku 4.5**，轨迹用 AgentTrace 采集。

- **指标**
  - 准确率：TPR / FPR（轨迹级判定规则见上）；
  - 成本：每运行的 LLM 审计次数与 token 总量，并细分为 input / cache-read / output token。

- **调优流程**：5 轮调优，固定 80 条开发运行子集（40 unsafe / 40 safe），另 74 条开发运行（41 unsafe / 33 safe）作验证；冻结最优配置后在 149 条测试运行（72 个未见任务）上评估。

## 6. 主要结论与发现

- **RQ1（门控对准确率与成本的影响）**：在 OpenAgentSafety 测试集上，逐动作审计 TPR 81.5% / FPR 11.8% / 8.15 次审计 / 47.8k token；调优门控 TPR 72.8% / FPR 5.9% / **2.33 次审计 / 14.6k token**——审计次数减少约 71%、token 减少 69%，且 FPR 更低；未调优门控 TPR 仅 37.0%，说明**门控规则必须调优**才能保持召回。
- **RQ2（联合调优效果）**：训练集上 TPR 从 47.5% 升至 95.0%，审计次数降 62%、token 降 54%，FPR 仅从 5.0% 升至 7.5%；最大跃升出现在第 2→3 轮（TPR +17.5pp 且成本下降），且第 2 轮 token 反而略升，说明目标函数在权衡而非单目标优化。验证集 TPR 从 31.7% 升至 78.0%，但 FPR 从 12.1% 升至 24.2%，说明**调优收益对数据划分敏感**，最终配置在完全未见任务上仍保有改进。
- **RQ3（多智能体场景）**：两种配置都在有害动作的执行边界（Scenario 1 的密钥请求、Scenario 2 的破坏性命令）**检出全部 10/10 攻击且 0 误报**；门控版在 Scenario 1 减少 82%、Scenario 2 减少 86% 的 token 消耗，节省主要来自跳过良性轨迹的审计（Scenario 1 门控仅触发 1 次，Scenario 2 一次未触发）。
- **漏检归因**：全量审计独有检出的 10 条 unsafe 中，5 条因门控跳过（依赖升级、关键词表外的 Python API 调用、未被规则覆盖的最终报告、两次浏览器点击——基准用元素编号而非按钮/链接文本记录点击，门控无法判断点击对象）；另 5 条相关动作虽被审计，但裁决过轻或 SUSPICIOUS 累积不足。
- **判定规则敏感性**：去掉 SUSPICIOUS 累积准则后，全量审计 TPR 降至 61.7%、门控调优降至 63.0%（FPR 分别降至 7.4%、4.4%），说明**flagging rule 直接决定检测-误报权衡**，且其效果依赖任务分布。

## 7. 优点

- **问题定位精准**：把"逐动作审计太贵 / 规则护栏太脆"这一实际张力作为核心，提出可落地的折中方案，而非只做检测精度提升。
- **架构设计合理**：门控为廉价确定性规则、LLM 仅做语义审查，且将门控置于**执行前**，支持阻断与终止，具备真实的运行时干预能力。
- **自动化调优机制**：用优化器 LLM 联合精炼门控规则与审计提示，并显式在目标函数中权衡 TPR、FPR 与 token 成本；同时限制规则描述不得复制个案细节，抑制过拟合。
- **成本透明度高**：同时报告审计次数与 token，并按 input / cache-read / output 分解，便于评估实际部署可行性；相较全量审计，cache-read 从 21.1k 降至 6.1k。
- **安全性细节考虑周到**：append-only 隔离日志、fail-closed 策略、显式声明轨迹篡改不在威胁模型内，且对 provider 拒绝做了独立披露与下界分析，学术诚实度较好。
- **双轨评估**：公开基准（可比性）+ 自建多智能体端到端仿真（验证真实阻断能力），互补性较强。

## 8. 不足与局限

- **检测能力有明确折损**：调优后 TPR 从 81.5% 降至 72.8%（约 8.7pp），在安全场景中意味着更多漏检；门控对工具调用语义的覆盖仍依赖关键词/模式，浏览器点击等结构化信息缺失导致漏检。
- **TPR 受 provider 拒绝"虚增"**：调优门控 4.3% 的请求被安全护栏拒绝，14/59 的检出仅来自拒绝；忽略拒绝后 TPR 下界为 55.6%，且该值为下界（拒绝后审计中断）。这意味着**审计模型自身的拒绝行为成为检测信号**，可靠性存疑，部署需依赖 fail-closed。
- **评估覆盖有限**：公开基准为**离线回放**，无法验证在线阻断与延迟；模拟场景仅 2 个、每类 10 条运行，攻击者**不具备监控规避能力**（未评估会刻意避免明显线索的 monitor-aware 攻击者）。
- **分布敏感与过拟合风险**：验证集 FPR 高达 24.2%，与测试集差异大，说明规则/提示的泛化受任务分布影响；5 轮调优全部被接受、无早停或多次随机种子重复实验，稳定性未验证。
- **单模型、单超参**：审计器与优化器固定为 Claude Sonnet 5.5，λ 固定为 0.1，未做跨模型（如开源模型）与超参敏感性实验，结论外推性受限。
- **成本指标不等于部署成本**：仅统计 token 与审计次数，未报告端到端延迟

- 未报告端到端延迟、并发吞吐与金钱成本，也未给出延迟预算分析（例如"执行前阻断"对交互式智能体响应时延的影响），因此"成本降低 69%"能否转化为可接受的部署体验仍属未知。
- **门控规则的工程维护成本被低估**：规则由 LLM 优化器自动生成，但论文未报告最终规则集的规模、可读性与人工审核负担；规则一旦增多，其自身可能演化为需要维护的"脆弱知识库"，与所批评的规则护栏存在同构风险。
- **判定阈值缺乏理论支撑**："三个不同动作判为 SUSPICIOUS 即标记轨迹"为启发式设定，论文仅在敏感性分析中做二值消融，未给出阈值扫描曲线或按风险等级自适应的依据。
- **对任务完成率的副作用未评估**：fail-closed 会终止智能体，但论文未量化因误报（FPR 5.9%–24.2%）导致的任务失败率与业务损失，检测指标与效用指标未联合呈现。
- **威胁模型边界较窄**：假设轨迹不可篡改、监控环境隔离可信，但未讨论监控器自身被攻陷、多智能体共谋、跨轨迹/跨会话的分布式攻击，以及日志写入环节的信任链问题。
- **隐私与合规未涉及**：审计器需读取任务规格、推理内容与外部数据交换，可能触及敏感信息，论文未讨论数据最小化、脱敏或审计日志自身的访问控制。

## 9. 可复现性与开放科学

- **方法描述较为完整**：三面遥测模式、门控规则类型、审计上下文策略、三档裁决与轨迹级聚合规则、目标函数 J 及 λ 取值均给出明确表述，原则上可据此重建框架。
- **外部依赖较重**：审计器、优化器与 judge 均为闭源商用 LLM（Claude Sonnet 5.5、GPT-4.1），模型版本随时间变化会使结果难以严格复现；基准评估又依赖 OpenAgentSafety 发布的既有轨迹，属于二次分析。
- **提示词与种子规则的具体文本**未在总结所覆盖的范围内完整呈现（种子配置仅描述为一条"审计所有状态改变/外发动作"的规则加一段通用提示），若正文附录未完整披露，将影响门控-审计联合调优的复现精度。
- **调优随机性未控制**：5 轮迭代全部被接受、无早停机制，也未报告多种子重复实验或方差，最优配置的稳定性不可验证。

## 10. 启示与可改进方向

- **在线端到端评估**：在真实运行时（而非回放）测量阻断延迟、任务成功率与资源占用，补足"检测-成本-效用"三维曲线。
- **引入 monitor-aware 攻击者**：评估刻意规避触发规则、伪装 provenance、逐步低强度试探的对手，检验门控的鲁棒性，而非仅对抗"不规避监控"的攻击。
- **门控从规则向轻量学习模型演进**：用可微/可学习的打分器替代纯正则与关键词匹配，以覆盖浏览器元素编号等语义缺失场景，同时保留可解释性。
- **自适应阈值与风险分级**：将"SUSPICIOUS 计数阈值"改为基于轨迹风险累积的概率判定，并按动作危害等级动态调整触发灵敏度。
- **把审计器拒绝显式建模**：provider 拒绝当前既是检测信号又是评估噪声，应将其作为独立类别处理，并在忽略拒绝的口径下报告主指标，避免 TPR 虚高。
- **跨模型与超参泛化**：以开源模型替换审计器、扫描 λ 与上下文长度 K，验证结论是否依赖特定模型的安全对齐强度。
- **扩展到更复杂威胁**：多智能体共谋、跨会话持久化攻击、监控器信任链加固，以及误报导致任务失败的成本建模。

## 11. 总体评价

本文抓住 LLM 智能体安全中"**审计覆盖**与**审计成本**不可兼得"这一真实痛点，提出"确定性门控筛选 + LLM 语义审计 + 联合自动调优"的两阶段框架，在公开基准上以约 1/3 的审计次数与 token 换取可控的检测折损，并在自建多智能体仿真中验证了执行前阻断的可行性。其贡献主要在于**架构层面的折中设计与成本-精度的显式联合优化**，而非单项指标刷新；同时论文对 provider 拒绝、验证集高 FPR、离线回放等局限的主动披露提升了可信度。主要短板在于评估的在线性、攻击者的规避能力、模型与超参的单一性，以及成本指标与真实部署开销之间的落差。总体而言，这是一项**工程落地导向明确、方法可迁移性强，但结论外推仍需更严格在线验证**的工作。
