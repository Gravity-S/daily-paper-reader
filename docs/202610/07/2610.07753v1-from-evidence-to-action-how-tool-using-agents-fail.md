## 摘要
使用工具的智能体会对外部状态做出有影响的改变，然而正确的结果并不保证其行动得到事先确立的证据支持。我们研究当智能体从决定是否行动转向执行单一行动和依赖型工作流时，这一证据到行动链条在何处断裂。在十种模型-框架配置中，较强的静态行动评估可以与弱得多的交互式执行并存。失败往往在执行之前就已开始：智能体在调查不完整时停止，或在所需证据确立之前就采取行动。一旦获得所需证据，单一行动的执行通常可靠，而多行动工作流还会暴露出未解决的前提条件和执行不完整。为进行这项分析，我们提出 SafeActBench，包含跨越六个操作领域和五种协议的 656 个案例，这些协议从静态行动判断和经调查的不行动，推进到单一行动和多行动工作流。一个溯源绑定的 Evidence Ledger 和确定性轨迹评估器追踪了哪些信息已被确立、行动何时发生，以及下游依赖是否得到满足。这些结果表明，失败不仅源于信息缺失，还源于智能体在决定和执行行动时如何使用已确立的证据。

## Abstract
Tool-using agents make consequential changes to external state, yet correct outcomes do not guarantee that their actions were supported by evidence established beforehand. We study where this evidence-to-action chain breaks as agents move from deciding whether to act to executing single actions and dependent workflows. Across ten model-harness configurations, strong static action assessment can coexist with much weaker interactive execution. Failures often begin before execution: agents stop with incomplete investigation or act before required evidence is established. Once required evidence is obtained, single-action execution is usually reliable, while multi-action workflows additionally expose unresolved prerequisites and incomplete execution. For this analysis, we introduce SafeActBench, comprising 656 cases across six operational domains and five protocols that progress from static action judgment and investigated non-action to single- and multi-action workflows. A provenance-bound Evidence Ledger and deterministic trajectory evaluator track what information was established, when actions occurred, and whether downstream dependencies were satisfied. These results show that failures arise not only from missing information, but also from how agents use established evidence when deciding and executing actions.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题起点**：基于 LLM 的工具型智能体（tool-using agents）越来越多地被期望"采取行动"而非仅"生成答案"——发放退款、发送文档、更新记录、触发下游操作等。作者将这类会改变应用状态或产生外部效果的调用称为**有后果的行动（consequential actions）**。
- **核心洞察**：对有后果的行动而言，正确性不仅取决于"做了什么"，还取决于**行动之前是否已确立与任务相关的事实（证据）**。一个行动可能被完整任务状态所允许、使用正确工具/目标/参数、并成功返回，但若其所需证据从未在可观测轨迹中确立，它仍是**不受支撑的（unsupported）**。
- **研究缺口**：既有评测已从静态函数调用准确率转向有状态环境中的交互执行（AgentBench、WorkArena、OSWorld、AppWorld、τ-bench 等），也有工作分别研究风险工具使用、策略违背、过度信任、求助与弃权。但较少被直接刻画的是：**每个有后果的行动是否由其执行前实际确立的证据所支撑**，尤其是实体/状态绑定与下游结果传播。
- **整体含义**：论文把"证据→行动"链条作为可观测对象来研究，主张不能只以任务终点成败论英雄；失败可能发生在调查、证据绑定、行动时机、依赖满足等多个环节。这对智能体评测范式和部署前的安全设计都有直接意义。

## 2. 方法论

### 2.1 核心思想：证据到行动链（Evidence-to-Action Chain）

- 区分**信息收集调用**与**有后果的行动**，要求每个有后果行动在执行前由可观测证据支撑。
- 支撑的三个条件：
  - **获取当前证据**；
  - **绑定到行动的精确目标与参数**（实体/状态绑定：C1 的金额不能支撑对 C2 的退款，即使数值相同）；
  - **把实际执行结果传播到依赖它的后续行动**。
- 三种基本情形：
  - **有证据才行动**：只有所有必要前提 `R(a)` 被确立后才执行；
  - **经调查的不行动（investigated non-action）**：应先完成相关调查以确立"为何不该行动"，再停止且不产生副作用；过早停止或过早行动都不合格；
  - **链式行动**：多行动任务中，前序行动的返回值（如 `refund_id=R42`）可能成为后续行动的必要证据，且依赖关系约束时序。

### 2.2 形式化判据

- 对行动 `a`，其要求集合记为 `R(a)`：
  - `Supported(a) ⇔ ∀ r ∈ R(a), r is established before a.`
- 即只有当每个前提 `r` 在 `a` 执行前已被确立，`a` 才算被支撑。
- 事实可能"在环境中为真"但未被观测/确立，因此不算支撑。

### 2.3 关键机制：Evidence Ledger 与确定性评估

- **溯源绑定的 Evidence Ledger**：把已确立事实绑定到其来源交互及所描述的实体/状态；只有具备所需溯源的证据才算满足要求。
- **确定性轨迹评估器**：重放轨迹，检查所需调查、正确工具/目标/参数、执行回执、行动依赖与最终状态变化；**不检查隐藏推理、不使用 LLM judge**。
- **V2/V3 依赖表示**：线性序列（V2）或有向无环图（V3）；V3 允许任意合法拓扑序，独立行动可任意排序，依赖行动必须等待所需结果/状态可用。

### 2.4 补充研究：SCGR 运行时

- **SCGR（SafeAct Contract-Guided Runtime）**：轻量、免训练的分析工具，用于检验"结构化证据边界"能否减少失败。
- **SCGR-Select**：由模型自行选择决策相关问题（每批 1–3 个），把回答存入持久证据账本，并用结构化证据依据 `b_i = (q_i, s_i, R_i, e_i)`（问题、评估 supported/missing/violated、引用调用 ID、解释）提交候选，运行时仅做公开结构检查。
- **SCGR-EG**：把公开观测组织为证据图，并在 V2 做有界工具发现扫描、V3 做全公开候选扫描（调用计入信息预算）。
- 两种变体都只使用公开任务、工具规范与观测响应，不接触 gold 证据要求、参考行动或评估器依赖图。

## 3. 实验设计

### 3.1 Benchmark：SafeActBench

- **规模**：656 个规范案例，覆盖 **6 个操作领域**：
  - 客户与政策运营 112、工程与基础设施 109、法律与金融 144、研究助理 97、智能家居 96、医疗 98。
- **五种协议**（从静态判断到依赖约束执行）：
  - **Legacy**（86 例）：对固定候选行动做 Allow/Block/Defer 静态判断；
  - **V0**（175 例）：经调查的不行动（完成必要调查后不产生有后果行动）；
  - **V1**（131 例）：证据确立后恰好一次正确行动；
  - **V2**（132 例）：线性多行动工作流，后续行动可消费前序真实结果；
  - **V3**（132 例）：依赖约束（DAG）多行动工作流，任意合法拓扑序。
- **复杂度**：V0–V3 平均需 5.6–7.1 次指定读取，单例最多 17 次；V2 有 317 个行动节点、185 条依赖边、182 处结果引用；V3 有 501 个行动节点、439 条依赖边、296 处结果引用，含 103 个 fork 与 96 个 join 案例。
- **指标**：主指标为**精确案例成功（ECS）**（二值）；另报协议宏平均 P-M、领域宏平均 D-M。诊断指标包括 BSR（V0 调查未完成即停止）、PAR（V1 证据未完成即行动）、CAS（V1 证据完成且有行动后的严格成功率）、Gap（V2/V3 行动检查点存在未满足要求）、Part.（V2/V3 执行了但工作流不完整）。

### 3.2 对比对象：十种模型-框架配置

- 五个模型族：**Claude Opus 5、GPT-5.6 Sol、DeepSeek-V4-Flash、Qwen3.8-Flash、GLM-5.2**。
- 每个模型配两种 harness：**家族关联 harness**（Claude Code、Codex、DeepSeek Harness (DSH)、Qwen Code、ZCode）与**共享 ReAct harness（Inspect AI）**，以便分离模型与框架效应。
- 所有配置接收相同公开任务与工具接口，私有评测规范全程隐藏。

### 3.3 实验类型

- **主评测**：每案例–配置对跑 3 次 rollout，主评测覆盖率 100%（无基础设施失败）。
- **匹配案例的静态–交互对比**：同一批 100 个 V1 案例上比较"给完整证据包判断候选行动"与"原始 V1 交互执行"；另做 99 个场景的三分类（Allow/Block/Defer）平衡控制。
- **受控证据干预**：43 个 V1 案例（DeepSeek–DSH、GLM–ZCode、Qwen–Qwen Code）：
  - **Withheld**：抽掉一条决定性记录；**Contradicted**（22 例）：修改字段使前提被违背；
  - **evidence-package**：把相关工具响应呈现给智能体；
  - **requester-claim**：请求方声称缺失记录已核实无误；
  - 另有 **generic urgency**、**system warning**、**distractor records** 探针。
- **配对 harness 分析**：同一模型在 570 个 V0–V3 案例上比较家族 harness 与 Inspect，用 5,000 次案例配对 bootstrap 估计置信区间。
- **跨 harness 证据敏感性**：DeepSeek 在 DSH/Inspect、GLM 在 ZCode/Inspect 上比较干预效果。
- **补充研究**：SCGR-EG 在全部十种配置上与基线对比；SCGR-Select 在四配置全 570 案例及 DeepSeek 部分队列上对比。

### 3.4 验证与审计

- 656/656 作者参考解通过评估器；277 个共享世界案例可重建；2,468 个冻结证据增量通过 schema 校验；132 个 V3 DAG 通过结构检查。
- **人工验证**：按协议×领域分层抽样 120 案例，两名标注者独立评估；行动支撑原始一致率 95.83%（κ=0.87），要求必要性 93.36%（κ=0.81），要求确立 86.72%（κ=0.74）。
- **轨迹审计**：300 条模型轨迹（150 评估器正、150 负）；假接受 3/150（2.0%），假拒绝 2/150（1.3%）。
- **替代证据路径审计**：测试替代检索路径、不同工具返回等价事实、多观测联合支撑等；20 个错误实体与 30 个过期证据负控全部被拒。

## 6. 主要结论与发现

- **静态判断强 ≠ 交互执行可靠**：GLM–ZCode 在 Legacy 达 97.7%，但 V1–V3 仅 32.1%/12.1%/34.1%；DeepSeek–DSH Legacy 96.5%，V1–V3 约 60%。匹配案例上静态准确率 95.0%–99.0%，交互 ECS 仅 28.0%–52.0%，配对差距 43–69 点且置信区间不含零。
- **失败多发生在执行之前**：V0 调查未完成即停止（BSR 21.7%–62.9%）；V1 证据未完成即行动（PAR 37.0%–66.9%）。
- **证据一旦完成，单步执行通常可靠**：V1 条件成功 CAS 在十配置中九个为 93.2%–100%，DeepSeek–Inspect 较低为 83.3%。
- **多步工作流暴露多种失败特征**：V2/V3 出现未解前提（Gap）与不完整执行（Part.），二者相对比例因配置而异（如 GLM–ZCode V2 Gap 80.3% vs Part. 33.3%），说明并非单一执行瓶颈。
- **框架效应显著且依赖模型**：DeepSeek 用 DSH 比 Inspect 高 4.4 点（CI 排除零），GLM 用 ZCode 比 Inspect 低 6.8 点（CI 排除零）；框架变化常改变失败类型而非统一升降（如 GLM 在 V1 上以"早行动"换取"不行动"）。
- **对证据缺失的敏感性有限**：抽掉决定性记录使行动概率下降 37.2–45.2 点，但仍有 46.5%–53.5% 的完成 episode 继续行动；矛盾证据使其下降 54.5–70.0 点。请求方的冲突声明比"证据缺失"本身更能抑制行动。
- **检索与克制不必同步**：干扰记录在 Withheld 下使平均信息调用增加约 1.0–1.2 次（CI 均高于零），但行动概率变化 CI 含零。
- **结构化证据运行时**：SCGR-EG 在十配置上均提升
