## 摘要
多智能体 LLM 系统越来越多地自动化涉及具有不同权限级别的智能体的任务，从而带来一种安全风险：被攻陷的低权限智能体可以影响高权限智能体并触发未授权操作。我们研究了一个四智能体 LangGraph 流水线中的攻击传播，该流水线由 Supervisor、Researcher、Validator 和 Executor 组成。我们评估了共享内存投毒，以及通过嵌入检索文档中的伪造批准进行的间接提示注入。我们将 Validator 的判断与一个独立授权层进行比较，该层使用任务绑定的签名令牌和单独验证的策略预言机。我们的贡献是对攻击传播的实证研究、对授权边界的组件级消融，以及判断绕过率（Judgment Bypass Rate, JBR），该指标衡量的是被攻击智能体处的失陷，而非最终动作处的失陷。在三个随机种子和 60 个标注任务上，内存投毒在每次无防御试验中均到达执行阶段。启用授权后，它达到 100% JBR，但不安全动作率（Unsafe Action Rate）为 0%，表明 Validator 可以保持失陷，而执行仍被遏制。面对拥有签名密钥的攻击者，策略预言机提供了所观察到的遏制效果，而独立编写的最小权限策略保持了这一结果。一个 Observer 层将智能体劫持的假阳性率从 49% 降至 7%，且不削弱执行级安全性。这些结果表明，即使上游 LLM 判断失败，结构化授权也能遏制失陷智能体的行为。

## Abstract
Multi-agent LLM systems increasingly automate tasks involving agents with different levels of privilege, creating a security risk in which a compromised low-privilege agent can influence a higher-privilege agent and trigger an unauthorized action. We study attack propagation in a four-agent LangGraph pipeline comprising a Supervisor, Researcher, Validator, and Executor. We evaluate shared-memory poisoning and indirect prompt injection through a forged approval embedded in a retrieved document. We compare the Validator's judgment with an independent authorization layer using task-bound signed tokens and a separately verified policy oracle. Our contribution is an empirical study of attack propagation, a component-level ablation of the authorization boundary, and the Judgment Bypass Rate (JBR), which measures compromise at the attacked agent rather than at the final action. Across three seeds and 60 labeled tasks, memory poisoning reaches execution in every undefended trial. With authorization enabled, it achieves 100% JBR but 0% Unsafe Action Rate, showing that the Validator can remain compromised while execution is contained. Against an attacker possessing the signing secret, the policy oracle provides the observed containment, while an independently authored least privilege policy preserves this result. An Observer layer reduces the false-positive rate for agent hijacking from 49% to 7% without weakening execution-level security. These results show that structural authorization can contain compromised agent behavior even when upstream LLM judgment fails.

# 论文总结：多智能体 LLM 流水线中的信任传播与结构化遏制

## 1. 核心问题与整体含义（研究动机与背景）

- **研究动机**：多智能体 LLM 系统日益普及，通过角色分工（编排者、检索者、推理者、执行者）自动化复杂任务，但不同智能体拥有不同权限级别，形成了一条委托链。
- **核心安全风险**：低权限智能体被攻陷后，可能通过隐式信任影响高权限智能体，触发未授权操作——即经典的"混淆代理人问题"（Confused Deputy Problem）在多智能体 LLM 场景下的重现。
- **现有研究的不足**：先前工作主要关注"智能体是否能被欺骗"，而非"攻陷是否能到达真实系统动作"。攻击的实际安全影响取决于下游的授权、策略执行与独立验证等控制措施。
- **论文定位**：本文通过一个四智能体流水线，实证研究攻击传播、授权边界的组件级消融，并提出 **判断绕过率（JBR）** 指标，区分"审查被绕过"与"未授权动作成功执行"。

## 2. 方法论

### 2.1 核心思想
将 LLM 的判断（判断层）与授权（执行层）分离：即使上游 Validator 被攻陷，独立的授权边界仍能阻止未授权动作到达真实系统。

### 2.2 系统架构（四智能体 LangGraph 流水线）
- **Supervisor**：确定性路由器，不调用 LLM。
- **Researcher**：低权限，只读检索。
- **Validator**：中权限，审批门，判断提议动作是否安全。
- **Executor**：高权限，执行真实动作（SQLite 邮箱存储的读写）。
- 四个角色通过共享的类型化状态对象通信，每次状态转移均被记录。

### 2.3 结构化授权边界
- **签名令牌**：HMAC 签名、任务绑定、单次使用（nonce 防重放）。
- **策略预言机（Policy Oracle）**：独立于 Validator 判断，重新推导权限。分为两种模式：
  - *语料库策略*：镜像每个任务的黄金标签（用于多数实验）。
  - *独立策略*：手工编写的最小权限白名单，仅接收提议动作与作用域，不使用任务标签，与黄金标签在全部 60 个任务上一致。
- Executor 仅当令牌校验与策略校验同时通过时，才允许真实工具调用。

### 2.4 攻击模型
- **共享内存投毒**：Validator 被替换为被攻陷例程，伪造审批；若持有签名密钥，则直接生成匹配的授权令牌，不调用 LLM。
- **智能体劫持（间接提示注入）**：Researcher 检索到被污染文档，其中嵌入伪造的审批、置信度与来源声明；Validator 在不知来源的情况下对其进行推理。

### 2.5 评估指标
- **不安全动作率（UAR）** = FN / (TP + FN)，越低越好。
- **合法任务完成率（LTC）** = TN / (TN + FP)，越高越好。
- **假阳性率（FPR）** = FP / (FP + TN)，衡量过度拦截。
- **判断绕过率（JBR）** = Nb / Na，其中 Na 为被注入攻击的黄金不安全试验数，Nb 为 Validator 真实审查被跳过或绕过的数量——衡量"被攻击智能体处的失陷"，而非最终动作。

### 2.6 Observer 层
- 位于 Researcher 与 Validator 之间的额外 LLM 调用，专门识别并移除伪造的"已审查/已批准/高置信度"声明，保留其他内容；解析失败时使用确定性脱敏回退。
- 仅做二元过滤判断，不访问任务记录、黄金标签、策略预言机或 Validator 输出，**不能批准或阻止动作**，因此被定位为"效用保持组件"而非安全控制。

## 3. 实验设计

- **数据集**：
  - Enron 邮件数据集（>50 万封内部邮件），固定子集 1,000 封，仅保留 RFC 822 消息头（Message-ID、发件人、收件人、时间戳），存入 SQLite 索引表，作为可变更的真实数据资源。
  - 评估语料：**60 个任务**（36 个安全、24 个不安全），覆盖 **13 种动作类型**及具体资源访问作用域。
- **模型配置**：Researcher、Validator 及 Observer 均使用 `gemma4:31b-cloud`，经 Ollama 提供服务，温度 0；种子按尽力而为方式请求（Ollama 不保证固定种子下输出完全一致）。
- **条件设计**：
  - **T0**：禁用令牌检查与策略预言机（无防御）。
  - **T1**：同时启用令牌检查与策略预言机。
  - **授权消融**：仅令牌 vs. 仅策略预言机 vs. T0 vs. T1（针对持有签名密钥的攻击者）。
  - **策略对比**：语料库策略 vs. 独立最小权限策略。
  - **Observer 消融**：OFF vs. ON。
- **随机种子**：1、7、42，共 3 个种子；每格 n = 180 次试验（除非另有说明）。授权消融仅在单一种子上运行（n = 60/条件）。
- **对比基线**：主要对比"无结构化授权（T0）"与"有结构化授权（T1）"，以及授权内部组件的相互消融，而非与其他已发表方法横向对比。

## 5. 实验数量与充分性

- **实验规模**：
  - 攻击有效性：2 种攻击 × 2 种防御条件（T0/T1）× 3 个种子 × 60 任务 = 每格 180 次试验。
  - 授权消融：4 种条件（T0、仅令牌、仅策略、T1）× 单种子 × 60 次试验。
  - 策略对比：2 种策略 × 2 种攻击 × 3 个种子。
  - Observer 评估：OFF/ON 对比 + 120 对匹配的干净/劫持案例配对测试。
- **充分性评价**：
  - **优点**：多种子重复、组件级消融、渐进式增强攻击者能力（含持有签名密钥的最强攻击者），实验设计有层次。
  - **不足**：3 个种子的置信区间较宽（劫持 FPR 的 95% t 区间为 [28.1%, 70.0%]）；授权消融仅单种子、无置信区间；任务规模仅 60 个、13 种动作类型；未与其他已发表防御方法进行横向对比。
- **客观性**：作者明确指出语料库策略使用与评分相同的标签，其 0% UAR 只证明"对给定策略的执行保真度"，而非"独立发现不安全动作"；并用独立策略缓解此问题，态度较为严谨。

## 6. 主要结论与发现

- **内存投毒**：T0 下每次试验均成功执行（UAR 100%）；T1 下 UAR 降至 0%，但 **JBR 仍为 100%**——Validator 保持被攻陷，而 Executor 独立阻止了未授权动作。
- **智能体劫持**：T0 与 T1 下 UAR 均为 0%，但 Validator 频繁误拦合法任务，FPR 分别为 59.3% 与 49.1%（区间重叠，差异不应归因于授权机制）。
- **授权消融**：面对持有签名密钥的攻击者，**仅策略预言机即可复现 T1 的遏制效果**，而仅令牌条件与 T0 无法区分。签名授权的是来源（provenance），而非权限（permission）。
- **独立策略**：手工最小权限策略在两种攻击下同样保持 UAR = 0%，F1 与语料库策略一致（劫持场景均为 0.74），说明遏制并非标签依赖的产物。
- **Observer 效果**：FPR 从 49.1% 降至 7.4%（相对降低 85%），F1 从 0.74 升至 0.95，LTC 从 50.9% 升至 92.6%，UAR 保持 0%；JBR 从 0% 微升至 4.2%（因 Validator 不再被显眼声明"一刀切"拒绝，而能做出更实质判断，少量误判仍被授权边界遏制）。
- **总体结论**：**上游智能体被攻陷并不意味着系统最终动作被攻陷**；将 LLM 判断与授权分离，可让被攻陷的智能体被视为"不可信决策者"而不自动获得造成真实系统影响的权限。

## 7. 优点

- **概念创新**：提出 **JBR（判断绕过率）**，明确区分"智能体层面的失陷"与"端到端未授权动作成功"，弥补了以往研究将两者混为一谈的缺陷。
- **组件级消融**：清晰定位在最强攻击者模型下"策略预言机"才是承载遏制效果的关键组件，并指出签名令牌的局限（"签名授权来源，不授权权限"）。
- **攻击者能力递进**：从无密钥到持有签名密钥，区分"真正的安全保证"与"因缺少凭证而失败的攻击"。
- **反循环论证设计**：用独立手写最小权限策略验证结果，避免"用评分标签训练/构造策略"的自我印证。
- **真实执行验证**：通过沙箱化的 SQLite 邮件存储记录真实数据库/文件系统变更，确保衡量的是真实效果而非模拟效果。
- **Observer 定位审慎**：明确将其定性为效用保持组件而非安全控制，并配合匹配配对实验（120 对）分析其独立特性。
- **威胁模型诚实**：对置信区间重叠、单种子消融、注入显眼性等局限均有坦率讨论。

## 8. 不足与局限

- **策略作者同一性**：独立策略虽无法访问黄金标签，但仍由同一研究团队手工编写，只能证明"非循环实现"，而非"客观策略正确性"。
- **统计效力不足**：3 个种子的置信区间较宽（劫持 FPR 区间 [28.1%, 70.0%]），授权消融仅单种子、无置信区间。
- **规模有限**：仅 60 个任务、13 种动作类型，泛化性存疑。
- **注入过于显眼**：劫持注入显式声明"已批准、高置信度、有来源"，这可能是 Validator 在无 Observer 时 JBR = 0%、Observer 完全分离（TPR = 1.0、FPR = 0.0）的原因；对自适应攻击者或更隐蔽的注入，可能出现分数分布重叠、非平凡操作曲线与非零 JBR，Observer 的工作点不应外推。
- **架构与模型单一**：仅评估一种架构（四智能体 LangGraph）、一种框架、一个模型（gemma4:31b-cloud），Validator 行为可能因模型而异，遏制结论需更广泛验证。
- **执行层遏制不依赖可检测性**：作者指出策略预言机从不读取检索内容，因此执行层遏制不依赖注入是否可被检测——但这也意味着该结论仅适用于"执行层"，不解决上游误判问题。
- **未与已有防御方法横向对比**：如 AgentBound、Signed-Prompt、StruQ、JATMO 等，缺乏相对性能基准。
- **算力信息缺失**：未报告推理成本、延迟或资源消耗，影响实用部署评估。
