## 摘要
由工具增强的大型语言模型（LLM）智能体能够通过工具调用作用于外部系统，从而自动化复杂的多步任务，如网页导航、代码生成和工作流编排。然而，LLM中的幻觉、分布不稳定性、对抗性操纵，以及某些工具调用的不可逆后果，都可能导致有害结果。现有防护措施要么使用随机LLM评判器事后对记录轨迹进行评分，要么一次一个调用地阻止不安全动作，尚无单一的确定性工件能同时支持这两种角色。我们提出ContrAgent，一个基于契约的框架，用于对LLM智能体进行符号时序监督。ContrAgent将智能体的行为捕获为一系列工具调用，并将其形式化为固定可检查谓词集合上的轨迹。然后，它使用有限轨迹线性时序逻辑（LTLf）中的假设-保证契约来规约所需行为。每个契约被编译为确定性有限自动机（DFA），其承担两种作用：在线门控智能体动作，以及离线评估记录轨迹。契约库作为可复用的知识库，独立于智能体的模型进行维护，并可应用于同一任务领域内的不同智能体。我们在涵盖这两种作用的四个基准上展示了该方法的有效性；ContrAgent与最先进的LLM评判器和基于规则的护栏基线相当，同时产生确定、可复现的判定，并且在线模式下每次调用的延迟低数个数量级。

## Abstract
Large language model (LLM) agents augmented by tools can automate complex, multi-step tasks, such as web navigation, code generation, and workflow orchestration, by acting on external systems through tool calls. However, hallucinations, distributional instability, and adversarial manipulations in LLMs, and the irreversible consequences of certain tool calls can lead to harmful outcomes. Existing safeguards either grade recorded trajectories post hoc with stochastic LLM judges or block unsafe actions one call at a time, and no single deterministic artifact supports both roles. We present ContrAgent, a contract-based framework for symbolic temporal supervision of LLM agents. ContrAgent captures an agent's behavior as a sequence of tool calls and formalizes it as a trace over a fixed set of checkable predicates. It then specifies required behaviors using assume-guarantee contracts in linear temporal logic over finite traces (LTLf). Each contract is compiled to a deterministic finite automaton (DFA) that serves two roles: gating agent actions online and evaluating recorded traces offline. A contract library, acting as a reusable knowledge base, is maintained independently of the agent's model and can be applied across different agents within the same task domain. We show the effectiveness of our approach on four benchmarks spanning both roles, where ContrAgent matches state-of-the-art LLM-judge and rule-based guardrail baselines while producing deterministic, reproducible verdicts and, in the online mode, orders-of-magnitude lower per-call latency.

## 1. 核心问题与整体含义

- **现有防护的缺口**：
  - 事后评估类方法使用 LLM 评审器或学习检测器给记录轨迹打分，但判定具有随机性，难以复现。
  - 在线拦截类方法逐动作判断，缺少跨轨迹的时序推理，或依赖特定智能体模型、语义意图而非工具调用行为。
  - **没有单一确定性工件同时支持在线门控与离线轨迹评估**。
- **整体含义**：论文提出 **ContrAgent**，用假设-保证契约（A/G contracts）与有限轨迹线性时序逻辑（LTLf / ALTLf）对 LLM 智能体的工具调用轨迹进行符号化、模型无关、确定性的时序监督，并编译为 DFA，使同一契约既能在线上阻止违规调用，又能离线复现性地评估轨迹。

## 2. 方法论

### 核心思想

- 将智能体行为抽象为**工具调用轨迹**，即调用事件与返回事件的有序序列。
- 用固定、可检查的**交互谓词**作为原子命题，描述调用、参数、结果、数据流、权限、计数、令牌数等。
- 用 **ALTLf 假设-保证契约**描述轨迹级要求：假设 φA 约束环境，保证 φG 约束智能体。
- 每个契约编译为**确定性有限自动机（DFA）**，在线门控动作、离线评估轨迹，契约库跨模型复用。

### 关键技术细节

- **智能体会话与轨迹**：会话为转移系统 \(T=(S,s_0,\Sigma,R)\)，状态 \(s=(\tau,\kappa,\rho)\) 包括事件轨迹、上下文映射与数值计数器；每次工具调用产生调用事件与返回事件。
- **交互谓词**：
  - 结构谓词：`Call(T)`、`ArgHas(T,f,p)`、`OutHas(T,p)`、`Said/In(p)`、`Match(f,k)`、`Subset(f,S)`、`Flow(s,d)`、`Perm(P)` 等。
  - 数值谓词：`Cnt(T)`、`Num(T,f)`、`Tok` 等，形式为 \(\theta(s,a)\ \triangleright\!\!\triangleleft\ c\)，支持算术约束，属于 ALTLf。
  - 谓词在事件点由监控器确定性求值，数值谓词通过计数器累积。
- **Agent Contract**：契约 \(C=(V,\varphi_A,\varphi_G)\)，其中 \(V=V_{ag}\cup V_{env}\) 为交互谓词集合，φA 是环境假设，φG 是智能体保证；语义为轨迹满足 \(\varphi_A \rightarrow \varphi_G\)。
- **运行时三值判定**：契约对具体轨迹取 IDLE(1)、ACTIVE(e)、FAIL(0) 三值，排序 \(0\le e\le 1\)。多契约通过 join 得到环境有效性 \(v_{env}\)，通过 meet 得到智能体有效性 \(v_{ag}\)：
  - \(v_{env}(\tau)=\bigvee_i \llbracket(A_i,G_i)\rrbracket(\tau)\)
  - \(v_{ag}(\tau)=\bigwedge_i \llbracket(A_i,G_i)\rrbracket(\tau)\)
  - 在线 enforcement 在首个非 \((e,e)\) 前缀返回 block；离线 evaluation 返回最终 \(v(\tau)\)。
- **契约编译**：
  - 支持人工编写 ALTLf，也支持从自然语言/政策文档“先提升后落地”：LLM 先生成含占位符的 ALTLf，再确定性映射到交互谓词，并回译供人工审查。
  - LTLf/ALTLf 公式按标准构造编译为 DFA，字母表为 \(2^V\)；数值谓词只在 grounding 时读取计数器，DFA 本身保持有限。
  - 契约库检查一致性、兼容性、无冲突；冲突时提取最小不可满足核定位需修复契约。
- **在线监督**：
  - 在每个事件进入轨迹前检查并推进各契约 DFA；若会违反保证则阻止调用，若会违反假设则抑制返回/输入事件。
  - 采用增量 residual formula 推进，单事件成本 \(O(|C|)\)，与轨迹长度无关。
  - 支持阻止、重定向到安全替代、升级人工等策略，并返回结构化反馈，如“issue_refund 被拒绝：请先调用 check_policy”。
  - 对 liveness 保证 \(G(trig \rightarrow F resp)\)，会话结束时对未满足项提示并最终判 FAIL。
- **离线评估**：
  - 对固定轨迹重放相同 DFA，返回每契约归因的三值判定；同一轨迹总是得到相同结果。
  - 多轨迹复用时 DFA 构建一次，事件判定可视为 \(O(1)\) 表查找。

## 6. 主要结论与发现

- **SOPBench**：ContrAgent 将 safety 从 base 的 32% 提升到 98%，同时 success 保持约 90%，优于 prompt 的 64% success 和 LLM-guard 的 24% success；额外运行时间约 0.135 s，低于 prompt 与 LLM-guard。
- **模型无关性**：在 gemini-2.5-flash-lite 弱模型上，prompt 的 safety 从 94% 降至 45%，ContrAgent 的 safety 保持 98%，说明确定性监督不依赖智能体能力。
- **AgentDojo**：no-detector 变体将 ASR 从 47.7% 降至 11.1%，utility 71.8%；trace-learned 变体 ASR 降至 0.79%，utility 72.6%，每次调用仅增加 0.16 ms，远低于分类器或 LLM 过滤器的 50–500 ms。
- **R-Judge**：平均 F1 达 91.8%（precision 97.0%，recall 87.0%），超过 GPT-4o 的 74.4% 和人类约 89%；低于使用检索记忆的 AgentAuditor，漏检多为语义性而非程序性。
- **τ²-bench**：Claude 3.7 的 outcome pass@4 为 25–60%，但 joint@4 在所有领域为 0%，说明大量奖励为 1 的轨迹仍违反程序规则，存在 reward hacking。
- **总体结论**：ContrAgent 以确定性、可复现、低延迟的方式统一在线安全门控与离线轨迹审计，契约库可跨模型复用。

## 7. 优点

- **统一在线与离线**：同一契约编译出的 DFA 同时用于在线门控和离线评估，避免两套不一致的防护机制。
- **确定性与可复现**：判定不依赖随机 LLM 评审，同一轨迹总得到相同 verdict，并给出具体契约与触发事件归因。
- **形式化与模块化**：基于 A/G 契约和 ALTLf，支持顺序、历史、计数等轨迹级属性；多策略可独立加载，冲突可定位。
- **模型无关与可移植**：契约写在工具调用接口的交互谓词上，不依赖具体 LLM 内部，可跨模型复用。
- **低延迟**：增量检查 \(O(|C|)\)，在线每调用延迟远低于 LLM 评审或分类器。
- **实验覆盖广**：四个基准分别验证在线 enforcement 与离线 evaluation，并补充跨模型、弱模型、约束规模、消融与延迟分析。

## 8. 不足与局限

- **仅覆盖工具调用结构**：只能约束可由工具调用结构暴露的属性，自由形式的语义危害需要额外内容级检查。
- **契约依赖人工审查**：论文中契约库使用前由人工检查；自然语言政策自动形式化未解决，留作未来工作。
- **信任观测通道**

- **信任观测通道**：在线门控与离线评估都以监控器收到的事件流为唯一事实来源；若工具调用日志可被篡改、遗漏、延迟，或智能体通过旁路通道执行动作、工具在监控器之外产生副作用、环境伪造返回结果，则契约前提不成立。实际部署需要可信日志、工具代理网关、执行隔离或日志完整性校验等机制配合。
- **契约工程与可扩展性**：契约库需要人工审查、版本管理与冲突消解。随着工具数量、领域和政策增长，契约可能冗余、重叠或相互冲突，最小不可满足核提取虽能定位问题，但维护成本仍会上升。ALTLf 到 DFA 的编译在复杂公式下也可能出现状态膨胀，影响冷启动与内存占用。
- **形式化表达边界**：交互谓词主要刻画调用结构、参数、返回、权限、计数和数据流，对自由文本语义、隐含意图、多模态内容、社会规范或“未调用工具但造成危害”的行为覆盖有限。因此它更适合程序性合规与安全门控，而非通用语义安全判定。
- **在线干预的副作用**：阻止、重定向或抑制事件可能改变智能体计划，导致任务失败、死锁或用户体验下降。论文展示了低延迟和可解释反馈，但策略选择、恢复机制、对 liveness 保证的最终判定，仍需按业务场景调参。
- **对抗自适应风险**：契约公开或可被推断时，攻击者可能改变攻击路径以规避结构谓词，例如把恶意语义包装成合法调用序列。确定性监督降低了随机性，但不能替代内容级检测、权限最小化和沙箱执行。
- **实验与部署局限**：部分基线数字引用已发表结果，并非全部在同一环境重跑；AgentDojo 中回放运行使效用不可能超过未防御智能体；R-Judge 对比条件不完全对等。真实生产中的并发调用、异步返回、多智能体协作、长周期会话和工具版本漂移，尚未被充分覆盖。
- **成本与工程复杂度**：论文未报告契约构建的 LLM 调用量、人工审查工时或训练算力。方法本身不训练模型，但将政策形式化、接地到工具接口并验证一致性，需要领域专家与形式化工程投入。
- **评测范围**：四个基准主要衡量工具调用层面的安全、SOP 合规和风险检测，对隐私、公平性、法律合规、长期社会影响等更广泛治理目标只能间接支持。

## 9. 总体评价与启示

ContrAgent 的核心贡献不是提出新的 LLM 能力，而是把智能体安全从“事后用另一个 LLM 打分”转向“用可检查的符号契约约束工具调用轨迹”。它用 A/G 契约与 ALTLf 将在线门控和离线审计统一到同一 DFA，实现确定性、可复现、低延迟和跨模型复用，这在当前以概率评审器为主的防护范式中具有明显差异化价值。

从实验看，它在 SOPBench 上显著提升 safety 且保持较高 success，在 AgentDojo 上大幅降低 ASR 而开销极小，在 R-Judge 上取得较高 F1，并揭示 τ²-bench 中结果奖励与程序合规之间的脱节。这些结果说明：对可结构化的工具调用行为，确定性时序监督是有效且工程可行的；对开放语义危害，则仍需与内容过滤器、权限系统、沙箱和人工升级机制组合使用。

实践上，该方法适合作为智能体执行层的“策略网关”：在调用前检查契约，在调用后记录可复现证据，并允许不同模型共享同一契约库。未来工作可关注自然语言政策的自动形式化、语义与符号监控的混合架构、并发与多智能体时序、可信观测通道，以及契约库的规模化治理。
