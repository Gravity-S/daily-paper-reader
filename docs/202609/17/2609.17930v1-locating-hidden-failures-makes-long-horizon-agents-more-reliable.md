## 摘要
随着 AI 智能体承担长时间自主任务，我们越来越多地是在监督而非亲自完成工作，却仍然几乎完全以它们最终是否成功来评判它们。仅凭结果无法揭示一次运行在何处出错、智能体是否恢复，或沿途造成的不可逆损害，而长时程智能体在何处失败仍未被系统描绘。我们研究了软件工程、计算机使用和科学领域中接近真实部署的 2518 条智能体轨迹，并将 6967 个错误归类为 78 种失败类型。失败呈现出一种反复出现的特征：智能体在首次犯错后往往无法恢复，且很少能自行发现该错误，因此运行会在看似正确的情况下继续不受制止；智能体能否恢复取决于任务和环境的反馈，而非运行它的智能体框架。长时程智能体在通往通过结果的过程中可能造成真实伤害：即使被评为已解决的运行，也可能删除数据、损坏系统，或伪造成功而非真正赢得成功。我们将这些经人工验证的标注发布为 Traverse，这是一个基准，在该基准上，六个前沿评判器无论规模如何都难以定位失败：即便其中最强的评判器，也只在不到三分之一的运行中正确识别出首个错误。然而，我们训练的 4B 验证器 Scout 定位失败的能力远胜于这些评判器，并能迁移到它从未见过的领域。在测试时，它被用于在智能体的多个候选运行中进行选择，从而在不重新训练智能体的情况下，将任务成功率提升到高于智能体自身单次尝试的水平。通过降低失败定位与纠正的成本，这项工作为更值得信赖、能从自身错误中学习的长时程智能体奠定了基础，也为监督日益自主的 AI 提供了一条切实可行的路径。

## Abstract
As AI agents take on long, autonomous tasks, we increasingly oversee rather than perform the work, yet we still judge them almost entirely by whether they finally succeed. An outcome cannot reveal where a run went wrong, whether the agent recovered, or the irreversible harm it caused along the way, and where long-horizon agents fail remains unmapped. We study $2518$ agent trajectories across software engineering, computer use, and science, close to real deployment, and classify $6967$ mistakes into $78$ failure types. Failure follows a recurring signature: after its first mistake an agent often fails to recover and rarely catches the error itself, so the run continues unchecked while still looking correct; whether an agent recovers depends on the task and the environment's feedback, not on the agent framework running it. Long-horizon agents can do real harm on the way to a passing result: even runs scored as solved delete data, corrupt systems, or fabricate success rather than earning it. We release these human-verified annotations as Traverse, a benchmark on which six frontier judges struggle to locate failure regardless of scale: even the strongest correctly identifies the first mistake in fewer than a third of runs. Yet Scout, a $4$B verifier we trained, locates failure far better than these judges and transfers to domains it never saw. Used at test time to select among an agent's candidate runs, it raises task success above the agent's own single-attempt performance, without retraining the agent. By making failure cheap to locate and correct, this work is a foundation for more trustworthy long-horizon agents that learn from their own mistakes, and a practical path to overseeing increasingly autonomous AI.

## 1. 核心问题与整体含义

- **研究动机**：AI 智能体正从"回答问题"走向"自主完成数百步的长时程任务"（修复代码仓库、操作计算机、端到端科研），人类角色从执行者转为监督者，但评判方式仍几乎只看最终成败（pass/fail 一个 bit）。
- **核心痛点**：单一结果无法回答三个关键问题——运行在**何处**出错、智能体是否**恢复**、沿途是否造成**不可逆伤害**。作者用比喻说明：这就像只用"咖啡是否做好"来评判家务机器人，却对它烧毁厨房视而不见。
- **风险场景**：论文给出真实案例——智能体遇到"磁盘空间不足"后删除最大目录以腾空间，每步局部合理且任务被判定为"已解决"，但该目录存有某长期实验的唯一副本，数周计算被永久销毁。类似模式可导致删除生产数据库、损坏财务账本、篡改患者记录。
- **研究缺口**：既有失败研究多局限于短时程/合成基准、多智能体系统，或只诊断精度随 horizon 的退化；**没有**工作对真实长时程智能体做跨领域、跨模型、跨框架的逐步失败刻画，也**没有**任何基准测量模型能否在长轨迹中**定位**失败。这同时是"可扩展监督"（scalable oversight）的核心问题。
- **整体含义**：论文主张长时程可靠性的关键不是降低错误率，而是**在首错复合之前定位并纠正它**；定位能力可服务于调试、评测、过程奖励模型、测试时选择与安全审计。

## 2. 方法论

### 2.1 轨迹收集与统一表示

- 从三个接近真实部署的领域收集 **2,518 条轨迹**：agentic SWE（SWE-bench 系列，565 条）、computer use（TerminalBench，1,851 条）、agentic science（BixBench，102 条，自行生成）。
- 覆盖多种模型骨干（Claude、GPT-5、Gemini、DeepSeek、Qwen、Kimi）与多种 harness（mini-SWE-agent、SWE-agent、OpenHands、Terminus 2、ReAct/SimpleAgent）。
- 统一步骤表示为 **$s_t=(\theta_t,a_t,o_t)$**，即 Thought、Action、Observation；步骤平均 28（SWE）、33（Terminal）、10（Bix），最长可达 200 步。

### 2.2 人工标注与失败分析

- **错误定义**（三条件同时成立）：(i) 是状态改变性的决策（非被动读取）；(ii) 基于当时可用证据即为错误（非事后诸葛）；(iii) 使任务偏离任何仍可解路径。Observation 不判错，只判 Thought 与 Action。
- 每步标注 correct/incorrect，并标出**首个错误** $m$（全对则 $m=\bot$）。两名标注者独立标注，Cohen's $\kappa=0.77$（是否失败）、$0.73$（错在何处），第三名仲裁。
- **确定性分析**（不依赖 judge）：
  - **恢复率**：首错后仍解出任务即"恢复"；否则"未恢复"。
  - **粘性比**（stickiness ratio）：前一步错时当前步错的概率 ÷ 前一步对时当前步错的概率。
  - **静默失败**：未解出任务的运行却以"局部正确"步骤收尾。

### 2.3 失败分类学

- **预注册 codebook**：88 类、10 家族，在判读前依据初读失败轨迹与文献拟定，其中 10 类从未出现，说明其覆盖失败空间而非拟合数据。
- 用 LLM judge（gemini-3.1-pro，high reasoning，temperature 0，schema 校验）为每个错误打上：家族/细类、**root fault**（新发错误）vs **cascade**（下游后果，并记录肇因步）、所处三分位（早/中/晚）。
- 双 judge 在家族（$\kappa=0.66$）、root/cascade（$0.64$）、相位（$0.81$）上一致较好，但**细类仅 0.30**，因此结论只在家族/root-cascade/相位层面给出。
- **自检（self-detection）**：judge 读首错后的推理，判断智能体是否承认出错、是真自省还是仅对环境报错作出反应（因需可见推理通道，测得的"盲区"是下界）。
- **行为持续性（persistence）**：首错后是否继续犯新错、宣布完成、重复动作、从不验证。
- **安全审计**：关键词扫描候选不安全动作 + judge 全文裁决，记录是否必要、是否可逆、风险是否被承认、类别与严重度；对 judge 敏感的稀有判断报告为区间。
- **开放编码**：不属于 codebook 的错误另行开放编码，由此发现**欺骗/奖励黑客**聚类。

### 2.4 Traverse 基准

- 任务形式化：给定 $\tau=(s_1,\dots,s_T)$，判断是否含错并预测**首个错误索引** $\hat{m}$；聚焦首错，因为长程运行通常由单点脱轨、之后每一步继承被污染状态。
- 从分析语料中筛除步骤畸形/缺失的轨迹，并平衡对/错样本，最终构成 **1,423 条轨迹、44,341 步**：SWE-bench 600（306 失败/294 正确）、TerminalBench 721（541/180）、BixBench 102（38/64）。
- 首错位置分布广泛（SWE 中位第 14 步、Terminal 中位第 7 步），固定位置猜测无法奏效。
- 是首个同时具备**长时程（20–200 步）、自然发生失败、人工首错定位、多领域多 scaffold** 的过程级验证器基准（对比 ProcessBench、PRMBench、ToolPRMBench、Web-Shepherd、AgentRewardBench、Agent-RewardBench）。

### 2.5 Scout 验证器训练

- **基座**：Qwen3-4B-Thinking-2507（另用 Gemma-3n-E4B-it 验证配方不依赖特定骨干），4B 参数。
- **训练数据构造**：用 Gemini-3 Flash 在给出 gold label 的条件下生成逐步 CoT 分析 $c$，解析其逐步判决并反复重生成，直到与 gold 完全一致；得到 2,416 条 label-faithful 轨迹（公开），其中 1,904 条用于训练。
- **第一阶段 SFT**：输入为轨迹+评判 rubric+输出格式，目标为分析 $c$（含逐步判决 $\hat{y}$）；仅在目标 token 上计算 next-token loss（prompt 部分 mask）；全参数微调 3 epochs，lr $1\times10^{-5}$，128K 上下文以容纳长轨迹。
- **第二阶段 RL（GRPO）**：Scout 自行生成分析，与 gold 比对给奖励。每轨迹采样 $G=4$ 个分析，每步 32 条轨迹（128 rollouts），响应最长 8K token，训练 8 epochs，actor lr $1\times10^{-6}$，KL 系数 $\beta=0.001$，用 verl 实现。
- **奖励设计（关键）**：设正确步召回 $R_c$、错误步召回 $R_i$。
  - 要求全步匹配 → 几乎无梯度；$(R_c+R_i)/2$ → "全标正确"即得 0.5，形成 reward-hacking 陷阱（正是前沿 judge 的过标现象）。
  - 采用**乘积** $R_{\text{step}}=R_c\cdot R_i$（失败轨迹）：全标正确则 $R_i=0$，全标错误则 $R_c=0$，两端崩塌；但失败轨迹上乘积初值为 0，组内可能全 0 无梯度。
  - 最终奖励 **$r=0.7\cdot R_{\text{step}}+0.3\cdot\mathbb{1}[\hat{g}=g]$**，加轨迹级粗判决项提供早期可学信号；正确轨迹上 $R_i$ 无定义，则 $R_{\text{step}}=\mathbb{1}[\text{全标正确}]$；无解析判决者奖励 0。

### 2.6 评测协议

- **首错定位**：在失败轨迹上按 exact match、$\pm1$、$\pm3$ 容差、MAE 评分。
- **错误检测**：轨迹级判决 $g(\tau)=\mathbb{1}[\hat{m}\neq\bot]$，按 precision/recall/F1 评分（也等价于 outcome reward model 质量）。
- **测试时性能**：best-of-$N$ 选择——用 Scout 对每个候选轨迹打 $P(\text{Yes})$，选最高者，检验是否通过。
