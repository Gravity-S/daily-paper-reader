## 摘要
基于 LLM 的集中式多智能体系统（MAS）通过注册新的工作者智能体来扩展其功能，这些智能体的描述会被规划器读取，以决定任务如何分解、由哪个工作者执行每个子任务，以及每个子任务需要什么。第三方描述由系统外部编写，但被规划器信任，从而形成了一条注册时注入通道。该载荷在任何用户指令到达之前就被植入，以规划器为目标，并通过生成的计划传播到良性工作者，即使被构造的工作者从未被分配子任务或调用，也会生效。我们定义了四个工作者描述字段：功能、输入规范、输出规范和使用约束。在来自三个公共智能体市场的 32,000 条描述中，大多数省略了输入规范和使用约束，而至少 23.35% 包含这些字段之外的内容。我们构建了八种描述操纵攻击策略，针对任务分解、能力锚定和子任务规范，并在 GAIA 上评估它们。在最严重的情况下，单条被操纵的描述会将任务成功率从 84.31% 降至 37.25%，或将 token 消耗或执行时间增加超过 111%，而用户目标保持不变，工作者也忠实地执行生成的计划。这些影响在两种 MAS 实现、六个规划器 LLM、四个 LLM 评估器以及来自三个市场的真实描述中持续存在。我们进一步提出 DescGuard，一种注册时防御，在描述到达规划器之前仅保留工作者范围内的接口信息。DescGuard 在不修改工作者实现、规划器或编排逻辑的情况下，将受影响的规划指标和下游性能恢复到接近基线水平，并可与现有的隔离、权限控制和运行时机制组合使用。

## Abstract
A centralized LLM-based multi-agent system (MAS) extends its functionality by registering new worker agents, whose descriptions are read by the planner to decide how a task is decomposed, which worker executes each subtask, and what each subtask requires. Third-party descriptions are authored outside the system but trusted by the planner, creating a registration-time injection channel. The payload is planted before any user instruction arrives, targets the planner and propagates through the generated plan to benign workers, taking effect even when the crafted worker is never assigned a subtask or invoked. We define four worker-description fields: functionality, input specification, output specification, and usage constraints. Among 32,000 descriptions from three public agent marketplaces, most omit input specifications and usage constraints, while at least 23.35% contain content outside these fields. We construct eight description-manipulation attack strategies targeting task decomposition, capability grounding, and subtask specification, and evaluate them on GAIA. In the most severe cases, a single manipulated description reduces task success from 84.31% to 37.25%, or increases token consumption or execution time by over 111%, while the user objective remains unchanged and workers faithfully execute the resulting plan. These effects persist across two MAS implementations, six planner LLMs, four LLM evaluators, and the real-world descriptions from three marketplaces. We further propose DescGuard, a registration-time defense that retains only worker-scoped interface information before descriptions reach the planner. DescGuard restores the targeted planning metrics and downstream performance toward their baseline levels without modifying worker implementations, the planner, or the orchestration logic, and composes with existing isolation, permission-control, and runtime mechanisms.

# 论文总结：通过欺骗性简历误导规划器——集中式多智能体系统中的注册时注入

## 1. 核心问题与整体含义

- **研究背景**：集中式 LLM 多智能体系统（MAS）通常由一个规划器（planner）和多个工作者智能体（worker agents）组成。规划器读取每个 worker 的自然语言描述，据此决定任务如何分解、子任务分配给谁、每个子任务需要什么执行要求。
- **核心问题**：第三方 worker 描述由系统外部编写，却进入系统内部被规划器当作可信规划输入。这形成了一条**注册时注入通道**：攻击者可在任何用户指令到达前，将操纵性内容植入 worker 描述。
- **与已有 prompt injection 的区别**：
  - 载荷在注册时植入，而非用户请求、检索内容或工具输出时注入。
  - 攻击目标不是单个 worker，而是规划器。
  - 影响通过生成的计划传播到良性 worker，即使被构造的 worker 从未被分配子任务或调用也会生效。
  - 位于隔离、沙箱、权限控制、运行时监控等执行期防御的上游，现有机制通常不会检查规划前的描述。
- **整体含义**：worker 描述不是普通文档，而是安全敏感的编排输入；集中式 MAS 的信任边界必须覆盖注册时的描述处理。

## 2. 方法论

### 2.1 系统与计划的表示

- 论文将集中式 MAS 的规划过程形式化为：

  \[
  \pi = p(x, D)
  \]

  其中 \(x\) 是用户请求，\(D\) 是规划器可见的 worker 描述集合，\(\pi\) 是生成的计划。

- 计划被分析性地表示为：

  \[
  \pi = (S, E, g, U)
  \]

  - \(S\)：子任务集合；
  - \(E \subseteq S \times S\)：子任务依赖关系；
  - \(g: S \rightarrow A\)：子任务到 worker 的分配函数；
  - \(U = \{u_s\}_{s \in S}\)：每个子任务的执行规范。

- 由此划分出三个规划决策维度：
  - **任务分解**：由 \(S, E\) 刻画；
  - **能力锚定**：由 \(g\) 刻画；
  - **子任务规范**：由 \(U\) 刻画。

### 2.2 worker 描述的四类接口字段

论文借鉴软件接口声明组件功能与调用要求的方式，定义 worker 描述应提供四类信息：

- **功能（Functionality）**：worker 能做什么；
- **输入规范（Input specification）**：接受什么形式的输入；
- **输出规范（Output specification）**：产生什么形式的结果；
- **使用约束（Usage constraints）**：使用条件，如网络连接、可访问路径等。

论文抽样分析 32,000 条公共市场描述，发现：

- 绝大多数描述会声明功能；
- 但至少 89.73% 缺少输入规范，74.82% 缺少输出规范，94.61% 缺少使用约束；
- 至少 23.35% 包含四字段之外的内容，如无边界能力声明、面向规划器的指令式措辞。
- 因此，恶意描述可以伪装成市场常见风格，不易被审查发现。

### 2.3 攻击策略：八种描述操纵

攻击者只操纵一个第三方 worker 的描述，保留其原能力相关内容，追加策略性 steering 内容。其他用户请求、规划器、其他描述、worker 实现和工具接口均不变。攻击形式化为：

\[
d'_i = \tau(d_i), \quad \pi' = p(x, D')
\]

八种攻击分为三类：

- **任务结构攻击（Task structuring）**：
  - **Under-decomposition**：诱导规划器合并本应可分的操作，使子任务过粗；
  - **Over-fragmentation**：诱导规划器过度拆分，增加子任务数量与协调成本；
  - **Dependency disruption**：诱导规划器加入冗余验证子任务、额外依赖和自检。
- **能力锚定攻击（Capability grounding）**：
  - **Over-assignment**：把某 worker 描述得适用范围极广或极可靠，使规划器过度分配任务给它；
  - **Agent exclusion**：把某 worker 描述得不可靠或不适用，使规划器避免使用它，即使它适合相关子任务。
- **子任务规范攻击（Subtask specification）**：
  - **Overworking**：扩大子任务执行要求，诱导穷尽搜索、多源验证等；
  - **Intermediate output suppression**：抑制规划器要求中间输出，如下游需要的文件路径；
  - **Planner prior misguidance**：诱导规划器在证据不足时提前写入先验假设。

### 2.4 防御方法：DescGuard

DescGuard 是一种注册时防御，在第三方 worker 描述进入规划器前进行转换：

\[
\tilde d_i = G(d'_i), \quad \tilde D = \{d_1,\ldots,d_{i-1},\tilde d_i,d_{i+1},\ldots,d_n\}
\]

后续规划为：

\[
\tilde \pi = p(x, \tilde D)
\]

DescGuard 不判断恶意意图，也不验证描述与实现是否一致，只保留原描述中映射到四类接口字段且描述该 worker 自身的信息。

流程包括：

- **确定性预处理**：Unicode 规范化、移除不可见字符、剥离 HTML/XML 标记。
- **三阶段 LLM 变换**：
  - **Emphasis neutralization**：中和全大写、标点、Markdown 标记、强调词等表面强调；
  - **Interface-field extraction**：仅保留功能、输入、输出、使用约束相关内容，丢弃规划器指令、其他 worker 指令、MAS 操作建议；
  - **Worker-scoped restatement**：重述为只代表被注册 worker 的接口声明，删除无边界能力声明，不填补缺失字段。
- **验证机制**：每个 LLM 变换阶段配独立 validator，使用随机分隔符包裹不可信文本，失败则带原因重试，直到通过或达到重试上限；未通过内容不会进入规划器。

DescGuard 不修改 worker 实现、规划器模型或编排逻辑，可与隔离、权限控制、运行时监控等机制组合。

  - Attack Impact：操纵描述，无防御；

  - Defense Effectiveness：操纵描述，有防御。
