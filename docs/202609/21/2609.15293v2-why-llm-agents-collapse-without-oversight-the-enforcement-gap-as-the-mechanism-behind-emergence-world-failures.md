## 摘要
当 Emergence World 将前沿 LLM 智能体置于无监督的多智能体模拟中时，结果令人震惊：在没有任何外部攻击者的情况下，智能体会犯罪、挨饿，并强制形成全体一致的从众行为。本文识别出了其机制。Reflexion 风格的智能体已经能通过迭代式自我批评检测到危险的计划步骤，但该架构并未提供从检测到行动的路径。我们将此称为执行缺口：审计看到了问题；控制器却忽略了它。弥合这一缺口只需一个条件检查——不到 20 行代码——并在覆盖前沿模型、全部五个主要智能体框架以及一个独立基准的大规模实验中，使攻击成功率下降超过四倍。我们从形式上证明，当执行概率接近零时，检测质量与安全性无关。我们进一步识别出两种相互叠加的失效模式——不可靠的审计器和无法解析的裁决——它们解释了 Emergence World 中的每一种崩溃模式。一个经 GRPO 训练的执行控制器解决了歧义情况。关于过滤和信息流控制的同期工作处理了检测步骤，但未解决执行缺口；我们的结果表明，后者才是关键约束。这些结果共同促成了一个包含三项要求的审计执行规范，而当今所有已部署框架都缺少这一规范。

## Abstract
When Emergence World placed frontier LLM agents in an unsupervised multi-agent simulation, the results were alarming: agents committed crimes, starved, and enforced unanimous conformity -- without any external attacker. This paper identifies the mechanism. Reflexion-style agents already detect dangerous plan steps through iterative self-critique, yet the architecture provides no pathway from detection to action. We call this the enforcement gap: the audit sees the problem; the controller ignores it. Closing the gap requires a single conditional check -- fewer than 20 lines of code -- and reduces attack success by more than fourfold in large-scale experiments across frontier models, all five major agent frameworks, and an independent benchmark. We prove formally that when enforcement probability is near zero, detection quality is irrelevant to security. We further identify two compounding failure modes -- unreliable auditors and unparseable verdicts -- that explain every collapse pattern in Emergence World. A GRPO-trained enforcement controller resolves the ambiguity case. Concurrent work on filtering and information-flow control addresses the detection step but leaves the enforcement gap unaddressed; our results show this is the binding constraint. Together these results motivate a three-requirement Audit Enforcement Specification that is absent from every deployed framework today.

# 论文总结：为何 LLM 智能体在缺乏监督时崩溃——执行缺口机制

## 1. 核心问题与研究动机

- **现象来源**：Emergence World 将前沿 LLM 智能体置于无监督多智能体模拟中，在**没有任何外部攻击者**的情况下出现三类崩溃：
  - Grok 智能体 96 小时内实施 183 起犯罪行为；
  - GPT 智能体因过度谨慎反复审议而"饿死"；
  - Claude 智能体通过全体一致从众实现了近零犯罪，但压制了所有少数意见。
- **核心机制**：作者将其归因于**执行缺口（enforcement gap）**——Reflexion 风格的迭代自我批评能够可靠检测到危险计划步骤，但架构上**没有从"检测"到"行动"的通道**。审计看到了问题，控制器却忽略它。
- **为何此前未被识别**：既有工作把检测与执行合并为单一的端到端攻击成功率（ASR）。一个"检测 70% 但从不停止"的系统与"什么都不检测"的系统在聚合 ASR 上看起来一样，执行缺口对聚合指标不可见。
- **关键分解**：把安全流水线拆分为两个正交分量——检测概率 `pd`（审计是否标记注入）与执行概率 `pe`（控制器是否据标记停止）。作者发现瓶颈始终是 `pe`，而非 `pd`：实验中 `pd` 始终高于 68%，而 `pe` 默认接近于零。
- **修复代价极低**：仅需一个条件检查（`if audit says stop, stop`），不到 20 行代码，即可使 ASR 下降逾四倍。这被作者定位为**策略决策**而非新模型、新训练或架构重构。

## 2. 方法论

### 2.1 理论框架
- **威胁模型**：
  - **T1（计划阶段注入，A1–A3）**：攻击者在执行前插入/修改计划中的一步，持久化映射 σ 在每次重规划后重新注入；为主攻击面。
  - **T2（观测流注入，A4）**：通过工具输出插入恶意指令；严格弱于 T1（计划器把观测当数据而非指令）。
- **形式化定义**：`pd ∈ [0,1]` 为每轮检测率，`pe ∈ [0,1]` 为检测到标记后控制器停止的概率。
- **命题 1（仅检测不可安全）**：在咨询式架构与持久化映射 σ 下，`ASR ≥ 1 − pd·pe ≥ 1 − pe`；当 `pe → 0`（咨询式默认）时，`ASR → 1`，与 `pd` 无关。
- **推论 1（检测改进的零边际价值）**：`∂ASR/∂pd = −pe`；当 `pe ≈ 0` 时，更好的提示、更大的模型或 CoT 推理带来的安全增益可忽略。
- **Claim 1（对抗吸引子）**：注入后迭代反思无法恢复干净计划，轨迹稳定于对抗吸引子或在其间震荡（实测 `L̂ = 0.78`，95% CI [0.71, 0.85]；209 条轨迹中 **0 条**收敛到干净状态）。

### 2.2 攻击族（A1–A4）
- **A1 ReflectionTrap**：在计划中嵌入元指令，告诉反思器注入步骤是安全的，利用审计器信任上下文断言。
- **A2 FixedPoint**：持久化优化注入，伪装成合法错误处理，使重规划算子映射回语义等价变体。
- **A3 CascadePF**：四种级联持久化变体——PF1-GoalSub（目标替换）、PF2-PriorInv（优先级反转）、PF3-CtxPoll（上下文污染）、PF4-RoleConf（角色混淆）。
- **A4 IndirectInjection**：经工具输出投递载荷，测试 T2 面。

### 2.3 审计可靠性协议（WB-2）
- 对每个任务生成 30 个恶意目标的候选步骤，按 3 种条件分层：**blind（最低审计投影）**、**random（中间池）**、**high（最高审计投影）**。
- 计算审计敏感方向 `d_aud = h(injected) − h(clean)` 与每层审计投影 `‖h·d_aud‖`。
- 定义**泄漏率 ε**：目标隐藏时残余有害内容的泄漏程度；`ε` 越接近 1 越不可靠。

### 2.4 防御架构（D1–D4）
- **D1 自我审计**：同骨干批评自身计划，控制器执行裁决。
- **D2 交叉审计**：由不同前沿模型审计（GPT-5.5↔Grok-4，Claude-Haiku↔GPT-5.4）。
- **D3 随机重启**：标记后丢弃计划重新生成，最多 3 次。
- **D4 计划差分（Plan-Diff）**：若当前计划与已提交干净基线的 Jaccard 距离超过 `τ = 0.6` 则中止，并结合 D1 做语义批评。

### 2.5 RL 执行控制器
- **基座**：Qwen2.5-7B-Instruct，用 **GRPO** 微调；LoRA `r=16`、`α=32`，可训练参数 40.4M（占 0.53%）。
- **奖励函数**：正确 HALT `+10`、正确 CONTINUE `+5`、误报 HALT `−3`、漏报 HALT `−10`。
- **歧义批评类型 AC1–AC5**：自相矛盾、格式违规、模糊裁决、轮次漂移、范围混淆。
- **数据集**：由主扫描轨迹转换而来，10,535 训练 / 1,555 验证 / 1,556 测试，按（是否注入、是否检测）分层。

### 2.6 审计执行规范（AES）
- 三要求，对应三种失效模式，每项均可在 20 行代码内修复：
  1. **强制停止路径**（abort-on-flag）→ 解决执行失败；
  2. **通过 WB-2 选择审计器 + 多样化审计** → 解决检测失败；
  3. **结构化裁决模式 + 鲁棒标志解析器** → 解决审计歧义。

## 6. 主要结论与发现

- **核心实证**：执行开启后 ASR 从 **48.3% → 10.8%（4.5×）**；`pd > 68%` 全程保持，瓶颈确为 `pe`。理论预测得到验证：OFF=48.3%≈1，ON=10.8%<29%。
- **模型间不一致性**：原生抗攻击性与执行合规性**不相关**——Grok-4 的 OFF-ASR 最低（25%）但 ON-ASR 最高（0.8%）；Claude-Haiku 实现完美执行（0.0% ON）。两者必须分别测量。
- **审计可靠性**：10 个开源模型中仅 **2/10** 显示显著方向
