## 摘要
当代云与分布式系统通过以资源为中心的抽象来暴露控制：服务、部署、网络流、执行图。与此同时，智能体系统和工具增强系统已将应用逻辑转向意图驱动、自适应执行。现有的控制平面、工作流引擎和服务网格缺乏面向意图级决策治理的抽象：它们无法将高层目标表示为一等控制对象，无法对从意图到执行计划的映射施加策略，也无法生成可审计记录以说明为何选择某条执行路径而非其他备选路径。因此，控制逻辑被嵌入应用代码，导致系统脆弱、不透明且难以治理。  我们提出 Brain API，一种面向受策略治理的智能体系统的意图感知控制平面。其核心贡献是决策产物：一份持久、带版本、可审计的记录，说明意图如何变为可执行计划，记录应用了哪些策略、评估了哪些能力、拒绝了哪些备选方案以及原因。一个具有启发性的用例是智能体数据集：在驻留、合规与成本约束下作为受策略治理能力参与的数据集。  我们使用两个并非由我们编写的外部策略语料库，对决策层原型进行评估。在 OPA Gatekeeper 约束库上，在全部 42 个可编码案例中，它与该库自身发布的判定一致：其中 19 个允许，23 个拒绝。在 Cedar 示例策略上，通过与其参考实现进行差分测试来标注，一个刻意选取的差异较大的领域暴露了我们模型中的三处缺陷，包括一个默认允许假设，该假设本会颠倒每一条授权策略。评估涵盖策略过滤与选择；上下文信号和排序仍属设计主张，负载下的决策延迟尚未量化。

## Abstract
Contemporary cloud and distributed systems expose control through resource-centric abstractions: services, deployments, network flows, execution graphs. Agentic and tool-augmented systems have meanwhile shifted application logic toward intent-driven, adaptive execution. Existing control planes, workflow engines and service meshes lack abstractions for intent-level decision governance: they cannot represent high-level goals as first-class control objects, cannot enforce policy over the mapping from intent to execution plan, and cannot produce auditable records of why one execution path was chosen over its alternatives. Control logic is therefore embedded in application code, leaving systems brittle, opaque and hard to govern.   We propose Brain API, an intent-aware control plane for policy-governed agentic systems. Its central contribution is the decision artifact: a durable, versioned, auditable record of how an intent became an executable plan, capturing which policies applied, which capabilities were evaluated, which alternatives were rejected, and why. A motivating use case is agentic datasets: datasets participating as policy-governed capabilities under residency, compliance and cost constraints.   We evaluate a prototype of the decision layer against two external policy corpora we did not author. On the OPA Gatekeeper constraint library it agrees with the library's own published verdicts on 42 of 42 encodable cases, 19 admit and 23 deny. On Cedar example policies, labeled by differential testing against its reference implementation, a deliberately dissimilar domain exposed three defects in our model, including a default-allow assumption that would have inverted every authorization policy. The evaluation covers policy filtering and selection; context-signal and ranking remain design claims, and decision latency under load is unquantified.

  - 无法对“意图 → 执行计划”的映射施加统一策略；
  - 无法生成可审计记录，说明为何选择某条执行路径而非其他备选；
  - 控制逻辑被迫嵌入应用代码，导致系统脆弱、不透明、难以审计与演化。
- **论文主张**：提出 **Brain API**，一种面向受策略治理的智能体系统的意图感知控制平面。其核心贡献是 **决策工件**：持久、带版本、可审计地记录意图如何转化为执行计划，包括适用策略、评估能力、被拒备选及原因。
- **整体含义**：论文试图把“决策”提升为与资源、任务、部署并列的控制平面原语，使智能体系统不仅可扩展、可靠，还可治理、可检查、可审计。

## 2. 方法论

### 2.1 核心思想

- **意图优先**：用户提交的是高层意图，而非固定步骤或具体 API 调用。
- **策略一等公民**：安全、合规、成本、数据驻留等策略显式声明，并在决策阶段统一执行，而非散落在应用代码中。
- **决策与执行分离**：控制平面负责“做什么、在哪做、为什么”，执行后端只负责“如何执行”。
- **决策工件**：记录完整推理链，包括意图引用、策略版本、上下文快照、候选集、选中计划、被拒替代项及拒绝理由、排序依据。
- **异构能力集成**：能力可以是微服务、批处理任务、工具、外部 API 或其他智能体，通过统一元数据注册与选择。
- **决策级可观测性**：不仅记录事件与资源指标，还记录决策过程本身。

### 2.2 系统模型

核心实体包括：

- **Intent**：高层目标或期望结果。
- **Policy**：声明式约束，覆盖安全、合规、成本、数据驻留等。
- **Capability**：可执行单元，带语义、成本、信任级别、数据访问约束等元数据。
- **Context**：动态信息，如运行时状态、环境条件、用户属性、历史轨迹。
- **Decision**：策略与上下文作用于意图和候选能力后的解析结果。
- **Execution Plan**：可执行的具体步骤结构。

决策函数可表示为：

> **Decision = F(Intent, Policies, Context, Capabilities)**

其中 F 同时产生决策工件与执行计划。

### 2.3 决策与路由语义

五阶段流程：

1. **候选生成**：根据意图语义与参数生成候选能力组合，输出候选集 C。
2. **策略过滤**：强制策略过滤候选，得到 C′，并附带义务或条件。
3. **上下文与记忆约束**：上下文可进一步过滤或影响排序；记忆信号提供偏好特征，但默认不覆盖强制策略。
4. **排序与选择**：在 C′ 上按成本、延迟、可靠性、合规风险、语义适配度等评分，选择最高分或 Pareto 最优候选。
5. **计划合成**：绑定具体端点、解析义务、排序步骤，生成可执行计划。

形式属性要求：

- **策略可靠性**：绝不选择违反强制策略的计划。
- **最佳努力完备性**：若 C′ 非空则返回计划；若为空则发出“不可满足意图”信号，而非静默选择不合规方案。
- **单调过滤**：增加策略只能缩小可接受集合。
- **评分独立于硬约束**：评分不能提升违规候选。
- **可复现性**：固定输入与评分配置时，决策确定；变化则产生新版本决策工件。

### 2.4 架构与接口

- **控制平面**：意图入口、策略引擎、能力注册表、决策引擎、可观测性平面。
- **数据平面**：执行适配器与异构后端，如 Kubernetes、Argo Workflows、Temporal、API 网关。
- **核心接口**：Intent、Policy、Capability、Decision、Execution 接口，以及审计与内省接口。
- **执行模型**：支持同步/异步步骤、状态与检查点、失败语义、策略驱动适配、并发协调、结果传播。
- **可观测与治理**：决策级遥测、跨控制/数据平面追踪、审计合规、控制层指标、策略执行与升级、可解释性接口。

## 6. 主要结论与发现

- **决策工件是核心新原语**：它记录“为什么这样选”，而事件日志只记录“发生了什么”。
- **意图级策略执行与准入控制不同**：区别不在于“执行前”，而在于准入控制裁决单个提案，Brain API 在替代方案中选择。
- **现有组件难以组合出 Brain API**：OPA、服务网格、工作流引擎、LLM 工具路由各自缺少决策工件、意图级策略和统一能力语义。
- **规则语言表达力是瓶颈**：真实治理策略大量量化于集合；标量比较仅覆盖 3/49，加入有界量化后 28/49，聚合与正则仍缺失。
- **外部语料暴露设计缺陷**：
  - Gatekeeper 暴露“逐元素合取条件”缺失；
  - Cedar 暴露默认允许假设、合取守卫缺失、跨实体比较不可表达三处问题；
  - 默认允许假设若用于授权会颠倒所有策略意图。
- **跨域迁移结论混合**：
  - 决策层结构可迁移；
  - 规则语言迁移差，授权策略大量依赖实体间关系，字段-常量比较覆盖不足四分之一。
- **审计与选择能力得到初步验证**：决策工件在可回答审计问题和替代方案选择上明显优于准入日志。

## 7. 优点

- **问题定位清晰**：准确指出资源中心控制平面在智能体治理中的结构性缺口。
- **决策工件概念有价值**：把“决策理由”作为持久、版本化、可审计的一等对象，具备合规、调试、重放与政策演化价值。
- **架构分层合理**：控制平面与数据平面分离，执行后端可插拔，便于与 Kubernetes、Argo、Temporal 等共存。
- **实验使用外部语料**：策略对象与裁决不由作者编写，降低自证偏差。
- **主动报告负面结果**：如实报告原始语法仅覆盖 3/49、Cedar 仅 8/35 可编码、聚合与正则不可达。
- **跨域差分测试**：用 Cedar CLI 作为第三方标签来源，并发现默认允许等重大缺陷。
- **审计实验设计巧妙**：Q6“仅凭工件重导决策”不依赖主观判断，10/10 成功增强说服力。
- **选择实验控制较好**：双顺序、中性位置命名，避免标签泄漏。
- **局限陈述充分**：明确区分已测阶段与设计主张，承认延迟、排序、上下文未验证。
