## 摘要
我们提出 RegLLM，一个用于受监管智能体工作流中有界自主性的诊断测试框架。它监测六个可信度信号：引用有效性、来源依据、模式合规性、升级正确性、宪法对齐以及不安全行动率。这些信号按监督来源区分：程序化验证器、任务级升级标签或AI评判分数。一个确定性运行时监督器会阻止无依据答案并强制升级，同时记录干预。同一领域宪法为评估、训练奖励和服务护栏提供依据。任务级应升级标签使行动与推迟决策成为可测量的训练信号。我们在冒烟规模上演示该测试框架。离线参考运行（n=12）在启用治理时，将升级召回率从0提升至0.67，并将不安全行动率从0.33降至0.08。两个单GPU Qwen2.5-3B LoRA/DPO试点（n=8，相同随机种子和评估划分）暴露出显著差异：名义上相同的RL-base配置产生任务成功率0.25对0.12，升级召回率1.0对0.5。答案质量适配器在Run A中将召回率从1.0变为0.5，但在Run B中从0.5变为1.0。一个升级感知变体在Run B中未产生可测量变化。这些小规模试点并不能确立可靠的适配器效应或生产就绪性。它们的贡献是诊断性的：配置方差可能压过有界自主性指标上表面上的调优效应，从而促使采用更大的评估集和重复运行。

## Abstract
We propose RegLLM, a diagnostic harness for bounded autonomy in regulated agentic workflows. It instruments six trustworthiness signals: citation validity, source grounding, schema compliance, escalation correctness, constitutional alignment, and unsafe-action rate. Signals are distinguished by their source of supervision: programmatic verifiers, task-level escalation labels, or AI-judge scores. A deterministic runtime supervisor blocks ungrounded answers and forces escalation, logging interventions. The same domain constitution informs evaluation, training rewards, and serving guardrails. Task-level should-escalate labels make the act-versus-defer decision a measurable training signal. We demonstrate the harness at smoke scale. An offline reference run (n=12) lifts escalation recall from 0 to 0.67 and reduces unsafe-action rate from 0.33 to 0.08 when governance is enabled. Two single-GPU Qwen2.5-3B LoRA/DPO pilots (n=8, same seed and evaluation split) expose substantial variation: nominally identical RL-base configurations yield task success of 0.25 versus 0.12 and escalation recall of 1.0 versus 0.5. An answer-quality adapter changes recall from 1.0 to 0.5 in Run A, but from 0.5 to 1.0 in Run B. An escalation-aware variant produces no measurable change in Run B. These small pilots do not establish reliable adapter effects or production readiness. Their contribution is diagnostic: configuration variance can overwhelm apparent tuning effects on bounded-autonomy metrics, motivating larger evaluation sets and repeated runs.

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体正被部署到金融合规、医疗建议、法律分诊等受监管高风险领域。在这些场景中，错误答案的代价不是"回复被纠正"，而是**监管罚款、客户受损或义务遗漏**。
- **技术缺口**：
  - 以可验证奖励为核心的强化学习（RLVR，如 DeepSeek-R1 系列）依赖数学/代码这类机器可判定的答案，但监管建议本质上是**判断题**，专家之间也存在分歧。
  - 现有智能体安全护栏（如 GuardAgent、AGrail）能监控与阻断有害动作，但**无法提供"何时回答、何时应升级给人类"的原则性依据**。当前系统普遍依赖手工设定的阈值。
- **核心观察与方法论转向**：论文提出，在给定任务级 `should_escalate` 标签的前提下，**"行动 vs. 推迟（act-versus-defer）"这一决策本身就是一个可验证的训练信号**。由此，有界自主性行为从"脆弱的手调阈值"变为**可度量、可训练、可审计**的对象。
- **整体含义**：同一部领域"宪法"（constitution）同时驱动软奖励项与运行时护栏，使**评估、训练、服务共享同一份治理工件**，从而把合规智能体的行为纳入可追溯的审计链路。

## 2. 方法论

### 2.1 核心思想

- 提出 **RegLLM** 诊断测试框架（diagnostic harness），把可信度信号**按监督来源**分为三类，分别对应不同的失效模式与审计要求，避免在智能体评估中混为一谈。
- 用一套**可插拔领域宪法**同时充当：(a) 混合奖励中的软约束项；(b) 运行时"有界自主性"策略，定义确定性护栏。

### 2.2 三类可信度信号

| 类别 | 具体信号 | 监督来源 |
|---|---|---|
| 程序化可验证 | 引用有效性、模式合规性、来源接地（grounding） | 确定性谓词 / 词汇重叠代理 |
| 任务级标签 | 升级正确性（`escalated == should_escalate`） | 人工/模板生成的 `should_escalate` 标签 |
| AI 评判 | 宪法对齐分（constitutional alignment） | LLM-as-a-Judge |

### 2.3 领域宪法

- 示例编码 **16 条英国 FCA 原则**，覆盖四大领域：
  - 金融伦理（公平对待、利益冲突、适当性、透明、客户优先）
  - 监管合规（准确性、完整性、时效性、适当来源）
  - 职业责任（能力边界、不确定性承认、专家转介、客户优先）
  - 伦理 AI（避免伤害、偏见缓解、可解释性）
- 接口**领域无关**：数据保护、临床指导等新领域只需提供自己的原则集，无需改动奖励或治理机制。

### 2.4 合规智能体与工具

- 采用 **ReAct 循环**，配备四个工具：
  - `RETRIEVE`（查询监管语料）、`CITE`（附加条款 ID）、`ANSWER`（输出有依据的最终答案）、`ESCALATE`（转交合格人类）。
- 每条轨迹记录全部步骤、引用条款与终止决策，作为奖励计算与审计日志的基础。

### 2.5 混合奖励公式

$$R(\tau) = w_v R_v(\tau) + w_c R_c(\tau) - \lambda \mathbb{1}[\text{guardrail violation}]$$

- **可验证项 $R_v$** 为四个子信号的平均：
  1. 引用有效性：引用条款在语料中真实存在的比例
  2. 接地性：答案与引用来源的词汇内容重叠代理（可替换为 NLI 模型）
  3. 模式合规：答案符合结构化格式
  4. 升级正确性：$\mathbb{1}[\text{escalated} = \text{should\_escalate}]$（**这是使有界自主性可训练的关键**）
- **宪法项 $R_c$**：抽样原则并用 AI 评判打分（Yes/Partial/No → {1.0, 0.6, 0.3}），补充验证器无法捕捉的软信号。

### 2.6 训练与运行时治理

- **训练**：按 $R$ 排序 rollout 构造偏好对，使用 **DPO + LoRA** 在小规模开源策略模型上微调；扩展配置使用 **GRPO** 以 $R$ 作为组相对奖励。
- **运行时护栏（确定性、模型外）**：
  1. 阻断无引用条款的 `ANSWER`，强制升级（对应原则 P9 "Proper Sourcing"）
  2. 当能力边界/不确定性原则（P10–P12）被触发时强制升级
  3. 将每一步与每次干预追加写入**只增审计日志**，按触发原则 ID 键控

## 6. 主要结论与发现

- **离线参考运行**（弱词汇基线上）：
  - 确定性运行时监督器将**升级召回率从 0 提升至 0.67**；
  - **不安全动作率从 0.33 降至 0.08**；
  - 引用有效性提升至 1.00，任务成功率 0.08 → 0.25，宪法对齐 0.62 → 0.70。
- **GPU 试点的核心发现是"方差本身"**：
  - 名义相同配置的 RL-base 在 Run A 与 Run B 间差异显著：**任务成功率 0.25 vs. 0.12**；**升级召回率 1.00 vs. 0.50**；引用有效性 0.50 → 0.38。
  - AQ 适配器的表观效应**方向翻转**：Run A 中 1.00 → 0.50，Run B 中 0.50 → 1.00。
  - 专门为 Run A 假设的失效模式设计的 **EA 适配器在 Run B 中无任何可测量变化**。
  - 因此，最初假设的失效模式（"答案质量 DPO 会削弱升级能力"）**无法安全归因于训练信号**。
- **运行时治理在两次 GPU 试点中完全失效（0 次干预）**：
  - 原因是 LLM 在每个被回答的回合都引用了条款（绕过无引用门），而本应升级的轨迹往往**不会到达可被门检查的终止答案**。
  - 结论：仅靠无引用门不足以支撑有界自主性，**能力边界检测必须作为一等运行时组件**，需要校准过的推理时评判器或更丰富的基座行为。
- **总体论断**：在当前智能体 AI 试点常见的样本量与训练预算下，**适配器对有界自主性指标的影响无法与采样和硬件方差区分**；负责任地评估受监管智能体需要多种子、更大评估集，这是现有偏好调优流程未曾预算的。

## 7. 优点

- **方法论创新清晰**：把 act-versus-defer 决策识别为可验证训练信号，是将 RLVR 范式迁移到知识密集型监管领域的一个有原则的切口。
- **"一部宪法、两种角色"的架构优雅**：同一工件同时驱动软奖励与运行时护栏，避免评估、训练、服务三者脱节，并天然支持审计。
- **三类信号的显式分离**：按"什么使其可信"区分程序化验证、任务标签、AI 评判，并让审计日志记录触发类别，这是对当前智能体评估混乱现状的有益纠偏。
- **诚实的负面结果**：作者主动报告 EA 适配器无效、治理层在 GPU 试点中零干预、自身假设被两次运行互相否定，具有很高的科研诚信价值。
- **诊断套件设计**：明确标注哪些行已被本次运行覆盖、哪些是后续工作，避免"看似完整"的误导。
- **工程可复现意识**：奖励项与确定性护栏门有单元测试，密钥
