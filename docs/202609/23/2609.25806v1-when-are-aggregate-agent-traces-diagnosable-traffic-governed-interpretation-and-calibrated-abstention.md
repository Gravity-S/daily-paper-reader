## 摘要
运行时轨迹看似透明，但闭环策略决定了哪些状态会被访问、哪些失败会变得可见。我们研究一个模拟的酒店定价智能体，它在不同需求机制下将时间、库存和市场状态映射为离散价格动作。当策略很少访问受影响的单元时，故障可能不会在聚合轨迹中留下痕迹。我们将进入仅基于聚合的故障解释这一步视为先于评分或定位的可诊断性决策。参考图门控要求重复的清洁策略支持；随后匹配的运行时门控要求清洁流与当前流中的联合支持。只有在两者都通过后才进行信号分析。我们在物理组件层面，在一个不相交的清洁流上校准误准入，并以受影响的清洁流量而非名义单元覆盖率来建模检测。在一个冻结的一次性留出集中，55/72（76.4%）的机制-组件单元被参考准入，代表20个物理组件；54/55通过了匹配的运行时准入，而被拒绝的单元则弃权。稳定误准入为0/20，单侧精确95%上界为0.1391，满足冻结的0.20标准。在嵌套于这20个簇中的540个重复单元-臂行上，受影响的清洁流量相对于单元覆盖率将负对数似然降低了29.3%，即每行提升0.1264纳特（簇自助法95%区间[0.0593, 0.1918]）。加入掩码族及其交互项使对数损失改善0.0015纳特/行（单侧上界0.0066），低于冻结的0.01实际充分性裕度。一项开发审计发现，在12/12个场景中，精确最小命中集与贪心选择选出了相同的支持集，因为单例证据已经解决了冲突。结果是一条用于解释聚合智能体行为的有界规则：先确立暴露，再对变化评分，并在轨迹无法支持该主张时弃权。

## Abstract
Runtime traces can appear transparent, but a closed-loop policy determines which states are visited and which failures become visible. We study a simulated hotel-pricing agent mapping time, inventory, and market state to discrete price actions under varying demand regimes. A fault may leave no aggregate trace when the policy rarely visits affected cells. We treat entry into aggregate-only fault interpretation as a diagnosability decision preceding scoring or localization. A reference-map gate requires repeated clean-policy support; a matched runtime gate then requires joint support in clean and current streams. Signal analysis occurs only after both pass. We calibrate false admission on a disjoint clean stream at the physical-component level and model detection by affected clean traffic rather than nominal cell coverage. In a frozen one-shot heldout, 55/72 (76.4%) regime-component units were reference-admitted, representing 20 physical components; 54/55 passed matched runtime admission, while the rejected unit abstained. Stable false admission was 0/20, with a one-sided exact 95% upper bound of 0.1391, meeting the frozen 0.20 criterion. Across 540 repeated unit-arm rows nested in those 20 clusters, affected clean traffic reduced negative log likelihood by 29.3% relative to cell coverage, a gain of 0.1264 nats per row (cluster-bootstrap 95% interval [0.0593, 0.1918]). Adding mask family and its interaction improved log loss by 0.0015 nats per row (one-sided upper bound 0.0066), below the frozen 0.01 practical-sufficiency margin. A development audit found that exact minimum hitting set and greedy selection chose identical supports in 12/12 scenarios because singleton evidence had resolved the conflicts. The result is a bounded rule for interpreting aggregate agent behavior: first establish exposure, then score change, and abstain when the trace cannot support the claim.

- **核心问题**：当策略很少访问故障所影响的区域时，组件可以失效却不产生任何可见的聚合变化；反之，需求漂移也能在无任何组件故障的情况下改变访问与动作汇总。因此**没有任何诊断算法能恢复测量中不存在的信息**。
- **关键论点**：忽略"暴露度"的轨迹解释会把"证据缺失"误读为"安心"，或把"普通漂移"误读为"故障"。论文主张把"进入仅基于聚合的故障解释"这一步，重新定义为**先于评分与定位的可诊断性决策**（diagnosability decision）。
- **情境**：一个模拟的酒店定价智能体，其策略将时间、库存、市场状态映射为离散价格动作，并在不同需求机制（regime）下运行。

## 2. 方法论

### 2.1 核心思想
- 将"可诊断性"实现为一个**状态机**，而非隐含假设：
  `REFERENCE_ABSTAIN → RUNTIME_ABSTAIN → SIGNAL_ELIGIBLE → {DETECTED, NOT_DETECTED}`
  箭头代表"测试"而非时间保证：未过第一道门的单元永不进入第二道；未过第二道门的单元永不进入信号解释。由此区分"无可用的比较"与"有可用比较但无稳定信号"。
- 局部化（localization）被置于整条流水线的**最末端**。

### 2.2 关键技术细节

**（a）单元定义**
- 24 个互斥的目标策略组件，按"时间四分位 × 库存二分 × 市场三分"索引；三种独立拟合的需求机制 λ0 ∈ {5, 7, 9}；机制-组件对称为"单元（unit）"，共 72 个单元。
- 聚合轨迹使用两个既有摘要：`region_d1`（区域分布距离）与 `mean_action_gap`（参考-当前平均动作差）。

**（b）故障掩码**
- 形式化故障将确定性子集的"方向可变目标字段单元"整体平移一个动作桶，测试外向（outward）与内向（inward）两个方向。
- 两个嵌套掩码族：`uniform`（可变更单元的有种子随机排序）与 `flow_weighted`（有种子加权无放回排序，高频访问的干净单元更早入选）。两者可有相同的选中单元比例，但受影响的流量差异极大。
- 嵌套前缀目标流量约为 0.15、0.30、0.50、0.75、0.95。

**（c）受影响干净流量（核心暴露变量）**
- 对组件单元 c，设 o_c 为其干净参考访问计数，方向性故障选中集合 S_d，则
  `τ_d = (Σ_{c∈S_d} o_c) / (Σ_{c∈component} o_c)`，主暴露 `τ = (τ_outward + τ_inward)/2`。
- 对照的"单元计数"协变量为 `f_cell = (f_outward + f_inward)/2`（选中方向可变单元的比例）。
- 若组件占用为零，则 τ 为零；零暴露案例单独报告，**不做任意常数平移**再取对数。

**（d）参考图门控（Reference-map gate）**
- 分区支撑：某组件的既有支撑计数 ≥ 12。
- 单元级准入：15 个干净参考分区中至少 14 个有支撑。全部 72 个单元均被筛选，不按身份或开发资格排除。

**（e）运行时双流门控（Runtime two-stream gate）**
- 仅当**同一分区内**参考支撑与当前支撑均 ≥ 12 时该分区才算受支撑；要求 15 个分区中至少 14 个满足联合支撑。
- 双向故障观测要求两个方向都通过。文中强调：分别 14 个支撑良好的参考分区与 14 个支撑良好的当前分区，**不保证**存在 14 个可用比较（若二者落在不同分区）。

**（f）稳定聚合信号**
- 每个匹配的参考-当前分区对定义
  `z = max(region_d1 / 0.20, |mean_action_gap| / 0.35)`，当 `z ≥ 1.50` 时该分区"发出信号"。
- 单元级运行时门控通过后，方向稳定性在全部 15 个匹配对上计数（而非在支撑-信号交集上）：某方向在 14/15 个信号分区上稳定；双臂（bi-directional）稳定要求两个方向都稳定。
- 阈值 1.50 在正式执行前从固定网格 {1.00, 1.25, 1.50, 1.75, 2.00} 中选定，不在正式零假设上调参。

**（g）三类彼此分离的失败量**
1. 参考图失效（reference-map invalidation）；
2. 运行时双流拒绝（runtime two-stream rejection）；
3. 稳定误准入（stable false admission）。
合并它们会掩盖问题究竟出在"参考图已变"、"并发证据不足"还是"信号噪声"。

**（h）漂移与刷新**
- 冻结的分裂式保形检测器（split-conformal detector）汇总每个干净-零分区，超阈值即报警；报警只请求**原子式地图重算**，不宣告故障或弃权。通过单元回到 `MAP_VALID`，未过刷新参考规则的单元进入 `REFERENCE_ABSTAIN`。

**（i）统计推断**
- 参考失效与运行时拒绝用组件级双侧精确 Clopper-Pearson 95% 区间作**描述性覆盖端点**，无通过阈值。
- 仅"稳定误准入"使用组件级单侧精确 95% 上界，且仅当 ≤ 0.20 时标注 `SAFETY CONFIRMED`。
- 功效率用 Wilson 95% 区间。
- 主模型在通过双门控的正暴露单元上拟合"稳定信号 ~ log(τ)"；匹配单元模型用 log(cell_fraction)。
- **流量优于计数**的判据：组件自助法对"每单元-臂行负对数似然改进 NLL(cell) − NLL(traffic)"的双侧 95% 下界 > 0。
- **族实际充分性**判据：加入掩码族及其与 log(τ) 的交互后，增广模型对数损失改进的组件自助法单侧 95% 上界 < 0.01 nats/行。
- 自助法抽样**物理组件**而非单元-臂行；固定生成 2000 次抽样，保留奇异与单类重复，不重抽；空或非有限分析返回 `NOT ESTIMABLE` 而非有利判定。

**（j）MHS 为何处于下游（负结果）**
- 精确 MHS 的最优性以保证冲突族为条件，不建立物理故障识别。
- 12 个审计场景中，非单例冲突占冲突集合 55.5%，冲突在 12/12 场景中重叠，但精确 MHS 与传播感知贪心仍选出相同支持集、精确恢复率同为 9/12。
- 后续审计发现 9/9 精确锚点与 9/9 硬探针案例中存在植入组件的单例冲突，传播后 0/9 存在非空残余冲突族——机制在上游：硬探针恰好改动一个组件并配以同组件作用域的谓词，把局部响应转成植入组件单例，传播因此在两种求解器能产生分歧之前就固定了答案。
