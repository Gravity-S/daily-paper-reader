## 摘要
由基础模型驱动的移动智能体如今能在真实设备上自动化执行复杂的多步工作流，但其轨迹可能违反特定应用的安全策略。现有的轨迹级防御依赖LLM提示或刚性规则，因而无法支持细粒度、自然语言策略，也难以跨应用和任务泛化。在这项工作中，我们提出MATE，一种轻量级、以策略为条件的审计器，它同时编码智能体轨迹和自然语言安全策略，以判断某条轨迹是否违反给定策略并解释原因。将策略视为可编辑文本而非固定模型参数，使MATE无需重新训练即可处理用户定义且不断变化的需求。为构建MATE，我们通过从全球数百款热门移动应用中提取应用描述、工作流和策略，并利用多阶段流水线合成超过14万条语义真实、以策略为条件的轨迹，构建了一个知识库。我们还发布了MATEBench，一个轨迹级审计基准，包含两个合成子集和一个由人工收集轨迹组成的真实世界子集。使用我们的合成驱动轨迹学习训练的模型在MATEBench上达到超过95%的准确率，在外部安全基准上保持强劲性能，并在真实设备上以超过95%的准确率审计来自智谱AutoGLM和阿里巴巴Mobile-Agent的轨迹，比先前方法高出超过20%。MATE表明，针对异构移动智能体的实用、细粒度安全审计既可行又有效。

## Abstract
Mobile agents powered by foundation models now automate complex, multi-step workflows on real devices, but their trajectories can violate app-specific security policies. Existing trajectory-level defenses rely on LLM prompting or rigid rules, and thus fail to support fine-grained, natural-language policies that generalize across apps and tasks. In this work, we introduce MATE, a lightweight, policy-conditioned auditor that encodes both agent trajectories and natural-language security policies to determine whether a trajectory violates a given policy and to explain why. Treating policies as editable text rather than fixed model parameters allows MATE to handle user-defined and evolving requirements without retraining. To construct MATE, we build a knowledge base by extracting app descriptions, workflows, and policies from hundreds of popular mobile apps worldwide, and synthesizing over 140K semantically realistic, policy-conditioned trajectories with a multi-stage pipeline. We further release MATEBench, a trajectory-level auditing benchmark with two synthetic subsets and one real-world subset of manually collected trajectories. Models trained with our synthesis-driven trajectory learning achieve over 95% accuracy on MATEBench, retain strong performance on external safety benchmarks, and audit trajectories from Zhipu's AutoGLM and Alibaba's Mobile-Agent on real devices with over 95% accuracy, outperforming prior methods by over 20%. MATE shows that practical, fine-grained security auditing for heterogeneous mobile agents is both feasible and effective.

## 1. 核心问题与整体含义

- **研究动机**：基础模型驱动的移动智能体（GUI agent）已能在真实手机上自动化执行多步任务（购物、邮件、社交发帖等），如智谱 AutoGLM、阿里 Mobile-Agent。但智能体轨迹可能违反应用特定的安全策略，造成不可逆的高影响操作（删除文件、转发敏感消息、未授权转账）。
- **现有防御的不足**：
  - **静态规则引擎**（如 MobileSafetyBench、AgentHarm 式规则匹配）：将策略简化为关键词/模式，无法处理应用特定 UI 语义、跨应用工作流与长程依赖，且难以随应用演化维护。
  - **LLM-as-a-Judge 提示式判断**：语义表达力较强，但成本高、延迟大、需将敏感轨迹发送给第三方（隐私不友好），且判断在不同提示/模型下不稳定。
- **关键洞察**：同一条轨迹在不同策略下可能合规也可能违规（如图 1 示例），因此安全审计必须**以部署特定的自然语言策略为条件**，而非无上下文的分类问题。
- **整体含义**：论文提出 MATE——首个面向移动智能体的**策略感知、轨迹级**安全评估模型。它将安全策略视为可编辑文本而非固定模型参数，实现细粒度、可泛化、无需重训的审计，并输出违规判定与自然语言解释。

## 2. 方法论

### 2.1 核心思想与形式化定义

- 将移动智能体交互建模为 MDP：轨迹 $\tau_I=\{(T_0,A_0,O_0),\dots,(T_n,A_n,O_n)\}$，其中 $T_i$ 为思考、$A_i$ 为 GUI 动作、$O_i$ 为自然语言观测摘要。
- 给定指令 $I$、轨迹 $\tau$、自然语言策略 $r$，审计器输出三元组：
  - $\text{MATE}(I,\tau,r)=(v,c,e)$
  - $v\in\{\text{yes},\text{no}\}$：是否违规；$c$：14 类风险类别（无违规为 none）；$e$：自然语言解释（指出冲突子序列或说明合规原因）。

### 2.2 四阶段流程

- **Stage 1 应用信息收集**：从 158 款热门应用（77 中文、81 英文）采集功能描述 $F(app)$、标准工作流 $W(app)$、安全策略 $S(app)$，构成知识库 $D_{app-info}$；用 LLM 将异构材料统一为结构化语义 profile。
- **Stage 2 知识驱动数据合成**（四阶段）：
  - **指令合成**：单应用指令满足四约束（任务范围、动作空间、功能覆盖、意图/风险多样性，覆盖全部 14 类风险）；跨应用指令（2–3 个应用）用"候选生成 + 约束对齐"两步法生成。
  - **轨迹合成**：LLM 生成 ReAct 风格多轮轨迹，遵循 10 种 GUI 原子动作（click、swipe、type、open 等），强调语义真实性（工作流忠实、受控扰动、策略条件风险行为），不要求点击坐标可执行。
  - **标注合成**：对每个 $(I,\tau,r)$ 生成违规标签、风险类别与解释，且标注始终以策略为条件。
  - **质量检查与修复**：三阶段——结构规范化、语义修复与策略对齐、人工验证。
- **Stage 3 数据增强与模型训练**：
  - 基础语料 $D_{single}\cup D_{multi}$，违规/非违规各半。
  - 三种增强：**轨迹–策略不匹配**（嵌入相似度 $sim(r^*,r')<\delta$，标签固定为 no）、**单轨迹多策略监督**（$k\in\{2,3,4,5\}$，含/不含原策略两种变体）、**跨应用任务**。
  - 形成 8 种训练配置（R1–R8，单/多应用 × 单策略匹配/不匹配/多策略含原策略/多策略不含原策略），训练集超 140K 轨迹。
  - 对 Qwen2.5-0.5B/1.5B/3B-Instruct 做**全参数 SFT**（lr=1e-5，8 epochs），得 MATE-0.5B/1.5B/3B。
- **Stage 4 模型部署**：
  - **轨迹适配器 $\phi_{traj}$**：将截图经 VLM 转为自然语言观测；将 HTML/XML/A11Y 树过滤关键节点后由 LLM 摘要，统一压缩为 ReAct 格式。
  - **策略检索器 $\phi_{policy}$**：基于 bge-m3 双编码器 + 对比学习，从近 1,000 条标准策略池中检索 top-k 策略（支持无显式策略输入）。
  - 部署公式：$\tau=\phi_{traj}(X)$，$r=\phi_{policy}(\tau,R)$，$(\hat v,\hat c,\hat e)=\text{MATE}_\theta(I,\tau,r)$。

### 2.3 风险分类法

- 按受害范围划分两级：**Personal Harm**（账户失陷、财务损失、隐私泄露、设备安全受损、声誉/心理伤害）、**Interpersonal Harm**（成为诈骗中转、泄露他人隐私、账户冒充损害信任、共享账户连带责任）、**Societal Harm**（助长虚假信息、破坏平台信任机制、助长黑灰产、引发群体冲突/公共资源浪费、削弱数字身份可信度），共 **14 个子类**。
