## 摘要
智能体技能通过可复用的指令、脚本和配置扩展 AI 智能体，但也容易受到新型攻击的影响，这些攻击可影响智能体的决策与行动。为应对这些风险，我们提出 SkillSecurer，一个完全智能体化的框架，用于生成、检测、定位和修复智能体技能中的安全风险。其红方智能体生成跨九种威胁类型的上下文兼容注入，同时记录确切的修改；其蓝方智能体分析完整的技能包，生成有依据的证据，并提出补丁。对于受控实例，验证器将发现结果和补丁与记录的注入进行比较，从而实现注入级评估。我们通过选择最佳后端 LLM、将其与竞争方案进行比较，并对每个评估阶段进行人工交叉验证，全面评估 SkillSecurer。在使用性能最佳的后端时，SkillSecurer 是唯一实现 100% 注入检测率的扫描器。接下来，我们分析来自 skills.sh 的流行技能，发现超过 17% 的受检技能中存在潜在漏洞。通过测试其中一些技能，我们触发了实际事件，表明运行未经验证的技能存在风险。我们的结果表明，上下文感知的 LLM 分析可以提供可靠的注入定位和可操作的修复方案，而不仅仅是技能级别的标记。

## Abstract
Agent skills extend AI agents with reusable instructions, scripts, and configuration, but are also open to new attacks to influence an agent's decisions and actions. To address these risks, we present SkillSecurer, a fully agentic framework for generating, detecting, localising, and remediating security risks in agent skills. Its red agent generates context-compatible injections across nine threat types while recording the exact modification; its blue agent analyses complete skill packages, produces grounded evidence, and proposes patches. For controlled instances, a verifier compares findings and patches with the recorded injection, enabling injection-level evaluation.   We thoroughly evaluate SkillSecurer by selecting the best backend LLM, comparing it with competitors, and manually cross-validating each evaluation stage. With its best performing backend, SkillSecurer is the only scanner to achieve a 100% injection detection rate. Next, we analyse popular skills from skills.sh, finding latent vulnerabilities in more than 17% of the skills examined. Testing some of those skills, we trigger actual incidents, showing the risks of running unverified skills. Our results show that context-aware LLM analysis can provide reliable injection localisation and actionable remediation beyond skill-level flagging alone.

- **分发模式带来的供应链风险**：技能通过 skills.sh、ClawHub.ai、OpenAI Codex skills catalog 等公共仓库分发，头部技能下载量达数百万次，使技能成为易获取的软件供应链组件。
- **攻击面扩张**：恶意或有缺陷的技能可通过指令操纵智能体、执行不安全代码、越权访问文件/凭证、调用外部服务、外泄或破坏数据。
- **现有工作的不足**：
  - 基准多为人工构造或固定模板生成，且**多数不记录确切的注入指令、文件或代码片段**，难以验证检测器是否正确定位漏洞。
  - 现有扫描器以静态检查、专用检测器或漏洞专用 LLM 提示为核心，输出通常为二值/粗粒度风险分类，**一般不提供修复方案**。
- **论文目标**：提出 **SkillSecurer**——据作者所述首个完全智能体化（fully-agentic）的端到端框架，覆盖智能体技能安全漏洞的**生成、检测、定位与修复**，并支持**注入级（injection-level）**评估。

## 2. 方法论：核心思想与关键技术细节

### 2.1 整体架构（三组件）

| 组件 | 角色 | 功能 |
|---|---|---|
| **REDINJECTOR** | 红方智能体 | 生成上下文兼容的注入并记录精确修改（仅用于受控评估） |
| **BLUEPATCHER** | 蓝方智能体（部署组件） | 分析技能包、产出有依据的发现、提出补丁 |
| **VERIFIER** | 验证器 | 将发现与补丁同记录的注入比对，实现注入级评估（仅用于有 ground truth 的受控实例） |

- 工作流用 **LangGraph** 实现，支持三种配置：完整受控流水线、单独运行 BLUEPATCHER、分析外部受控实例（如 Skill-Inject）。
- 提供轻量 Web 界面浏览技能、发现、证据片段、补丁与 ground-truth 评估结果。

### 2.2 检测与修补（BLUEPATCHER）

- 输入为技能的**静态快照 SUT**；关键设计是 BLUEPATCHER **不接触**良性对照版本、注入规格或任何 ground truth，保证检测与评估相互独立。
- **第一遍检测**：产出结构化报告 D，每条发现包含安全类别、严重度、解释、**引用证据片段（quoted evidence span）**及其在技能中的位置。
  - 形式化：`B_detect(SUT) = D`
  - 每条证据片段需与提交的 SUT 快照校验映射，只有能落到技能实际内容的证据才被保留（保证定位"有据可依"）。
- **第二遍修补**：若 D 非空，则对每条发现生成修复，产出补丁技能 P。
  - 形式化：`B_patch(SUT, D) = P`
  - 修补要求"最小改动"，移除/中和被报告行为同时保留合法内容（完整功能保持需运行时测试）。
- 整体：`B(SUT) = (D, P)`；若 `D = ∅`，则 `P = SUT`。

### 2.3 受控注入生成（REDINJECTOR）

- 给定良性技能 S 与目标威胁类型 τ ∈ T（共 **9 类威胁**），生成修改后技能 S′ 与注入规格 Δ：
  - `R(S, τ) = (S′, Δ)`
- 指令要求生成与 S 的上下文和既定功能**兼容**的修改，保留无关内容，并记录修改于 Δ。
- 9 类威胁包括：任意脚本执行、凭证泄露、数据外泄、Guardfall（shell 过滤绕过）、间接注入、权限提升、提示劫持、资源耗尽、供应链攻击。

### 2.4 Ground-Truth 评估（VERIFIER）

- 输入：原技能 S、注入版 S′、注入规格 Δ、发现 D、补丁 P；输出：`V(S, S′, Δ, D, P) = (L, R)`，L 为定位结果、R 为补丁移除结果。
- 若 D 为空 → 记为漏检，不算相似度。
- **词法相似度路由**：设 δ 为 Δ 中记录的注入文本，q_i 为发现 f_i 的引用证据，计算
  - `r = max_{1≤i≤n} sim(norm(δ), norm(q_i))`
  - `norm` 做小写化、空白折叠、去 Markdown 格式字符；`sim` 用 Python `difflib.SequenceMatcher` 的 ratio（0–1）。
  - 若 `r ≥ 0.8` → 直接记为确认定位（该阈值仅用于路由明显词法匹配，非语义安全判定阈值）。
- **其余情形交由独立 LLM 裁判**：输入记录注入、原版-注入版 diff、所有发现及其证据/解释、补丁 P，判断是否有发现命中记录注入、补丁是否移除/中和对应行为。
- 定位结果映射：至少一条发现识别出记录注入 → 真阳性（TP），否则假阴性（FN）。
- 验证是**静态**的：可判断记录注入是否被识别、对应行为是否从补丁中移除，但**不能保证所有合法功能被保留**。

### 2.5 评估指标

- **GDR（Generic Detection Rate）**：扫描器对注入技能文件报告至少一条发现的比率（不论位置）。
- **IDR（Injection Detection Rate）**：扫描器识别出对应注入组件的比率，是更严格的指标，衡量真正的真阳性检测能力。
- 发现按两个维度标注：**来源（provenance）**——injected / pre-existing / configuration / ambiguous；**安全类别**——映射到 **OWASP Agentic Security Initiative（ASI）** 分类法。
