## 摘要
大语言模型智能体正越来越多地被部署用于长时程任务执行。然而，当前的评估范式面临三大局限：仅终端评估忽略中间过程，难以高效且准确地定位错误；单一参考匹配会惩罚有效的替代解决方案路径；事后轨迹评判成本高昂，且无法提前终止失败的运行。为解决这些问题，我们提出 DynSTEER，一种面向智能体的动态阶段式轨迹评估框架。DynSTEER 将 rollout 划分为由关键已完成动作锚定的多个阶段，在具备充分上下文的情况下将评估聚焦于关键里程碑，同时支持有针对性的策略调整。它从公开任务视图中构建路径容忍的里程碑图，以尊重多样的合法策略而不泄露真值。此外，它自适应地在多层级评审器之间路由评估查询，并在线终止不可恢复的执行，以抑制资源浪费。实验表明，DynSTEER 将跨 LLM 智能体的评估区分度较原生评估提高了 85.2%，以统计显著性区分所有模型对，并在失败的 rollout 上节省了 34.51% 的执行步骤。

## Abstract
Large language model agents are increasingly deployed for long-horizon task execution. However, current evaluation paradigms face three major limitations: terminal-only assessment ignores intermediate processes and struggles to localize errors efficiently and accurately, single-reference matching penalizes valid alternative solution paths, and post-hoc trajectory judging incurs high costs without the ability to halt failed runs early. To address these issues, we propose DynSTEER, a dynamic stage-wise trajectory evaluation framework for agents. DynSTEER segments rollouts into stages anchored by key completed actions, focusing evaluation on essential milestones with adequate context while enabling targeted strategy adjustments. It compiles a path-tolerant milestone graph from public task views to respect diverse legitimate strategies without leaking ground truth. Furthermore, it adaptively routes evaluation queries across multi-tier judges and halts unrecoverable executions online to curb resource waste. Experiments demonstrate that DynSTEER improves evaluation discriminability across LLM agents by 85.2\% over native evaluation, separates all model pairs with statistical significance, and saves 34.51\% of execution steps on failed rollouts.

## 2. 方法论

### 2.1 核心思想

DynSTEER（Dynamic Stage-wise Trajectory Evaluation and Execution-time Review）由三个协同组件构成：

1. **执行前**：从公开任务视图生成路径容忍的里程碑有向无环图（DAG），保留执行多样性；
2. **执行中**：以动作闭包与支配点（dominator）为锚点做阶段式轨迹评估；
3. **动态策略适配与执行时早停**：把评估资源聚焦到薄弱片段，并及时中止不可恢复的执行。

### 2.2 问题形式化与双时钟观测模型

- 任务形式化为元组 `T = (x, S0, A, C)`：用户指令、初始状态、可用工具 API 目录、环境状态不变式与安全契约。
- 为防止测试污染，DynSTEER 严格只使用**公开任务视图** `V_public = (x, A, I0)`，隔离隐藏参考路径 τ* 与终端单元测试。
- **双时钟观测模型**：
  - **原始事件时钟 k**：每个原子事件（思维、工具调用、环境响应）递增，用于对致命雷区操作 `e_k ∈ M_fatal` 的即时安全拦截；
  - **闭动作时钟 t**：仅当工具调用收到返回且智能体交还控制权（语义闭合）时推进，里程碑结算与打分只在闭动作边界发生，确保工具结果被完整观测后再评分。

### 2.3 里程碑图生成（执行前）

- 目标：把公开视图编译为路径容忍的里程碑 DAG `G = (M, E, K, M_fatal)`（里程碑集、优先级边、参数绑定、危险操作）。
- **多候选合成与契约校验**：用温度采样 LLM 提示生成 C 个候选计划（如直接关键词查询 vs. 分层过滤等不同探索启发式）；每个候选 `G_c = (Mc, Ec)` 需通过确定性校验：Schema 检查 ∧ 无环 ∧ 绑定一致性，剔除幻觉 API、类型不匹配或循环依赖。
- **严格多数共识**：仅当某里程碑在有效候选中出现次数 ≥ ⌈(C_valid+1)/2⌉ 时才保留，优先级边同理聚合。
- **传递归约**：对多数边集做传递归约 `E = TR(E_majority)`（Tarjan 线性时间），消除冗余捷径依赖，得到能容纳多样合法策略的最小 DAG。

### 2.4 阶段式轨迹评估（执行中）

- **就绪前沿匹配**：在已结算里程碑 `M_<t` 之外，只在就绪前沿 `F_t = {m ∈ M \ M_<t | Pred(m) ⊆ M_<t}` 中匹配；当动作 `a_t` 与状态增量满足语义谓词 `φ_m*(a_t, s_t) = 1` 时结算里程碑 m*。限制在 F_t 可防止乱序结算与"刷分"。
- **支配点锚定的阶段隔离**：用 Lengauer–Tarjan 算法计算 m* 的直接支配点 `idom(m*)`（从起点 s0 到 m* 的每条有向路径都必经的节点），阶段证据窗口定义为 `W(m*) = [t_idom(m*), t]`。该窗口既能排除并行无关分支，又能捕获通往 m* 的全部中间推理、试错与参数调整——兼顾"全轨迹评估定位不清"与"单步评估上下文不足"的缺陷。
- **多维质量打分**：每个里程碑在 Correctness、Efficiency、Safety、Tool Compliance 四个正交维度上评分，复合阶段分为各维度得分按动态归一化权重 w 的加权和。

### 2.5 动态评审器适配与早停

- **三级评审器阶梯**：
  - Tier 1 `J_cheap`：确定性结构评估器，检查工具状态码、schema、证据规则，零 LLM 推理开销；
  - Tier 2 `J_std`：统一多字段 LLM 评估器，单次结构化 JSON 输出同时给所有维度打分并聚合多采样置信度；
  - Tier 3 `J_exp`：单维度专家 LLM 评估器，使用专门 rubric 与多次深思的反事实分析。
- **动态策略调整**：
  - 维度权重按指数梯度缩放更新：`w_d^(t+1) ∝ w_d^(t) · exp(α(1 − s_d) + β·u_d)`，其中 s_d 为维度分、u_d 为不确定性，α、β 控制对质量缺陷与不确定性的敏感度；
  - 基线层级：若阶段分高（≥ θ_pass + δ_margin）、各维不确定性低且无致命事件，则回落到 `J_cheap`，否则用 `J_std`；
  - 单维度层级沿 `J_cheap < J_std < J_exp` 自适应升级：得分低于失败阈值直接升到 `J_exp`；低于警告阈值或不确定性过高则升一级；否则沿用基线。
- **执行时早停的四个判据**：
  1. **致命雷区拦截**：在原始事件时钟上立即中止危险/不可逆操作；
  2. **结构性不变式失败**：持续出现无法解析的载荷或重复 schema 错误；
  3. **持续低质量**：累计阶段缺陷表明目标漂移不可恢复；
  4. **前沿停滞**：连续 N_stag 个动作未推进就绪前沿，用于检测病态死循环。
- 中止时输出可审计诊断报告，记录步数、支配点锚点与因果失败维度。
