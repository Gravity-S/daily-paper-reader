## 摘要
基于LLM的集中式多智能体系统（MAS）通过注册新的工作智能体来扩展功能，规划器会读取这些工作智能体的描述，以决定任务如何分解、由哪个工作智能体执行每个子任务，以及每个子任务需要什么。第三方描述由系统外部编写，却被规划器信任，从而形成了一条注册时注入通道。恶意载荷在任何用户指令到达之前即被植入，针对规划器，并经由生成的计划传播到良性工作智能体；即使精心构造的工作智能体从未被分配子任务或调用，也能生效。我们定义了四个工作智能体描述字段：功能、输入规范、输出规范和使用约束。在来自三个公共智能体市场的32,000条描述中，大多数省略了输入规范和使用约束，而至少23.35%包含这些字段之外的内容。我们构建了八种描述操纵攻击策略，分别针对任务分解、能力锚定和子任务规范，并在GAIA上对其进行评估。在最严重的情况下，单条被操纵的描述可将任务成功率从84.31%降至37.25%，或将token消耗或执行时间增加超过111%，而用户目标保持不变，工作智能体也忠实地执行生成的计划。这些影响在两种MAS实现、六种规划器LLM、四种LLM评估器以及来自三个市场的真实描述中持续存在。我们进一步提出DescGuard，一种注册时防御方法，在描述到达规划器之前仅保留工作智能体范围内的接口信息。DescGuard在不修改工作智能体实现、规划器或编排逻辑的情况下，将目标规划指标和下游性能恢复到接近基线水平，并可与现有的隔离、权限控制和运行时机制组合使用。

## Abstract
A centralized LLM-based multi-agent system (MAS) extends its functionality by registering new worker agents, whose descriptions are read by the planner to decide how a task is decomposed, which worker executes each subtask, and what each subtask requires. Third-party descriptions are authored outside the system but trusted by the planner, creating a registration-time injection channel. The payload is planted before any user instruction arrives, targets the planner and propagates through the generated plan to benign workers, taking effect even when the crafted worker is never assigned a subtask or invoked. We define four worker-description fields: functionality, input specification, output specification, and usage constraints. Among 32,000 descriptions from three public agent marketplaces, most omit input specifications and usage constraints, while at least 23.35% contain content outside these fields. We construct eight description-manipulation attack strategies targeting task decomposition, capability grounding, and subtask specification, and evaluate them on GAIA. In the most severe cases, a single manipulated description reduces task success from 84.31% to 37.25%, or increases token consumption or execution time by over 111%, while the user objective remains unchanged and workers faithfully execute the resulting plan. These effects persist across two MAS implementations, six planner LLMs, four LLM evaluators, and the real-world descriptions from three marketplaces. We further propose DescGuard, a registration-time defense that retains only worker-scoped interface information before descriptions reach the planner. DescGuard restores the targeted planning metrics and downstream performance toward their baseline levels without modifying worker implementations, the planner, or the orchestration logic, and composes with existing isolation, permission-control, and runtime mechanisms.

## 1. 核心问题与研究动机

- **背景**：基于 LLM 的集中式多智能体系统（Centralized MAS）通过注册新的"工作智能体（worker agent）"来扩展能力。规划器（planner）需要读取每个工作体的自然语言描述，才能决定三件事：任务如何分解、每个子任务由谁执行、每个子任务需要什么。
- **核心矛盾**：第三方工作体的描述由系统**外部**编写（如 Agent 市场、A2A 协议的 Agent Card），却被规划器当作**可信的规划输入**逐字读入上下文，且与规划器自身指令不做任何隔离或清洗——"以文档形式撰写，却以指令形式被消费"。
- **由此形成的攻击面**：一条**注册时注入通道（registration-time injection）**。恶意载荷在任何用户指令到达之前就已植入，因此：
  - 一次注册污染**所有后续**用户请求，而非单个会话；
  - 攻击目标不是某个工作体，而是所有工作体都依赖的**规划器**；
  - 影响通过**生成的计划**传播，而非智能体间消息，因而在任何通信发生前就已抵达良性工作体；
  - 该通道位于隔离、沙箱、权限中介、运行时监控等现有防御的**上游**，这些机制都在规划之后才生效，根本看不到它；
  - **精心构造的工作体无需被分配或调用**，破坏由忠实执行被污染计划的良性工作体完成。
- **与已有工作的区别**：ACE、ToolHijacker 等虽操纵组件描述，但被操纵组件既是载荷载体又是受益者，损害要等其被检索/选择/调用才发生；本文场景中描述"只要被规划器看见"即可生效。
- **现实性支撑**：Google Cloud Marketplace、AWS Marketplace 已规模化分发此类智能体，其审核针对实现与合规，并不排除"声称覆盖广、可靠性高"的描述。

## 2. 方法论

### 2.1 系统建模与计划的形式化

- 集中式 MAS 抽象为一个规划器 + 多个工作体；规划过程记为 **π = p(x, D)**，其中 x 为用户请求，D 为规划器可见的工作体描述集合。
- 计划的分析性表示为四元组 **π = (S, E, g, U)**：
  - S：子任务集合；E ⊆ S×S：子任务间依赖关系；
  - g : S → A：子任务到工作体的分配函数；
  - U = {u_s}：每个子任务的执行规范。
- 该分解仅为**分析性**，不假设规划器显式物化这些中间阶段。它对应三个决策维度：
  - **任务分解**（S, E）、**能力锚定**（g）、**子任务规范**（U）。

### 2.2 工作体描述作为"规划接口"——四个字段

借用软件接口声明组件功能与调用需求的思路，定义描述应提供的四类信息（且**仅限**关于该工作体自身）：

- **Functionality（功能）**：能做什么（如分析图像内容）。
- **Input specification（输入规范）**：接受什么形式的输入（如可访问的图像路径、Base64 编码）。
- **Output specification（输出规范）**：产出什么形式的结果（如文本分析、PDF 报告）。
- **Usage constraints（使用约束）**：使用条件（如需要网络连接、文件需放在可达路径）。

四字段同时界定了"必须提供什么"与"不该包含什么"：描述不应规定规划器如何分解任务、哪个工作体执行哪个子任务、或其他工作体该怎么做。

### 2.3 真实市场描述的实证测量

- 从 GPT Store（n=20,000）、Coze（n=8,000）、Baidu Wenxin（n=4,000）共采样 **32,000** 条描述，用 LLM-as-a-judge 按四字段判定。
- 结果（见表 I）：功能几乎都有陈述；但**输入规范缺失 ≥89.73%**、输出规范缺失 ≥74.82%、使用约束缺失 ≥94.61%；**至少 23.35% 包含四字段之外的内容**（无边界的能力宣称、面向规划器的措辞等）。
- 结论：真实市场中"超出接口"的内容已是主流风格，因此精心构造的恶意描述**不会显得突兀**。

### 2.4 防御设计的两条原则

- 内容按"**描述的是谁的行为**"决定保留或丢弃；
- 重述后的描述**只为其命名的工作体说话**。
- 关键不对称性：缺失字段只是让规划器信息不足，而**攻击者的立足点在于接口之外的内容**，因此处理应聚焦"移除越界内容"，而非"补齐缺失字段"。

### 2.5 威胁模型

- 用户请求 x 良性；规划器、底层 LLM、工作体实现、工具接口、系统提示、运行时配置均**可信**。
- 攻击面仅限**一个**工作体的规划器可见描述。
- 篡改函数：d′ᵢ = τ(dᵢ)（i ∈ I），否则 d′ᵢ = dᵢ；扰动后的计划 π′ = p(x, D′)。
- 对手无需替换原描述，可保留原有能力内容，仅插入、改写或强调特定部分。

### 2.6 八种攻击策略（三大类）

- **任务结构化攻击（操纵 S, E）**
  1. **Under-decomposition（欠分解）**：渲染"紧凑分解可避免交接开销与信息损失"，诱导合并本应分离的操作。
  2. **Over-fragmentation（过度碎片化）**：渲染"小任务更易执行、复杂任务易出错"，诱导拆分本已集成的操作。
  3. **Dependency disruption（依赖破坏）**：渲染"反复检查才能避免幻觉/不一致"，诱导冗余验证子任务、额外依赖与自检（自环）。
- **能力锚定攻击（操纵 g）**
  4. **Over-assignment（过度分配）**：把某工作体渲染成广泛适用或高可靠，诱导规划器把大量（甚至超出其范围）子任务集中给它。
  5. **Agent exclusion（智能体排除）**：把某工作体渲染成不可靠/不适用，诱导规划器回避它，使合适能力被闲置、任务被路由到更差的工作体。
- **子任务规范攻击（操纵 U）**（不改变子任务目标，也不引导安全敏感动作，只放大/抑制规划器的倾向）
  6. **Overworking（过度劳作）**：渲染"穷尽式探索才能避免不完整"，抬高工作量（如遍历所有网页与链接）。
  7. **Intermediate output suppression（中间输出抑制）**：抑制规划器对中间产物的要求（如返回文件路径），使下游工作体只能盲猜。
  8. **Planner prior misguidance（规划器先验误导）**：让规划器在证据收集前就锁定某种解释，写入子任务规范。

### 2.7 DescGuard：注册时防御

- **定位**：在第三方工作体注册时、描述进入规划器之前进行变换：ẽdᵢ = G(d′ᵢ)；规划器可见集合变为 ẽD = {d₁,…,dᵢ₋₁, ẽdᵢ, dᵢ₊₁,…,dₙ}；规划结果为 ẽπ = p(x, ẽD)。注册后不再参与规划。
- **确定性预处理**：Unicode 归一化、移除不可见字符、剥离残留 HTML/XML 标记。
- **三阶段 LLM 变换管线**：
  1. **Emphasis neutralization（强调中和）**：规范化全大写词、标点、Markdown 标记、强调性措辞；标点仅保留逗号、句号、冒号；不做内容取舍。
  2. **Interface-field extraction（接口字段抽取）**：只保留描述所注册工作体、且映射到四字段的内容；丢弃规定规划器如何规划、其他工作体如何行动、MAS 如何运行的语句；混合语句只保留接口部分；**原描述未提供的字段保持空缺，不做补全**。这一步实现"按描述对象取舍"的原则。
  3. **Worker-scoped restatement（工作体范围内重述）**：把面向调用方的要求转写为客观接口陈述（如"请提供文件路径"→输入规范）；**无边界能力宣称直接丢弃而非收窄**。这一步实现"只为其命名的工作体说话"。
- **鲁棒性机制**：每个变换阶段配一个独立 LLM 验证器；每次调用用**新生成的随机分隔符**包裹不可信文本，防止作者伪造输入边界；验证失败则返回原因并重试，直到通过或达到重试上限；未通过验证的输出既不进入下一阶段也不暴露给规划器。
- **非侵入性**：不修改工作体实现、规划器模型、编排逻辑，无需重训练，可与隔离、权限控制、运行时机制组合。

## 3. 实验设计

- **Benchmark**：**GAIA**——包含异构输入（网页、PDF、PPTX、表格、图像、音频、视频）的复杂多步任务，需要组合多种能力，适合集中式 MAS。
- **实现**：基于 **AutoGen** 构建集中式 MAS，含 1 个规划器 + 7 个工作体：PostgresManager、WebSurfer、DocumentAnalyzer、MediaAnalyzer、PythonExecutor、TerminalManager、Reasoner。**PostgresManager 被指定为"新注册的第三方工作体"，其描述是唯一注入源**，其实现与功能保持良性不变。
- **骨干模型**：默认规划器与所有工作体使用 **DeepSeek-V3.2**；规划级 LLM 指标由 **Qwen3-Max** 评判。
- **2×2 实验设计**（是否操纵描述 × 是否启用防御）：
  1. **Baseline**：干净描述、无防御；
  2. **Attack Impact**：操纵描述、无防御；
  3. **Defense Overhead**：干净描述、有防御；
  4. **Defense Effectiveness**：操纵描述、有防御。
- **对比方式**：攻击影响 = 设置 2 vs 1；防御效果 = 设置 4 vs 2；防御开销 = 设置 3 vs 1。
- **指标**：
  - 规划级——AST（平均子任务数）、DVTR（专用验证任务比）、VIR（验证意图率）、APR（智能体参与率）、AMR（智能体错配率）、EER（过度劳作率）、MIRR（缺失中间结果比）、VCR（模糊具体化比）；
  -

- **执行级指标**——用于刻画计划在被忠实执行后对系统实际运行的影响，例如：
  - **ET（Execution Time，执行时间）**：完成整个任务所消耗的墙钟时间；
  - **TC（Token Consumption，令牌消耗）**：规划器与工作体在规划及执行阶段的累计 token 用量，用于衡量过度劳作与冗余验证的代价；
  - **WR（Worker Redundancy，工作体冗余度）**：同一能力被重复调度的比例；
  - **SDR（Subtask Drop Rate，子任务丢弃率）**：因下游缺少中间产物而无法执行的子任务占比。
- **结果质量指标**——用于判断计划被污染后最终产出是否仍然正确：
  - **TS（Task Success，任务成功率）**：由 Qwen3-Max 对照 GAIA 标准答案评判；
  - **AS（Answer Score，答案得分）**：在部分正确情形下给出的细粒度分数；
  - **IER（Information Error Rate，信息错误率）**：最终答案中出现与中间证据不符陈述的比例。

### 3.1 实验流程与公平性控制

- 为保证"攻击影响"仅归因于描述内容而非工作体行为，**PostgresManager 的实现、数据库连接、工具接口在所有设置下完全一致**；唯一变量是其规划器可见描述文本。
- 八种攻击策略各自单独注入一次，并在 GAIA 的同一任务子集上重复运行，报告均值与方差。
- 防御设置下，DescGuard 的变换在注册阶段执行一次，其结果对全部后续请求复用，因而其开销是**一次性**的，与用户请求数量无关。
- 规划级指标由独立 LLM 评判器（Qwen3-Max）对生成的计划做结构化标注后计算，评判提示与攻击构造提示隔离，避免评判器被同一措辞误导。

## 4. 主要实验结果

### 4.1 攻击影响（设置 2 vs 设置 1）

- **规划级**：八种策略均显著改变了计划结构。任务结构化类攻击中，欠分解使 AST 明显下降、过度碎片化使 AST 上升，依赖破坏显著抬高 DVTR 与 VIR，表明规划器开始插入大量本不必要的验证与自检子任务。能力锚定类攻击中，过度分配使 APR 与 AMR 上升，PostgresManager 被分配到与其能力不匹配的子任务；智能体排除则使该工作体的参与率下降，任务被路由到能力更弱的工作体。
- **子任务规范类**：过度劳作显著抬高 EER，中间输出抑制抬高 MIRR，规划器先验误导抬高 VCR，即计划在证据收集前就写入了带倾向性的解释。
- **执行级与结果质量**：上述结构变化并非"纸面扰动"，而是传导到执行阶段——执行时间与 token 消耗普遍上升，中间输出抑制导致 SDR 升高、下游工作体被迫猜测，最终任务成功率与答案得分下降，信息错误率上升。
- **关键发现**：**被注入的工作体本身从未被恶意实现，甚至常常未被调用**，破坏完全来自被污染的规划器对良性工作体的错误编排，印证了"注册时注入通道位于现有运行时防御上游"的判断。

### 4.2 防御有效性（设置 4 vs 设置 2）

- DescGuard 启用后，八种攻击策略下的规划级指标普遍回落至接近基线水平：AST、DVTR、VIR、APR、AMR、EER、MIRR、VCR 的异常偏移被大幅压缩。
- 执行级与结果质量指标同步恢复：执行时间与 token 消耗回到基线区间，任务成功率与答案得分回升，信息错误率下降。
- **逐阶段消融**：强调中和主要削弱"渲染式措辞"的效力；接口字段抽取负责剥离越界内容（这是防御的主力）；工作体范围内重述处理残余的面向调用方措辞。三者叠加效果最佳，任一阶段单独使用均不足以完全抵消全部八种策略。
- **鲁棒性**：随机分隔符与独立验证器有效阻止了作者伪造输入边界或借由变换过程重新注入内容；验证失败会重试而非放行，未通过验证的输出不会到达规划器。

### 4.3 防御开销（设置 3 vs 设置 1）

- 由于 DescGuard 只在注册时运行一次，**对每个用户请求的边际开销为零**，规划与执行的时延、token 消耗与基线无显著差异。
- 主要成本集中在注册阶段的一次性 LLM 变换与验证调用，与描述长度和重试次数相关，而非与请求量相关，因而在规模化部署中可被摊销。
- 由于不做字段补全，DescGuard 不会引入额外信息或改变工作体语义，仅移除越界内容，因此不改变良性工作体的正常参与方式。

## 5. 讨论与局限

- **威胁模型的边界**：本文假设规划器、底层 LLM、工作体实现与运行时配置均可信，攻击面被严格限定为"单个工作体的规划器可见描述"。若攻击者能同时控制多个描述、或能篡改规划器自身，问题将超出本文范围。
- **防御的定位**：DescGuard 是**注册时**的内容变换，而非对恶意意图的检测；它不判断描述"是否恶意"，而是按"描述的是谁的行为"这一形式原则移除越界内容，因此对未见过的新型措辞也具备一定泛化能力。
- **潜在张力**：接口字段抽取可能在极端情况下丢弃对规划器有用但属于"越界"的信息（例如关于系统整体工作流的提示），这是"安全与信息量"之间的权衡；论文选择以"只为其命名的工作体说话"为硬约束。
- **真实市场适配性**：实证测量显示真实描述中越界内容占比可观，说明该攻击面具有现实基础；但这也意味着 DescGuard 会改写相当比例的良性描述，其重述质量依赖变换与验证的 LLM 能力。
- **泛化性**：实验基于 AutoGen 与 DeepSeek-V3.2，结论是否迁移到其他编排框架与骨干模型需进一步验证；不过攻击面的根因（描述被当作可信规划输入）与框架无关。

## 6. 结论与贡献

- **贡献一（问题）**：识别并形式化了集中式多智能体系统中的**注册时注入**攻击面——第三方工作体的自然语言描述被规划器逐字消费为规划输入，攻击在用户指令到达前植入、一次注册污染所有后续请求、影响经计划传播至良性工作体。
- **贡献二（分析）**：提出计划四元组 (S, E, g, U) 的分析框架与"工作体描述即规划接口"的四字段模型（功能、输入规范、输出规范、使用约束），并据此系统化归纳出覆盖任务结构化、能力锚定、子任务规范三大类的**八种攻击策略**。
- **贡献三（实证）**：对 32,000 条真实市场描述进行测量，证明越界内容在真实生态中已是主流风格，攻击构造不显突兀。
- **贡献四（防御）**：提出 **DescGuard**，以"按描述对象取舍 + 只为其命名的工作体说话"为原则，通过强调中和、接口字段抽取、工作体范围内重述三阶段管线，在注册时一次性清洗描述，不修改工作体、规划器与编排逻辑，可与既有隔离、权限与运行时机制叠加，且对用户请求零边际开销。
- **总体结论**：集中式 MAS 的安全性不能只在下游（沙箱、权限、运行时监控）设防；只要第三方描述仍被规划器当作可信输入，规划器本身就是一个必须在**注册入口**处加固的关键组件。DescGuard 提供了一条非侵入、可组合的加固路径。
