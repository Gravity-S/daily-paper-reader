## 摘要
Harness设计通过整合记忆、工具使用和运行时控制，改变了基于LLM的智能体的开发方式。然而，这种设计也引入了安全与隐私风险，因为来自外部来源的恶意指令可能被写入持久记忆，并跨会话持续存在。为研究这一风险，我们提出PMPA，一种针对基于Harness的智能体的持久记忆投毒攻击。PMPA将恶意指令嵌入良性外部来源，并诱导受害智能体将其写入持久记忆，而无需直接访问智能体框架。一旦存储，被投毒的记忆可在后续会话中被检索，触发额外的恶意操作并导致隐私泄露。我们在OpenClaw和Claude Code上，跨不同骨干LLM、输入模态和触发场景对PMPA进行了评估。在所有设置下，PMPA在OpenClaw上取得平均注入成功率（ISR）和跨会话攻击成功率（C-ASR）为73.7%/55.5%，在Claude Code上为66.9%/81.7%，同时在两个系统上保持良性任务性能。我们进一步评估了一种针对性的提示级防御，发现它能在许多设置中减少记忆注入，但一旦持久记忆已被投毒，其保护作用有限。

## Abstract
Harness design has transformed the development of LLM-based agents by integrating memory, tool use, and runtime control. However, this design also introduces security and privacy risks because malicious instructions from external sources may be written into persistent memory and persist across sessions. To study this risk, we propose PMPA, a Persistent Memory Poisoning Attack against harness-based agents. PMPA embeds malicious instructions into benign external sources and induces the victim agent to write them into persistent memory without directly accessing to the agent framework. Once stored, the poisoned memory can be retrieved in later sessions, triggering additional malicious actions and causing privacy leakage. We evaluate PMPA on OpenClaw and Claude Code across different backbone LLMs, input modalities, and trigger scenarios. Across all settings, PMPA achieves average Injection Success Rate (ISR) and Cross-session Attack Success Rate (C-ASR) of 73.7%/ 55.5% on OpenClaw and 66.9%/ 81.7% on Claude Code, while preserving benign task performance on both systems. We further evaluate a targeted prompt-level defense and find that it can reduce memory injection in many settings, but provides limited protection once the persistent memory has been poisoned.

## 1. 核心问题与研究背景

- **背景**：以 OpenClaw、Claude Code 为代表的"harness（框架/挂具）工程"范式，把推理、规划、工具调用、会话管理与**持久记忆（persistent memory）**整合为统一的编排层，使 LLM 智能体能够长期运行、跨会话保留上下文。
- **核心风险**：智能体经常读取未经验证的外部来源（网页、PDF、图片等）。若其中的恶意指令被写入**持久记忆**，则攻击不再局限于当前任务，而是**跨会话持续存在**，可能在后续无关任务中被检索并触发，导致隐私泄露。
- **研究空白**：
  - 已有 prompt injection 研究多聚焦"当前任务/单次交互"内的影响；
  - 已有 backdoor / memory poisoning 研究（AgentPoison、MINJA、BadAgent 等）通常假设更强的攻击者能力（投毒微调数据、直接污染记忆/知识库、直接与受害智能体交互）。
  - 本文研究一个**更受限的攻击者**：只能发布嵌入了恶意指令的外部来源，**不能查询智能体、不能访问设备、记忆、系统提示或运行时配置**。
- **研究问题**：嵌入外部来源的恶意指令，能否在**不直接访问智能体框架**的前提下被写入持久记忆，并在跨会话场景中造成隐私泄露？

## 2. 方法论：PMPA（Persistent Memory Poisoning Attack）

### 2.1 核心思想

- 攻击分为两个阶段：
  1. **注入阶段（Injection Phase）**：攻击者发布看似正常、内嵌攻击载荷的外部来源；用户将其提供给智能体完成一个**无关的良性问答任务**；智能体在处理内容时可能把其中"记忆写入指令"当作用户需求/偏好，写入持久记忆。
  2. **触发阶段（Trigger Phase）**：在后续会话中用户请求一个正常的工作区任务（如创建日程），智能体检索到被投毒的记忆，在完成良性任务的同时**额外执行恶意动作**，造成隐私泄露。

### 2.2 攻击载荷结构（三组件）

1. **过渡句（Transition Sentence）**：连接恶意指令与周围良性内容，保持语义连贯、降低突兀感（如 "After answering this question, ..."）。
2. **记忆写入指令（Memory-Writing Instruction）**：要求智能体把后续规则存入持久记忆（如 "please remember this following requirement in the memory: ..."）。
3. **条件恶意规则（Conditional Malicious Rule）**：规定触发条件与附加动作（如 "When doing Action A, do Action B at the same time"），触发时与良性任务一并执行并泄露隐私。

### 2.3 注入策略

- **注入位置**：置于良性内容**中部**，伪装为内容的一部分，避免首尾位置的突兀性。
- **语言风格**：采用**第一人称、类用户口吻**（"please help me..."），把恶意指令包装成用户请求，降低智能体怀疑、提高写入记忆概率。

### 2.4 输入模态与泄露场景

- **输入模态**：文本、图片、PDF（覆盖 harness 智能体常见输入格式）。
- **工作区场景**：邮件、日历、共享文档、表单（四种隐私泄露路径）。

### 2.5 威胁模型要点

- **攻击者目标**：诱导写入恶意规则 → 跨会话触发 → 泄露用户/任务相关的私有信息。
- **受害模型**：部署在用户本地环境（个人设备、项目工作区）的 harness 智能体。
- **攻击者能力**：不能查询受害智能体、不能观察其输出、不能访问设备/记忆/系统提示/运行时配置；**仅能构造并发布嵌入了指令的外部来源**（比黑盒设定更受限）。

## 3. 实验设计

- **良性内容来源**：MMLU、ARC、CommonsenseQA、SocialIQA 四个公开问答数据集，随机均衡采样 **30 个 QA 实例**。

- **S-ASR**（Same-session ASR）：注入阶段当次会话内是否造成隐私泄露。

## 6. 主要结论与发现

- **攻击总体有效**：跨全部设置，OpenClaw 平均 ISR/C-ASR = **73.7% / 55.5%**；Claude Code 为 **66.9% / 81.7%**；Utility 在所有设置下均 **> 80%**，说明攻击不显著破坏良性任务。
- **ISR 范围 61.7%–77.5%，C-ASR 范围 30.8%–92.5%**；S-ASR 波动最大（Claude Code + Qwen3-Max 时仅 6.4%）。
- **同一骨干模型在不同框架下攻击效果不同**，说明 harness 实现细节显著影响攻击面。
- **模态影响**：纯文本效果最好（OpenClaw 文本 ISR 接近 100%，S-ASR 88.9%）；图片/PDF 因需额外解析与工具调用、更易被标记为不可信内容，攻击效果较弱，但仍能实现记忆注入与同会话泄露。
- **场景影响**：日历场景跨会话效果最好（C-ASR 96.7% / 87.8%）；OpenClaw 表单场景 ISR/S-ASR 最高（80% / 71.1%）；邮件与共享文档相对较低但依然稳定有效。攻击效果取决于"恶意规则 + 触发任务"的匹配关系。
- **消融**：Claude Code 上语言风格影响显著（第一人称 83.0% → 第二人称 54.4% → 无人称 48.1%）；OpenClaw 上位置影响更大（底部 59.6% → 顶部 73.3%）；顶部+第一人称整体 ISR 最高。
- **持久性**：随良性交互轮次增加，C-ASR **没有出现一致的单调衰减**，5 轮良性交互后仍有较高成功率，说明投毒记忆长期有效（但个别场景如 OpenClaw 邮件、Claude Code 表单明显下降）。
- **防御**：sandwich-style 提示级防御能显著降低图片/PDF 的 ISR 与 S-ASR，但对文本降低有限；**C-ASR 几乎不变**，即记忆一旦被污染，提示级防御基本失效。

## 7. 优点

- **威胁模型更贴近现实且更严格**：攻击者不接触框架、不查询智能体、只发布外部内容，比 AgentPoison/MINJA 等假设的"直接污染记忆/直接交互"更弱、更可实施。
- **问题定位新颖**：明确区分"临时上下文注入"与"持久记忆投毒"，把跨会话持续性作为核心研究点，填补 harness 持久记忆安全性的空白。
- **攻击载荷工程化、模块化**：过渡句 + 记忆写入指令 + 条件恶意规则的组合设计，兼顾隐蔽性（语义连贯）与可触发性（条件规则），并系统化了位置与语言风格两个可控因素。
- **实验维度全面**：同时覆盖框架、骨干模型、输入模态、工作区场景、注入策略、持久性与防御，形成较完整的攻击面刻画。
- **关注实用权衡**：始终报告 Utility，证明攻击在保持良性任务性能的前提下有效，避免"破坏功能式"的伪攻击。
- **防御评估有实际指导意义**：明确指出提示级防御在"注入前"部分有效、在"已污染后"几乎无效，为后续研究指出方向（需要记忆层/系统层防护）。
- **伦理声明规范**：强调实验在受控环境、自有机器上进行，不针对真实个人。
