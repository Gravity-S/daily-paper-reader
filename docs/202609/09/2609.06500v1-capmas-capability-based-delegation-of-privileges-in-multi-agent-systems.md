## 摘要
代理系统需要跨多个协作代理安全高效地委托特权。现有方法分为两类。一些方法直接将用户身份传播给代理，模糊了责任归属并造成持续的过度特权风险，这种风险因AI代理的非确定性行为而被放大。另一些方法依赖与中央身份与访问管理（IAM）提供商的持续同步，引入了额外的延迟和通信开销。我们提出了CAPMAS，一种用于多代理系统中安全端到端查询执行的新型架构。CAPMAS新颖地将基于对比学习的语义范围界定管道（在执行前将自然语言查询映射到有界特权集）与基于Macaroon的可表达令牌相结合，后者支持离线、防篡改的代理间单调特权递减委托。通过将身份验证和委托执行与代理推理解耦，CAPMAS在实施严格最小特权保证的同时实现了实用的代理执行。通过消除与IAM的同步委托交换，与OAuth 2.0令牌交换（RFC 8693）相比，CAPMAS实现了30倍的更快委托操作、2倍的更低委托延迟和高达3倍的更低带宽使用。其语义范围界定管道在包含超过3100个端点的企业级API模式上，能在17毫秒内实现超过90%的完美特权包检索，同时与将所有用户特权传播给代理的系统相比，将不必要特权减少99.5%。

## Abstract
Agentic systems require secure and efficient delegation of privileges across multiple collaborating agents. Existing approaches fall into two categories. Some propagate user identities directly to agents, obscuring accountability and creating persistent over-privilege risks that are amplified by the non-deterministic behaviour of AI agents. Others rely on continuous synchronization with a central Identity and Access Management (IAM) provider, introducing additional latency and communication overhead.   We present CAPMAS, a novel architecture for secure end-to-end query execution in multi-agent systems. CAPMAS newly combines a contrastive learning-based semantic scoping pipeline that maps natural-language queries to bounded privilege sets before execution with expressive Macaroon-based tokens that enable offline, tamper-evident delegation with monotonic privilege reduction across agents. By decoupling authentication and delegation enforcement from agent reasoning, CAPMAS enables practical agentic execution while enforcing strict least-privilege guarantees.   By eliminating synchronous delegation exchanges with the IAM, CAPMAS yields 30 times faster delegation operations, 2 times less delegation-oriented latency and up to 3 times lower bandwidth usage than the OAuth 2.0 Token Exchange (RFC 8693). Its semantic scoping pipeline achieves over 90% perfect privilege-bundle retrieval within 17 milliseconds on enterprise-scale API schemas containing over 3,100 endpoints, while reducing unnecessary privileges by 99.5% when compared to systems that propagate all the user's privileges to agents.

## 1. 核心问题与研究动机

- **背景**：AI Agent（尤其是基于 LLM 的多智能体系统）正在被广泛用于代替用户访问企业或个人服务。多智能体架构通过将复杂任务拆解为子任务并在多个 Agent 间协作执行，但这种架构显著扩大了“权限委托面”。
- **核心问题**：如何在不模糊责任归属、不导致过度授权的前提下，将用户的高层自然语言请求转化为最小且足够的权限，并安全、高效地在多个自治 Agent 之间传递这些权限。
- **现有方案的不足**：
  - **直接传递 JWT/用户凭证**：所有下游 Agent 都继承用户完整权限，违反最小权限原则；一旦某个 Agent 出现幻觉或被注入恶意提示，整个服务生态都可能被波及。
  - **基于 OAuth 2.0 Token Exchange（RFC 8693）的在线委托**：每次委托都需要同步访问中央 IAM 重新签发令牌，带来额外延迟、通信开销和中心化瓶颈。
  - **二者共同缺陷**：均假设确定性软件组件请求结构化 API 权限，无法应对由非确定性 LLM 驱动的非结构化自然语言工作流。且 IAM 中心化同步式委托无法随多智能体规模扩张。
- **作者声明**：此前尚没有一种实用架构能够同时实现“离线令牌衰减委托”和“基于自然语言语义的请求权限界定”。

## 2. 方法论

### 2.1 核心思想

CAPMAS 将“权限授权与委托”从 Agent 的推理过程中解耦，提出一种端到端架构：

> 先用**对比学习语义范围管道**在 IAM 端将自然语言查询映射为有界的最小权限集；再把这些权限封装到**基于 Macaroon 的能力令牌**中，使各 Agent 可在本地以离线、防篡改的方式单调缩减权限后逐级委托。

### 2.2 关键技术细节

- **Macaroon 令牌实例化**
  - Macaroon 支持离线衰减：任何人可本地追加 caveat（限制条件），并通过 HMAC 链式签名实现防篡改，无法删除或削弱已有限制。
  - CAPMAS 定义两类 caveat：
    - **确定性可验证 caveat**：`rid`（请求 ID）、`iss`（签发者）、`exp`（过期时间）、`aud`（目标接收者）、`agent_id`（路径上的 Agent 身份）、`permit`（允许执行的权限声明）。
    - **推理与可追溯性 caveat**：`query`，保存原始用户意图和中间 Agent 的子查询指令，用于事后语义异常检测。
  - 采用 **default-deny 的严格许可语言**：`permit` 是唯一可累计的权限声明方式；验证时，IAM 计算所有 `permit` 的**交集**作为最终授权范围。若某个 Agent 漏加限制，结果只是“拒绝执行”，而非权限放大。
- **状态隔离与传播**
  - 父 Agent 为每个子任务克隆当前 Macaroon，再在克隆副本上追加限制；分支之间互不影响，父节点保留原有较宽令牌用于并行委托其他子任务。
- **语义 Token 范围界定（Semantic Token Scoping）**
  - 将“从自然语言查询推导权限”重构为**语义检索问题**：离线用对比学习把各 API 端点/权限的描述文本嵌入向量空间；运行时对新查询做向量检索，取相似度最高的 **top-k** 个权限作为根令牌的 `permit`。
  - 采用 Siamese（Shared Encoder）结构，配合 **InfoNCE 损失**训练。
  - 在达到 max-k 前引入 **elbow-drop 阈值 α**：若相邻候选权限的余弦相似度骤降超过 α，则提前停止检索，以降低对简单任务的过度授权。
- **完整请求流程**（以查询“Salary of project Phoenix lead?”为例）
  1. 用户向 IAM 登录并提交查询。
  2. IAM 验证身份，运行 `getReqScopes` 得到权限集（如 Projects、HR），创建根 Macaroon 并加入 `rid`、`exp`、`permit`、`aud`、`agent_id=user`、`query` 等 caveat。
  3. 根令牌返回用户，用户将其发给协调 Agent。
  4. 每个中间 Agent 在自己的 agentic loop 中决定子任务；克隆令牌并本地追加 `permit`、`aud`、`agent_id`、`query` 等 caveat 后进行委托。
  5. 目标服务在执行业务前调用 IAM 的 `verifyAndEvaluate`。
  6. IAM 三段式验证：①重算 HMAC 链校验完整性；②检查确定性 caveat 是否构成合法委托链、目标动作是否在所有 `permit` 的交集内；③用 LLM 做语义异常检查（判断最终动作是否与原始用户意图一致）。

## 3. 实验设计

- **微基准（Micro-Benchmark）**：比较三种授权范式在 `Create-Token`、`add-Caveat`、`Verify` 三个核心操作上的延迟和令牌体积；caveat 数量 N = 1、5、10、100。
- **扩展性实验（Scaling）**：模拟长度为 N=1~25 的非分支委托链，统计总委托延迟和带宽消耗。

## 6. 主要结论与发现

- **性能优势**：相比 RFC 8693，CAPMAS 的委托操作快约 30 倍；整体委托相关延迟减少约 2 倍；带宽消耗降低约 3 倍；令牌体积随 caveat 数**线性增长**（Signed Nested 呈几何增长，N=100 时超过 500MB 触发 OOM）。
- **语义检索有效**：在包含 3,176 个端点的 XLAM 数据集上，以 max-k=10 的约束下做到约 92% 的 Perfect Bundle Capture，检索延迟约 17ms；在 ASTRA 上约 90.9%，远高于 Basic Agent 的 37.4%，并将 Complete Miss Rate 从 53.0% 压到 2.1%。生成式 LLM 在 XLAM 上因上下文超限完全失败。
- **最小权限得到大幅改善**：相对“向所有 Agent 传播用户全部权限”的 legacy 系统，CAPMAS 可将不必要特权减少 99.5%。
- **对比训练必要**：预训练好的文本编码器在不做对比训练时仅约 71.6% 的 Perfect Bundle Capture，经任务对比优化后提高到 92.3%，说明针对硬权限边界的专门优化是必需的。
- **安全与效用可权衡**：提高 k 值能提高检索成功率（k=20 达 93.9%，k=60 达 96.9%），但会增大绝对过度授权。实际系统可结合 elbow-drop 与下游 Agent 的进一步衰减来平衡两者。
- **端到端可行性**：真实多 Agent 原型的任务平均耗时 10.8 秒，其中约 10 秒为 LLM 推理；授权/密码学开销只占约 800ms，说明 CAPMAS 对 AI 执行主流程引入的额外负担很小。

## 7. 优点

- **架构设计巧妙**：将“NL 查询 → 权限范围”的难题从运行期 LLM 推理中剥离，转化为离线可训练的语义检索问题，从根本上绕开 LLM 上下文窗口、幻觉和延迟问题。
- **密码学原语选择契合需求**：Macaroon 的 HMAC 链式结构天然支持无中心、离线、单调限制的委托，避免每跳都访问 IAM 的瓶颈，且令牌自含完整委托历史，支持审计与快速撤销。
- **安全属性清晰**：明文列出了动态最小权限、权限交集、防篡改、可追溯、会话内即时撤销等性质，并对恶意 Agent（身份伪造、静默转发、查询路由篡改）给出了攻击分析与改进方向。
- **工程落地考虑充分**：提供与 MCP 等 Agent 框架的集成方式、面向不支持 Macaroon 的 legacy 服务的代理方案；实验代码开源。
- **评估角度完整**：不是只报端到端延迟，而是区分 agent-to-agent 与 agent-to-IAM 的延迟和带宽，分别揭示不同方法的瓶颈来源。

## 8. 不足与局限

- **明文 caveat 的信息泄露**：用户查询和中间 agent 推理内容以明文随令牌传播；Agent 的持久化记忆可能导致不同任务/用户间上下文串扰，敏感信息可能被下层 Agent 看到，CAPMAS 本身无法强制 Agent 内存隔离。
- **k 值选择困难**：top-k 上界是硬安全保证，但“需要多少权限”完全依赖人工预设。k 过小会阻断合法工作流，k 过大则削弱最小权限原则。虽然 elbow-drop 与后续衰减可部分缓解，但总体上仍是部署相关、难以自动最优化的参数。
- **IAM 中心化风险**：最终验证和语义监控都集中在 IAM。虽然验证为无状态操作、可水平扩展，但信任与可用性仍是单点；去中心化需引入非对称签名或账本，会牺牲效率。
- **诚实但好奇而非恶意模型**：核心保护假设是 Agent 代码不会主动作恶。对恶意共谋攻击（如两端恶意 Agent 篡改中间 Agent 可见的明文 caveat 历史）只提供了启发式缓解，没有实现验证；若改用服务网格层或第三方 caveat 则带来额外基础设施和往返开销。
- **威胁模型系统性有限**：只关注过度授权与权限逃逸，没有深入覆盖推理侧攻击（如提示注入对语义检查的对抗、令牌在应用层被截获重放等）。
- **实验覆盖仍有限**：首个端到端原型规模小（每次任务约 18 次 LLM 调用），对更大规模多跳、分支并发场景缺乏真实网络测试；baseline Basic Agent 仅在较小 ASTRA 上实现，对 XLAM 直接报“上下文超限”，未尝试使用更长上下文的模型或分块检索方案；对手工构造的恶意 Agent 场景没有量化评估。
- **与 JWT 生态兼容成本**：现实中大量服务用 JWT/非对称验签，接受 Macaroon 需要代理转换层；虽然论文给了方案，但这限制了直接应用面。基于对称 HMAC 的 Macaroon 也缺乏公开可验证性，跨组织审计更困难。

## 总评

CAPMAS 是一个思路清晰、工程味道浓厚的多智能体授权架构：它把“最小权限”拆成“语义上界”和“委托衰减”两步，前者由对比学习在 IAM 端离线完成，后者由 Macaroon 在 Agent 间本地完成，从而兼顾安全、延迟和扩展性。其性能结论在自建微基准与 ASTRA/XLAM 数据集上具备较强说服力，代码公开增强了可复现性；但实验规模、对抗性威胁覆盖和真实企业级部署验证仍有明显提升空间。
