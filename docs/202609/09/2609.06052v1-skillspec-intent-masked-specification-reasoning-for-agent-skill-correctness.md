## 摘要
自主智能体系统越来越依赖于可复用的技能抽象来整合经验知识和领域专业知识。这些工件通常将自由形式的指令与异构资源捆绑在一起。然而，确保其正确性仍然具有挑战性。它们的故障模式超越了常规代码缺陷，延伸到微妙的语义不一致，如意图冲突，这些冲突表现为由底层模型掩盖的静默故障。此外，技能正确性必须基于预期的任务边界和泛化性。我们提出了SkillSpec，一个Hoare风格的框架，将技能正确性表述为一个规范推理问题。它将异构技能库转换为统一的图表示，对齐描述、指令和代码工件。对于每个节点，SkillSpec从周围声明的意图中推导出ExpectSpec，并在部分披露的意图下从编码行为中推断出FactSpecs。意图掩码调节对整体、谱系、邻域和局部视图的访问，以平衡过多上下文引入的偏差与不足上下文导致的无根据推断。SkillSpec共同推理这些视图以标记候选缺陷，并在隔离的沙箱中自动验证它们。在来自SkillsBench和广泛下载的存储库的515个真实世界技能上，SkillSpec识别了239个技能中的763个人工确认的缺陷，实现了61.2%的精确度。跨多个模型族的节点级分析表明，规范推理对代码节点始终可靠，而纯文本节点仍然是主要瓶颈。大多数缺陷出现在声明意图与实现之间的边界，表明显式规范为真实世界智能体生态系统中的技能质量保证提供了实用基础。

## Abstract
Autonomous agent systems increasingly depend on reusable skill abstractions for consolidating experiential knowledge and domain expertise. These artifacts typically bundle free-form instructions with heterogeneous resources. However, ensuring their correctness remains challenging. Their failure modes transcend conventional code defects to subtle semantic inconsistencies such as intent conflicts, which manifest as silent failures masked by the underlying model. Moreover, skill correctness must be grounded in intended task boundaries and generalizability. We propose SkillSpec, a Hoare-style framework that formulates skill correctness as a specification reasoning problem. It transforms a heterogeneous skill repository into a unified graph representation that aligns descriptions, instructions and code artifacts. For each node, SkillSpec derives an ExpectSpec from the surrounding declared intent, and infers FactSpecs from encoded behavior under partially disclosed intent. An intent mask regulates access to holistic, lineage, neighborhood, and local views to balance the bias introduced by excessive context against unsupported inference caused by insufficient context. SkillSpec jointly reasons over these views to flag candidate defects, and automatically validates them in an isolated sandbox. On 515 real-world skills from SkillsBench and widely downloaded repositories, SkillSpec identified 763 manually confirmed defects across 239 skills, achieving 61.2% precision. The node-level analysis across multiple model families shows that specification reasoning is consistently reliable for code nodes, whereas plain-text nodes remain a major bottleneck. Most defects arise at the boundaries between declared intent and implementation, demonstrating that explicit specifications provide a practical foundation for skill quality assurance in real-world agent ecosystems.

- 整体含义：该论文将“技能正确性”重新定义为**规范一致性（specification consistency）问题**，为智能体软件生态引入了类似传统程序验证中的 Hoare 风格推理框架，试图将质量保证从依赖人工审查或表面功能测试推进到自动化、可解释、可验证的层面。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想

- 将技能正确性建模为 Hoare 风格规范推理问题，形式类似于 `{P} C {Q}`：
  - `P` = 前置条件（precondition）
  - `C` = 工作流或代码单元的行为
  - `Q` = 后置条件（postcondition）
- 对每个行为单元，推导两类文本化规范：
  - **ExpectSpec**：由周围“已声明意图”（declared intent）推导的预期行为规范；
  - **FactSpec**：由“实际编码行为”在部分披露意图条件下推导的事实行为规范。
- 通过比较二者的一致性来识别缺陷：若 FactSpec 强化了前置条件、弱化了后置保证、或引入了超出声明范围的副作用，即构成潜在缺陷。

### 2.2 统一图表示（解决异构工件问题，即挑战 C1）

- 将整个技能仓库转换为**统一图表示**，包含两个子图：
  - **工作流 DAG**：由 LLM 从 SKILL.md 中重建，节点分为结构单元（root、stage、context）和操作单元（plain、inline_code、ref_code）；
  - **代码图（code graph）**：将 Python、JavaScript/TypeScript、Shell 等脚本解析为语言无关的中间表示（IR），构造函数级调用图，支持精确解析而非 grep 式启发。
- **双向绑定**：将工作流节点（尤其 ref_code/inline_code 单元）与代码图中的函数/文件入口关联，使“意图→实现”可以正向追踪，“代码发现→工作流归因”可以逆向回溯。

### 2.3 意图掩码（intent mask，解决意图披露粒度问题，即挑战 C2）

- 设计一个“意图掩码”投影算子，控制规范提取过程中周围声明意图的可见性。
- 定义四种可见性层级：
  - **Self**：仅目标节点自身；
  - **Neighbors**：目标节点所在阶段内的同级单元与协调上下文；
  - **Lineage**：沿任务层级传播至目标节点的上游约束；
  - **Holistic**：全局目标与整体约束。
- 每个 FactSpec 视图都包含 Self 层，并附加一部分高层上下文；ExpectSpec 则使用 FULL 视图，但**屏蔽目标节点自身内容和所有实现内容**，仅基于外围意图推导。
- 这种多视图设计用于平衡两个偏差：上下文过多导致“事实提取被预期行为污染”；上下文过少则导致“无根据的行为边界推断”。

### 2.4 多视图规范推理

- 对每个合格节点（工作流中的操作节点、代码图中可绑定且超过 8 行的函数定义），推导一个 ExpectSpec 和多个不同意图可见度下的 FactSpec；
- 将意图视为“oracle”，逐步检查 FactSpec 是否违反 Hoare 式精化契约——前置条件变强、后置条件变弱、存在未声明效果等；
- 对候选缺陷进行可达性、可观测性和原始上下文证据链筛查，过滤外部环境因素导致的偏差；
- 每个节点最多报告一个缺陷，附加证据链以支持定位与解释。

### 2.5 沙箱验证

- 对候选缺陷做自动化验证，不是在**真实环境**中，而是在隔离的 OpenCode 沙箱内执行：
  - 按技能复用 warm container，每个候选使用全新 workspace 与 agent context；
  - 代码级缺陷：构造最小探测/测试用例，执行原始仓库逻辑复现；
  - 工作流级缺陷：根据原始技能说明构造场景与触发指令，检查相关说明是否沿技能加载链可达；
  - 输出四种判定之一：validated / refuted / skipped / failed。

## 6. 主要结论与发现

- **技能缺陷普遍存在**：515 个技能中 239 个（46.4%）含有至少一个确认缺陷，共 763 个；缺陷呈**显著长尾分布**——30 个技能集中了 41.7% 的缺陷。
- **精确率存在明显的工件类型差异**：代码节点确认精确率 67.1%，而工作流（文本）缺陷仅为 55.4%，因为代码有确定性 oracle，纯文本说明则依赖更高程度的语义解释。
- **缺陷集中于“意图—实现”的边界**：74.0% 的工作流缺陷属于需求制定/约束传播层问题；91.6% 的代码缺陷则是实现偏离既有意图，显示技能正确的关键是生命周期级的意图保真。
- **多视图联合推理优于任何单视图**：确认 261 个缺陷（48.2% 确认率），优于 Self（42.9%）、Lineage（45.8%）、Neighbors（43.2%）、Holistic（44.1%）；单视图结果并集仅覆盖多视图结果的 97.7%，说明跨视图推理可以发现单视图遗漏的缺陷。
- **跨模型族稳定性较好**：所有后端模型均确认 211–303 个缺陷技能；Qwen3.8-27B 虽更保守但在验证率上不落下风，说明方法不依赖最强模型；不过文本解释瓶颈在所有后端上均存在。
- 运行时 LLM 可补偿部分偏差（约 19.8% 工作流误报来自 agent 的运行时修复），说明技能正确性是端到端性质，需要整链评估而非孤立测试。

## 7. 优点

- **问题定位新颖且准确**：将技能正确性从“代码缺陷检测”重构为“声明意图与实现行为的规范一致性问题”，切中了智能体技能静默失败的核心。
- **面向异构工件的统一图表示**：把 Markdown 文档、多语言脚本和配置文件统一到同一结构，支持意图—实现双向追踪，比单纯 grep 或浅层静态检查更系统。
- **意图掩码设计精巧**：通过四层可见度实现“期望规范”与“事实规范”的分层提取，在过度上下文导致的偏差和不足上下文导致的臆测之间取得平衡。
- **静态推理与动态验证结合**：规范推理生成缺陷假设，沙箱验证提供可复现的运行证据——这种“静态筛、动态验”的闭环在智能体技能质量保障中具有开创性。
- **可解释性与证据链机制**：每个缺陷附带来源、推理路径、触发指令和运行日志，便于定位与人工复核。
- **实验覆盖现实生态**：既有基准技能（SkillsBench）又有真实下载技能（SkillsTop），规模合适，且对多个模型后端做了鲁棒性对比。
- **审慎的指标设计**：将“人工复核不确定”单独归类，不将模糊边界强行计作正/误，提高结论的合理性。
- 数据集与代码开源，具备良好的可复现性基础。

## 8. 不足与局限

- **无召回率**：因真实缺陷全集不可穷举，只能估计整体精确率（约 61.2%），无法评估漏检程度。
- **文本类技能的验证瓶颈**：纯文本节点仍是最大弱点，在 SkillsTop-Text 上确认率与验证率最低；自然语言推论的歧义性使文本缺陷不可避免包含大量人工误报与漏报。
- **构造效度上的固有模糊**：技能意图只评估了 SKILL.md 中显式声明的意图，无法判断是否完整反映了作者的真实意图或用户期待，故存在不可消除的盲区。
- **内部效度风险**：LLM 作为推理和判断主体本身有不确定性；工作流图分解没有唯一解；沙箱验证受 API 凭据、依赖、GPU 等外部条件制约；另有验证模型偏好等潜在偏差。
- **外部效度限制**：仅覆盖 515 个技能，偏向上可执行、可验证（SkillsBench）和高下载量（SkillsTop）的社区技能，未必推广到生态中的长尾技能；当前仅支持 Python、JS/TS 和 Shell。
- **成本偏高**：主实验使用前沿 API 模型，端到端平均 2.585 美元/技能，规范推理占比 74.1%，对大仓库规模化审计成本显著。
- **召回率评估缺失之外还存在过滤风险**：将“短于 8 行”的定义直接剪枝，虽然降低了成本，但可能漏过存在于短但语义关键定义中的缺陷。
- **方法依赖模型能力**：对于较为基础的本地模型（Qwen3.8-27B）验证率虽然尚可，但候选覆盖面下降明显，说明在弱模型条件下方法可能“求稳但漏检”。
