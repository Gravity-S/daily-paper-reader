## 摘要
现实世界中备受瞩目的 AI 智能体外壳通常依赖供应商专有或不透明的设计来进行上下文组装，导致组装上下文的来源和底层逻辑难以理解，由此产生的安全风险在很大程度上未被探索。在本文中，我们首次对真实 AI 智能体外壳中的上下文组装设计进行了系统分析。我们研究并揭示了智能体外壳如何设计用于从不同来源收集和组装上下文，并识别出由这些设计引发的一系列实际攻击向量。我们的分析揭示了真实外壳上下文组装中的两类新颖攻击：(1) 消息角色上下文特权提升（M-CPE），当源自低特权上下文的攻击者控制内容被合并到更高特权的消息角色时发生。(2) 跨范围上下文特权提升（X-CPE），当攻击者控制的内容持续存在于其引入上下文之外时发生。我们对针对 12 个真实智能体外壳（包括 Claude Code 和 Codex）的 CPE 攻击进行了系统性安全分析。由此产生的后果包括完全智能体入侵、远程代码执行、拒绝服务以及被操纵的工具或技能调用等。

## Abstract
Real-world, high-profile AI agent harnesses often rely on vendor-proprietary or opaque designs for context assembly, leaving the sources and underlying logic of assembled context poorly understood and the resulting security risks largely unexplored. In this paper, we present the first systematic analysis of context assembly designs in real-world AI agent harnesses. We study and uncover how an agent harness is designed to collect and assemble context from diverse sources, and identify a set of practical attack vectors arising from these designs. Our analysis brings to light two novel categories of attacks in the context assembly of real-world harnesses: (1) MessageRole Context Privilege Escalation (M-CPE), which occurs when attacker-controlled content originating from a low-privileged context is incorporated into a higher-privileged message role. (2) Cross-Scope Context Privilege Escalation (X-CPE), which occurs when attacker-controlled content persists beyond the context in which it was introduced. We performed a systemic security analysis of the CPE attacks against 12 real-world agent harnesses, including Claude Code and Codex. The resulting consequences include full agent compromise, remote code execution, denial of service, and manipulated tool or skill invocations, etc.

- **关键洞察**：LLM 提供商（如 OpenAI、Anthropic、Google）已设计了消息角色特权层级（system > developer > user > assistant > tool），用于约束低信任内容（如工具输出）的影响。然而，智能体外壳在组装上下文时存在设计层面的缺陷，使攻击者控制的内容能够从低特权上下文源**传播并提升**到高特权上下文源，打破角色和范围的信任边界。
- **整体意义**：本文是首次对真实智能体外壳的上下文组装机制进行系统性安全分析的研究，揭示了间接提示注入之外更根本的结构性攻击类别，开辟了智能体外壳安全研究的新方向。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 背景模型与核心假设

- **基础模型**：智能体执行每轮迭代时，基于当前上下文向 LLM 发请求，选择调用工具并执行。上下文会累积模型回复与工具输出。
- **增强模型（核心扩展）**：论文提出，上下文不是扁平的累积历史，而是由多个带不同特权角色和生命周期/作用范围的子组件组成：
  - 每个上下文源定义为三元组：**Sₖ = (sₖ, ρₖ, σₖ)**
  - sₖ 为内容，ρₖ 为角色（r0 最高到 r4 最低），σₖ 为作用范围（σ_user > σ_project > σ_session），即持久性层级。

### 2.2 两类新型攻击定义

- **消息角色上下文特权提升（M-CPE）**：攻击者控制、低特权源的内容被传播到更高特权消息角色的源中（满足 ρ_j < ρ_k 且内容相似）。
- **跨范围上下文特权提升（X-CPE）**：攻击者控制的内容从临时、局部作用范围（如会话级）传播到更持久、更广泛作用范围的源中（满足 σ_j < σ_k 且内容相似）。
- 两种攻击可同时发生。

### 2.3 攻击向量分类体系

- 构建了 **16 个新型攻击向量的分类体系**，涵盖三大类别：
  - **异构上下文来源**（A 类）：特定智能体的记忆文件、记忆搜索目录、运行时记忆加载、特有技能搜索路径、运行时技能发现、环境信息加载（目录树/Git 元数据）、递归记忆导入。
  - **上下文标记语法**（B 类）：标记标签注入（伪造闭合标签逃逸）、标记标签解释（利用模型输出标签操纵工具调用）。
  - **上下文组装逻辑**（C 类）：记忆文件加载优先级、技能加载优先级、技能重复消解策略、智能体自修改配置、上下文源内联动作、上下文刷新机制、未沙箱化内置工具。

### 2.4 自动分析工具 CORA

- 设计并实现 LLM 辅助的自动化分析管道 **CORA（Context Risk Analyzer）**，分四个阶段：
  - **阶段一：静态分析**——分析源代码结构，识别初始化边界、LLM 端点接口、候选上下文源码及其角色与作用范围，以及使用的上下文标记。
  - **阶段二：构建与插桩**——对目标智能体代码插桩，挂钩发送给远程 LLM 的请求函数，记录请求参数。
  - **阶段三：来源验证**——为每个候选来源生成环境规范（EnvSpec），在隔离容器中构造含随机金丝雀值的环境，执行智能体并对比捕获请求，验证来源的实际可达性、角色与作用范围（通过不同路径/目录的差分启动测试区分 user/project/session 范围）。
  - **阶段四：CPE 路径验证**——枚举低特权源到高特权源的候选路径，执行两轮验证（第一轮验证注入内容能否从低源传播至高源，清理后第二轮验证高源负载是否产生预期行为）。

## 6. 论文的主要结论与发现

- **CPE 普遍存在**：12 个真实智能体外壳全部存在 M-CPE 和/或 X-CPE 攻击面，证明该问题不是个别厂商的缺陷，而是智能体外壳上下文组装设计中的**系统性结构性问题**。
- **角色分配不透明且不一致**：283 个已验证来源中 64.9% 以最高的 r0（系统）角色加载；同一类型的来源（如项目记忆文件）在不同智能体中被分配不同角色，且各智能体对同类来源的角色分配差异明显，用户难以察觉。
- **上下文组装逻辑存在多类可利用缺陷**：包括记忆递归发现、技能动态加载、加载优先级漏洞、配置自修改、未沙箱化的机制等。
- **攻击后果严重**：成功实现完全智能体失陷、远程代码执行（RCE）、拒绝服务、工具/技能调用被操纵、持久性跨项目记忆注入与配置篡改等后果。
- **有效缓解方向**：建议厂商发布“上下文清单”（类比软件物料清单 SBOM），公开披露上下文来源、角色、作用范围与组装逻辑，提高透明度，缩小攻击面；部分厂商（如 OpenAI Codex、Gemini CLI、Cline）已针对报告的问题发布修复版本。

## 7. 优点

- **首次系统性研究**：首次将“智能体外壳上下文组装”作为独立安全研究对象，提出了形式化建模方法和通用的攻击分类学，为该方向后续研究奠定了概念基础。
- **自动化安全分析工具 C ORA**：将 LLM 的语义理解能力与确定性验证机制分离设计——用 LLM 工人做识别与推理，用金丝雀值匹配、差分启动、隔离容器做事实验证，避免了纯 LLM 幻觉导致的误报，也弥补了纯静态规则无法跨语言泛化的不足。识别精度高（精确率 ≥ 97%）。
- **严格闭环的实验方法论**：区分“来源可达性/可加载性”与“模型是否遵循指令”两个层次，并报告候选路径的下界效果，实验结果具有较高可信度。
- **现实可操作性强**：攻击场景均以实际高频场景为背景（PR 审查、网页模板下载、Issue 分类、代码审查、IDE 协作），具备清晰现实映射；全部 12 个智能体均实现了端到端 PoC 验证。
- **覆盖面广且模型多样性高**：跨 12 个独立代码库、3 种以上实现语言和多个主流 LLM 后端进行验证，结论说服力较强。
- **负责任披露**：与所有受影响厂商沟通，部分厂商已发布缓解版本。

## 8. 不足与局限

- **算力与实验细节披露不足**：论文未说明所用 GPU/服务器资源、API 调用次数、单次实验耗时等复现所需的基础设施信息，可复现性受限。
- **对“行为验证”结果需谨慎解读**：CORA 的后半部分（是否产生预期行为）取决于模型遵循指令能力；同一路径在不同模型上差异显著（如 OpenClaw 在 GPT-5.4-mini 下 45% 加载，在 GPT-5.5 下仅 48% 加载且成功率波动），这类结果具有时效性（模型更新后可能变化）。
- **简单注入模板的下界局限**：自动注入载荷为简单模板，真实攻击者可用多向量组合（论文端到端案例已验证这一点）显著提升成功率。文中验证数量和成功率并不等同于现实恶意复杂攻击的最坏情况。
- **人工基准范围有偏**：仅对 Codex 和 Gemini CLI 建立人工 ground truth（40 人-小时），其余 10 个框架未进行同等深度人工交叉验证，精确率/召回率评估的外部效度有限。
- **Python 版 Claude Code 的获取途径特殊**：通过官方 npm 的 source map 获取源码用于评估，虽采用受控环境与不扩散研究方式，但论文未将 Claude Code 结果纳入 CORA 工具发布中的可复用复现包。
- **某些攻击场景的随机性未量化**：例如 Claude Code RCE 场景依赖 LLM“主动选择”使用恶意技能，若模型未选择该技能则攻击失败，论文未报告这类端到端场景中各模型的多次尝试成功率或失败率，缺乏充分的统计置信度。
- **时间标记为未来日期**（2026 年 9 月），文中所涉框架版本与模型（如 GPT-5.5、Claude Opus 4.6 等）均为较新状态，底层模型安全更新后某些攻击路径可能自然失效，结论的长期适用性有待持续跟进验证。
