## 摘要
当模型内部的置信度信号（如token对数概率）不可用时，可靠的Web智能体监控变得困难。在本工作中，我们研究利用可观察的轨迹信号对Web智能体进行前缀级风险预测：给定一个不断演化的前缀，估计当前执行是否仍在正轨，抑或趋于失败。我们推导出两种可观察的轨迹表示：宏观特征总结了跨步骤的智能体-环境交互行为及反馈；微观特征则通过重复的黑盒查询来衡量意图、动作和预期状态变化之间的一致性。我们没有沿用最终结果标签，而是将观察到的延续中未被纠正且与最终失败相关的第一个关键错误标记为关键步骤边界，并将失败轨迹的有效早期前缀保留为“在轨”样本。在WebArena-Lite和Online Mind2Web这两个Web智能体基准上，使用五种开源与闭源骨干模型，可观察轨迹信号与基于内部信号的基线表现相当。由此得到的预测器还支持在固定误截断预算下的早期干预，并能跨保留网站类别进行迁移。这些发现表明，可观察的轨迹信号支持有价值的风险预测能力。

## Abstract
Reliable web-agent monitoring is difficult when model-internal uncertainty signals such as token logits are unavailable. In this work, we study prefix-level risk prediction for web agents using observable trajectory signals: given an evolving prefix, estimate whether the current execution remains on track or is tending toward failure. We derive two observable trajectory representations: Macro features summarize cross-step agent--environment behavior and feedback, while Micro features measure the consistency of intention, action, and anticipated state change through repeated black-box queries. Instead of inheriting the final result label, we label the first critical error that remains uncorrected in the observed continuation and is associated with final failure as a key-step boundary, preserving valid early prefixes of failed trajectories as on track. Across WebArena-Lite and Online Mind2Web web agent benchmarks with five open- and closed-source backbones, observable trajectory signals are competitive with internal-signal baselines. The resulting predictors also support early intervention under fixed false-cut budgets and transfer across held-out website categories. These findings show that observable trajectory signals support valuable risk prediction abilities.

### 1. 核心问题与整体含义（研究动机与背景）

Web智能体通过与环境的多步交互来完成任务，但在长序列交互中极易出错。当智能体已走向必然失败的轨迹时，继续运行只会浪费大量时间与token。然而，传统做法通常仅在任务终结时才判断成败，错过了中途干预与纠正的机会。因此，本文研究的核心问题是：

> **在前缀级（prefix-level）条件下，能否仅凭可观察的轨迹信号，实时预测当前执行是否仍在正轨或已趋于失败？**

该问题面临两大挑战：

- **输入可观测性挑战**：现有不确定性量化方法多依赖token logits、隐藏状态等模型内部信号，而闭源模型不会暴露这些信息。黑盒方法虽不依赖内部信号，但多聚焦于单步输出评估，难以覆盖多步演化轨迹。部署时，监控方可观察到的只有智能体输出的文本、执行的动作和环境反馈——这些信息是否足以支撑前缀级监控，仍是开放问题。
- **前缀监督挑战**：任务结果只提供稀疏的终结标签。如果简单地将失败标签传播到失败轨迹的每一个前缀，在时间上是不准确的：失败的轨迹往往始于正确的动作，其早期行为与成功轨迹并无二致。若在失败分叉前强行标记为失败，会造成监督信号冲突。

### 2. 方法论

#### 2.1 总体思路

论文将问题拆解为两个独立子问题分别求解：
- **输入信号层面**：设计两类互补的可观察轨迹信号——宏观特征（Macro）与微观特征（Micro）；
- **监督标签层面**：标注“关键失败步（key failure step）”，仅将该步之后的前缀标记为趋于失败，保留早期有效前缀的“在轨”标签。

#### 2.2 问题形式化

设 `τ≤k` 表示截至第k步的轨迹前缀，`Fi ∈ {0,1}` 表示轨迹 i 的最终成败。定义关键失败步 `k⋆i` 为**第一个在后续观察中未被纠正且与最终失败相关的关键错误**。则前缀标签为：

```
y_{i,k} = 1 当且仅当 F_i = 1 且 k ≥ k⋆i
```

即：失败轨迹中从关键步开始的所有前缀标记为“趋于失败”，其余前缀及所有成功轨迹的前缀标记为“在轨”。预测目标是条件概率：

```
r_{i,k} = P( y_{i,k} = 1 | τ_{i,≤k} )
```

#### 2.3 宏观特征（Macro Features）：从已实现轨迹中提取行为模式

宏观特征直接从真实交互前缀中计算，**无需额外查询模型**，共31维，包括：

- **前缀位置**：当前步索引；
- **动作重复与循环结构**：单动作循环数、双动作交替循环数、尾部循环类型、不同动作数、当前动作重复次数、最大动作重复次数、动作重复率、距离最新动作的步数等；
- **执行与落地错误**：累积落地错误数、解析错误数、尾随错误串长度、当前步是否错误、连续错误串计数等；
- **动作构成与目标多样性**：点击/输入/滚动/返回的累积次数、指向的不同元素数量、动作类型熵、累计输入字符数等；
- **推理文本诊断信号**：推理文本是否自述动作无效、是否处于错误情境/页面、是否遇到环境错误等；
- **推理长度统计**：当前步推理文本长度、前缀累积均值与最大值。

#### 2.4 微观特征（Micro Features）：从重复查询中测量决策一致性

微观特征通过在当前上下文中重复查询智能体（N=10次）来测量其**意图、动作、预期状态变化**三个层面的一致性。每次采样解析为：意图（Intention）、可执行动作（Action）、预期状态变化（State Change），再通过语义嵌入与层次聚类将文本归入离散语义类别。得到经验分布后提取6个指标：

1. 意图熵 H(S|X)；
2. 状态变化熵 H(C|X)；
3. 落地熵（动作条件于意图）H(T|S,X)；
4. 条件状态变化熵 H(C|T,S,X)；
5. 意图对动作的信息贡献 H(T|X) − H(T|S,X)；
6. 残差动作不确定性 H(T|S,C,X)。

每个指标在前缀上用均值、最大值、当前值三种聚合方式，共生成18维微观特征。

#### 2.5 前缀风险预测器

预测器使用 ℓ2 正则化的逻辑回归：

```
fθ(z) = σ(wᵀz + b)
```

输出值越高表示越趋于失败。训练采用正则化二元交叉熵损失。

#### 2.6 关键步标注流程

采用LLM作为裁判（Gemini-3.5-Flash）+人工审阅蒸馏的代码手册，两阶段定位关键步：
1. **逐遍违规分析**：前向扫描轨迹，对每步判断是否符合任务预期，记录违规、错误描述及初步恢复判断；
2. **按时间顺序根因判定**：从最早违规开始独立复核其是否在后继动作中得到纠正，跳过已纠正错误，选择第一个未纠正且与最终失败相关的错误作为关键失败步。

该裁判还按AgentErrorTaxonomy分类法分配失败原因（记忆、反思、规划、动作或系统五类）。

### 6. 主要结论与发现

1. **可观察轨迹信号有效**：在Mind2Web全部15项组合和WebArena-Lite 9/15项组合中达到或超过最强的内部信号基线；Stacked L2在所有10项设置中的E-AURC与AUROC均被超越，说明优势不来自监督拟合本身。
2. **宏观特征更强、微观特征有条件的互补性**：Macro是更稳定、更强的单信号；Micro虽整体落后于Macro，但在若干骨干-基准对上超过校准基线。加入Micro一致性地改善Mind2Web上全部5种骨干的3项指标，但在WebArena-Lite上无一致增益。
3. **关键步监督显著减少误切**：在γ=0.5时，关键步监督将成功轨迹的误切断率从87.3%~93.0%降至27.6%~28.6%，验证了时间对齐监督的价值。
4. **支持早期干预**：在8个运行点上，可观察信号配置在7个上超过HTC-Full；在20% FCR下两基准上分别达到44.3%和44.5%的失败检测率。
5. **跨类别迁移良好**：大小匹配的跨类别训练的AUROC/E-AURC/Brier与域内训练差距仅−0.0005/−0.0039/+0.0030，远小于类别间差异；M&M在5个类别中的4个上为最优。
6. **信号来源互补**：HTC-Full在轨迹早期判别力强，可观察信号在中后期随交互证据积累持续增强（WebArena-Lite晚期Macro AUROC 0.778，Mind2Web晚期M&M AUROC 0.779），表明两类方法可互为补充。

### 7. 方法或实验设计上的亮点

1. **无内部信号假设贴近真实部署**：整套信号提取只依赖智能体输出文本、已执行动作和环境反馈，不触达模型参数、隐藏状态或token概率，对闭源模型同样适用。
2. **双视角信号框架构思清晰**：宏观看“已做了什么”（行为模式与环境反馈），微观测“同样条件下决策的一致性”（意图-动作-状态变化三层解耦），两者形成互补。
3. **关键步监督概念精确**：定位“第一个未被纠正且关联最终失败的关键错误”，既保留失败轨迹的有效早期前缀为在轨样本，又避免将收敛于失败的后期行为误判为正常，解决了粗粒度终态标签造成的时间错配问题。
4. **LLM裁判流程设计严谨**：两阶段定位（前向扫描→自后向前复核）避免了对初步恢复判断的盲信；代码手册人工蒸馏、3次独立运行验证（90.9%标签一致）、与人类标注对照（89.8%一致）等多层质量控制使标注可靠度高。
5. **状态化早停仿真设计精细**：采用按阈值依次切轨迹的状态化策略，失败轨迹仅在关键步后才算“检测成功”，成功轨迹任何提前切都算误切，贴近真实干预场景，比纯排序类评估指标更实用。
6. **对照组设置合理**：Stacked L2使用与本文相同逻辑回归控制监督学习收益，排除了“简单分类器优势”的替代解释。
7. **大模型亦可监督大模型**：用LLM-as-judge做大规模关键步标注，为轨迹级标注自动化提供了可复制的设计范式。

### 8. 不足与局限

1. **框架覆盖单一**：实验仅基于ReAct式智能体框架，对其他架构（如规划-执行分离、多智能体协作、工具调用差异化框架）的适用性未知。
2. **Stacked L2非完全控制**：其表现弱可能既因为特征内容不足，也因为特征维度过低，监督学习收益与特征维度的效应没有被完全分离。
3. **不保证全面占优**：论文坦诚地指出，在若干骨干-基准-指标组合上，内部信号或更简单的基线仍更强（如HTC-Full在Qwen上AUROC达0.858，而M&M仅0.838）。
4. **微观特征成本高**：N=10的重复采样和语义聚类增加推理开销；在WebArena-Lite上增益不显著却要付出额外查询代价，实际部署时需权衡基准类型与采样预算。
5. **关键步依赖完整轨迹标注**：标注需要完整失败轨迹以判断恢复情况——“未被纠正”只能基于观察到的延续，而非客观上不可恢复的状态；理论上存在恢复可能但被误标为关键步的情况。
6. **关键步标签依赖LLM判断**：虽然经过了可靠性验证，但标注仍然主要基于LLM且采用同一个模型族，跨模型族的泛化误差未充分评估。
7. **样本量限制统计效力**：配对分析只有5个骨干（N=5），部分显著性检验只能取到两尾最小p值0.0625，结论更宜视为方向性证据而非强断言。
8. **时间精度有限**：人类与LLM关键步存在±1步偏差（80%以内）的情况，对于极短轨迹（如3~5步）这种偏差可能覆盖较大比例的前缀。
