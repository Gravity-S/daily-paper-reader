## 摘要
已部署的LLM智能体日益依赖持久化、带版本的系统资产，例如路由规则、知识片段、提示指令和可复用技能。故障定位方法可以识别错误在智能体或执行轨迹中的显现位置，但修复需要不同的决策：应更改哪个可编辑系统资产，以及该更改是否预期能改善任务结果？我们通过组件-属性故障归因来研究这一差距，其中诊断针对的是带版本、可寻址的项，而非执行位置。我们提出检测感知归因框架（Detection-Aware Attribution Framework, DAAF），它学习有效属性替换的效果，并将这种干预证据摊销到部署时诊断中。DAAF结合稀疏且含噪的故障信号来判断是否有必要进行干预，从由可执行任务结果评估的受控重放中学习以组件类型为条件的替换效果，并在具有兼容干预响应的请求之间共享监督。在诊断时，DAAF仅使用观察到的执行、注册候选和可用的故障信号；它既不需要反事实重放，也不需要任务奖励，并在证据不足时返回 no_change、一个修复目标或未解决的决策。在留出的 tau^2-bench Telecom 任务上，DAAF 达到 80.72% 的属性 Hit@1，恢复 62.65% 的失败执行，同时将干净任务回退限制在 3.23%，并达到 71.93% 的整体任务成功率。这些结果表明，基于干预的属性归因可以将故障定位与可执行系统修复连接起来。

## Abstract
Deployed LLM agents increasingly rely on persistent, versioned system assets such as routing rules, knowledge segments, prompt instructions, and reusable skills. Failure-localization methods can identify where an error manifests in an agent or execution trace, but repair requires a different decision: which editable system asset should be changed, and is that change expected to improve the task outcome? We study this gap through component-attribute failure attribution, where diagnosis targets versioned, addressable items rather than execution locations. We propose the Detection-Aware Attribution Framework (DAAF), which learns the effects of valid attribute replacements and amortizes this intervention evidence into deployment-time diagnosis. DAAF combines sparse and noisy failure signals to decide whether intervention is warranted, learns component-type-conditioned replacement effects from controlled replays evaluated by executable task outcomes, and shares supervision across requests with compatible intervention responses. At diagnosis time, DAAF uses only the observed execution, registered candidates, and available failure signals; it requires neither counterfactual replay nor task reward and returns no_change, a repair target, or an unresolved decision when evidence is insufficient. On held-out tau^2-bench Telecom tasks, DAAF achieves 80.72% attribute Hit@1, recovers 62.65% of failed executions while limiting clean-task regression to 3.23%, and reaches 71.93% overall task success. These results show that intervention-grounded attribute attribution can connect failure localization to executable system repair.

## 1. 核心问题与研究动机

- **背景**：部署中的 LLM 智能体越来越像"持久化系统"，依赖可版本化、可复用的系统资产，如路由规则、检索知识片段、提示指令、运行时策略和可复用技能。这些资产随数据、策略和依赖变化而演化，故障可能来自跨请求持续存在的系统状态，而非单次输入。
- **现有方法的缺口**：现有故障定位方法（Who&When、TraceElephant、CHIEF、AgentDebug 等）输出的是"智能体身份、执行步索引或模块标签"，即**执行位置**。但修复需要回答另一个问题：**应该修改哪个可编辑的系统资产？该改动是否真能改善任务结果？**
- **关键洞察**：一个检索步骤可能执行正确，但使用了由上游规则选中的过期知识——"哪里出错"与"该改什么"并不对应。可行的修复可能包括替换知识片段、修改选择规则或修订指令，它们作用于不同的持久对象、影响其他复用请求，且效果可能是正向、中性、有害或依赖交互的。
- **研究目标**：提出**组件-属性故障归因（component-attribute failure attribution）**，诊断目标为"带版本、可寻址的项"而非执行位置；归因由"有效替换带来的带符号任务级效果"定义。核心问题转化为：训练阶段收集的干预结果，能否预测新执行是否需要修改、以及哪个已注册编辑最可能有效。
- **三大挑战**：
  - 失败证据不完整：轨迹异常、用户反馈、重复运行分歧的可用性与可靠性因请求而异；
  - 编辑异质且相互交互：知识片段与运行时设置的约束不同，却需用同一任务级结果比较；
  - 修复证据需**选择性**跨请求迁移：两个执行可能触及相同资产却不共享同一失败原因。

## 2. 方法论：DAAF（Detection-Aware Attribution Framework）

### 2.1 核心思想
- 将智能体诊断形式化为**对持久化可编辑系统资产的修复决策**：先判断证据是否支持干预，再预测哪个已注册变更能改善任务结果。
- 训练时可访问可执行环境，因此可以施加替换、重放并用任务结果评估；**诊断时不可用**，只依赖观察到的执行、当前系统注册表与当时可得的失败信号。
- DAAF **不生成替换内容**，只预测"哪个已注册资产应被更改"。

### 2.2 问题设定
- 诊断输入 `z = (q, τ, v, C_v, s, m)`：请求、轨迹、系统版本、可编辑注册表、失败信号向量 `s` 及可用性掩码 `m`。
- **可编辑资产分层**：组件（component）按功能角色分组，属性（attribute）是原子可注册项，具有稳定 ID、组件类型 `t(c)`、源位置、当前版本和一个或多个已验证替换。
- 五类角色：**Node**（路由/迭代控制）、**Harness**（执行钩子/运行时设置）、**Knowledge**（检索证据）、**Prompt**（模型指令）、**Skill**（可复用流程）。
- **干预结果定义**：`R_z(S)` 为对属性集 `S` 施加替换策略 ρ 后、在匹配任务条件下由官方可执行评估器（τ²-bench 的二元任务评估器，非 LLM 裁判）给出的期望结果。

### 2.3 三大技术组件

**（a）MSWSD：多信号弱监督失败检测**
- 使用注册的弱失败信号：轨迹异常、可见用户反馈、匹配重复执行间的分歧。
- 检测器显式表示"不可用"观测，而非把缺失当作 0：
  `p_θ(z) = σ(b + Σ w_i m_i u_i s_i + Σ v_i (1 - m_i))`，其中 `u_i` 为固定可靠性值。
- 遵循 data programming / Snorkel 思路：噪声种子标注 + 标注函数被组合为带置信度的软失败目标 `ỹ_z, c_z`；标签模型拟合与目标生成使用**不同训练折**（交叉拟合）。
- 损失为置信度加权的 BCE（种子集 + 其余交互集，后者权重 β）；开发集仅用于校准与阈值选择。
- 信号细节：行为分歧 `s1` 为多轮运行的答案/动作序列差异均值（只有一轮则视为不可用）；轨迹异常 `s2 = 0.5r_err + 0.3r_rep + 0.2e_empty`；用户反馈按固定映射表赋分与可靠性（如显式负结果 1.00/0.75，放弃 0.50/0.30）。

**（b）CTCA：干预监督的组件类型条件归因**
- **边际干预效应（Shapley 风格）**：对候选集 `C(z)` 均匀采样置换 π，`P_π(c)` 为 c 之前的属性集合，目标为
  `φ_c^ρ(z) = E_π [ R_z(P_π(c) ∪ {c}) − R_z(P_π(c)) ]`。
- 正值表示该替换倾向于改善任务结果，负值表示有害；在**组合替换情境**中评估可暴露孤立测试下不存在的效果。
- **无需重放的预测**：共享编码器表示请求、相关执行上下文、当前属性内容与替换描述；按组件类型分设头，输出带符号量 `a_ψ,c(z) ∈ [-1, 1]` 逼近 `φ_c^ρ(z)`。
- 训练损失为对有效重放目标的均方误差；**不可用的比较被省略，而非视为 0**。
- 表示细节：SHA-256 令牌哈希 + NFKC 归一化 + 小写，映射到 64 维带符号桶并 L2 归一化；每候选拼接 64 维请求块 + 64 维可见执行块 + 64 维属性/替换块 + 8 个数值特征 + 5 类类型指示，共 205 维；32 单元共享隐层接 5 个类型特定头；Telecom 归因模型仅 **6,757 个可训练参数**。

**（c）联合学习与修复决策**
- **跨请求一致性**：仅在同系统版本、同候选集、同替换策略、同评估器的案例间构造训练邻域：
  `W_ij = κ(q_i,q_j)·ω_iω_j·exp(−‖φ̂_i^MC − φ̂_j^MC‖² / 2ℓ²)`，其中 κ 为请求兼容度、ℓ 控制对干预响应差异的敏感度。
- **路由与弃权**：将正预测效果转为路由权重 `r_c = [a_ψ,c]_+ / (ε₀ + Σ_j [a_ψ,j]_+)`，未解决质量 `r_⊥ = ε₀ / (ε₀ + Σ_j [a_ψ,j]_+)`，`f_c = p_θ r_c`。
- 联合目标：`L = L_det + λL_attr + μL_cons`（一致性项为邻域内输出分布的加权 L2 差异，边依赖观测到的干预响应，而非仅文本相似）。
- **诊断规则（最多返回一个注册编辑）**：
  - `p_θ(z) < τ_f` → `no_change`；
  - `p_θ(z) ≥ τ_f` 且 `max_c r_c ≤ r_⊥` → `⊥`（未解决）；
  - 否则 → `repair(c*)`，`c* = arg max_{c: a_ψ,c>0} r_c`。
- 组合修复在正文中单独研究，不属于主单编辑诊断规则。
- **理论性质（附录 D）**：命题 1 给出重复信号聚合的 Hoeffding 型集中界 `Pr(|p_n − p_∞| ≥ t) ≤ 2exp(−nt²/(32‖α‖₁²))`；命题 2 给出有限预算归因估计界 `‖φ̂^MC − φ^ρ‖_∞ ≤ √(2log(2d/δ)/M)`，随 M 以 O(M^{-1/2}) 下降、对候选数只呈对数依赖；另有交替块梯度下降的收敛性分析。

## 3. 实验设计

### 3.1 数据集 / 场景与 Benchmark
- **主 benchmark：τ²-bench Telecom**（Barres et al., 2025）——可执行客服环境，含官方任务评估器与可修改、可重执行的持久系统资产。这是主要评测对象。
- 留出评测集：全部 **114 个官方 Telecom 默认任务**，在冻结配置下含 **83 个自然失败**与 **31 个自然成功**。
- **辅助 benchmark：Who&When**（Zhang et al., 2025）——含原生 agent 级/step 级失败标签的多智能体轨迹（126 条 Algorithm、58 条 Handcrafted），**不暴露可编辑系统资产**，故仅用于轨迹级定位的兼容性检查。
- 训练/开发/评测划分按**规范基础任务身份**隔离，避免同任务变体泄漏。

### 3.2 训练监督规模
- MSWSD：**476 条轨迹 / 395 个任务**（327 个失败导向种子、149 个成功导向种子）。
- CTCA：**220 个训练任务、5 个注册属性**；2 个采样替换顺序 × 2 次匹配重复 → 每任务 24 次有效重放 → **5,280 次受控执行、1,100 个带符号边际效应目标**。
- 独立开发集：**50 个任务**（25 失败 / 25 成功），仅用于模型选择与校准。

### 3.3 对比方法
- **No-edit Rerun**：不改动系统直接重跑（下界参照）。
- **Component-aware LLM**：接收完整执行轨迹与候选描述，直接选择编辑。
- **LLM + MSWSD**：加入学到的失败检测器，但保留 LLM 的编辑提议。
- **LLM + CTCA**：保留 LLM 提议接口，仅加 CTCA 作为部分组件。
- **Uniform candidate choice**：在已验证候选集上均匀选择（期望 Hit@1 = 37.35%）。
- **Detection-only control**：保持 DAAF 修复管线但去掉替换效应监督（类型头冻结在初始化）。
- **AgentDebugX**：Who&When 上的轨迹级定位对照。

### 3.4 评测指标
- **Attribute Hit@1**（top-1 编辑是否属于独立验证的修复集）、**Joint F1**（同时计入不必要干预）、**Failure Recovery**（自然失败经修复后成功比例）、**Clean Regression**（自然成功变失败比例）、**Overall Success**（114 任务总体成功率）。
- 修复结果用 **3 次匹配执行重复**（任务-重复种子跨方法共享），报告均值 ± 标准差；置信区间用 10,000 次按基础任务的成对 bootstrap（种子 20260926）。
- 修复标签**独立于方法预测**验证：三个匹配种子上对比未改动配置，需一致的失败→成功证据且无相反转变，边界情形经"预测盲"裁定流程处理；这些标签仅用于评测，不参与拟合。

  - **替换策略 ρ 的敏感性未充分展开**：边际效应依赖替换集合与置换采样（每任务仅 2 个采样替换顺序 × 2 次重复），附录的交互分析虽统计了 4,400 步重放，但对"替换顺序/组合是否改变排序结论"的稳健性报告有限。
  - **缺少人类/专家一致性校验**：修复标签由"预测盲"裁定流程独立验证，但未报告标注者间一致性（如 Cohen's κ）或与人工专家判断的对比，归因"正确性"的语义效度仍依赖自动化评估器。
  - **消融覆盖不全**：未见到对 MSWSD 各弱信号（s1/s2/用户反馈）的逐项留一消融、对可靠性值 `u_i` 设定的敏感性分析，也未报告对阈值 `τ_f`、弃权温度 `ε₀`、一致性权重 `λ/μ`、邻域带宽 `ℓ` 的系统性超参扫描。
  - **统计口径**：3 次匹配重复 + 10,000 次 bootstrap 的设计合理，但重复次数偏少，且在 114 任务、83 个自然失败的规模下，Failure Recovery 等比例的置信区间可能较宽，论文主表是否给出效应量（而非仅显著性）值得关注。

**总体判断**：实验在"控制变量"的意义上是扎实的——尤其是 Detection-only 与 LLM+CTCA/LLM+MSWSD 的拆解式对照，能较好支撑"检测与归因互补、且归因监督不可省"的核心主张；但在"外部效度"上偏薄，单一小候选集 benchmark 使其结论更像一次严格的概念验证（proof-of-concept），而非已充分证明可推广的诊断范式。

## 6. 主要结论与贡献

- **问题重述的贡献**：把 LLM 智能体故障诊断从"执行位置定位"（agent/step/module）重新表述为"对带版本可寻址系统资产的修复决策"，并给出以**带符号任务级干预效应**定义的归因目标 `φ_c^ρ(z)`。这是本文最核心的概念贡献——它使"该改什么"成为一个可用任务结果直接监督的量。
- **方法贡献**：DAAF 将三件事统一在一个轻量框架内：(i) 显式建模观测可用性的多信号弱监督失败检测（MSWSD）；(ii) 以 Shapley 风格边际干预效应为监督、按组件类型分头的归因器（CTCA）；(iii) 仅在"同版本、同候选、同策略、同评估器"条件下构造的跨请求一致性正则与带弃权的单编辑修复规则。
- **实证结论**：
  - 组件感知 LLM 直接选编辑、或仅叠加检测器，均不足以稳定命中有效修复；加入 CTCA 的干预效应监督是提升 Attribute Hit@1 的关键。
  - 归因器可在**无重放**条件下预测带符号效应，且诊断时仅需极少环境执行（Full DAAF 每自然失败约 2.00 次），显著低于离线监督所需的 5,280 次受控重放。
  - 在修复效果上，DAAF 在提升 Failure Recovery 的同时抑制了对自然成功案例的破坏（Clean Regression），即"少改、改对"的联合收益。
  - 不完整证据处理需显式建模缺失（missingness-aware），均值填补与零填充均劣化——验证了"缺失 ≠ 0"的设计选择。
- **理论贡献（附录 D）**：给出重复信号聚合的 Hoeffding 型集中界、有限预算下边际效应估计的 O(M^{-1/2}) 误差界（对候选数仅对数依赖），以及交替块梯度下降的收敛性分析，为"用少量重放估计效应"提供了一定的理论支撑。

## 7. 局限、风险与伦理考量

- **安全与误改风险**：DAAF 返回的是"应修改哪个注册资产"的建议，若被自动执行，可能对复用该资产的**其他请求**产生负外部性。论文以 Clean Regression 部分度量了这一点，但组合修复的副作用（尤其负向交互）在正文中未纳入主决策规则，实际部署需保留人工审核或灰度回滚。
- **评估器依赖**：`R_z(S)` 完全依赖官方可执行评估器（τ²-bench 二元任务评估器），因此方法的有效性被绑定在"存在可靠、可重放、任务级自动评估"的前提上；对开放式、无客观成功判据的任务（写作、咨询、创意）适用性未讨论。
- **反馈信号的博弈/噪声风险**：用户反馈被映射为固定分值（如显式负结果 1.00/0.75、放弃 0.50/0.30），这类映射在真实场景中易受用户表达习惯、恶意反馈或稀疏性影响，论文未做对抗性或分布漂移测试。
- **数据与隐私**：轨迹、用户反馈与知识片段可能含敏感信息，论文未讨论脱敏、访问控制或存储策略。
- **可复现性缺口**：**未报告 GPU 型号/数量、训练时长、API 调用总量与成本**，且核心 LLM 依赖具体商用模型（GPT-5.6-luna、DeepSeek-V4-Flash），外部复现会受模型版本变动影响。

## 8. 对该领域的启示

1. **"定位"与"修复"应解耦为两个问题**：把诊断输出从执行坐标改为可寻址资产，能使诊断结果直接对接版本控制、灰度发布与回滚机制，更贴近真实运维闭环。
2. **干预效应可作为归因的监督信号**：在有可执行环境时，"替换—重放—评估"产生的带符号效应比人工标注更廉价、更贴近目标，且天然支持组合与交互分析。
3. **缺失必须显式建模**：弱信号在真实请求中普遍不可用，把缺失当 0 会系统性偏置检测与路由，这一工程细节值得被后续工作继承。
4. **一致性约束应基于"干预响应相似"而非"文本相似"**：只在可比的系统版本、候选集与评估器之间迁移修复证据，是避免负迁移的关键设计。
5. **轻量归因器 + 强 LLM 执行器的分工**：6,757 参数的类型条件头即可承担决策，提示归因不必然需要大规模模型，这对成本敏感的部署具有实际意义。
