## 摘要
LLM 智能体正日益通过与用户、策略和外部工具的交互采取具有后果的行动。审计这些智能体需要将实际发生的动作自动归因到其历史依据。然而，现有归因表述无法为多样化的审计目标提供针对具体问题的追踪。此外，当对行动模型的访问受限时（例如仅在 API 部署中），可用的方法通常依赖昂贵的输入扰动或外部 LLM 对完整轨迹的分析。因此，我们提出查询条件化的智能体动作归因这一新任务：它以自然语言审计查询为输入，并为动作中查询所指定的方面恢复来源及有序的中间证据。我们以 A^3Bench 实例化该任务，该基准包含 1,396 条审计查询，涵盖策略依据、参数来源、故障传播和不安全行为追踪。为实现高效且针对具体查询的归因，我们使用小型开放权重模型作为归因提议器，将查询条件化的梯度显著性与查询语义相关性相结合，以对历史单元进行排序。与开放权重基线相比，我们的提议器始终以更低的推理成本取得更强的来源和证据排序，在仅需两次前向传播和一次反向传播的情况下，将来源 MRR 提升最多 40.9%，将证据 MAP 提升 42.1%。受控评估证实，我们的提议器能够通过使其排序适应审计查询中的细粒度变化，提高归因的特异性。在提议器集成的基础上，我们的端到端系统在来源准确率上超过最强的前沿模型基线（64.5% 对 60.4%），同时相对于最快的前沿 API 基线将实际部署延迟降低 29.9%。代码和数据将在最终验证与清理后的初始评审期结束后发布。

## Abstract
LLM agents increasingly take consequential actions through interactions with users, policies, and external tools. Auditing these agents requires automated attribution of realized actions to their historical basis. However, existing attribution formulations do not provide question-specific traces for diverse auditing objectives. Additionally, when access to the acting model is limited (e.g., in API-only deployments), applicable methods commonly rely on costly input perturbations or external LLM analysis of complete trajectories. We therefore formulate $\textit{query-conditioned agent action attribution}, a new task that takes a natural-language auditing query as input and recovers the source and ordered intermediate evidence for the query-specified aspect of an action. We instantiate this task with $A^3Bench$, a benchmark comprising 1,396 auditing queries across policy basis, parameter provenance, failure propagation, and unsafe-behavior tracing. To enable efficient, query-specific attribution, we use small open-weight models as attribution proposers that combine query-conditioned gradient saliency with query-semantic relevance to rank history units. Our proposer consistently achieves stronger source and evidence rankings at lower inference cost than open-weight baselines, improving source MRR by up to 40.9\% and evidence MAP by 42.1\% with only two forward passes and one backward pass. Controlled evaluations confirm that our proposer improves attribution specificity by adapting its rankings to fine-grained changes in the auditing query. Building on a proposer ensemble, our end-to-end system surpasses the strongest frontier-model baseline in source accuracy (64.5\% vs.\ 60.4\%) while reducing empirical deployment latency by 29.9\% relative to the fastest frontier API baseline. Code and data will be released after the initial review period following final validation and cleanup.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体越来越多地在网页导航、客服、行政流程等场景中执行有后果的动作（更新记录、取消预订、发起交易）。要提升系统可靠性，不仅需要失败归因，还需要在**执行成功**的情况下把每个动作追溯到其历史依据——例如该动作是否由某条策略驱动、参数值从何而来、是否包含不必要的工具调用。
- **问题一：归因特异性（C1）**。现有归因方法（如 ContextCite、Leave-one-out、PrefixDelta、以及各类"主归因组件 + 证据链"工作）通常为每个动作给出**唯一**的"主要"归因结果，即把归因焦点隐式固定。但同一个动作往往包含多个决策：例如"取消预订"这一动作，其**工具选择**由治理策略与用户确认决定，而其**预订号参数**则来自更早的用户请求。不同审计问题需要不同的来源与证据链，单一归因无法覆盖。
- **问题二：归因效率（C2）**。在只提供 API 的部署中，行动模型内部不可访问，可用方法要么依赖反复的输入扰动（约 41–64 次前向），要么让外部 LLM 分析整条轨迹，推理成本随轨迹长度与待审动作数量增长，难以规模化。
- **核心主张**：把归因**条件化在自然语言审计查询**上，使归因焦点显式化，并设计一种低成本、不访问行动模型内部的代理式归因方法。

## 2. 方法论

### 2.1 任务形式化

- 输入三元组 $(H, a^\star, q)$：历史单元序列 $H=(h_1,\dots,h_N)$、已实现的目标动作 $a^\star$、自然语言审计查询 $q$。
- 输出归因轨迹 $A_q=(S_q, E_q)$：为每个历史单元赋予查询相关角色 $r^q_j \in \{\text{SOURCE}, \text{INTERMEDIATE}, \text{NONE}\}$。
  - **SOURCE**：某查询相关依据**首次生效**的历史单元；
  - **INTERMEDIATE**：此后承载、变换或应用该依据直至目标动作的单元（按时序排列）；
  - 允许存在多个来源，也允许中间证据为空。
- 归因在**可观测轨迹层面**定义（区别于对行动模型内部计算的因果归因）。

### 2.2 归因提议器（Attribution Proposer）

核心思想：用**小型开放权重模型**作代理，融合两个互补信号对历史单元打分排序。

1. **查询条件化梯度显著性**
   - 仅用"观测动作"做目标无法指明应归因动作的哪个方面，因此为每个查询构造一个**对照动作** $\bar a_q$：由 $q$ 与 $a^\star$ 推导，移除查询所指定的承诺（如"不提交被查询的参数值"）。构造只依赖关系模板与轻量关键词规则，**不需要任何归因标注**。
   - 在历史后追加 assistant 前缀，把 $a^\star$ 与 $\bar a_q$ 呈现为二选一，定义标量目标 $J(H,q,a^\star)=\frac12(M(A)+M(B))$，其中 $M(A), M(B)$ 来自**标签交换（A/B 互换）**后的两个 prompt，取平均以降低对选项标号分配的敏感性。
   - 对完整上下文求导，token $i$ 的梯度显著性为 $a_i(q)=\|\nabla_{e_i} J\|_1$。

2. **查询语义相关性**
   - 高梯度灵敏度不等于与查询相关（可能落在通用句法/结构上下文上）。定义相关性 $R(i,q)=\cos(e_i,\hat q)$，其中 $\hat q$ 是对**过滤后**的查询 token 嵌入做均值池化；过滤表包括 "policy, user, assistant, which, was…" 等通用词与固定小节标题（避免 "policy" 造成结构性词面匹配）。

3. **分布重加权融合（有理论推导）**
   - 把梯度显著性归一化为基分布 $p_0(i\mid q)$，求解带 KL 正则的约束优化：
     $p^\star_q=\arg\max_{p\in\Delta}\big[\mathbb{E}_{i\sim p}[R(i,q)]-\tau D_{KL}(p\|p_0)\big]$
   - 拉格朗日求解得**指数重加权**：$p^\star_q(i)\propto p_0(i\mid q)\exp(R(i,q)/\tau)\propto a_i(q)\exp(R(i,q)/\tau)$。
   - 排序只用未归一化分数 $w_i(q)=a_i(q)\exp(R(i,q)/\tau)$；温度 $\tau$ 控制"语义相关性 vs 梯度信号"的平衡。

4. **单元级聚合**
   - 单元 $h_j$ 的得分 $\sigma_q(h_j)=\frac{1}{\sqrt{|T_j|}}\sum_{i\in T_j} w_i(q)$，用平方根归一化缓解长度偏置，同时不压制分散在多个信息 token 上的证据。

### 2.3 端到端归因（基于提议器集成）

- 三个冻结的开放权重骨干（Qwen3.5-2B、Granite 3.3-2B、SmolLM3-3B）产生三份完整排序。
- **一致性解码**：若三者 Top-1 完全相同，直接作为预测来源；否则调用轻量 LLM **解析器**（Qwen3.5-4B），仅在**三者 Top-3 候选并集**中择一。
- **中间证据**：用等权 **Borda 排序融合**（分数尺度不可跨骨干比较），在来源之后的时间区间内取 Borda 分最低的至多 $K$ 个候选（全局 $K=4$，在开发集选定后固定），再恢复时序形成 $\hat E_q$。
- 全程**无需训练**，仅需 2 次前向 + 1 次反向。

## 3. 实验设计

- **新基准 A³Bench**：1,396 条审计查询、7 个领域，覆盖四类归因关系——**策略依据、参数来源、故障传播、不安全行为追踪**；轨迹取自 τ²-bench 与 AgentDojo。
  - GPT-4.1 子集：1,141 查询 / 871 轨迹；Qwen3.5-9B 子集：255 查询 / 214 轨迹。
  - 每条原子查询恰有一个标注来源（基准设计选择，非任务限制）；>95% 实例含多步中间证据；干扰步中位数 19，来源距离中位数 5。
  - 标注由 GPT-5.6 辅助生成 + 人类审校；两名评审在 109 条重叠样本上来源判断一致率 **97.2%**；全量 17.6%（246/1396）被至少一人标记，全部经仲裁达成共识，并做了剔除标记实例的敏感性检验。
- **评测划分**：从 GPT-4.1 子集中取 100 条**轨迹不相交**开发集，其余 1,041 条为留出集；所有超参仅在开发集上选择。
- **对比方法**：
  - 提议器排序：ContextCite（稀疏线性代理）、Leave-one-out（逐单元删除）、PrefixDelta（前缀似然变化）——均以其**原始的目标条件化形式**运行（因无基线支持查询条件化）。
  - 端到端：直接提示前沿模型做查询条件化归因（Gemini 2.5 Pro、Claude Sonnet 4.6、Claude Haiku 4.5、GPT-4.1）以及 Qwen3.5-4B/9B。
  - 泛化：Who&When（失败归因）、ATBench（风险来源归因）。
- **指标**：来源 Hit@1/3/5、MRR；证据 Recall@|GT|、MAP、macro/micro F1、Exact；成本用前向/反向次数、生成 token 数、实测 wall-clock 时间。
- **消融与受控实验**：累积消融（梯度求和 → 加长度归一化 → 加查询梯度 → 加查询相关性）、温度 τ 调参、细粒度查询条件化（原始查询 / 控制查询 / 错配查询，跨关系与关系内两种设置）、增量式提议器集成、解析器规模消融（2B/4B/9B vs Borda 回退）、关系级性能与错误定位、跨模型代理分析、干净子集复评与 bootstrap 置信区间。
