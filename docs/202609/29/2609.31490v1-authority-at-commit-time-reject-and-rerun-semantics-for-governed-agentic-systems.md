## 摘要
企业智能体可基于策略、事实、任务状态、模型、工具与验证器的一份快照计算数秒或数小时，而这些内容可能在其工作成果影响现实之前发生变化。因此，仅凭完成本身并不能赋予制度性权威。我们将智能体视为提案生产者，并将一个逻辑上具有权威性的服务视为受治理效应的唯一权威。在准入时，该服务将提案所声明的依赖项与组件清单同当前状态进行比较，应用当前验证器，并且要么为发件箱派发预留一个幂等效应，要么拒绝受影响的过期工作以进行重新同步与重跑。未受影响的工作可以继续；丢失的响应通过规范裁决与回执得以解决。该协议组合了乐观并发控制、语义验证与事务性发件箱派发。其独特的读取集包括规范性权威以及产生该提案的模型组件。我们通过一个已实现的受治理工作生命周期、一个本地权威、发件箱与对账组合，以及当完整中介不可用时委派效应权威的多进程回退方案，来评估该设计。本地组合保留了选择性回退、未受影响的工作、重试与重启恢复，以及包重建。完整中介产生了18条权威命令和18个外部效应。直接凭证分支产生了八个额外效应，全部通过独立日志对账被检测到，而在受中介对照中没有任何误检。结果支持提交时拒绝并重跑语义，并揭示了由委派准入引入的时钟、租约、排序与法定人数义务。它们并未确立对绕过效应的预防或逆转、外部日志完整性、生产吞吐量、广域可用性、语义完整性或验证器正确性。

## Abstract
Enterprise agents can compute for seconds or hours from a snapshot of policy, facts, task state, models, tools, and verifiers that may change before their work reaches the world. Completion alone therefore cannot confer institutional authority. We treat agents as proposal producers and a logically authoritative service as the sole authority for governed effects. At admission, the service compares a proposal's declared dependencies and component manifest with current state, applies the current verifier, and either reserves an idempotent effect for outbox dispatch or rejects affected stale work for resynchronization and rerun. Unaffected work may continue; lost responses resolve through canonical verdicts and receipts.   The protocol composes optimistic concurrency control, semantic verification, and transactional outbox dispatch. Its distinctive read set includes normative authority and the model components that produced the proposal. We evaluate the design through an implemented governed-work lifecycle, a local authority, outbox, and reconciliation composition, and a multi-process fallback that delegates effect authority when complete mediation is unavailable. The local composition preserved selective fallback, unaffected work, retry and restart recovery, and package reconstruction. Complete mediation produced 18 authority commands and 18 external effects. Direct-credential arms produced eight additional effects, all detected with independent journal reconciliation and none falsely detected in the mediated control. The results support commit-time reject-and-rerun semantics and expose the clock, lease, ordering, and quorum obligations introduced by delegated admission. They do not establish prevention or reversal of bypass effects, external-journal completeness, production throughput, wide-area availability, semantic completeness, or verifier correctness.

## 一、核心问题与整体含义

- **背景**：企业可同时运行数千个智能体，每个智能体从一份快照（策略、事实、任务状态、模型、工具、验证器）出发，可能计算数秒乃至数小时。在此期间，任何治理输入都可能变化：策略被修订、客户事实被更正、任务被取消、验证器被替换、模型被下架、或他人已记录了先前效果。
- **核心问题**：智能体"完成任务"并不等于其产出具有**制度性权威**。真正的问题不是提案看起来是否合理，而是它在**提交（admission）时刻是否可被接纳**。
- **整体主张**：把智能体视为**提案生产者**，把逻辑上唯一的权威服务视为**受治理效果的唯一授权方**。每个效果作用域内存在一个当前有序权威，任何智能体侧状态都不能绕过它提交。
- **关键前提**：**完整中介（complete mediation）**——所有受治理效果路径必须终止于权威服务控制的适配器。这被视为核心前置条件，而非实现细节；因为一旦外部效果通过未受治理路径发生，事后记账只能记录/补偿/上报，无法让原效果"未发生"。
- **与既有工作的关系**：论文明确声明这不是新的并发算法，而是把**乐观并发控制（OCC）**的读—验证—写—中止重试结构，扩展到制度性工作；其新意在于**读集的构成**与**写入时点的利害**。
- **研究脉络定位**：本文是作者系列工作的第四篇——从"正确不等于受治理"（Paper 1）、"治理记录作为监督"（Paper 2）、"学习工件在权威变化下的治理"（Paper 3），推进到**运行时的前瞻性提交**。

## 二、方法论

### 2.1 核心思想与不变量

- **提案定义**：`p = (q, Sb, D, M, E, a)`，其中 `q` 为任务，`Sb` 为基础快照，`D` 为声明的治理依赖集，`M` 为模型/适配器/工具/验证器清单，`E` 为证据包，`a` 为请求动作。
- **权威提交不变量**：只有当提案的治理依赖在准入时仍然当前（current），且**当前验证器**予以接纳时，提案才能成为制度性效果；否则不提交任何效果。
- **范围敏感比较**：旧的全局面快照标识并不自动致命（若变化发生在无关作用域）；反之，粗粒度 epoch 匹配也不充分（若某个声明的治理头或必需组件哈希不同）。

### 2.2 技术继承与"治理增量"

- **OCC 继承**：读集 = 治理依赖与组件集；验证 = 与当前头比较；写 = 权威控制的效果提交；冲突则 reject-stale 并重跑。
- **读集的独特扩展**：不仅包含数据库对象，还包含**规范性权威版本**与**模型、适配器、提示、工具、验证器的组件清单**。
- **语义并发控制**（Garcia-Molina, 1983）：版本一致是必要条件但非充分条件，因为当前验证器仍可能返回 reject-verify。
- **事务性发件箱**（Helland, 2007；Richardson）：本地记录意图 → 至少一次中继 → 效果幂等。
- **补偿的边界**：补偿本身是一个新的受治理效果，当前权威可以拒绝它，因此不承诺通用回滚（区别于 Sagas）。

### 2.3 状态对象

- `AuthoritySet`（策略、权限、撤销、决策契约）、`FactSet`（版本化事实与取代链接）、`TaskSet`（义务、完成定义、许可工具、稳定任务标识）、`CompletionReceiptSet`（不可变的尝试与效果证据）、`SupervisorVerdict`（pass/fail/incomplete/rework/block/escalation）。
- **SnapshotManifest** 绑定上述集合的头与组件哈希；**ProposalEnvelope** 声明基础清单、依赖子集、稳定任务标识、唯一尝试标识、幂等效果标识、请求动作与证据哈希。

### 2.4 准入事务（算法流程，文字描述）

1. 认证提交者，检查其对任务 `q` 的权限；
2. 解析每个声明治理依赖的当前头；
3. 比较提案清单与当前必需组件清单；
4. 若变更的头或组件影响 `q`：追加 stale-attempt 裁决，返回 `reject-stale` 与重新同步计划；
5. 否则以当前验证器验证提案与证据；
6. 验证失败：追加 `reject-verify` 与 rework/block/escalation 义务；
7. 成功：**原子地**预留效果标识，追加 accepted 裁决与发件箱命令；
8. 幂等派发后：追加外部完成回执，或失败与对账义务。

- **原子单元** = 当前治理头比较 + 验证器结果 + 效果标识预留 + 裁决与发件箱追加。线性化存储（Herlihy & Wing, 1990）是实现路径之一，但准入事务本身就是权威的线性化点。
- **五种准入结果**：accept / reject-stale / reject-verify / duplicate / unavailable；**任何拒绝路径都不提交请求的效果**。

### 2.5 拒绝并重跑规则

受影响时返回 `reject-stale` 与机器可读原因，工作方须：(1) 使过期尝试及其未提交后代失效；(2) 安装当前权威/事实/任务/验证器/模型/适配器/工具状态；(3) 从权威输入检查点重启；(4) 以新尝试标识、相同稳定任务与效果标识重新提交。**牺牲的是过期计算，而非制度安全**。

### 2.6 分区、丢包与联邦

- **分区**：无法联系权威的节点暂停受治理提交与效果执行；重连后发送最后的快照哈希与回执序号，接收签名清单与缺失回执。
- **丢失确认**：并非模糊状态——账本已记录裁决与发件箱状态，重传同一效果标识即返回规范裁决或当前回执（至多一次已提交效果）。
- **统一权威 + 作用域账本**：可按客户/司法辖区/产品/风险分片，但每个作用域仍有唯一有序历史；跨作用域提案须声明各作用域当前头并由协调者验证。缓存发现记录可用 TTL，**授权记录不可**。

## 三、实验设计

论文采用**三层互不汇总的证据结构**（不合并为单一结论）：

### Layer A：已实现的受治理工作生命周期（Matrix 原型）

- **系统**：Matrix 原型中央治理服务，仅追加 JSONL 事件日志、全局序号、SQLite 物化状态、类型化操作校验、版本化事实与显式取代、依赖导向失效、重收敛任务、结果验证与重放。
- **场景/基准**：取自冻结的受治理工作阶梯中两个已完成档位 **L4（版本化变更恢复）** 与 **L5（组合受治理闭环）**，均为自撰的合成供应商准入工作流，在 **3 个 Phi-4 种子**上评估。
- **L4**：法律身份与税务证据两条独立分支；税务标准由 v1 取代为 v2，须使旧税务回执与先前闭环失效、保留法律回执、仅重跑税务、从当前证据闭环；另有省略必需事实引用的准入挑战。
- **L5**：组合法律身份、税务证据、安全审查与供应商激活；**每条路由 20 条生命周期断言**（3 路由共 60 条）。
- **对比**：直接控制臂（direct control）获得相同的自撰修订与目标结果，但**没有** Matrix 的准入、回执或选择性失效机制。

### Layer B：本地网络化组合与独立对账（冻结 v2 研究）

- **实现**：独立本地 HTTP 进程 + SQLite WAL；权威服务认证提案信封、按 epoch 与作用域解析组件准入、运行固定版 VAL、原子追加裁决与发件箱命令；中继派发稳定效果标识至独立外部效果服务；对账器比较外部日志与权威发件箱/完成记录。
- **工作负载**：重放先前记录的、经 VAL 接纳的 **Qwen3-14B 提案**（集成负载，非新的模型能力评测）。
- **三个臂**：完全中介 + 对账；直连凭证绕过（不对账）；同绕过计划 + 对账。
- **冻结用例**：组件撤销与回退、未受影响的专家、验证器拒绝、丢失确认与重复重试、中继重启、**8 个可观测直连绕过**、**6 类重建损坏**。
- **判定门（claim-bearing gates）**：无 stale / 验证器拒绝 / 重复的中介效果；当前工作活性；250 ms 内检出全部 8 个日志化绕过；中介臂零误报；所有损坏包被拒。

### Layer C：完整中心中介不可用时的委派回退（冻结 v1/v1.1 研究）

- **架构**：3 个网关进程 + 3 成员本地 etcd 控制平面；主臂组合版本化发布、本地时钟、影响范围时间栅栏、发布观察、网关租约、原子效果标识与验证式回退；密封的 oracle 时钟评分时间而不对网关可见。
- **测试**：健康运行（假设是否成立）+ 两个压力测试（本地时钟超出声明误差界；控制平面失去多数派）+ 一个单独冻结的确认（在 oracle 盲执行器内为实际效果打时间戳）。
- **要求保留 5 个独立裁决**：健康有界运行、原始时钟探针、时钟效果确认、分裂 epoch 一致性、多数派丢失压力。

  - 结论：作为**受控组合证据**是充分的、且对照设置公平（直接控制臂共享相同修订与目标结果）；但**不足以支撑生产频率、吞吐、WAN 行为等外推**。

## 六、主要结论与发现

- **实现层面**：Matrix 原型能够把智能体输出当作提案，**在准入前不发放工作**，使受影响的证明失效，仅重跑已声明的依赖工作，并要求当前回执才能闭环（L4/L5 各 3/3，60/60 断言通过）；移除保留断言的回归会在"业务终态为绿"的情况下阻止运行，说明**结果外观本身不能满足生命周期契约**。
- **本地组合层面**：完全中介产生 **18 条权威命令与 18 个外部效果**；两个绕过臂中权威账本**内部可重建却漏掉全部 8 个直连效果**；独立外部日志在受对账臂中检出全部 8 个（延迟 60.607–130.249 ms，低于 250 ms 本地门限），且完全中介对照**零误报**。
- **委派回退层面**：健康有界运行通过（16 次运行
