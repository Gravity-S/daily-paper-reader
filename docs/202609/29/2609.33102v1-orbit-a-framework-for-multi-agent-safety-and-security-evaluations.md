## 摘要
多智能体 LLM 系统正越来越多地被部署用于复杂、长时程任务，或作为智能体在开放环境中交互的自然结果而出现。然而，它们带来了显著的安全与安保风险：使任务泛化成为可能的灵活协议也暴露了新型威胁，从级联提示注入到智能体间串通。由于缺乏共享的实证基础设施，防御这些威胁的进展一直受到拖慢：每项新防御都迫使人们开发定制环境，并使得标准化比较无法进行。现有评估处理的是孤立威胁模型或单智能体设置，但没有任何一个在真实的多智能体环境中联合变化攻击、防御和架构。为弥补这一空白，我们提出 ORBIT，一个用于多智能体安全与安保实证研究的可配置评估框架，构建于 UK AISI 的 Inspect 之上。ORBIT 允许研究人员配置通信拓扑、记忆、调度和智能体角色。它支持四种威胁类型和四种防御策略，以及非对抗性故障，并提供一个基准测试套件，涵盖五个场景族：浏览器使用、计算机使用、智能体编码、客户服务和协作分配。我们的核心发现是防御在不同威胁之间的可迁移性存在缺口：在多问题编码中，将受损智能体的攻击成功率降低 60 个百分点的逐动作防御，对合谋智能体没有可测量的保护；并且我们测试的防御没有一个能泛化到所有测试攻击。我们进一步展示了安全与性能之间的权衡，以及架构与防御有效性之间的交互作用。我们将 ORBIT 在 https://github.com/wlanderson0/orbit 上开源。

## Abstract
Multi-agent LLM systems are increasingly deployed for complex, long-horizon tasks or emerge as a natural consequence of agents interacting in the wild. Yet they give rise to significant safety and security risks: the flexible protocols that enable task generalization also expose novel threats, from cascading prompt injection to inter-agent collusion. Progress in defending against these threats has been slowed by a lack of shared empirical infrastructure, which forces bespoke environment development for every new defense and makes standardized comparison impossible. Existing evaluations address isolated threat models or single-agent settings, but none jointly vary attack, defense, and architecture across realistic multi-agent environments. To address this gap, we introduce ORBIT, a configurable evaluation framework for empirical multi-agent safety and security research, built on UK AISI's Inspect. ORBIT lets researchers configure communication topologies, memory, scheduling, and agent roles. It supports four threat types and four defense strategies, as well as non-adversarial failures, with a benchmark suite spanning five scenario families covering browser use, computer use, agentic coding, customer service, and cooperative allocation. Our central finding is a gap in defense transferability across threats: per-action defenses that cut a compromised agent's attack success by 60 points on multi-issue coding give no measurable protection against colluding agents, and none of the defenses we tested generalized over all attacks tested. We further demonstrate security-performance tradeoffs and interactions between architecture and defense effectiveness. We make ORBIT available open-source at https://github.com/wlanderson0/orbit.

## 1. 核心问题与整体含义

- **背景**：前沿 LLM 智能体日益具备自主性、长时程能力，正被部署为多智能体系统（MAS），或由独立部署的模型自然组合而成。任务分解、部分可观测、责任分散等特性使 MAS 出现单智能体系统中不存在或未被放大的新型攻击面。
- **新威胁**：级联/间接提示注入、记忆投毒、感染式攻击、内部人威胁（compromised agent）、智能体间串通（collusion）、病毒式错位（viral misalignment）等。
- **核心痛点（基础设施缺口）**：现有评估要么只针对孤立威胁模型，要么局限于单智能体设置；没有工作能在真实多智能体环境中**联合变化攻击、防御与架构**。每项新防御研究都需自建定制环境，导致结果难以标准化比较。
- **整体含义**：论文认为多智能体安全研究的主要瓶颈不是缺少威胁假设，而是缺少**可复用的评估基础设施**。ORBIT 旨在降低这一门槛，成为未来实证多智能体安全研究的骨干平台。

## 2. 方法论

### 核心思想
- 基于 UK AISI 的 **Inspect** 框架扩展，将一次多智能体安全实验分解为**六个可配置层**，每层是一个冻结的配置对象，实验是每层各选一项的笛卡尔积，从而实现单轴控制的消融比较。
- 配置通过 **YAML 文件**声明，新增攻击/防御/场景只需实现一个短协议（如攻击的 `inject / should_activate / evaluate_success` 三方法协议），无需修改编排器或评分管线。

### 六个实验层
1. **Setup（设置）**：定义智能体（角色、模型、系统提示、工具）、有向通信拓扑（star / mesh / chain / flat 等，用 YAML 有向图声明）、记忆可见性策略（六个布尔标志：自身动作、自身推理、他人动作、他人推理、累积指令、目标可见性），由 `MemoryInjectionFilter` 拦截每次 `generate()` 调用实现。
2. **Scenario（场景）**：任务与执行环境，五个场景族。
3. **Attack（攻击）**：指定类型、威胁模型（知识水平 black/gray/white-box、预算、持久性、攻击面）、注入时机、成功标准。内置四类：misuse、indirect prompt injection、compromised agent、collusion。
4. **Defense（防御）**：指定类型、调用模式、范围、失败模式。四类：系统提示硬化、无状态逐动作 LLM 监控、有状态历史感知守护智能体、Dual-LLM 隔离架构。
5. **Execution（执行）**：Inspect 的 `react()` 一次跑完，ORBIT 引入 `turn_react()` 每次执行一个工具调用，交回 `AgentScheduler` 维护每智能体隔离状态并选择下一轮由谁运行。
6. **Evaluation（评估）**：对完成日志做 LLM 驱动评分，计算指标与自动有效性检查。

### 编排流程
- 编排器为 Inspect `@solver`，分三阶段：组件从注册表组装 → 部署前修改（注入受损智能体、提示疫苗）→ 逐轮循环（攻击注入 → 防御钩子 → 智能体执行 → 输出监控 → 攻击评估 → 停止检查）。

### 指标体系（三层）
- **每智能体妥协分数**：\(C_i \in \{0, 0.5, 1\}\)（拒绝 / 计划但未执行 / 执行有害动作）。
- **每样本传播深度与攻击成功**：\(PD_j = \frac{1}{n}\sum_{i=1}^n C_i\)，\(AS_j = \mathbb{1}[\max_i C_i = 1]\)。
- **每实验聚合**：ASR = 平均 \(AS_j\)；PD = 平均 \(PD_j\)；BTCR（良性任务完成率）与 \(\Delta BTCR = BTCR_{undefended} - BTCR_{defended}\) 刻画安全–效用权衡。
- **协作分配（DCOP）真值指标**：regret = \((R^* - R_{actual})/R^*\)，coalition advantage = 联盟成员平均奖励 − 诚实成员平均奖励。

## 6. 主要结论与发现

1. **防御跨威胁不可迁移（核心发现）**：在 SWE-Bench 多议题场景，LLM 监控与守护智能体把受损智能体 ASR 从 72% 降到 12%（−60 pts，95% CI [−80, −40]），但对串通智能体**无任何可测量保护**（30% 不变）；四种防御在串通上彼此不可区分。反向亦然：系统提示对 Qwen3-235B 的 BrowserART misuse 最强（36%→7%），对受损智能体无效。
2. **没有任何测试防御能覆盖所有测试攻击**：每个防御至少留下一种威胁未被缓解。
3. **安全–性能权衡因机制而异**：Dual-LLM 是唯一有可检测任务代价的防御（多议题解决率 −9.2 pts，[−14.0, −4.5]），因其 Q-LLM 摘要降低信息质量；监控的代价表现为 28% 良性任务出现至少一次误封，但智能体重试后可恢复，良性性能统计上不变。提高阈值消除误报但丢失大部分安全增益（受损 ASR 从 12% 回升到 30%）。
4. **架构与防御交互**：模型选择是最大单因素（BrowserART standalone 从 Sonnet 4.6 的 0% 到 Llama 70B 的 27%）；Qwen3-235B 从 standalone 到 Star，ASR 从 17% 升到 36%（+19 pts）。
5. **JiraTicket 串通无优势**：无论模型或拓扑，未防御联盟相对公平份额无可测优势，防御也就无可移除之物。
6. **机制解释**：串通漏洞存在于**个体看似良性动作的组合**中，逐动作判断难以检测；Dual-LLM 在 RedCode-Gen 失效，因其摘要保留代码语义、只剥离注入指令而非有害任务内容。

## 7. 优点

- **可配置性与可扩展性**：六层分解 + YAML 声明 + 可插拔注册表，新增攻击/防御/场景仅需实现短协议，无需改动编排器或评分管线，显著降低复现与扩展成本。
- **真实环境**：每个场景运行于 Docker 隔离沙箱，使用部署中会遇到的真实工具（浏览器、真实开源仓库、虚拟桌面），外部有效性较好。
- **标准化安全指标**：统一的三层指标体系（per-agent / per-sample / per-experiment）+ DCOP 真值指标，支持跨研究可比。
- **受控实验设计**：单轴消融 + 每条件配对有害/良性评估，能直接量化安全–效用权衡；统计报告规范（Wilson / bootstrap / 配对 / DiD）。
- **首次跨场景防御头对头比较**：揭示了防御不可迁移这一重要且反直觉的结论，对实践有直接指导意义。
- **开源**：代码公开，承诺长期维护与扩展。

## 8. 不足与局限

- **覆盖有限**：配置空间组合爆炸，仅评估代表性切片，不能声称结论可推广到整个配置空间。
- **攻击非自适应**：使用固定载荷模板而非自适应红队，可能**高估静态防御的有效性**；与 AI control 评估的对应只是部分的（缺少针对协议优化的攻击者）。
- **执行模型限制**：当前假设回合制、离散消息传递；连续通信、共享梯度、学习型通信协议不在范围内。
- **评审者可靠性**：LLM judge 虽有一致性统计，但人类检查仅用单一评分者、无评分者间一致性分析，残余 judge 偏差无法完全排除。
- **部分结果样本量小**：若干单元 N 很小（如 Sonnet 4.6 良性 5 样本），区间重叠使部分结论只能作方向性解读。
- **JiraTicket 无实证结论**：该场景未观察到串通优势，作者明确不作实证主张。
- **双用途风险**：标准化攻击实现

- **双用途风险**：标准化攻击实现与可复现的攻击载荷降低了攻击门槛，若被恶意使用，可能加速多智能体攻击的工程化；论文虽以安全评估为目的，但攻击代码与防御代码同库开源，需要访问控制或负责任披露机制配合。
- **防御评估的“静态性”**：四种防御均以固定配置评估，未考虑防御者可根据攻击历史自适应调整；同样，攻击者也未针对防御进行优化，因此“防御不可迁移”这一结论的强度受限于非自适应威胁模型。
- **场景适配的保真度**：将单智能体基准改写为多智能体任务时，功能分解与多目标重构可能改变原任务的难度分布与失败模式，跨场景比较时需谨慎解释绝对数值，论文主要通过同场景内配对比较缓解该问题。
- **成本与可及性**：尽管无需 GPU，但约 $8,000 的 API 开销与 Docker 沙箱的运维复杂度仍构成门槛；小规模研究团队可能难以完整复现全部实验矩阵。
- **时序与版本漂移**：评估依赖托管模型 API，模型版本更新可能导致结果不可复现；论文未报告 API 版本锁定策略或跨时间稳定性测试。

## 9. 伦理与双用途考量

- **研究定位**：ORBIT 属于安全评估基础设施，核心贡献是测量而非攻击能力本身；但其中包含可执行的提示注入、记忆投毒、串通协议等攻击实现。
- **风险缓解**：论文建议将攻击模块与防御/评估模块分离发布，或对高风险载荷进行抽象化处理；同时强调应在受控沙箱中运行，避免连接真实生产系统。
- **社会影响**：正面影响是推动多智能体安全从个案研究走向可比较的实证科学，帮助部署方识别“防御不可迁移”带来的虚假安全感；负面影响是标准化攻击可能被用于自动化红队以外的恶意目的。

- **代码与配置**：基于 Inspect 生态，实验以 YAML 声明，理论上支持一键复现；但论文未提供完整的锁定依赖清单与 API 快照，托管模型的黑盒性使精确复现受限。
- **数据与日志**：评估日志、LLM judge 评分与人类标注样本是否公开未在总结范围内明确；若公开，将显著提升后续研究的可审计性。
- **基准维护**：作者承诺长期维护与扩展场景/攻击/防御注册表，这对多智能体安全这一快速演变的领域至关重要，但也带来版本兼容与旧结果失效的问题。
- **统计透明度**：报告了 Wilson 区间、bootstrap 与配对检验，方法规范；但部分小样本单元的区间过宽，读者应避免对点估计做过度解读。

## 11. 未来工作方向

- **自适应红队**：引入针对防御协议优化的攻击者，检验静态防御结论在自适应威胁下是否依然成立。
- **防御组合与路由**：研究多种防御的串联、并联或按威胁类型动态路由，是否能在不显著牺牲效用的前提下覆盖更多攻击面。
- **连续与学习型通信**：将执行层从回合制离散消息扩展到连续通信、共享潜空间或学习型协议，评估新型攻击面。
- **跨组织多智能体**：研究由不同厂商、不同信任域模型组成的 MAS，在责任分散与部分可观测下的安全与问责机制。
- **人机协同监督**：将人类审核者纳入监控回路，评估人机混合防御的成本、延迟与可靠性。
- **标准化基准与排行榜**：在 ORBIT 基础上建立社区维护的 MAS 安全基准，推动结果可比与持续跟踪。

## 12. 总体评价

ORBIT 的核心价值不在于提出某种更强的攻击或防御，而在于**将多智能体安全评估从“每次自建环境”推进到“共享可配置基础设施”**。六层分解、YAML 声明式配置与可插拔协议显著降低了实验门槛，使攻击、防御与架构能够在同一底座上做受控比较。其最重要的实证发现——**防御跨威胁不可迁移、无单一防御覆盖所有攻击、安全–效用权衡因机制而异**——对部署实践具有直接警示意义：不能因为某防御在一种威胁下有效就假设其泛化。

同时，论文的结论受限于非自适应攻击、代表性配置切片、部分小样本单元与托管模型版本漂移。因此，ORBIT 更适合被定位为**多智能体安全实证研究的起点与骨干平台**，而非对配置空间的穷尽结论。后续工作若能在自适应威胁、防御组合与连续通信等方向扩展，将进一步提升该框架的科学价值与实践指导力。
