## 摘要
自主LLM智能体可以将不可信内容转化为有实际效果的操作，例如支付和权限变更。如果同一进程既解释该内容又控制可复用的签名凭证，提示注入就能跨越判断边界并触及执行权限。我们提出KITA，一种从审查到授权的架构，将用户的个人秘密签名密钥以及每一个门限签名密钥份额都置于所有LLM进程之外。在门限签名不可伪造性以及我们的系统假设下，即使攻陷提议者以及少于t个审查者-签名者域，如果没有来自t个不同域的签名贡献，也无法为新操作生成有效授权。因此，任何此类授权都包含来自未受攻陷域的一个份额，该份额绑定到规范操作，并且仅在经过认证的审查者批准后才释放。这建立了执行绑定的授权完整性。我们使用结构化输出LLM适配器和门限BLS实现了完整的审查者到执行者路径。六项系统测试验证了该接口处的法定人数门控和消息绑定，而密码学微基准测试则测量在线签名路径及其扩展行为。

## Abstract
Autonomous LLM agents can turn untrusted content into effectful actions such as payments and permission changes. If the same process interprets this content and controls a reusable signing credential, prompt injection can cross the judgment boundary and reach execution authority. We present KITA, a review-to-authorization architecture that keeps the user's personal secret signing key and every threshold signing-key share outside all LLM processes. Under threshold signature unforgeability and our system assumptions, compromising the proposer and fewer than t reviewer-signer domains cannot produce a valid authorization for a new action without signing contributions from t distinct domains. Thus, any such authorization includes a share from an uncompromised domain, bound to the canonical action and released only after authenticated reviewer approval. This establishes execution-bound authorization integrity. We implement the complete reviewer-to-executor path with a structured-output LLM adapter and threshold BLS. Six system tests validate quorum gating and message binding at this interface, while cryptographic microbenchmarks measure the online signing path and its scaling behavior.

## 1. 核心问题与研究动机

- **问题背景**：自主 LLM 智能体可将不可信内容（网页、商品页、外部文档）转化为有实际副作用的动作，如支付、权限变更。这类流程混合了两类计算：**判断**（解释信息、可能出错）与**执行**（改变用户状态、可能不可逆）。
- **核心风险**：若同一个 LLM 进程既解析不可信内容、又持有可复用的签名凭证，则间接提示注入（indirect prompt injection）可越过"判断边界"直达"执行权限"，触发未授权转账或权限变更。因此安全问题不只是"模型判断是否可靠"，而是"暴露于不可信输入的单一 LLM 进程能否自行执行该判断"。
- **现有工作的空白**：
  - AP2（Google, 2025）用签名 mandate 绑定开放/封闭授权，并要求在确定性代码中校验，但**不要求由门限数量的模型审查者来批准该签名**（自主模式下由 Agent Key 直接签）。
  - 多智能体辩论/投票/模型小组（Du 等、Verga 等、Choi 等）只提升语义判断质量，输出仍是**咨询性**的，无强制力。
  - 策略与委托系统（Progent、Bounded Agents 等）约束权限，但模糊证据仍依赖模型判断。
  - 门限/集体签名（Borselius 等、Syta 等）使门限成为密码学必要条件，但把**审查语义与执行边界留给外围系统**。
- **本文定位**：填补上述组合空白——将"基于模型的审查"与"针对精确可执行动作的门限授权"绑定，同时把所有签名密钥材料隔离在 LLM 进程之外；执行者只在动作携带对已审查字节的有效门限签名时才接受它。

## 2. 方法论

### 2.1 核心思想

KITA（Key-Isolated Threshold Authorization）将**提案、审查、签名、执行**四者分离，提供三重联动保护：
1. 任何 LLM 进程都拿不到用户个人签名密钥或门限签名份额；
2. 每个批准与签名份额都绑定到同一规范动作 *m*；
3. 执行者仅在持有有效门限签名时接受 *m*。

由此，被提示控制的代码无法直接行使可复用签名权、无法用另一动作替换已批准动作、也无法用软件投票计数替代缺失的批准。

### 2.2 系统组成与角色

- **Principal（用户）**：定义策略 π，授权一个委员会。
- **Proposer P（提案者）**：可处理不可信内容，但**不持有任何签名密钥份额**，负责构造规范授权对象 *m*、证据清单 *E* 与策略 π。
- **审查者–签名者域 (Ri | Si)**：Ri 为独立实例化的 LLM 审查者，仅评估数据；Si 为隔离的签名服务，持有份额 sk_i，暴露窄接口"签名份额"。二者配对，批准只解锁其配对的 Si。
- **Combiner（组合者）**：可为不可信方，收集并验证份额后插值出最终签名。
- **Verifier V（验证者/执行者）**：独立校验最终签名、策略与密钥纪元、有效期、重放状态，然后**精确执行 m**。

### 2.3 四步在线协议（各步为下一步建立前提）

1. **提出单一审查对象**：P 向所有审查者发送相同的 (m, E, π)，给出唯一共同决策目标；因 P 无份额，选择提案不等于能授权提案。
2. **审查、认证、释放**：Ri 返回 reject / revise(c) / approve(m)。经认证的 approve 只送达其配对 Si，Si 先校验消息摘要，再返回 σ_i = SignShare(sk_i, m)。任何修改（如降低金额）产生新字节 m′，审查流程**重新开始**。
