## 摘要
AI 介导的平台通过为不同委托方行事的 LLM 智能体来协调工作。在这些工作流中，隐私损失可能在最终答案出现之前就已产生：一次记忆写入、共享工作区更新、智能体间消息或工具事件，都可能将下游暴露成本强加给另一个委托方。我们将这种失效模式建模为隐私传播外部性，其中原始披露的成本不仅取决于内容，也取决于拓扑与扇出。我们提出 PAPC，一种平台中介机制，在信息移动事件更新共享状态或外部通道之前对其进行拦截。PAPC 结合策略、溯源、拓扑/扇出、权限和内容信号，以允许事件、发布策略安全的抽象、隔离原始内容、阻止状态转换或收窄后续权利。该模型解释了为什么最终输出控制会遗漏中间暴露成本，以及为什么高扇出对象会放大传播。在检索记忆和多智能体工作流基准上，PAPC 保持确定性任务完成，并消除所测得的精确原始值和外部原始值暴露。这些结果将事件级中介定位为面向智能体介导在线工作的平台治理原语。

## Abstract
AI-mediated platforms coordinate work through LLM agents acting for different principals. In these workflows, privacy loss can be created before a final answer appears: a memory write, shared-workspace update, inter-agent message, or tool event may impose downstream exposure cost on another principal. We model this failure mode as a privacy-propagation externality, where the cost of a raw disclosure depends on topology and fanout as well as content. We present PAPC, a platform-mediated mechanism that intercepts information-moving events before they update shared state or external channels. PAPC combines policy, provenance, topology/fanout, privilege, and content signals to allow an event, release a policy-safe abstraction, quarantine raw content, block a transition, or narrow onward rights. The model explains why final-output control misses intermediate exposure costs and why high-fanout objects amplify propagation. Across retrieval-memory and multi-agent workflow benchmarks, PAPC preserves deterministic task completion and eliminates measured exact raw-value and external raw-value exposure. The results position event-level mediation as a platform-governance primitive for agent-mediated online work.

## 1. 核心问题与研究动机

- **背景**：AI 介导的在线平台越来越多地把协调工作委托给为不同委托方（内部团队、客户、供应商、分析师、平台服务）行事的 LLM 智能体。这些智能体在共享运行时状态（记忆、工作区文档、摘要、消息、工具输出、最终更新）上协作。
- **核心问题**：隐私损失往往**在最终答案出现之前就已产生**。一次记忆写入、共享工作区更新、智能体间消息或工具事件，都可能把下游暴露成本强加给另一个委托方。
- **形式化失效模式**：作者将其定义为**隐私传播外部性（privacy-propagation externality）**——原始披露的成本不仅取决于内容，还取决于平台**拓扑与扇出（fanout）**。同一原始值写在私有记忆、单跳交接、以规划者为中心的星型结构，或多人可读的黑板（blackboard）中，后果截然不同。
- **现有控制的不足**：
  - 最终输出过滤器只能观测传播链的末端，无法撤销中间状态已产生的暴露；
  - 仅基于通道的访问控制知道"工作区是共享的"，但不知道载荷是否含他人原始秘密、策略是否只允许抽象、目标对象是否高扇出、该转换是否提升了后续权限；
  - 表层提示过滤器只能做局部筛查，无法约束持久化平台状态中的后续传播。
- **整体含义**：隐私治理在智能体介导平台中必须是**对运行时状态转换的中介**，而不仅是最终输出的审核；论文据此把"事件级中介"定位为一种**平台治理原语**。

## 2. 方法论：PAPC 机制

### 2.1 核心思想

- 在信息移动事件**更新共享状态或触达外部通道之前**进行拦截，在传播起点实施中介。
- 对每个事件，综合**策略、溯源、拓扑/扇出、权限、传播权利状态与运行时内容信号**，输出五类动作之一：
  1. **允许（allow）**
  2. **安全视图重写（safe-view rewrite）**：发布经校验的策略安全抽象
  3. **隔离（quarantine）**：原始内容进入模型不可见区域
  4. **阻断（block）**
  5. **传播权利收窄（propagation-right downgrade）**：降低可见性/移除外部或工具权限/减少扇出/限制转发

### 2.2 形式化模型

- **平台与事件图**：平台建模为 $(A, P, O, E, G)$，事件 $e=(a,p,r,c,o,z,x,H,t)$，分别记录行为智能体、行为委托方、接收委托方、通道、目标对象、目标区域（private/shared/external/quarantine）、载荷、因果父节点与步数；因果父节点诱导出信息移动转换上的事件图 $G$。
- **策略与抽象**：受保护项 $s$ 具有所有者、原始值检测器、授权原始读者、允许抽象、禁止通道、敏感度权重。`raw(s,x)` 表示载荷含原始值，`auth(s,e)` 表示事件被授权携带该原始值；未授权原始暴露与外部原始暴露据此定义。
- **福利目标**：
  $$W(M)=\sum_t\sum_{p\in P}B_p(M(e_t))-\sum_t\sum_{q\in P}L_q(M(e_t))-C_{med}(M)$$
  即保留策略允许的协调收益，同时降低未授权下游暴露，$C_{med}$ 涵盖规则维护、延迟与过度阻断成本。
- **事件级传播代价代理**：
  $$Cost(e)=\sum_{s\in S}\mathbb{1}\{raw(s,x_e)\wedge\neg auth(s,e)\}\cdot\lambda_s\cdot\phi(e)$$
  其中 $\lambda_s$ 为敏感度，$\phi(e)$ 刻画触达（外部投递、权限提升、下游扇出）。
- **两条平台含义**：
  - **中间状态损失**：若原始项在事件 $e_i$ 被写入未授权非最终共享对象，损失在写入可读时即已产生；最终输出中介只能观测更晚的最终通道事件，无法改变已发生的损失；事件级中介可在写入落地前用允许抽象 $\alpha(s)$ 替换 $x_{e_i}$。
  - **拓扑放大**：若被污染工件 $o$ 每步最多被 $F(o)$ 个下游智能体读取、传播深度为 $d$，潜在被污染转换数上界为 $1+F(o)+\cdots+F(o)^d$；完整中介通过在首次未授权高扇出写入前隔离或抽象载荷来切断后代。

### 2.3 关键实现细节

- **风险打分**：$r(e)=\min(1,\sum_i w_i f_i(e))$，特征包括：原始内容违规 $f_{raw}$、跨委托方流 $f_{cross}$、下游扇出 $f_{fanout}$、权限提升 $f_{priv}$、外部投递 $f_{external}$、敏感细节请求压力 $f_{sem}$。实现采用固定权重、固定阈值与规则覆盖（如"外部→内部 + 毒化/原始内容"触发阻断；"毒化 + 共享原始/共享文档"触发隔离；风险 ≥ 0.50 触发安全视图重写；风险 ≥ 0.30 触发租约降级）。
- **安全视图构造**：确定性策略驱动重写，如把精确预算值替换为"存在预算约束"、把内部延迟理由替换为粗粒度抽象、隐藏客户/项目标识与凭据类标记；若校验失败（无法确认无精确原始值）则**失败关闭（fail closed）**，改为隔离。
- **隔离与传播权利收窄**：原始载荷存入非模型可见区域，下游只收到决策记录、安全占位符或已校验安全视图；通过确定性控制元数据把原始可见性降为抽象可见性、移除外部/工具权限、减少扇出或限制转发。
- **运行时步骤（7 步）**：事件归一化并挂接因果父节点 → 依据策略注册表检测受保护片段与允许抽象级别 → 检查原始读者授权、禁止通道与目标区域约束 → 计算风险特征与分数 → 选择动作 → 构造并校验安全视图 → 发出中介后事件、更新传播状态、记录脱敏审计条目。
- **不变量**：在完全中介与安全视图可靠的前提下，PAPC 发出的所有非隔离写入、发送、工具调用与最终输出均满足注册的原始披露策略；证明通过对事件序列的归纳完成。

## 3. 实验设计

- **主场景**：企业供应商更新（vendor-update）工作流。内部智能体通过私有记忆、共享原始记忆、安全视图记忆、工作区文档与智能体间消息协作，准备面向供应商的项目更新。任务允许粗粒度披露（承认存在预算约束或内部时间问题），禁止精确预算值、事件理由、私有客户/项目引用与凭据类标记。
- **智能体角色**：特权规划者（Planner）、特权财务智能体（Finance）、内部文档撰写者（Document Writer）、外部供应商端点（External Vendor）。
- **三种拓扑**（控制变量）：
  - **chain⁴**：规划者 → 财务 → 文档撰写者 → 供应商（窄而深）
  - **star⁴**：规划者为中心枢纽（聚合风险）
  - **blackboard⁴**：全对全交互 + 共享工作区（扇出最高）
- **攻击设置（7 种）**：none、摘要投毒（直接/间接）、工作区投毒（直接/间接）、通信劫持（直接/间接）；另有保留的**改写（paraphrase）变体**用于免标签验证。直接攻击显式索取敏感细节，间接攻击把请求伪装在业务文本中。
- **对比防御（4 种）**：
  - **No mediation**：无守卫，仅记录事件轨迹
  - **Static ACL**：阻断硬禁止通道与未授权原始接收者，无语义/拓扑推理
  - **Prompt filter**：直接短语/模式过滤，无安全视图重写
  - **PAPC**：加入溯源、拓扑/扇出、安全视图重写、隔离与传播权利收窄
  - 另有 **PAPC label-free**（移除攻击标签/标识/模式与评测标签）与 **No-semantic ablation**（去掉语义敏感细节模式）
- **Benchmark 与运行矩阵**：
  - RQ1：适配的检索记忆（AgentPoison 风格）containment check
  - RQ2：确定性拓扑套件，54 个攻击阳性无中介运行（每拓扑 18 次）
  - RQ3：MiniMax 最终写入者矩阵 252 次（3 拓扑 × 7 攻击 × 4 防御 × 3 种子），其中 PAPC 子集 63 次
  - RQ4：确定性免标签 540 次（3×10×6×3）+ 定向 MiniMax 免标签 72 次（2×3×4×3）；匹配比较计数为 90 与 18
- **指标**：任务成功（确定性规则/模板检查）、未授权原始暴露（跳过隔离/阻断事件的精确原始值字符串匹配）、外部原始暴露、级联规模/深度、权限触达（0–5 级）、评测标签使用计数。

  - **公平性限制**：多个"持平"出现在干净或低压组（双方本已零暴露），因此改进幅度主要体现在高压/间接攻击组；未做完整的组件隔离消融（只做了去语义模式一项）；未测试自适应对手。

## 6. 主要结论与发现

- **RQ1（中间状态暴露）**：无防御时被投毒检索内容被暴露（0.467）、攻击显现非零（0.253）；PAPC 下风险内容可在内部被检索（0.440），但**暴露给模型的上下文与

最终输出均不含未授权原始值（原始暴露与外部原始暴露均为 0.0），攻击标签显现也归零；即 PAPC 把“风险内容可被内部检索”与“风险内容可进入模型上下文、写入共享状态或抵达外部通道”解耦，从而验证了事件级中介对中间状态损失的控制能力。

- **RQ2（拓扑放大）**：在 54 次攻击阳性、无中介的确定性拓扑运行中，chain、star、blackboard 的暴露与级联表现随扇出和共享程度上升而恶化；blackboard 因全对全读写与共享工作区，最易把一次未授权原始写入放大为多跳、多读者污染，star 次之，chain 相对较窄但仍可通过最终写入者外泄。PAPC 在各拓扑下均在首次未授权高扇出写入或外部投递前介入，使级联规模/深度与权限触达显著收缩，说明隐私损失不仅取决于“谁说了什么”，也取决于平台拓扑与事件顺序。

- **RQ3（最终写入者矩阵）**：在 3 拓扑 × 7 攻击 × 4 防御 × 3 种子的 252 次 MiniMax 最终写入者运行中，No mediation 在直接/间接投毒与通信劫持下出现未授权原始暴露和外部原始暴露；Static ACL 能挡住硬禁止通道与未授权原始接收者，但对经摘要、工作区或改写包装后的语义泄漏无能为力；Prompt filter 可拦截显式敏感短语，却无法处理拓扑扇出、权限提升与持久化共享状态中的后续传播。PAPC 的 63 次子集全部任务成功（1.0），未授权原始暴露与外部原始暴露均为 0.0，且未以牺牲任务完成为代价；其优势主要出现在高压、间接与高扇出组，而在干净或低压组多与基线持平，符合“只在风险事件上介入”的设计预期。

- **RQ4（免标签与鲁棒性）**：确定性免标签 540 次与定向 MiniMax 免标签 72 次表明，移除攻击标签、评测标识与专用攻击模式后，PAPC 仍能依据策略、溯源、拓扑/扇出、权限和传播权利状态作出中介决策；匹配比较中的 90 组确定性与 18 组定向 MiniMax 运行显示，PAPC 相对无中介、Static ACL 与 Prompt filter 在“改进/持平”计数上占优，且未出现明显任务成功回退。改写变体下，表层关键词过滤进一步失效，而 PAPC 的安全视图重写与隔离仍可阻断原始值语义的未授权外泄，说明其不依赖固定攻击字符串。

- **消融发现**：No-semantic-pattern 消融在任务成功上与完整 PAPC 持平，但未授权原始暴露升高，外部原始暴露大体持平。这表明语义敏感细节模式主要贡献于“内部共享状态与模型上下文中的原始值识别”，而外部暴露控制还依赖拓扑、通道与权限规则；同时也说明 PAPC 的效果并非单一模式匹配，而是多信号组合与失败关闭策略共同作用。

- **总体结论**：论文主张，在 AI 介导工作流中，隐私治理应从“最终输出审核”上升为“运行时状态转换的中介”。PAPC 将策略、溯源、拓扑/扇出、权限、传播权利状态与内容信号统一到事件级决策中，通过允许、安全视图重写、隔离、阻断与传播权利收窄五类动作，在信息落地前切断未授权原始值的下游传播。其核心贡献不是某个单点过滤器，而是把事件级中介确立为一种平台治理原语：同一原始值在不同拓扑与扇出下具有不同外部性，因而治理必须理解“信息将流向何处、被谁读取、是否提升权限、是否触达外部”。

- **局限与边界**：作者未报告 GPU 型号、数量或训练时长，因为方法本身不训练模型，算力消耗仅为少量 MiniMax 最终写入调用；未系统测量延迟、吞吐与过度阻断成本，也未在真实多租户平台上部署验证。实验覆盖单一企业供应商更新场景、一个最终写入模型与有限智能体角色，未测试自适应对手、模型自身记忆持久化或跨平台联邦传播。消融仅覆盖去语义模式一项，未完整隔离溯源、拓扑、权限、传播权利等组件贡献。因此，PAPC 的证据更应被理解为“在受控基准与确定性中介条件下有效”，其平台级收益与代价仍需在更开放、对抗性更强的环境中检验。

- **启示**：对平台设计者而言，隐私控制点应前移到记忆写入、工作区更新、智能体消息与工具调用等事件；对研究者而言，需要把拓扑与扇出纳入隐私外部性度量，并发展可验证的安全视图、传播权利租约与失败关闭机制；对评测而言，免标签验证与匹配比较比仅报平均泄漏率更能揭示防御是否真正依赖攻击先验。
