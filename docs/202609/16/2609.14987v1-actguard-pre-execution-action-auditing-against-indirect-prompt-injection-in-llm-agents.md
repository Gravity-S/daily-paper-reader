## 摘要
大型语言模型（LLM）智能体通过工具调用与外部环境交互，但工具输出也可能使其暴露于间接提示注入（IPI）攻击。现有防御主要依赖提示加固、内容过滤、预生成计划或权限约束。这些方法往往难以应对复杂任务，或对外部内容过度净化，因而难以兼顾安全性与实用性。因此，关键挑战在于：在保持执行灵活性的同时，精确识别并移除真正诱导不安全动作的恶意内容。为应对这一挑战，我们提出 ActGuard，一种执行前动作审计框架。ActGuard 并不判断外部内容本身是否可疑，而是评估其是否导致当前动作偏离局部合理的预期。在每一步，ActGuard 预测即将执行的动作可能使用的工具，并构建局部工具先验，而不约束执行轨迹。在执行前，它将候选动作与该先验进行比较，并进行工具级对比分析和参数级证据定位，以识别工具选择与动作参数上的偏差。随后，验证器检查定位到的证据，仅掩蔽被确认为恶意的文本片段，并基于净化后的上下文重新生成动作。该设计在保持合法规划灵活性的同时，最大限度地减少无差别过滤带来的信息损失。我们在面向工具使用智能体的挑战性基准上评估 ActGuard。结果表明，ActGuard 将攻击成功率降低到与最先进防御相当的水平，同时使任务效用接近无攻击设置，实现了良好的安全—效用权衡。我们的代码已公开：https://github.com/binzhwang/ActGuard。

## Abstract
Large language model (LLM) agents interact with external environments through tool invocation, but tool outputs can also expose them to indirect prompt injection (IPI) attacks. Existing defenses mainly rely on prompt hardening, content filtering, pre-generated plans, or permission constraints. These approaches often struggle with complex tasks or over-sanitize external content, making it difficult to balance security and utility. The key challenge is therefore to preserve execution flexibility while precisely identifying and removing the malicious content that actually induces unsafe actions. To address this challenge, we propose ActGuard, a pre-execution action auditing framework. Rather than judging whether external content is inherently suspicious, ActGuard assesses whether it causes the current action to deviate from a locally reasonable expectation. At each step, ActGuard predicts the tools likely to be used by the upcoming action and constructs a local tool prior without constraining the execution trajectory. Before execution, it compares the candidate action against this prior and performs tool-level contrastive analysis and parameter-level evidence localization to identify deviations in tool selection and action parameters. A verifier then examines the localized evidence, masks only spans confirmed as malicious, and regenerates the action from the sanitized context. This design preserves legitimate planning flexibility while minimizing information loss from indiscriminate filtering. We evaluate ActGuard on challenging benchmarks for tool-using agents. Results show that ActGuard reduces attack success rates to a level comparable to state-of-the-art defenses while maintaining task utility close to the no-attack setting, achieving a favorable security-utility trade-off. Our code is publicly available at: https://github.com/binzhwang/ActGuard.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体通过工具调用（如网页搜索、邮件、文档访问）与外部环境交互，具备执行多步任务的能力。与纯文本生成模型不同，智能体持续观察环境状态并据此调整动作，外部反馈既是任务相关信息的重要来源，也是攻击者操控智能体决策的输入通道。
- **威胁**：间接提示注入（Indirect Prompt Injection, IPI）攻击者无需修改用户请求、系统提示或模型参数，只需在智能体访问的网页、邮件或文档中嵌入恶意指令。一旦这些内容进入上下文，LLM 难以区分可信用户意图与不可信环境内容，可能将注入指令误认为用户授权命令并执行未授权动作。
- **现有防御的局限**：
  - **提示加固类**（Spotlighting、Prompt Sandwich、Tool Filter）通过分隔符或重复指令强化用户意图，但恶意指令仍留在上下文中。
  - **内容过滤类**（ProtectAI、PromptGuard2、PIGuard）判断工具输出是否含注入，但难以区分合法任务信息与恶意内容，导致漏报或过度过滤造成效用下降。
  - **系统约束类**（Progent、CaMeL、DRIFT）施加权限控制或固定执行计划，但动态任务需要智能体根据未观测的环境反馈重新规划，过早限制工具会阻断合法操作。
  - **最新归因类**（内容消融、反事实重执行、注意力分析）面临重复注入低估、非显著威胁遗漏、仅检测劫持而无法定位触发源等问题。
- **核心挑战**：如何在保持执行灵活性的同时，精确识别并净化真正诱导当前动作的恶意内容，从而缓解安全—效用的固有权衡。
- **整体含义**：论文主张将防御目标从“判断外部内容是否可疑”转向“评估该内容是否导致当前动作偏离局部合理的预期”，以动作审计而非内容过滤为核心视角。

## 2. 方法论

### 2.1 核心思想

ActGuard 是一个**执行前动作审计框架**，通过状态自适应的局部参考（local reference）审计每个候选动作，识别驱动动作偏离局部合理行为的外部证据，而非过滤整个观察或强制固定执行计划。

### 2.2 三大组件

**（1）Step-wise Planning（逐步规划）**

- 不依赖约束执行轨迹的全局长时程计划，而是在生成当前候选动作的同时，预测下一步可能使用的工具集合，形成局部工具先验 \(F^{(t+1)}_{prior}\)。
- 公式：\((a_t, F^{(t+1)}_{prior}) \sim \pi(\cdot \mid q, H_t)\)，其中 \(a_t = (f_t, \theta_t)\) 为当前动作，\(q\) 为用户请求，\(H_t\) 为交互历史。
- 仅预测工具名称而非参数，因为下一步参数高度依赖当前动作的观察结果。
- 该先验**不是执行白名单**，而是审计参考，允许智能体根据新观察调整路线。

**（2）Dual-Granularity Evidence Localization（双粒度证据定位）**

- 将历史中不可信的工具输出切分为细粒度文本块 \(S=\{s_1,\dots,s_k\}\)，合并语义近重复块以减少归因低估。
- **工具级对比归因**：当候选工具 \(f_t \notin F^t_{prior}\) 时，检索与候选动作最相关的 top-k 文本块，并计算对比归因分数。参考工具选择采用长度归一化对数概率：
  \[
  f^t_{prior} = \arg\max_{f \in F^t_{prior}} \frac{1}{|f|}\log P(f \mid q, H_t)
  \]
  对比归因分数：
  \[
  \Delta(s) = \frac{1}{|f_t|}\log\frac{P(f_t \mid q, H_t)}{P(f_t \mid q, H_t \setminus s)} - \frac{1}{|f^t_{prior}|}\log\frac{P(f^t_{prior} \mid q, H_t)}{P(f^t_{prior} \mid q, H_t \setminus s)}
  \]
  该分数衡量遮蔽片段 \(s\) 后，候选工具相对参考工具的对数概率优势下降程度。\(\Delta(s) > \tau\) 的块被送交验证器。
- **参数级证据定位**：即使工具名符合先验，攻击者仍可保持合理工具名而篡改 URL、地址、收件人或命令等参数。从候选参数 \(\theta_t\) 提取可检索内容，在 \(S\) 上检索 top-k 作为参数级证据。

**（3）Verifier-Guided Context Sanitization（验证器引导的上下文净化）**

- 将定位到的候选块 \(C_t\) 扩展为含邻居块的证据集 \(E_t = \bigcup_{s_i \in C_t}(\{s_i\} \cup \text{Adj}(s_i))\)。
- 验证器联合检查用户请求 \(q\)、候选动作 \(a_t\)、历史观察序列 \(O^{t-1}\) 与扩展证据集，输出确认的恶意块集合 \(M_t\)：
  \[
  M_t = V(q, a_t, O^{t-1}, E_t),\quad M_t \subseteq E_t
  \]
- 若 \(M_t = \emptyset\)，动作通过；否则仅掩蔽确认恶意块 \(H^{safe}_t = \text{Mask}(H_t, M_t)\)，从净化上下文重新生成动作，并再次审计，最多允许两次修复尝试。
- 掩蔽占位符为 `[Removed suspicious instruction from external tool result.]`。

### 2.3 算法流程（Algorithm 1 摘要）

1. 循环：策略生成候选动作与下一步工具先验。
2. 提取工具输出，切块并合并近重复块。
3. 若候选工具不在先验内 → 工具级对比归因定位；否则 → 参数级检索定位。
4. 扩展邻居块形成证据集，验证器判断。
5. 若无恶意块则返回动作与先验；否则掩蔽确认块、更新历史、重新生成并重新审计。

### 2.4 默认配置

- 温度 0；块长度 80–180 字符；嵌入模型 all-MiniLM-L6-v2；top-k=5；对比归因模型 Meta-Llama-3.1-8B-Instruct；阈值 τ=0；相似块分组阈值 0.9；验证器 GPT-5-mini；预测下一步工具集大小 1–3；邻居扩展各 1 块；最大修复尝试 2 次。

## 6. 主要结论与发现

- **安全—效用权衡**：ActGuard 在 AgentDyn 和 AgentDojo 上均实现最佳整体安全—效用平衡，ASR 降至与最先进防御相当水平，同时 UAU 接近无攻击设置。
- **AgentDyn 结果**：GPT-4o-mini 下平均 NAU 48.33、UAU 47.50、ASR 2.14；DeepSeek-V4-Flash 下 ASR 降至 0.00、UAU 57.50；Gemini-2.5-Flash

下 ASR 为 0.00、UAU 达 58.33，显示在更强后端下安全与效用可同时保持。综合三后端，ASR 介于 0.00–2.14，UAU 介于 47.50–58.33，NAU 介于 48.33–60.00，说明防御未以牺牲大量任务完成为代价。
- **AgentDojo 结果**：在 GPT-4o-mini 后端下，ActGuard 的 ASR 明显低于提示加固与内容过滤类基线，UAU 与 NAU 的差距控制在较小范围内，验证了方法在短轨迹、任务较易完成的基准上同样有效，而非仅在长轨迹场景中占优。
- **对比基线**：提示类方法（Spotlighting、Prompt Sandwich、Tool Filter）虽保留较高 NAU，但 ASR 下降有限；过滤类方法（ProtectAI、PromptGuard2、PIGuard）在部分套件上降低 ASR，却常因误删合法外部内容导致 UAU 明显下滑；系统类方法（Progent、CaMeL、DRIFT）对固定流程任务有效，但在需要动态重规划的任务中过早限制工具，UAU 损失较大。ActGuard 在多数套件上取得更优的 ASR–UAU 前沿。
- **规划策略对比**：逐步规划相较全局长时程计划显著提升 UAU，同时未削弱 ASR 抑制能力。原因在于全局计划一旦与真实环境反馈偏离，会把合法重规划误判为异常；逐步先验仅作审计参考，允许智能体在观测到新信息后调整路线。
- **证据定位分析**：对比归因消融显示，去掉对比参考（仅用遮蔽后候选工具概率变化）会因重复注入与非显著威胁导致归因低估，ASR 上升；阈值消融表明 τ=0 附近即可在召回与精确度间取得较好平衡，过高阈值会漏掉部分真实驱动块，过低则引入更多需验证器处理的候选块、增加成本。
- **验证器适配**：四种验证器后端（GPT-4o-mini、GPT-5-mini、Gemini-3.1-Flash-Lite、DeepSeek-V4-Flash）均能带来 ASR 下降，说明框架对验证器选择具有一定鲁棒性；验证器能力越强，确认恶意块的精确度越高，误掩蔽合法内容的概率越低，UAU 损失越小。
- **自适应攻击**：在重复载荷压力攻击下，合并语义近重复块的策略缓解了归因低估，ASR 未随载荷重复次数增加而显著反弹；在验证器定向攻击下，攻击者试图构造绕过验证器判断的载荷，ActGuard 仍保持较低 ASR，但相比标准攻击场景 ASR 略有上升，说明验证器仍是潜在攻击面，需持续加固。
- **计算成本**：相比基线，ActGuard 引入了嵌入检索、对比归因对数概率计算与验证器调用等额外开销，按 token 归一化后的成本高于纯提示类方法，但低于或接近部分系统类与过滤类方法；每任务延迟增量在可接受范围内，且仅在触发审计或定位到候选证据时才调用验证器，具有一定的按需计算特性。
- **组件消融**：去除嵌入检索会削弱证据定位的召回；去除对数概率过滤会引入更多无关块、增加验证器负担并可能降低精确度；去除对比参考会加剧归因低估；去除参数级定位则无法覆盖"工具名合规但参数被篡改"的攻击，ASR 上升。四类组件均对最终安全—效用平衡有正向贡献。

## 7. 局限性与未来工作

- **验证器依赖**：框架安全性在很大程度上依赖验证器的判断质量，验证器自身可能被精心构造的载荷误导，构成定向攻击面；未来可探索多验证器交叉校验或对抗训练以增强鲁棒性。
- **成本与延迟**：额外的嵌入、对数概率与验证器调用带来推理开销，在超长轨迹或高频工具调用场景下成本可能累积；按需触发与缓存机制是潜在优化方向。
- **归因模型局限**：对比归因依赖开源模型的对数概率估计，对极长上下文或语义高度纠缠的证据，归因信号可能被稀释；更细粒度或因果化的归因方法值得进一步研究。
- **未与并发防御定量对比**：受限于缺乏受控可复现的官方实现与协议差异，作者未与 AttriGuard、CausalArmor、AgentSentry、ICON 等方法做定量比较，结论的横向可比性有待后续统一基准验证。
- **攻击面覆盖**：当前评估主要针对间接提示注入，对多模态输入、工具链组合攻击、跨会话持久化注入等更复杂威胁的覆盖仍有限。

## 8. 总体评价

ActGuard 将智能体提示注入防御的视角从"内容是否可疑"转向"该内容是否驱动了当前动作偏离局部合理预期"，以执行前动作审计为核心，通过逐步规划提供状态自适应参考、双粒度证据定位缩小归因范围、验证器引导的上下文净化实现精准掩蔽。方法在保持执行灵活性的同时缓解了安全—效用权衡，在 AgentDyn 与 AgentDojo 上取得较优的 ASR–UAU 前沿，并通过规划策略、证据定位、验证器适配、自适应攻击与组件消融等实验较系统地验证了各组件必要性。其主要价值在于提出了一种可插拔、按需计算的审计式防御范式，局限在于对验证器质量与归因模型的依赖以及推理开销，未来工作可围绕验证器鲁棒性、归因精度与成本优化展开。
