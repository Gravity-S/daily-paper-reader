## 摘要
Agent2Agent（A2A）协议目前由 Linux 基金会管理，是一项开放标准，使自主 AI 代理能够跨组织边界相互发现、认证并委派任务。A2A 旨在补充用于工具集成的模型上下文协议（MCP），正迅速成为多代理生态系统的横向通信层。然而，该协议的安全性尚未得到任何系统性分析。本文提出 A2ABreak，这是对 A2A 协议的首个严格系统性安全分析。我们引入一种新颖框架，利用 LLM 辅助直接从自然语言规范中提取经验证的有限状态机，从 929 条形式化陈述中生成包含 37 个状态和 76 个迁移的统一模型，然后在该模型上进行系统性推理，在完全合规假设下通过对抗性验证发现协议级漏洞。我们的分析揭示了 11 个新漏洞，每个漏洞均可由符合规范的对手利用，而无需任何实现缺陷。这些发现包括通过未受保护的上下文标识符进行跨客户端上下文注入、通过委派链中的多跳身份丢失进行凭证窃取，以及通过宣称未经证实能力声明的恶意代理进行数据外泄。A2ABreak 在独立专家评审下达到 73.3% 的精确率和 84.6% 的 F1 值，而基于同一规范的零样本 LLM 基线产生零个已确认发现，表明明确的模式化基础对于可靠的协议安全分析至关重要。

## Abstract
The Agent2Agent (A2A) protocol, now governed by the Linux Foundation, is an open standard that enables autonomous AI agents to discover, authenticate with, and delegate tasks to one another across organizational boundaries. Designed to complement the Model Context Protocol (MCP) for tool integration, A2A is rapidly emerging as the horizontal communication layer of the multi-agent ecosystem. Yet the protocol's security has received no systematic analysis.   This paper presents A2ABreak, the first rigorous systematic security analysis of the A2A protocol. We introduce a novel framework that utilizes an LLM-assisted extraction of a verified finite-state machine directly from the natural-language specification, producing a unified model of 37 states and 76 transitions from 929 formalized statements, and then systematically reasons over this model to discover protocol-level vulnerabilities through adversarial verification, under a full-compliance assumption.   Our analysis uncovers 11 new vulnerabilities, each exploitable by a specification-compliant adversary without requiring any implementation flaw. Among the findings are cross-client context injection through unprotected context identifiers, credential harvesting via multi-hop identity loss in delegation chains, and data exfiltration through rogue agents advertising unattested capability claims.   A2ABreak achieves 73.3% precision and 84.6% F1 against independent expert review, while a zero-shot LLM baseline operating over the same specification produces zero confirmed findings, demonstrating that explicit formal grounding is essential for sound protocol security analysis.

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想
将自然语言协议规范转化为**经验证的有限状态机（FSM）**，再在 FSM 上进行受约束的 LLM 推理与**对抗性验证**，在"完全合规假设"下发现协议级漏洞。整个流程由三阶段构成，阶段边界设有人工检查点，防止错误静默传播。

### 2.2 形式化定义
- **规范语料**：C = ∪ₖ Cₖ，去重后 |C| = N。
- **协议 FSM**：F = (S, s₀, T, Σ, S_f)，其中 S 为状态集，s₀ 为初始状态，S_f ⊆ S 为终止状态，Σ 为事件字母表，T ⊆ S × Σ × G × S 为带守卫条件 G 的迁移关系；迁移 τ = (s, σ, g, s′) 表示在守卫 g 满足下由事件 σ 触发从 s 到 s′ 的状态变化。
- **协议漏洞**：V = (π, ρ, ϕ)，即一条可行攻击迹 π = ⟨τ₁,…,τ_k⟩、一个被违反的安全属性 ρ、以及一个其缺失导致违反的缺失原语 ϕ。可行要求每条迁移存在于 T 中，且守卫可由完全合规方满足。

### 2.3 三大技术挑战（C1–C3）
- **C1**：自然语言规范缺乏形式语义，同一句话可能同时包含前置条件、规范要求与数据类型约束，无法直接解释出忠实模型。
- **C2**：LLM 生成开放式，缺乏真值参考模型，错误会静默传播；人工构建成本极高（蜂窝协议曾需约 2800 人时）。
- **C3**：漏洞分析必须**可靠（sound）**——提取规则须对应真实规范陈述，形式表示须保持语义，报告的缺失原语须确实不存在（而非定义在其他章节）。

### 2.4 三大解决方案（S1–S3）
- **S1 双通道语义分离**：将规范解释拆为独立的**结构抽取**（数据类型、字段、对象层次、枚举）与**行为抽取**（状态迁移、守卫、规范要求、协议操作）两遍，分别用各自优化的抽取模式，再对账合并，避免定义语义与行为语义交叉污染。
- **S2 输入归约 + 扩展思考**：将开放式综合问题分解为一系列有界、可独立验证的决策。例如 929 条陈述中仅 283 条（30%）带迁移结构进入 FSM 构建，其余提前过滤。每步用具备扩展思考能力的模型。
- **S3 领域特定约束语言**：在所有提示中嵌入形式化约束，充当领域特定语言。抽取阶段定义带类型字段的迁移模式 `s1 --c/a--> s2`（用 &、|、! 与点限定属性表达守卫/触发/后置条件），强制产出机器可验证形式表示而非自由文本摘要；分析阶段定义何谓有效发现（缺陷必须存在于"协议未说"之处；模糊委派不算有意排除；只规定结果而未给机制即缺失原语）。

### 2.5 三阶段流程

**Stage A：规范形式化（产出 929 条结构化陈述）**
- A1 结构抽取：产出 FSM_STATE（初始/中间/终止）、CONSTRAINT（全局不变量）、IMPLICIT_TRANSITION（由定义表和流程图隐含、无 RFC 2119 关键词的状态变化）。
- A2 行为抽取：仅针对含 RFC 2119 关键词的句子，编码为 BEHAVIORAL 迁移，保留规范性强度（must/shall/should/may），不重复抽取定义表。
- A3 对账：合并两遍输出，检测并折叠精确/近似重复，保留双向来源标识；歧义案例由 LLM 解决并强制人工复核。
- A4 规范验证：每条陈述对照实时规范源文本独立核验，自动检测幻觉状态、误归因关键词、来源中不存在的守卫；失败者修正或删除，形成强制性人工检查点。
- 每条迁移表示为 ⟨s1, pre_cond, trigger, post_cond, s2⟩。

**Stage B：FSM 构建**
- B1 输入过滤（无 LLM）：按协议阶段分区，仅保留具备足够迁移结构的陈述，输出六个阶段输入包。
- B2 逐阶段 FSM 合成：为六个阶段分别构建完整 FSM，去重状态、丢弃非协议会话状态、推断隐含状态；每个状态赋予 actor 字段（client/server/shared/unknown），**shared-actor 状态标记信任边界，是 Stage C 的主要目标**；缺口查询实时规范，无法解决者记入诊断列表（人工检查点）。
- B3 阶段间迁移解析：识别六个阶段间的跨阶段边（含 Task Execution ↔ Interruption 的双向循环），确定触发事件与守卫，仅产出跨阶段迁移。
- B4 统一 FSM 组装：确定性合并六阶段 FSM 与跨阶段边，再进行两轮去重：
  - D1 确定性：规范命名、合并跨阶段重复状态、移除身份迁移、合并语义等价迁移、结构验证与启发式检测。
  - D2 LLM 语义：处理候选问题，移除抽象元状态并重分配其行为、折叠平凡直通状态、丢弃不可达的部署生命周期状态、为断开的子生命周期补全入边。
- 最终得到 **37 个状态、76 条迁移**、零孤儿状态、完整引用完整性的统一 FSM。

**Stage C：安全分析（完全合规假设）**
- C1 漏洞发现：检查敏感迁移上缺失授权守卫、阶段边界缺失检查、未经过必需前驱即可到达的状态、事件字母表缺口等结构属性。两个前置过滤：(1) 攻击迹必须完全在 A2A 协议内可执行、无带外机制；(2) 网络搜索原始规范确认缺口是真实缺失原语而非有意设计。多次独立发现运行合并候选以提高召回。
- C2 对抗与人工验证（四步）：(1) 在统一 FSM 中锚定攻击迹，丢弃无法由有效状态/迁移重构的路径；(2) 在完全合规下逐步执行确认可利用性，且无现行规范规则可阻止；(3) 全面检索规范确认原语确实缺失；(4) 独立人工评审验证 FSM 迹与规范证据。失败者降级为不确定或丢弃并记录理由。最终输出分为已确认发现、已丢弃候选、不确定案例，保留完整审计轨迹。

## 6. 主要结论与发现

- **发现 11 个协议级漏洞**，均可在完全合规、无任何实现缺陷或错误配置下被利用，覆盖发现、发起、任务执行、中断四个阶段（映射到 STRIDE 与 CIA 影响，见表 3）。代表性三项：
  1. **跨客户端上下文注入（Cross-Client Context Injection，§3.4.1、§3.4.3）**：contextId 无所有权绑定与访问控制，任何已认证客户端只要知道有效 contextId，即可用 `SendMessage(taskId=∅, contextId=X)` 向他人上下文注入任务，读取受害者的累积状态并污染后续交互。根因是 §13.1 的授权 MUST 仅作用于 task 操作，上下文层无对应要求。
  2. **多跳身份丢失（Multi-Hop Identity Loss，§7.2、§7.6.2）**：身份仅在传输层逐跳建立、不跨委派跳传播；下游代理与凭证提供者无法验证原始主体身份与委派来源，恶意中间代理可静默截留并重放转发凭证。
  3. **未认证能力声明（Unattested Skill Claims，§4.4.5、§8.4）**：AgentSkill 数据模型全为自声明字段，无验证/证明/质询机制；AgentCard 签名（JWS）只证明"谁发布了卡"，不证明技能真实性。合规恶意代理可虚报能力、接收含敏感数据的委派任务、返回伪造产物而不触发任何协议级错误。
- **性能结论**：漏洞分析精确率 **73.3%**、F1 **84.6%**；FSM 构建在 TCP 基准上精确率 0.76、召回率 0.95、F1 0.84（恢复全部 11 状态、19/20 迁移，唯一遗漏为 LISTEN → SYN_SENT 边因事件标签变体）。
- **零样本对比结论**：Claude Opus 4.6 两次独立运行共 9 个候选攻击，**全部被对抗验证拒绝**，主要因其攻击迹已被模型未考虑到的规范要求禁止——表明若无显式 FSM 作为基础，即使先进推理模型也缺乏对协议行为的精确表示。

- **精炼结论**：RQ3 显示 FSM 从"粗粒度合成"到"统一组装"经历了大幅收敛——B2 逐阶段合成得到约 38 状态 / 245 迁移，经 B4 的两轮去重（D1 确定性 + D2 LLM 语义）后压缩为 37 状态 / 76 迁移，即约 **69% 的迁移被判定为冗余、等价或非协议会话状态**而被移除；D2 单独成本仅 $1.08，却贡献了对抽象元状态、平凡直通状态与不可达部署生命周期状态的清理。这印证了 S2"输入归约"与"分阶段合成 + 后置合并"策略的有效性：先允许过度生成以保证召回，再用确定性与语义两轮收敛保证精度，同时保持零孤儿状态与完整引用完整性。
- **规范复杂度分布结论（RQ4）**：A2A 规范在六个协议阶段上的陈述、状态与迁移分布高度不均，任务执行（Task Execution）与发现（Discovery）阶段承载了最多的行为规则与信任边界（shared-actor 状态集中于此），而中断（Interruption）阶段因存在与任务执行的双向循环边，成为跨阶段攻击迹的关键枢纽——这解释了为何最终确认的漏洞集中落在发现、发起、任务执行、中断四个阶段。
- **成本结论（RQ5）**：端到端单次运行 $40.97，其中规范形式化与 FSM 构建占 $34.67（约 85%），安全分析仅 $6.30（约 15%）；成本主要由"高推理 + 扩展思考"的 Opus 调用驱动，最贵单步 B2（$11.64）体现了逐阶段 FSM 合成的推理负担。无 LLM 的确定性步骤（B1、B4、D1）零成本，说明流水线在架构上刻意将"昂贵推理"限制在不可归约的决策点上。
- **整体含义**：论文的核心论断是——A2A 规范把**上下文所有权、委派来源、能力证明、凭证作用域**等本应作为"协议不变量"的安全属性，降格为"实现问题"或"部署责任"，因此在**完全合规**前提下即存在可利用的协议级缺陷。这不仅是 A2A 的问题，更是对"以自然语言 RFC 定义、以 SHOULD/MAY 表达关键控制"的代理互操作标准的一次结构性警示：规范合规 ≠ 安全。

## 7. 局限性

- **单一目标协议**：分析对象仅为 A2A v1.0 一个规范，结论的外部有效性有限；A2A 与 MCP 的组合攻击面（水平 + 垂直通信栈）未被覆盖。
- **外部 FSM 基准代表性不足**：唯一真值基准是 PSMBench 的 TCP 状态机（11 状态 / 20 迁移），规模远小于 A2A 的 37 状态 / 76 迁移，且领域差异大，难以充分证明抽取能力可线性外推。
- **流水线依赖 LLM 的非确定性**：尽管设有 A4、B2 缺口、C2 等多处人工检查点与自动核验，仍无法从原理上保证抽取的**完备性**（可能漏掉未被注意到的规范陈述），因此"漏洞集合"应理解为**下界**而非穷举。
- **召回样本量偏小**：漏洞发现仅 5 次独立 C1 运行、共 17 个候选，统计稳健性有限；零样本基线也仅 2 次运行。
- **人工评审细节缺失**：未报告评审专家人数、资历、独立性与一致性指标（如 Cohen's κ），"11 个真阳性"的可重复性难以评估。
- **缺乏系统性消融**：双通道语义分离（S1）、输入归约 + 扩展思考（S2）、领域特定约束语言（S3）各自的独立贡献未被定量拆分。
- **缺乏横向对比**：未与 ProVerif、Scyther、Tamarin 等形式化验证工具，或其他 LLM 驱动的协议抽取方法对比。
- **未验证实际部署影响**：漏洞的可利用性是在 FSM 模型层面确认的，未在真实 A2A 实现或多代理系统上做端到端 PoC 验证。
- **成本与可扩展性**：$40.97/次 且强依赖顶级闭源模型，对更长规范或频繁迭代的协议，成本与可重复性均构成门槛。

## 8. 对后续研究的启发

- **把安全属性提升为协议不变量**：后续 A2A 版本（或同类标准）应考虑将 contextId 所有权绑定、跨跳身份传播、AgentSkill 证明等从 SHOULD/MAY 提升为 MUST 级协议约束，并为 AgentCard 签名引入能力质询机制。
- **"NL 规范 → 经验证 FSM → 对抗验证"范式的推广**：该流水线可迁移至 MCP、其他代理互操作协议、乃至传统网络协议的规范审计，尤其是缺乏参考实现、无法做实现级分析的新兴标准。
- **形式化方法的混合使用**：将 LLM 抽取的 FSM 作为前端，接入 ProVerif/Tamarin 等后端做自动化性质证明，可弥补 LLM 推理的可靠性与完备性缺口。
- **基准建设**：亟需面向代理协议的 FSM 抽取与漏洞发现基准（含真值状态机与标注漏洞），以支撑可比较的评估。
- **多代理生态的组合安全**：A2A（水平）× MCP（垂直）的交叉信任边界、委派链上的凭证传播与重放防护，是值得系统研究的新方向。
- **成本—可靠性权衡研究**：如何在保证可靠性的前提下，用更小/更廉价的模型或缓存复用替代昂贵的逐阶段 Opus 推理。

## 9. 总体评价（客观定位）

- **贡献层面**：论文的突出价值在于**方法论首创性**——首次给出 A2A 的完整交互生命周期 FSM、首个结构化威胁模型，以及一套"合规假设下发现协议级漏洞"的可审计流水线。11 个确认漏洞中的跨客户端上下文注入、多跳身份丢失、未认证能力声明三项，均指向规范层面的结构性缺失而非实现缺陷，具有现实指导意义。
- **方法严谨性**：三层验证（自动核验 A4、对抗验证 C2、独立人工评审）与"接受 / 拒绝 / 重复 / 不确定"的完整审计轨迹，使其在 LLM 驱动安全分析类工作中属于较严谨的一档；精确率 73.3%、F1 84.6% 的漏洞分析与 TCP 上 0.76/0.95 的 FSM 抽取指标，提供了可量化基线。
- **主要保留**：结论的**完备性**受制于单一协议、单一外部基准、小样本运行与 LLM 非确定性；人工评审的独立性细节缺失削弱了金标准说服力；缺少消融与横向对比，使各组件贡献与相对优势难以归因。因此，其"发现 11 个漏洞"应被读作**在给定假设下可靠确认的下界集合**，而非穷举清单。
- **实践启示**：对 A2A 部署方而言，论文提示不能依赖"规范合规"作为安全保证，需在应用层自行补足上下文访问控制、委派来源验证与技能证明；对标准制定方而言，则提示关键安全语义必须显式写入协议不变量，而非留给实现者。
