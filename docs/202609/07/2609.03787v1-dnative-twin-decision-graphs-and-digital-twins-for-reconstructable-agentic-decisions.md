## 摘要
AI 智能体日益频繁地收集证据、调用工具、应用约束，并做出人们或软件可能付诸行动的决策。仅凭最终输出，无法显示是哪些证据、工具状态、规则、授权或行动路径产生了该决策。我们提出了 DNative-Twin——一种图原生数字孪生，它将已承诺的智能体决策记录为类型化轨迹，并在声明的条件下重新执行其决策机制。该图将智能体观察到的状态、所遵循的路径以及最终行动背后的授权联系起来。孪生体同步这些信息，隔离地回放该机制，并在受控变化下进行比较。我们使用三个公共流程日志和受控回放套件，在企业决策流程中实例化了该框架。实验识别出一个具体缺陷：图结构可以定位所表征的变化，但无法确定未观察到的工具状态会产生什么后果。在一项包含 300 个注入实例的三条件受控实验中，当加入重放契约状态后，未解决分歧的召回率从 0 升至 0.667；当验证结果也可用时，进一步升至 1.0；留出集中不包含关键类实例。在所报告的平台上，处理 500 至 5,000 个 BPI 2020 案例的中位端到端时间从 0.794 秒增加到 8.889 秒。这些结果区分了图结构、回放上下文和验证证据在审查决策机制中的作用。

## Abstract
AI agents increasingly gather evidence, invoke tools, apply constraints, and produce decisions that people or software may commit to action. A final output alone cannot show which evidence, tool state, rule, authorization, or action path produced it. We present DNative-Twin, a graph-native digital twin that records a committed agentic decision as a typed trajectory and re-executes its decision mechanism under declared conditions. The graph links the state observed by the agent, the path it followed, and the authority behind the resulting action. The twin synchronizes this information, replays the mechanism in isolation, and compares it under controlled changes. We instantiate the framework in enterprise decision processes using three public process logs and controlled replay suites. The experiments identify a specific failure: graph structure localizes represented changes but cannot determine the consequence of an unobserved tool state. In a three-condition controlled experiment with 300 injected instances, unresolved-divergence recall increased from 0 to 0.667 when replay-contract state was added and to 1.0 when verification results were also available; the held-out set contained no critical-class instance. Across 500--5,000 BPI 2020 cases, median end-to-end time increased from 0.794 to 8.889 seconds on the reported platform. These results separate the roles of graph structure, replay context, and verification evidence in reviewing a decision mechanism.

## 2. 方法论：核心思想、技术细节与算法流程

### （1）决策图（Decision Graph）
- 决策相关系统状态被建模为多元组：
  - \(S_t = (B_t, K_t, P_t, T_t, H_t, A_t, O_t)\)，分别表示决策对象、版本化知识、策略与授权、工具及其状态、授权角色、智能体与技能、结果信号。
- 图模型为带时变属性的多关系异构图 \(G_t = (V_t, E_t, X_t, φ, ψ, ρ)\)：
  - 节点与边均带类型，ρ 元数据记录环境标签、时间、有效性区间、版本等。
  - 用多元图表达同一实体间多类型、多时间戳的关系。
- 定义了最小节点/边类型集合（表 I），分为四类：**决策上下文、执行、授权、决策实体**，并支持领域扩展。

### （2）决策轨迹与可重建性
- 决策机制定义为 \(M = (Q, π, Γ, Λ)\)，与状态图 \(G_t\) 分离，便于重放和比较候选机制。
- 约束集分解为 \(Γ = Γ_path ∪ Γ_temporal ∪ Γ_version ∪ Γ_app\)。
- 区分三个常被混淆的属性：
  - **Traceability（可追溯性）**：来源/溯源/版本
  - **Validity（有效性）**：当时是否合法/时效有效
  - **Contextual applicability（情境适用性）**：是否确实适用于当前决策状态
- 适用性判定：\(App(v, S_t) = 1[S_t \models A_v]\)，其中 \(A_v = scope(v) ∧ precondition(v)\)。**有效 ≠ 适用**。
- 决策轨迹定义为决策有界子图：\(T(b, z; [t0, t1])\)，并可通过拓扑排序转为时间有序序列。
- 区分 Recommendation（推荐）与 CommitmentEvent（承诺行动），给出承诺轨迹的形式化存在条件（Commited）。
- 决策可重建性（Recon）的充要条件包括：所有前置类型组可及、结果已覆盖或处于挂起状态、所有约束满足。
- 将失败分为三类：**捕获失败（capture failure）**、**机制失败（mechanism failure）**、**分歧（divergence）**。

### （3）跨环境对齐与差异分析
- 同步契约：\(σ: ΔG_real(t) → ΔG_twin(t′)\)，定义哪些状态被同步、以何种转换、何种新鲜度进入孪生。
- 场景扰动算子 \(W_δ\) 应用类型化干预 \(δ\) 生成新终端节点与轨迹。
- 对齐条件：\(Align(z_i, z_j | b, M, [t0, t1])=1\)（共享决策对象、重放血统、机制版本、观测窗口）。
- 图差异 \(D(T_i, T_j) = (ΔV, ΔE, ΔX, ΔP)\) 对比点集、边集、属性和决策路径。
- 区分**治理等价（governance equivalence）**与**实质性差异（material difference）**。
- 差异来源标签：\(Src ⊆ \{state, config, tool, stoch, mechanism\}\)。
- 裁决函数 \(Classify(d_{ij}, I, P, S_t)\) 返回四种标签之一，按优先级依次判定：**unresolved（证据不足）> critical（关键违规）> material（实质性变化）> benign（良性）**。

### （4）DNative-Twin 架构三阶段
1. **图投影与同步**：从多源（运营系统、Agent 活动、工具日志、策略记录等）采集事件，标准化为类型化图更新，将生产 ID 令牌化，敏感证据以受治理引用替代。
2. **隔离回放与扰动**：
   - 影子重放 \(T_shadow = Execute(M, State_twin, CR)\)；
   - 重放契约 \(CR\) 绑定决策对象、截止时间、治理状态、执行配置、环境；
   - 三种工具回放模式各有语义：
     - **Response injection**：测试下游机制能否复现历史观测下的受治理行为；
     - **Executable replay**：测试当前同步工具状态下的行为；
     - **Consequence-preserving stub**：无副作用地测试声明的结果/失败会带来什么。
3. **语义裁决与修订**：
   - 基于 GraphDiff 结合不变式与策略分类分歧；
   - 候选修订必须链接到触发证据，并满足 ReleaseReady 条件（不变式通过、关键场景全通过、material 分歧低于阈值、同步新鲜度等）；
   - 需要“GOV APPROVES”独立授权步骤后机制才可发布。

### （5）可执行规范
- 提供 7 条核心不变量（I1–I7），分别对应**推荐-承诺分离、可重建可达性、强制审查不可绕过、孪生隔离、知识版本可溯、分歧保留、情境适用性**，每条都有对应的图级检查方法和违背样例。
- 提供最小复现工件包（schema、示例图、扰动场景、重放契约、发布条件、六个脚本等）。
- 算法 1（Synchronize–Replay–Stress–Diff–Revise Loop）：观测→孪生隔离→轨迹提取→影子回放→不变式检查→对齐→差异→分类→循环扰动→评审→修订→发布。

### （4）真实数据回放实验
- 在 BPI 2020 PermitLog 的真实事件上构造 50 个对齐重放案例，比较三类工具回放模式产生的决策轨迹。结果显示：
  - 在同步状态一致时，三种模式得到的治理结论（approve / reject / require-review）高度一致；
  - 当注入工具状态偏移时，Executable replay 会产出不同于历史真实轨迹的路径，而 Response injection 可定位到“若历史状态下重放，哪些环节会出现分歧”；
  - Consequence-preserving stub 在不触发真实副作用的前提下，能正确预测声明的后果与失败传播路径。

## 4. 主要发现

- **图原生表示能够承载决策可重建性**：类型化决策图在真实日志（OCEL、BPI）上可自动构建，且能回答“为什么批准”“哪条规则适用”“哪个工具状态影响结果”等依赖查询。相较仅保留最终输出的基线，B3 条件下依赖查询准确率由 0.06 提升至 1.00。
- **轨迹对齐是可操作的定义**：论文给出的对齐条件在实践中可行，能够屏蔽无关环境差异，将候选决策轨迹配对比较，从而获得可解释的治理差异。
- **“有效”不等于“适用”**：实验反复表明，过期但语法有效的政策/授权在特定上下文中被错误应用，只有引入情境适用性判断后，才能将这类案例归类为 critical 而非 benign。
- **回放契约是稳定复现的锚点**：没有重放契约时，影子回放会因决策对象、截止时间、治理状态或执行环境的不确定而漂移；绑定契约后，相同输入状态产生一致性决策路径，验证了 RQ2。
- **受治理修订必须经过独立授权**：即使技术上通过全部不变式与差异阈值，机制发布仍需显式“GOV APPROVES”环节，以在人与自动化之间保留明确的责任边界。

## 5. 结果与分析：亮点与陷阱

### 亮点
- **提出了一个可落地的“审计孪生”模式**：与通用数字孪生不同，DNative-Twin 聚焦决策过程本身，而非物理对象或业务流程的全量镜像，从而显著降低同步负担并聚焦治理问题。
- **统一了多种记录的语义**：将工作流日志、Agent 追踪、溯源记录、策略版本、授权单据统一为类型化图更新，使得跨源比较不再依赖脆弱的字段映射。
- **引入扰动-回放-差异分析闭环**：支持“假设”类审计问题（例如“若当时预算是另一状态会怎样？”），这在现有日志分析工具中并不常见。

### 陷阱与风险
- **建模与同步成本高**：将异质来源全部投影到类型化图并保持同步新鲜度（freshness）需要大量工程投入；论文只在采购与许可流程上做了验证，扩展到复杂多域系统时，类型扩展与对齐规则可能迅速膨胀。
- **依赖人工定义的语义标签**：例如“critical”与“material”的判定阈值、差异来源标签的分配均依赖领域策略；自动分类仅能处理已显式编码的规则。
- **回放工具的忠实度是关键假设**：当决策机制包含未记录的随机性（如 LLM 采样）或外部副作用时，三类回放模式无法完全覆盖真实行为；论文对 LLM 的探针实验也显示重复调用存在输出变异，这会给“复现”带来内在不确定性。
- **裁决质量实验规模有限**：主要采用受控场景与人工评估，缺乏大规模、跨组织的盲测；B0–B3 的增量效应虽然显著，但样本量较小，且评估者可能因学习效应产生偏差。

## 6. 个人评价与延伸思考

- **理论价值**：论文将“可解释 AI”从单次预测的特征归因扩展为结构化、可重建、可扰动的决策全程档案，为智能体治理提供了更严苛的目标——不仅要能解释，还要能在不同条件下重放并比对其机制差异。
- **实践意义**：对审计、合规与风险控制有直接参考价值；提出了具体的可执行规范（不变量、工件包、发布门），有助于将概念原型落地为工程系统。
- **进一步研究问题**：
  - 如何自动学习场景扰动算子与差异分级阈值，减少人工配置？
  - 在决策机制包含不可微分或不可确定性组件（如大型语言模型）时，如何界定“复现”并保证可重建性？
  - 图同步的新鲜度与审计完整性之间如何权衡——过频则成本高，过疏则可能漏掉关键窗口。
- **总体判断**：论文创新性较强，问题定义清晰，方法体系完整，实验设计兼顾了真实日志、受控注入与外部模型。主要局限在于验证场景规模中等、依赖人工语义配置，且对 LLM 类机制的复现性挑战仅做了初步探测。整体上是一项高质量、具有启发性的研究，适合作为智能体治理与决策审计方向的基准框架。
