## 摘要
大语言模型智能体将外部技能的输出置于其执行上下文中，从而使攻击者控制的数据得以影响后续敏感操作。现有防御主要对不可信内容进行分类，或对提议操作进行授权，但并未直接解决不可信数据进入智能体状态后其未来权限应如何变化的问题。我们提出 SkillGuard，一种执行框架级强制层，将该事件视为污染并限制未来能力，以将结果状态与部署者定义的禁止状态隔离。在可靠的技能摘要和策略下，SkillGuard 使用技能影响图表示安全相关转换，通过可操纵性签名明确规定对技能参数的允许控制，并利用内联引用监视器对调用进行调解。污染发生后，它采用二值、分数或分数流策略计算加权能力限制，无需辅助语言模型推理。我们在四个 AgentDojo 套件上使用 Gemini 2.5 Flash 与 Llama3.3-70B 两个后端 LLM 评估 SkillGuard，并与纯 LLM 无防御基线以及不同系统层的三种防御（Spotlighting、CaMeL 和 AttriGuard）进行对比。我们构建了一个组合攻击基准，其中每次攻击组合了单独均不足以诱发目标违规的观测，并在其上评估相同基线。在 AgentDojo 的 Tool Knowledge 攻击下，SkillGuard 在两个后端上消除了四个套件中三个套件的攻击成功，并将 Slack 上的攻击成功率降至 4.8% 和 14.3%。面对组合攻击，它在 Llama 上优于所有基线，并在更高的良性效用下与 Gemini 上最强基线相当。相同攻击成功率下，分数流限制比二值限制保留的能力显著更多。在两种设置中，SkillGuard 均未增加模型调用或令牌开销。

## Abstract
Large language model agents place outputs from external skills into their execution context, allowing attacker-controlled data to influence later privileged actions. Existing defenses mainly classify untrusted content or authorize proposed operations. They do not directly address how an agent's future authority should change once untrusted data enters its state. We present SkillGuard, a harness-level enforcement layer that treats this event as contamination and restricts future capabilities to disconnect the resulting state from deployer-defined forbidden states. Given sound skill summaries and policies, SkillGuard represents security-relevant transitions with a Skill Impact Graph, specifies admissible control over skill parameters via steerability signatures, and mediates invocations with an inline reference monitor. Following contamination, it computes weighted capability restrictions using binary, fractional, or fractional-flow strategies without auxiliary language-model inference. We evaluate SkillGuard on four AgentDojo suites with two backend LLMs, Gemini 2.5 Flash and Llama3.3-70B, against an LLM-only No Defense baseline and three defenses at different system layers: Spotlighting, CaMeL, and AttriGuard. We construct a compositional attack benchmark in which each attack combines observations individually insufficient to induce target violation and evaluate the same baselines on it. Under AgentDojo's Tool Knowledge attacks, SkillGuard eliminates attack success on three of four suites for both backends and reduces it to 4.8% and 14.3% on Slack. Against compositional attacks, it outperforms every baseline on Llama and matches the strongest baseline on Gemini at higher benign utility. Fractional-flow restriction preserves substantially more capabilities than binary restriction at the same attack success rate. Across both settings, SkillGuard adds no model calls or token overhead.

## 1. 论文的核心问题与整体含义

- **研究动机**：LLM 智能体执行任务时会调用外部技能（如网页检索、数据库、API、代码执行器等），并将外部技能返回的内容直接放入模型上下文。攻击者若控制这些外部内容，即可实施**间接提示注入**，诱导智能体以用户权限执行恶意操作，形成经典的“混淆代理人”问题。
- **现有防御的不足**：
  - 模型层防御（提示区分、检测、训练对齐）依赖模型能否可靠区分“指令”与“数据”，但当前 LLM 无法做到；
  - 系统层防御（CaMeL、AttriGuard 等）主要回答“某个操作是否被授权”，属于逐动作授权问题；
  - 现有研究很少回答一个**互补的可达性问题**：一旦不可信数据进入状态，未来哪些能力必须被限制才能保证不会到达部署者定义的禁止状态；
  - 目前基准很少隔离“组合式攻击”——单个观测不足以致害，需多个工具输出的信息组合才能达成攻击目标；
  - 运行时防御往往引入大量额外 LLM 推理（CaMeL 与 AttriGuard 最多增加 15 次模型调用和 69K token）。
- **核心含义**：将间接提示注入的防御从“内容分类”或“动作授权”转向**能力约束**：把外部数据进入状态视为“污染事件”，随后对智能体未来可调用的工具能力进行限制，使得从当前污染状态出发的任何允许执行路径都无法到达部署策略所禁止的状态。

## 2. 论文提出的方法论

- **整体思路**：SkillGuard 是一种 **harness 级强制层**，它不依赖语言模型对内容的甄别，而是基于图模型的可达性计算和工具参数级约束来保证安全。
- **核心组件**：
  1. **Skill Impact Graph（SIG，技能影响图）**
     - 有标签迁移系统 \(G=(Q,Σ,δ,q_0)\)：
       - \(Q\)：安全相关状态节点；
       - \(Σ\)：注册的技能集；
       - \(δ\)：技能执行诱导的状态转移；
       - \(q_0\)：初始状态。
     - 执行事件 \(e=(σ,p,o)\) 表示技能 \(σ\)、参数 \(p\)、输出 \(o\) 从状态 \(q\) 迁移到 \(q‘\)。
     - 图只保留安全相关状态，用于分析禁止状态的可达性。
  2. **Steerability Signatures（可控性签名）**
     - 每个技能参数被映射为类型和“可控性包络”：
       \[
       σ:(p_1:τ_1⟨E_1⟩,\dots,p_n:τ_n⟨E_n⟩)→τ_{out}
       \]
     - \(E_i\) 分为三类：
       - **Exact**：由类型/有限集精确定界；
       - **Harness-enforced refinement**：由 harness 在执行边界强制细化谓词（如路径限制在 `/home/user/reports/*`）；
       - **Conservative**：无可靠边界时取 \(E_i=⊤\) 全允许。
     - 要求 \(A_i⊆E_i\)，其中 \(A_i\) 是攻击者实际可诱导的取值集合，保证签名是可靠的。
  3. **Inline Reference Monitor（IRM，内联引用监视器）**
     - 在 LLM 与技能执行之间拦截调用；
     - **预检查**：技能是否在当前能力集 \(K(q)\) 中、参数是否满足可控性签名；
     - **执行后检查**：验证技能输出是否合法，不合法则丢弃，不更新状态；
     - 相当于一个“抑制自动机”，不终止代理、不插入合成动作。
  4. **能力限制机制**
     - 当状态发生污染时，SkillGuard 重新计算最小代价限制，使受限后的 SIG 中 \(q\) 到禁止集合 \(B\) 不可达：
       \[
       (R^*,T^*)=\arg\min_{R,T}W(R,T)\ \text{s.t.}\ Reach_{G(R,T)}(q)∩B=∅
       \]
     - 三种策略：
       - **Binary（二值）**：将整个技能从能力集移除；
       - **Fractional（分数式）**：保留技能但收紧可控性包络；
       - **Fractional-flow（分数流，推荐）**：联合优化多个技能的限制和收紧，利用最小费用流/割模型，在处理共享路径时更精细地保留能力。
- **安全性质**：通过归纳证明，满足四个性质：
  - **State Safety (SS)**：不允许到达禁止状态；
  - **Context Integrity (CI)**：参数不被未授权源污染；
  - **Capability Non-Escalation (CNE)**：能力集只减不增；
  - **Information Flow Confidentiality (IFC)**：敏感信息只流向授权技能。
- **复杂度**：将能力限制转为图上的最小割问题，网络 \(|V|=O(n+m)\)、\(|E|=O(kn+m)\)，使用 Dinic 算法总复杂度 \(O((n+m)^2(kn+m))\)，不调用 LLM。

## 3. 实验设计

- **基准（Benchmark）**：
  - **AgentDojo (v1.2.2)**，包含四个应用套件：Workspace、Slack、Travel、Banking。
  - 攻击类型：
    1. **单步 Tool Knowledge 攻击**（全部四套件）；
    2. **完整提示注入基准**（Travel 域，16 种攻击，含 7 个 Instruction-Hijacking 和 9 个 DoS/Direct Injection）；
    3. **组合式多步攻击**（自建数据集）：
       - 基于 AgentDojo 四个套件，涵盖三种组合策略：碎片化指令注入、跨源信息组合、多步工作流操纵；
       - 全部经过消融验证：单个片段无法诱导攻击，组合后才会成功；
       - 最终包含 22 个有效场景（最初 39 个候选，淘汰 17 个）。
  - 排除文本到文本攻击（不涉及工具调用），丢弃 20 个实例，保留 97 个用户任务和 929 个攻击实例。
- **后端 LLM**：Gemini 2.5 Flash（reasoning budget 8,192 tokens）和 Llama 3.3-70B，覆盖闭源/开源。
- **对比方法**：
  - No Defense（无防御基线，依赖模型自身对齐能力）；
  - Spotlighting（提示层防御，标注/分离不可信内容）；
  - CaMeL（系统层控制/数据流强制）；
  - AttriGuard（基于反事实回放的动作归因防御）；
  - 此外还有 SkillGuard 自身的变体：IRM Only、IRM+Binary Cut (BC)、IRM+Fractional-Flow Cut (FFC)。
- **评估指标**：
  - ASR（攻击成功率）、BU（良性任务完成率）、UA（攻击下任务完成率）、TPR/FPR、RCR（残余能力比例）、ACR（攻击导致删除的能力数）；
  - 自适应攻击用 Sec_Ag（AgentDojo 安全判定）、Reach_B（是否到达禁止状态）、Harm（实际损害）三个指标。
- **自适应攻击**：额外构造了 8 种机制感知攻击，考察限制范围、强制时间、包络鲁棒性等，共 16 次试运行。

## 6. 论文的主要结论与发现

- **单步 Tool Knowledge 攻击**：SkillGuard 在 Travel、Banking、Workspace 三个套件、两种后端上均取得 **0% ASR**；Slack 上降至 Gemini 4.8%、Llama 14.3%，且不依赖额外 LLM 推理。
- **组合攻击**：在 Llama 上取得最低 ASR（8.00%）和最高的 UA（81.82%）；在 Gemini 上 ASR 为 14.29%，与 CaMeL 的 14.00% 相当，但 BU 高约 10 个百分点（92.27% vs 82.27%）。
- **精细限制优于粗暴删除**：Travel 上 fraction-flow 的 RCR 为 93.21–94.08%，而 binary 只有 76.25–79.29%，两者 ASR 均为 0%。
- **无额外模型开销**：SkillGuard 全程不调用模型，保护延迟远低于 LLM 辅助防御，同时还能提升良性任务完成率（如 Llama-Travel 下相比 AttriGuard，ASR 下降而同增 BU/UA）。
- **残留失败的原因**：
  - 攻击未通过工具调用实现（纯文本输出致害）；
  - 攻击目标不在 SkillGuard 禁止状态集合内（例如将某技能调用定义为污染事件而非违规，如 Slack 中 `get webpage`）；
  - 执行顺序导致限制生效时间晚于恶意动作（如先发恶意消息后触发污染）；
  - 分数流策略保留的包络仍可被“合法但恶意”的参数变体利用（URL 改写、邮件别名、去 `www` 等）。
- **防御机制不依赖特定模型或攻击内容分类**，而是通过图可达性限制实现系统化保护。

## 7. 优点

- **视角新颖**：将间接提示注入的防御重新表述为“污染后可达性收敛”问题，而非“单动作授权”问题，直接对应攻击者利用方式。
- **可解释且不需要额外推理**：强制执行完全基于状态图、可控性签名、最小割等结构化机制；无辅助模型调用，比 LLM 依赖型方法更可控、更轻量。
- **具备形式化保障**：给出安全性质的归纳证明，明确依赖条件（harness 可信、技能摘要可靠、策略正确等）。
- **细粒度限制**：从“删除整个能力”细化到“收紧参数包络”，明显缓解安全与效用之间的矛盾，并通过 RCR 与 UA 指标验证。
- **组合攻击评估创新**：自建经严格消融验证的组合攻击数据集，填补了现有基准缺乏组合隔离的空白。
- **实验框架严谨**：采用跨域、跨模型、多基线、消融、免开销、自适应等维度，对安全性和可用性均有充分刻画。

## 8. 不足与局限

- **范围限制**：
  - 不覆盖直接 Jailbreak、训练时投毒、恶意/坏总结的技能实现、harness 自身被攻破、LLM+人工执行（文本到文本）等；
  - 不支持不依赖工具调用即可致害的攻击变种。
- **策略完备性依赖人工设计**：SIG、禁止状态集合、可控性包络及污染源标记依赖部署者的正确设计；不可靠的策略会造成防护漏洞，甚至“无能力可用”。
- **残留语义漏洞**：分数流包络收紧无法覆盖未预定义的语义等价参数变体（URL 缩写、defanged URL、plus 别名等），可能导致攻击绕过。
- **时序问题**：如果一次请求中恶意动作先于污染触发发生，则无法回滚（“enforcement timing”限制）。
- **组合攻击目标超过单包络语义**：单个调用合法而组合序列致害时，必须预先在 \(B\) 中加入跨步序属性，否则 min-cut 无法阻止。
- **资源开销与规模**：Workspace 的 SIG 图较大时，Min-Cut 计算需 7–12 秒/任务，存在可扩展性问题（作者也承认未来需做图分区分簇）。
- **效用损失**：部分套件中 SkillGuard 在完全消除 ASR 的同时会显著降低 BU/UA，出现过早受限、导致真正任务失败的情形；作者提议后续用强化学习动态调优限制成本。
- **数据完整性与公平性风险**：多个表格缺空，CaMeL 在许多设置下因无法处理失败任务而显示零/低 ASR；基线超参是否充分调优未说明，可能低估某些现有方法。
- **作者提交并自行评估自适应攻击**：虽然用 Reach_B × 16 说明未违反可达性保证，但仍提醒“策略假设 vs 实际损害”之间并不总是一致，暴露了部署/场景定义的风险。
