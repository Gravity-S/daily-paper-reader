## 摘要
长周期智能体会执行数千个动作，导致其呈现的是顺序性故障而非孤立错误。当一个编程智能体删除生产数据库，或一次提示注入在智能体间传播时，事件会引发关于因果性、权威性和不可抵赖的第三方验证问题。Agent飞行记录器将每个智能体动作捕获为一个结构化、经过规范序列化的事件，绑定从意图、执行到来源的八个语义字段。哈希链与Merkle批处理提供防篡改证据和紧凑的包含证明。对于任何参与方的基础设施均不能作为中立方的跨组织争议，周期性将纪元根锚定到链上，使任何掌握所披露负载和Merkle证明的验证者都能独立核对记录，而无需预先约定可信中介。其链上占用极小：每个锚点存储一个32字节的纪元根和一个回指指针，任何事件内容均不上链。我们在合成智能体工作负载上，通过五种累积消融配置对系统进行了评估。完整系统使每事件中位延迟增加约48微秒，每事件增加512字节。在100事件/纪元的条件下，L2锚定成本为每10万事件2.30美元。完整的完整性栈可100%检测编辑、删除、重排和分叉篡改，且零误报。结构化取证查询在护栏与委派查找上达到1.0的精度，而非结构化文本搜索分别为0.013和0.077。

## Abstract
Long-horizon agents execute thousands of actions, resulting in sequential failures rather than isolated errors. When a coding agent deletes a production database or a prompt injection spreads across agents, the incident raises questions of causality, authority, and non-repudiable third-party verification. The Agent Flight Recorder captures each agent action as a structured, canonically serialized event binding eight semantic fields from intent through execution to provenance. Hash chaining and Merkle batching provide tamper evidence and compact inclusion proofs. For cross-organizational disputes where no party's infrastructure qualifies as neutral ground, periodic on-chain anchoring of epoch roots lets any verifier with the disclosed payload and Merkle proof check the record independently, without pre-agreeing on a trusted intermediary. The on-chain footprint is minimal: each anchor stores a 32-byte epoch root and a back-pointer, and no event content touches the chain. We evaluate the system across five cumulative ablation configurations on synthetic agent workloads. The full system adds ~48 microseconds median per-event latency and 512 bytes per event. L2 anchoring costs $2.30 per 100K events at 100-event epochs. The full integrity stack detects edit, delete, reorder, and fork tampering at 100% with zero false positives. Structured forensic queries achieve 1.0 precision on guardrail and delegation lookups where unstructured text search yields 0.013 and 0.077 respectively.

# 《Agent Flight Recorder》论文详细总结

## 1. 核心问题与整体含义

- **研究背景**：长周期（Long-Horizon）工具使用型智能体可在数小时或数天内自主执行数千次工具调用（读文件、调用 API、修改数据库、委派任务给其他智能体等），其失败模式主要是"错误的动作序列"而非"错误的单一答案"。例如：编程智能体删除生产数据库、提示注入在多个智能体间传播、未授权的权限提升等，均引发关于因果性、权威性与不可抵赖第三方验证的严峻问题。
- **核心痛点——从可观测性到可审计性的鸿沟**：现有智能体观测栈（OpenTelemetry spans、LangSmith、Langfuse 等）假设日志可变、由单一可信方生产与消费，不具备防篡改和外部可验证能力。当操作者本身被攻破或存在篡改历史的动机时，这类日志无法作为争议解决的证据基础。
- **研究含义**：本文提出一种"证据结算架构"（evidentiary settlement architecture）而非单纯的观测工具，旨在将智能体每个动作记录为可独立验证、防篡改、支持选择性披露的审计证据，并为跨组织争议提供不依赖任何预信任中介的验证路径。

## 2. 方法论

- **总体架构**：由本地记录器（Local Recorder）、锚定器（Anchorer）与验证器（Verifier）三部分组成，采用"本地哈希链 + Merkle 批处理 + 链上锚定"三层组合。
- **核心思想——单一动作的有序序列才是危害单位**：审计系统必须将"智能体检索了什么、框架检查了什么策略、系统咨询了哪位人类、命令在什么环境执行"这一有序因果链作为头等对象捕获和保存。
- **八语义字段事件结构**：每个事件绑定以下八个语义字段——
  - ① 意图（Intent）：模型提出的工具名与结构化参数（刻意排除 CoT 推理轨迹，因不稳定且涉 IP 风险）；
  - ② 策略评估（Policy evaluation）：执行的护栏及其裁决（允许/拒绝/升级）与策略版本；
  - ③ 人类批准（Human approval）：是否有人授权、批准者身份、显示的批准提示与时间戳（生产部署应含签名）；
  - ④ 执行（Execution）：实际运行的命令/API 调用/变更的确切参数；
  - ⑤ 效果（Effects）：返回值、状态差异、外部响应或错误；
  - ⑥ 上下文来源（Context provenance）：消费的检索源（含内容哈希）、上游工具输出、环境身份；⑦ 代码来源（Code provenance）：智能体二进制哈希、工具包装器与技能/包哈希；⑧ 委派来源（Delegation provenance）：请求方智能体身份、父事件哈希与委派权限范围。
- **规范序列化**：采用确定性 CBOR（RFC 8949 §4.2）进行规范序列化，克服 JSON canonicalization 的哈希稳定性问题（浮点歧义、键序不定、Unicode 归一化差异），所有哈希基于该规范字节序列计算。
- **负载与记录分离**：事件负载（敏感）与事件记录（定长元数据：事件 ID、序号、负载哈希、前驱摘要、明文元数据）分离存储。负载默认加密，完整性结构（哈希链/Merkle/纪元根）仅操作事件记录，不含敏感内文。
- **三层密码学构造**——
  - 第 1 层（哈希链）：每个条目包含前驱哈希（`eᵢ.prev = H(eᵢ₋₁)`），建立全序，使后缀删除可检测；
  - 第 2 层（Merkle 批处理）：每 N 个事件构成 Merkle 树叶子（SHA-256），提供 O(log N) 包含证明；非 2 幂时复制最后叶子；
  - 纪元根链：每个纪元产生 Merkle 根 Mt，纪元根链化 `Rₜ = H(Mₜ ∥ Rₜ₋₁)`（R₀ = H(M₀ ∥ 0³²)），仅 Rt 上链，支持空洞检测。同时通过事件中逻辑时钟（logical_clock）与可选的并发组标签区分因果顺序与观测顺序。
- **链上锚定协议**：锚定器在纪元关闭时向公共链提交包含纪元根 Rt 与前一根哈希 H(Rₜ₋₁) 的事务；链上合约仅记录 32 字节根和回指指针，附调用者地址（msg.sender）、纪元号和区块时间戳。锚定模式类似于 L2 Rollup 的"本地执行 + 批量承诺 + 公共结算"，但承诺的是事件完整性而非状态转换正确性。
- **验证工作流**（两种级别）——
  - 完整性验证（不披露负载）：由事件记录、Merkle 证明与链上锚点引用，重算 Merkle 路径至纪元根 Rt → 核对链上锚点 → 验证纪元连续性；
  - 内容验证（有披露）：先用披露的按事件解密密钥解密密文，验证明文哈希与已承诺记录中的负载哈希一致，再执行上述步骤。
- **选择性披露方案**：基于 HKDF 的两级密钥层级——主密钥派生每纪元密钥 `Kₜ = HKDF(master, epoch_idₜ)`，再派生每事件密钥 `kₜ,ᵢ = HKDF(Kₜ, event_idᵢ)`。审计者仅获得被调查事件的解密密钥。局限：获得纪元密钥 Kₜ 即可派生该纪元所有事件密钥，提供的是合作审计下的选择性披露而非强制披露下的保护。
- **信任模型**：沿用 Schneier–Kelsey 边界，主机完全沦陷后无法保证新写入条目的真实性，只能保护沦陷前历史的完整性；锚定频率限制该窗口但不消除。
- **实现**：约 1,500 行 Python 原型，配约 30 行 Solidity 锚定合约；单写者路径序列化并发工具完成事件。

## 6. 主要结论与发现

- **开销可忽略**：完整系统较 Baseline 在每事件中位数上约增加 48 μs（47.6 vs. 20.3 μs）；存储从 272 → 512 字节/事件（+88%）。Merkle 批处理在每第 100 个事件触发纪元封口导致 P99 尖峰 ~4.1 ms；完整配置（含 ECDSA 纪元签名）P99 约 30 ms。
- **Schema 层扭亏为盈**：确定性 CBOR 比嵌套 dict 的 json.dumps 更快（中位 6.0 vs. 20.3 μs），但字节数增加 75%。
- **链上锚定成本极低**：L2 锚定 100K 事件（100 事件/纪元）仅需 $2.30；L1 相同配置约 $6,885（差约 3,000×）；纪元大小为 10 时 L2 也仅 $22.95，使亚分钟级妥协窗口可行。
- **四类攻击 100% 检测且零误报**——但需注意分层归因：
  - Chain 层：编辑/删除检测率 90%（末端事件 N−1 因无后继者而漏检）、重排 100%；
  - Merkle 层：补齐末端事件漏检，单日志所有攻击达 100%；
  - Full（链上锚定）：唯一能检测分叉/等量歧义的配置——分叉分支的纪元根与链上锚定不匹配。仅靠单日志验证无法检测分叉，需争议验证协议。
- **结构化取证优势显著**：结构化字段查询精度达 1.0（护栏查询、委派查询），而文本 grep 分别为 0.013 和 0.077；文本无法重建完整因果链（精度/召回 0.0），结构化搜索可循委派父指针完成关系型追溯。链上锚定是唯一支持中立第三方验证的配置。

## 7. 优点

- **问题定义准确贴合前沿**：以长周期智能体特有的"序列化失败"为切入点，三个动机场景（删库、提示注入传播、跨组织纠纷）在现实中均有对应真实案例支持。
- **模式设计具有语义深度**：八字段事件模式将意图→策略→批准→执行→效果→来源链纳入单一对象，较此前日志格式（如 IETF 草稿）显著充实；明确排除 CoT 也体现了实际部署约束意识（稳定性、IP、合同限制）。
- **架构分层与信任模型清晰**：哈希链防内部篡改、Merkle 树紧凑证明、纪元根链防空洞、链上锚定防分叉——每一层针对特定攻击类别，定位逻辑严密。明确采用 Schneier–Kelsey 威胁边界，不夸大系统能力。
- **"非交互式"验证设计**：与乐观/挑战式方案（需争议窗口和诚实验证者）相比，Merkle 证明 + 链上根即可随时独立验证。
- **隐私设计周到**：负载/完整性结构分离、HKDF 逐事件密钥派生支持细粒度审计披露。
- **消融与多维评估全面**：覆盖开销、成本、安全性与可用性四个维度，既有合成压力测试又有真实 trace（SWE-bench/SWE-agent）与真实链上部署（Base Sepolia）验证。
- **实验诚实度高**：对内部/外部/构念效度威胁均有明确交代，如实报告限制。

## 8. 不足与局限

- **完整性边界**（根本性限制）：若动作绕过被插桩的网关，记录器将看不到该事件；纪元内的事件抑制无法从日志本身检测。作者建议以 TEE 远程证明提升为结构性保证，但作为未来工作而非当前属性。
- **妥协后不可信**：主机完全沦陷后的新条目无法保证真实。锚定频率只能缩小窗口但不能消除。
- **负载可恢复性依赖外部安排**：链上锚点只证明日志存在；若负载存储丢失且无外部副本，内容不可恢复。链上锚定消除的是"预信任承诺媒介"需求，而非"数据可用性与披露安排"需求。
- **选择性披露的强制披露弱点**：审计者若获得纪元密钥（如传票），可派生该纪元所有事件密钥；不具备针对强制披露的 ZK 级隐私保护。
- **侧信道盲区**：仅捕获工具调用语义，不覆盖模型内部状态或频带外智能体间通信。
- **实验局限**（文中已承认）：合成数据为主（虽经真实轨迹验证）；RQ3/RQ4 使用单次确定性运行而非统计性重复；基线为纯 JSON 日志而非成熟审计系统——消融用于归因组件价值而非声称优于现有平台；分叉检测非单日志属性，篡改表仅覆盖单日志验证；取证精度改善部分反映查询后端特性，不应过度泛化。
- **外部效度与操作风险**：gas 价格波动使美元数字仅为说明性；锚定延迟（链拥堵）、链重组/最终性边缘情况、密钥管理失败、规范序列化边界情况、以及 L2 单排序器的审查风险（Force-inclusion 可缓解但存在）均可能削弱保证。锚定可用性中断时妥协窗口扩大。
- **对监管合规仅作有限主张**：加密擦除的 GDPR 充分性未作法律断言，视司法辖区、元数据可链接性与保留政策而定。
