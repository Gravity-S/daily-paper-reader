## 摘要
大语言模型（LLM）代理的失败往往包含多个相关错误，而非单一失误。现有归因方法通常识别责任代理、步骤或根因，但未显式建模错误之间的依赖关系。我们提出EDGE，一个错误依赖图引导的多错误归因框架。EDGE从观察到的错误事件中构建错误依赖图，并通过反事实推演验证可靠因果子集。推理图指导两阶段LLM作为评判者的检测器进行错误归因，而经干预验证的子图为解释和修复分析提供更可靠的基础。在TRAIL和MAST上的实验表明，EDGE在大多数评估模型和设置中改善了类别级多错误归因。采用适配Who&When风格提示的实验表明，该图有助于多种提示策略。这些结果表明，依赖结构是代理失败的有用诊断先验，超越孤立的根因预测。

## Abstract
Large language model (LLM) agent failures often contain multiple related errors rather than a single mistake. Existing attribution methods usually identify a responsible agent, step, or root cause, but do not explicitly model dependency between errors. We introduce EDGE, an Error Dependency Graph-guided multi-Error attribution framework. EDGE constructs an error dependency graph from observed error events and validates a reliable causal subset through counterfactual rollout. The inference graph guides a two-stage LLM-as-judge detector for error attribution, and the intervention-validated subgraph provides a more reliable basis for explanation and repair analysis. Experiments on TRAIL and MAST show that EDGE improves category-level multi-error attribution across most evaluated models and settings. Experiments with adapted Who&When-style prompts show that the graph helps across prompting strategies. These results suggest that dependency structure is a useful diagnostic prior for agent failures beyond isolated root-cause prediction.

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）代理系统被广泛应用于涉及规划、检索、工具调用与推理的复杂多步任务。当执行失败时，最终结果只能表明任务失败，却难以解释失败是怎样逐步演化形成的。
- **问题**：一个失败轨迹中往往存在**多个相互关联的错误**（如上游触发错误→下游传播错误→终止错误），而非单一独立失误。现有归因方法（如 Who&When、AgentErrorBench、CHIEF、AgentRx 等）大多聚焦于**单一根因**（某个代理、某一步骤、某一关键错误），未显式建模多错误之间的依赖与传播关系；即便扩展为多标签输出，各错误也被视为孤立预测目标，忽略了"一个错误会提高另一个错误发生概率"的级联结构。
- **核心观点**：多错误归因应被理解为**依赖感知的诊断任务**——利用轨迹内错误出现的时序顺序和跨轨迹的规律性，捕捉错误类别如何在失败的执行中重复出现、传播与演化，从而超越孤立的根因预测。

## 2. 方法论：EDGE 框架

### 2.1 总体流程概览

EDGE 包含三大步骤：**（1）观测图构建**——从错误事件统计数据中推断观测相关图与因果候选图；**（2）干预验证**——通过受控反事实回滚（counterfactual rollout）验证因果边；**（3）图引导检测**——利用验证后的图注入 LLM-as-judge 检测器完成多错误归因。

### 2.2 问题形式化

- 轨迹定义为时序跨度序列 T = (s₁,…,s_N)，每个轨迹标注错误事件集合 E(T) = {(cⱼ, ℓⱼ)}，其中 cⱼ ∈ 错误类别集合 C，ℓⱼ 为错误首次出现的跨度标识。
- 目标：预测每一条轨迹的**类别-位置对**的集合 Ê(T)。
- 定义 X_A(T) ∈ {0,1} 表示类别 A 是否出现在轨迹 T 中，t_A(T) 表示 A 首次出现的位置索引。

### 2.3 观测图构建（两步走）

**第一步：Suppes 筛选（构建观测相关图 G_S）**

- 借鉴癌症进展建模领域 CAPRI/TRONCO 的 Suppes-Bayes 因果网络思想，但核心适配是将类别出现视为进展事件，利用跨度标注提取事件时序变量。
- 对每条候选有向边 A→B，要求同时满足两个条件：
  - **时间优先**（Prec）：在 A、B 共现的轨迹中，A 先于 B 出现的比例，即 Prec(A,B) = |{T∈T_AB : t_A(T) < t_B(T)}| / |T_AB|
  - **概率提升**（ΔPR）：P(X_B=1|X_A=1) − P(X_B=1|X_A=0) > 阈值
- 保留边的权重 w_S(A,B) = √(Prec(A,B)·ΔPR(A,B))，即几何平均，用于推理时边缘排序。

**第二步：CAPRI 式剪枝（构建稀疏因果候选图 G_C）**

- 对 Suppes 筛选结果进行基于 AIC 分数的 DAG 搜索，目标函数为 −2·logL(G;X) + 2·dim(G)，通过爬山法（边增/删/反向）在无环约束下寻找稀疏因果候选图。

### 2.4 干预验证（构建验证图 G_V）

- 对每条因果候选边 A→B，收集满足 t_A(T) < t_B(T) 的共现轨迹，利用**类别专用补丁模板**（patch library）对 A 首次出现的跨度做最小化局部修复（do(A=0)）。
- **受控反事实回滚**：所有工具输出保持原值不变，仅让修复跨度及其下游推理发生变化，从而将 B 的变化归因于 A 的修复（即受控直接效应）。
- **两级 LLM 判定**：
  - Judge A（修复验证器）：确认补丁是否真正消除了错误 A（resolved=1 才进入效应估计）；
  - Judge B（效应评估器）：标记 A 修复后错误 B 在后沿轨迹中是否仍然存在。
- 边效应量化为布尔风险差：Δ(A→B) = E[X_B(T) − X_B^cf(T;A)]，Δ > τ_val（0.15）的边进入验证图 G_V。

### 2.5 推理图构建（G_τ）

- 仅用因果验证图 G_V 覆盖率可能不足，因为干预证据有限，许多观测相关性强的边无法被验证。
- 推理图取**验证因果边 ∪ 高分观测相关边**：
  R_τ = {A→B ∈ R_S : w_S(A,B) ≥ τ} ∪ R_V
- 权重分配：验证边的权重取 Δ(A→B)，纯观测边取 Suppes 几何均值 w_S。
- 角色分工：G_τ 用于归因覆盖预测，G_V 用于解释与修复分析。

### 2.6 两阶段图引导检测器

- **第一阶段**：Judge 接收完整轨迹、类别体系及推理图 G_τ 的全局上下文，输出初始预测集合 Ê⁽¹⁾(T)；
- **动态激活**：根据第一阶段的检测类别集合 D(T)，从 G_τ 中检索源类别已检测到、目标类别未检测到的候选下游边，满足聚合权重超过阈值 τ_GI（0.10）的边组成轨迹级边子集 R_τ(T)；
- **第二阶段**：仅当 R_τ(T) 非空时触发，Judge 在收到"已检测错误清单 + 轨迹特定边子集指导"后输出额外错误类别（不含阶段一已覆盖的类别）；
- **合并输出**：两阶段结果按类别去重合并为最终预测。

## 6. 主要结论与发现

1. **图引导带来显著且稳定的归因提升**：在 TRAIL-GAIA 上，Gemini-2.5-Pro 的 F1 达 42.13（较基线 +8.62），开源模型最高提升 +14.17（Qwen 系）；TRAIL-SWE-Bench 上 GPT-oss-20B 提升 +20.58；MAST 上 GPT-4o 提升 +7.09，多数开源骨干也获益。
2. **提升集中在类别检测而非精确定位**：图引导显著改善错误类别的召回（尤其是 Planning & Coord. 下游类别），但 Span 定位增益较小——SWE-Bench 长上下文轨迹（中位数约 213K 字符）的 Loc/Joint 增益有限。
3. **MAST 存在准确率-召回率的权衡**：7/8 骨干出现准确率小幅下降（−0.33 至 −3.74）而召回率同步上升（最高 +17.52）。由于非"始终全否"基线已有 69.5% 准确率，准确率必须结合召回率解读。
4. **两阶段动态注入是增益的操作杠杆**：静态图引导（+CG）不稳定（15 个骨干单元中 14 个不如 EDGE），证明增益来自"基于阶段一结果按轨迹过滤图边后再验证"的机制，而非仅提供图信息。
5. **图结构泛化到未见轨迹**：80/20 留出实验中 EDGE 在四个骨干-数据集单元中全部提升加权 F1，排除仅拟合评估语料的解释。
6. **图对其他提示策略有可迁移性**：Who&When 风格 All-at-once / Step-by-step 加入图引导后多数情况下收益提升。
7. **验证图 G_V 是可解释的传播图**：例如 TRAIL 中"格式错误→上下文处理失败"、MAST 中"行为-推理不匹配→过早终止"等干预验证的因果关系可以为系统级修复优先级提供依据——修复有多个验证出边的上游节点比直接修症状更有效。

## 7. 方法优点

1. **问题重构有新意**：将多错误归因从"多标签孤立预测"重构为"依赖感知诊断"，显式建模错误间的级联传播结构，切中真实代理故障的级联性本质。
2. **图构建既有理论根基又务实**：采用 Suppes 概率因果理论和 CAPRI 风格 AIC 评分，从时序优先与概率提升两方面筛选依赖边，且对稀疏、部分有序、语义化的代理错误轨迹做了适配。
3. **预测与解释角色分离设计精巧**：用 G_τ（因果+高相关观测边）提升覆盖，用 G_V（仅因果验证边）保障解释可信度——既解决了干预证据不足导致的覆盖问题，又不牺牲因果解释的可靠性。
4. **反事实干预设计审慎**：固定工具输出、仅允许局部修补源错误跨度的设置，使 Δ(A→B) 近似反映沿推理路径的受控直接效应；规则化补丁库与两级 LLM 判定（Judge A/B）形成可审计的验证管线。
5. **检测器设计有区分度**：两阶段"先检源→检索图→验证目标"的动态机制将图从静态上下文变成显式精化工具，且通过 +CG、random-K 等消融充分验证了该机制的必要性与图的信号价值。
6. **跨设定验证充分**：覆盖两种错误体系/标注粒度/推理环境（可回放 vs 录制对话）、11 种模型、多种提示策略，验证了方法对错误分类体系的无关性（taxonomy-agnostic）。

## 8. 不足与局限

1. **数据稀缺性与标签依赖**：目前包含多错误标注的语料极少（每类别支撑不足），图从完整标注语料构建，因此整体是"分类体系级依赖归因"而非逐轨迹个性化学习，存在一定的评价语料适应风险（虽有留出实验缓解）。
2. **定位能力薄弱**：图依赖类别共现统计，对事件检测的帮助大于对轨迹定位（Loc）的帮助；SWE-Bench 长上下文下位置增益接近持平，限制了在真实代码修复场景中的端到端效用。
3. **LLM 判定引入噪声**：修复验证（Judge A）、效应评估（Judge B）、MAST 步骤标注全部依赖 LLM 判定，未经完整人工校验，可能产生系统性偏差；MAST 约 70% 的效应标签为 not_observable（得益于 LLM 模拟回滚的局限性），严重削弱验证图的效力。
4. **验证边数受限**：干预验证受每个候选边的共现轨迹数量限制（TRAIL 中有的边仅 1 条验证轨迹），统计功效弱；论文用观测相关边补覆盖，但这些扩展边缺少因果证据，分布漂移下可靠性未知。
5. **MAST 事件标注质量未测量**：覆盖率虽达 82.0%，但未衡量事件位置的正确率，错误位置会影响时序优先估计进而干扰图的推断。
6. **无条件应用图引导**：图引导对所有轨迹统一注入，不做模型置信度或任务复杂度的门控。在部分基线已很强的单元（如 Gemini-2.5-Flash 的某些指标、QwQ-32B）图引导反而效果有限，缺少自适应开关。
7. **因果解释的边界**：干预验证固定工具输出，边效应反映沿推理路径的传播而不包含经由工具重执行的间接路径；G_τ 中的相关边可能过度放大传播声明；对高风险的代理部署，若无人工审查就把图引导结果视为确定性因果诊断可能造成误用（论文亦在 Potential Risks 中如此警告）。
8. **复现性限制**：全部数值为单次运行点估计，LLM 推理的固有随机性导致无法保证他人复现完全相同的结果。
