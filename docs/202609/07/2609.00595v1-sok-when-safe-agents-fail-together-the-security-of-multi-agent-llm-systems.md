## 摘要
安全的智能体也可能共同失效。多智能体LLM系统（MAS）跨越主体边界传递信息、状态、决策和权限，从而产生局部检查可能遗漏的失效模式。若缺乏执行层面的视角，多智能体环境很容易被误认为存在真正的多智能体安全效应的证据。因此，我们通过对197项工作进行以执行分析为中心的系统化研究，覆盖六种交互接口、四种对手位置、七类系统级风险及八种常见攻击路径。我们提出一个A-I-R框架，按对手位置、交互接口及由此产生的系统级风险组织攻击，将MAS中原本碎片化的攻击机制统一起来。我们通过包含路径目标、观察、干预、信任边界和恢复五部分的契约来组织防御，并指出路径闭合与恢复是关键挑战。我们审计了44项评估与基准工作，并识别出在隔离交互效应、设计可比较且可诊断的指标、支持跨MAS设计复用以及评估开放系统运行方面的开放挑战。综上，这些发现促使我们采用一种交互感知的MAS安全视角：端到端追踪攻击，测试防御是否闭合这些路径，并使用适当的反事实来评估系统级效应。

## Abstract
Safe agents can fail together. Multi-agent LLM systems (MAS) move information, state, decisions, and authority across principal boundaries, creating failures that local checks may miss. Without an execution-level view, a multi-agent setting can easily be mistaken for evidence of a genuinely multi-agent security effect. We thus systematize MAS security through an execution-centered analysis of 197 works, covering six interaction interfaces, four adversary positions, seven system-level risks, and eight recurring attack paths. We introduce an A-I-R framework that organizes attacks by adversary position, interaction interface, and resulting system-level risk, unifying otherwise fragmented attack mechanisms across MAS. We organize defenses through a five-part contract covering path target, observation, intervention, trust boundary, and recovery, and identify path closure and recovery as key challenges. We audit 44 evaluation and benchmark works and identify open challenges in isolating interaction effects, designing comparable and diagnostic metrics, supporting reuse across MAS designs, and evaluating open-system operation. Together, these findings motivate an interaction-aware view of MAS security: trace attacks end to end, test whether defenses close those paths, and evaluate system-level effects with appropriate counterfactuals.

### 研究动机与背景
- **核心问题**：在**多智能体 LLM 系统（Multi-Agent LLM Systems, MAS）** 中，单独使用时是安全的智能体（agent），一旦共同协作，便可能经由跨主体边界的交互产生**系统性安全失败**，且这种失败往往是局部检查（如单智能体验证、单条消息过滤）无法发现的。
- **现有研究缺口**：
  - 已有的安全综述多围绕模型、提示词、记忆、工具等组件展开，缺乏对攻击**如何在多智能体系统中一步步穿越边界、最终造成系统级后果**的执行级视角。

- **论文含义**：需要用**交互感知（interaction-aware）** 的安全视角，以**端到端执行轨迹**为分析单元，统一刻画攻击、防御与评估，回答以下问题：攻击从哪里进入？经由哪些交互接口传播？最终引发什么系统级失效？防御应在何处干预、依赖何种信任假设？评估是否验证了真实的系统级后果？

## 二、方法论

### 1. 系统模型与分析单元
- **主体验证（principal）**：将 MAS 中每个可独立寻址的参与者定义为“principal”；MAS 的本质特征是多个 principal 之间通过消息、共享状态、集体决策或委托动作相互影响。
- **四种交互角色**（区分交互在安全后果中的作用）：
  | 类型 | 含义 | 证据要求 |
  |---|---|---|
  | inherited effect | 移除交互关系后失效基本不变 | 可作为对照标签，不构成 MAS 特异性因果证据 |
  | interaction-amplified effect | 交互使失效的可能性、传播范围、持久性、权限或影响增强 | 需单主体对照或关系移除反事实 |
  | composition-induced effect | 仅在多个主体/步骤组合后才出现 | 需分离组合前后对比 |
  | structurally multi-agent effect | 安全属性本身由主体间关系（如共谋、群体决策）定义 | 需保留关系的对照比较 |

### 2. A-I-R 框架（核心贡献）
- **A → I → R**：将攻击描述为从攻击者位置（A），经由一个或多个交互接口（I），最终引发系统级安全失效风险（R）的执行路径。
- **四种攻击者位置（A1–A4）**：
  - A1：外部攻击者（控制 MAS 边界外的内容或服务）；
  - A2：用户级攻击者（通过合法用户界面操作）；
  - A3：成员攻击者（控制一个或多个参与主体）；
  - A4：基础设施攻击者（控制协调器、状态库、路由器、遥测或防御平面）。
- **六种交互接口（I1–I6）**：
  - I1：准入（Admission，输入/新主体/数据进入）；
  - I2：消息传递（Message Transfer）；
  - I3：状态传播（State Propagation，记忆、摘要、计划等持久化）；
  - I4：权限转移与行动（Authority Transfer & Action，工具/凭据调用）；
  - I5：集体承诺（Collective Commitment，投票、共识、决策聚合）；
  - I6：检测与干预（Detection & Intervention，即安全控制的观测和执行点）。
- **七类系统级风险（R1–R7）**：
  - R1：遏制失效（含恶意影响跨主体传播/持久化）；
  - R2：独立性丧失（主体间秘密共谋或隐性依赖，使“多方共识”失去证据价值）；
  - R3：集体决策完整性失效；
  - R4：轨迹与目标完整性失效（群体交互使目标发生越界偏移）；
  - R5：跨主体保密性破坏（含内部上下文、架构、拓扑等泄露）；
  - R6：传递性授权失效（权限沿委托链超出原始目的/范围）；
  - R7：可用性与资源隔离失效。
- **八条配置维度（C1–C8）**：用于描述执行发生的外部条件，即通信拓扑（C1）、协议语义（C2）、主体构成（C3）、协调机制（C4）、状态架构（C5）、成员与信任（C6）、权限布置（C7）、监督架构（C8）。

### 3. 八条典型攻击路径（P1–P8）
| 路径 | 典型 A→I→R | 含义 |
|---|---|---|
| P1 | 准入/组合注入 | 局部分散的可接受输入组合后产生有害语义（如拼接式提示攻击） |
| P2 | 传播与持久化 | 局部危害演变为系统级/持久性危害（如跨主体蠕虫、记忆污染） |
| P3 | 路由/角色操纵 | 篡改通信或改变路由/角色分配以扩大影响 |
| P4 | 对抗协调与集体操纵 | 通过隐写、说服、恶意投票等扭曲集体决策 |
| P5 | 同伴/状态引导 | 通过同伴交互使主体目标/轨迹发生（安全相关）漂移 |
| P6 | 跨主体信息泄露 | 执行过程暴露受保护的内部信息 |
| P7 | 委托与权限升级 | 沿委托链传递导致越权行动 |
| P8 | 共享资源/控制面干扰 | 利用共享资源或控制面造成跨主体拒绝服务 |

### 4. 防御框架（五部分防御合同）
- 每个防御机制从五个维度刻画：
  1. **路径目标（Path target）**：针对哪个 R1–R7 或路径段；
  2. **观察（Observation）**：能看到执行轨迹的哪个层面（单消息/边/子图/全迹）；
  3. **干预（Intervention）**：能改变什么、在什么时机；
  4. **信任边界（Trust boundary）**：依赖哪些主体和组件保持可信；
  5. **恢复（Recovery）**：阻止失败后，残留影响能否被撤销/修复。
- **四类防御控制原语 + 一种跨切面策略**：
  - D1：身份/策略/权限执行（主要应对 P1/P7，降低对消息内容的依赖）；
  - D2：信任与交互结构控制（针对 P3/P4，改变通信拓扑、聚合规则或信任评估）；
  - D3：检测、归因与遏制（覆盖 P2–P4 等，基于消息异常/传播预测进行阻断）；
  - D4：状态/来源/信息流治理（针对 P2/P6/P7，控制共享记忆与跨主体信息流）；
  - **自适应防御分配**（跨切面策略）：在有限防御资源下按安全相关性剪枝通信边或聚焦防护关键路径（如 SafeSieve、MESA）。

### 2. 对 44 个评估/基准工作的审计
- 审计对象：语料中 43 篇有论文的基准 + 1 篇仅有软件存档（Zenodo）的基准。
- 对每个工作记录：攻击者位置（A1–A4）、配置维度（C1–C8）、交互接口（I1–I6）、攻击路径（P1–P8）、系统级风险（R1–R7），以及**观察深度、比较设计、成员设置、人工制品可用性**等。
- 覆盖特点：

### 3. 评估指标与比较方式的审计发现
- **13/44** 个基准计算自己的 ASR（Attack Success Rate），另有 ATAG 记录他方 ASR 值；
- **ASR 的含义高度不一致**——不同工作对“攻击成功”的定义、统计口径（每条消息/每个主体/每次运行）各不相同，不能直接横向比较；
- **21 个基准**评估了可对应单主体版本的攻击：其中 6 个设置了匹配的单主体对照，15 个只在 MAS 内或不同 MAS 配置间比较；
- **36 个不具备单主体对照的基准**中：12 个包含“关系聚焦比较”（如 MESA 去除通信边、CalBench 比较协调协议），24 个缺少此类对照；
- **轨迹级证据不足**：20 个记录全轨迹，但只有 Agent-BOM 1 个重建了显式的依赖/来源图，难以支撑因果归因。

## 六、论文的主要结论与发现

1. **关系本身即攻击面**：即使消息内容完全不变，路由、角色分配、聚合规则和委托链的结构性变化本身就足以改变安全结果。
2. **安全影响可以比触发它的交互存活更久**：共享状态、生成的工件、派生子体和继承的权限可能使危害在原始攻击源移除后仍持续存在。
3. **受保护对象不只是最终输出**：独立性、拓扑/工作流信息、专用主体内部上下文、委托权力链等可以在最终回答看似正常的情况下被破坏。
4. **观察到攻击路径 ≠ 归因其成因**：完整执行轨迹能显示危害走向，但必须辅以匹配的单主体对照或关系去除/消融，才能确定交互是否造成或放大了失败。
5. **防御缺乏路径闭合与恢复能力**：拦截一个转换点（如一条消息）并不等于闭合整个端到端攻击路径；停止传播不等于撤销已提交的状态与授权。
6. **评估亟需规范化**：应实现三类改进——（i）针对不同交互效应使用匹配的比较设计；（ii）限定 ASR 的计算单位并用来源/依赖图承载因果路径；（iii）建立可配置、可扩展、支持开放系统与动态成员的基准。

## 七、优点

- **提出统一分析框架**：A→I→R 框架首次将攻击者位置、交互接口和系统级风险串联在同一执行模型内，能统一描述分散的攻击机制，突破了以组件或攻击名称分类的既有范式。
- **分析与评估维度明确**：
  - 用“关系去除反事实”清晰地划分 inherited / amplified / composition-induced / structurally multi-agent 四类交互安全效应，并与相应证据标准绑定；
  - 将配置维度（C1–C8）、接口（I1–I6）、风险（R1–R7）与路径（P1–P8）显式标注于表 3，可重复性较强。
- **防御视角系统化**：五部分防御合同（路径目标、观察、干预、信任边界、恢复）直击现有防御文献的盲点，明确指出“遏制≠恢复”与“局部保护≠路径闭合”。
- **严谨的负向结论报告**：对 P5/P8 路径证据稀疏、恢复研究缺失、44 个基准中对照组设计不足等问题进行如实披露，避免了对领域成熟度的过度乐观推断。
- **具有明确的方法论指导价值**：不仅总结现状，还给出未来基准设计的可执行建议（如按评估单元限定 ASR 名称、使用显式依赖图、设计可配置接口、覆盖开放系统生命周期等）。

## 八、不足与局限

- **领域快速演化带来的时效局限**：论文发布时间为 2026 年 9 月，但其语料截止时点必然早于此；文中引用了大量 2025–2026 年的预印本（Set 2），这部分证据未经同行评审，稳定性有限。
- **MAS 范围界定的主观性**：将“单主体内部的多步骤管线（planner-critic-verifier）”排除在外、仅在 principal 之间发生交互才纳入 MAS，这一划分在实现层面可能模糊（例如单主体内部的多模块也可共享状态或产生类交互效应）。
- **实验/审计自身不能证明因果**：44 个基准的审计虽揭示了比较设计的不足，但论文本身没有运行新的攻防实验来验证框架的实际区分度。其分类信度（inter-coder reliability）没有报告。
- **不同文献的证据质量差异未被显式加权**：Set 1（审稿或高引）与 Set 2（预印本）在综合中承担不同角色，但面对具体结论时，正文没有给出统一的证据等级评定。
- **对“安全价值判断”的处理存在边界模糊**：论文将“一致性/准确度/行为漂移”仅在

- **对“安全价值判断”的处理存在边界模糊**：论文将“一致性/准确度/行为漂移”仅在**其与受保护的系统级目标（如 R4 的轨迹/目标完整性、R2 的独立性或 R5 的保密性）建立可追溯关联时才纳入安全分析范畴**，但对“某项偏离在何时构成安全相关后果”的判定仍然高度依赖应用语境与审阅者的主观判断，框架未给出形式化的判定阈值或统一的论证程序。同一行为（如同伴间协商中的目标漂移）在一种语境下是无害的协作过程，在另一种语境下却可能被归为完整性破坏。
- **框架编码的客观性与可复现性仍有提升空间**：论文虽提供了表 3 这样覆盖面较广的编码矩阵，但未报告编码者间一致性信度（inter-coder reliability），也未展示外部研究者使用该框架对同一批文献进行独立归类时能得到多大程度的重合。在“交互效应四分类”和“某风险是否属于 R1–R7”等关键判断上，不同研究者可能出现分歧。
- **四类交互效应在实证落实中存在成本障碍**：论文清晰地给出了 inherited / amplified / composition-induced / structurally multi-agent 的概念边界，并强调应以匹配的单主体对照或关系移除反事实作为证据标准；但在真实系统中，移除通信边、动态替换成员或构造“单主体等价版本”的成本通常很高，甚至可能改变任务语义，这使得论文提出的证据标准在短期内难以被多数基准完整落实。
- **对类 MAS 边界情况讨论不足**：论文将“单一主体内部的多步骤管线”排除在 MAS 之外，但在实现层面，单主体内的多模块若共享状态、具备独立寻址能力或可被分别注入提示，其交互特征与 MAS 主体间交互在实际安全后果上可能难以区分；论文虽承认此分歧，却未对这类“灰色地带”系统的审计给出专门指引。
- **未充分展开生命周期与运维视角**：A-I-R 框架主要覆盖执行期（interaction-time）的攻击路径与防御干预，对模型更新、主体退役、记忆长期累积与遗忘、系统升级过程中的安全退化等跨版本生命周期问题着墨较少，而这恰是 R2（独立性丧失）与 R6（传递性授权）在长期运行中可能累积放大的重要场景。

## 九、适用场景与可迁移性

- **最适用的场景**：需要系统化盘点某一族 MAS 攻击与防御的研究者、希望设计“可辩护”的 MAS 安全基准的评测者、以及需要在架构评审中回答“攻击从哪里进入、经何处传播、最终破坏什么”的安全工程师。
- **次适用场景**：作为安全课程或综述写作的统一术语表——A1–A4、I1–I6、R1–R7、P1–P8 与 D1–D4 的命名法可降低不同论文之间描述不一致造成的沟通成本。
- **不适用或需谨慎使用的场景**：若要证明某一具体防御机制在某特定系统上的有效性增益，或需对某商业 MAS 产品做量化风险定级，论文提供的是分析框架而非即用型方法论，仍需结合具体系统的威胁模型与实测数据。
- **可迁移性评价**：框架本身不绑定特定 LLM 后端或消息格式，理论上可迁移到非 LLM 的多智能体系统（如传统软件代理、机器人集群）；但其证据标准高度依赖“可执行完整轨迹记录”与“可控的实验环境”，在真实生产系统（缺少插桩、存在外部不可控依赖）中可迁移性会明显下降。

## 十、结论性评价

总体而言，这是一篇**结构清晰、框架贡献突出、且自我暴露程度较高**的系统化综述。它真正的价值不在于罗列了多少种攻击，而在于提供了一套可以共同讨论“多智能体系统性安全失效”的统一语言与证据标准：A-I-R 打通了威胁入口、交互传播路径与系统级风险之间的因果链条；五部分防御合同将防御研究从“单点拦截”推进到“路径闭合 + 可恢复”的更高标准；对 44 个基准的比较设计审计则直接指出了该领域在因果归因与指标规范化上的系统性短板。

与此同时，该框架目前仍是定性分析工具，其分类边界的可操作性与编码信度有待后续工作验证；论文对证据薄弱的路径（P5、P8）与缺失的研究环节（恢复机制）的坦率披露，反而增强了其作为领域地图的可信度。对于未来的研究者，这篇论文既是一份攻击与防御的路线图，也是一份“如何避免产出不可比较的 MAS 安全基准”的方法论提醒。作为 SoK，它达成了“系统化知识”的核心使命，并在此之上提供了超出一般综述的分析深度。
