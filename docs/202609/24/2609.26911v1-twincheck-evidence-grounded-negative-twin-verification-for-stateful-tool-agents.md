## 摘要
一次局部看似合理的工具调用，就可能使原本成功的智能体轨迹偏离正轨。仅凭怀疑不足以支持干预，因为替换本身可能引入验证旨在防止的那种失败。我们提出 TwinCheck，一种推理时验证策略；仅当轨迹满足与轨迹局部失败假设相关的证据条件时，才考虑替换。它构建一个以轨迹为依据的反事实替代方案，即负孪生，并且仅当该孪生通过结构检查且成对验证器在两种候选顺序下都更偏好它时，才替换智能体的提议。对于配对评估，精确重放会固定智能体已解析的响应和动作，直到第一次被接受的替换，从而将干预效应与重采样分离开来。在对 159 个具有完整精确重放配对的多轮 BFCL V4 任务的主要分析中，完整策略将 GPT-5.6 Sol 的任务成功率从 45.3% 提升至 58.5%（95% 任务自助法置信区间 [8.2, 18.8]），且未观察到成功转为失败的回归。总之，这些发现将执行边界修复重新表述为一种受限比较，使反事实动作本身成为验证的对象。

## Abstract
A single locally plausible tool call can derail an otherwise successful agent trajectory. Suspicion alone does not justify intervention, because the replacement itself can introduce the very failure verification is meant to prevent. We introduce TwinCheck, an inference-time verification policy that considers replacement only when the trace satisfies an evidence condition tied to a trace-local failure hypothesis. It constructs a trace-grounded counterfactual alternative, a negative twin, and replaces the agent's proposal only if the twin passes structural checks and the pairwise verifier prefers it in both candidate orders. For paired evaluation, exact replay holds the agent's parsed responses and actions fixed until the first accepted replacement, separating intervention effects from resampling. In the primary analysis of 159 multi-turn BFCL V4 tasks with complete exact-replay pairs, the complete policy raises task success for GPT-5.6 Sol from 45.3% to 58.5% (95% task-bootstrap CI [8.2, 18.8]), with no observed success-to-failure regressions. Together, these findings recast execution-boundary repair as a constrained comparison, making the counterfactual action itself the object of verification.

## 1. 核心问题与整体含义

- **研究背景**：语言模型智能体越来越多地通过外部工具执行动作，而非只输出单一答案。有状态（stateful）智能体必须把每一次工具调用与当前请求、环境状态、以及此前调用的结果连接起来（ReAct 等范式），而 BFCL 表明多轮函数调用即便在单轮调用很强时仍然困难。
- **核心问题**：一条原本可能成功的轨迹，可能因**单个局部看似合理的工具调用**而整体失败（例如撤销了一个用户从未要求撤销的成功前置操作）。
- **关键矛盾（风险不对称性）**：在执行边界上，拒绝替换会保留智能体原提案，而一次不必要的替换可能把成功变成失败。因此"怀疑"本身不足以支持干预——**替换动作自身可能引入验证本来要防止的失败**。已有研究表明：无新证据的自我纠错会损害正确推理；模型裁判存在系统性偏差（如候选顺序敏感性）。
- **整体含义**：论文把"执行边界修复"重新表述为一个**受约束的比较问题**，让反事实动作本身成为被验证的对象；验证必须为"替换"建立理由，而不只是为"反对原提案"建立理由。作者称待验证的智能体为 **actor（行动者）**。

## 2. 方法论

### 2.1 核心思想
- TwinCheck 是一个**推理时验证策略**：仅在轨迹满足与"轨迹局部失败假设"绑定的证据条件时，才考虑替换；构造**基于轨迹的反事实替代方案（negative twin，负孪生）**；仅当孪生通过结构检查、且成对验证器在**两种候选顺序下都更偏好它**时，才替换 actor 的提案。
- 三个设计原则：默认保留（preservation is default）；证据条件既授权修复也约束修复范围；反事实需经受反顺序偏好的双重检验。

### 2.2 形式化设定
- 任务 $j$ 在步 $t$ 的可见上下文 $c_{j,t}$（用户请求、轨迹前缀、工具 schema、已观测工具输出）；actor 提案 $a_{j,t}$（可为一个或多个工具调用、澄清请求或最终回复）；wrapper 选择执行 $a_{j,t}$ 或替换为 $\tilde a_{j,t}$；环境评估器返回最终成功 $Y_j\in\{0,1\}$。
- **连续检测器**：$d_{j,t}=d(c_{j,t},a_{j,t})\in[0,1]$ 表示轨迹级异常，失败排序用 $D_j=\max_t d_{j,t}$。
- **切换分数** $g_{j,t}\in[0,1]$：仅当动作满足证据条件、存在结构合法的孪生、且成对验证器达成共识时才非零；干预条件为 $g_{j,t}\ge\gamma$，阈值 $\gamma$ 在测试前冻结。
- **配对结果定义**：rescue（actor 失败而 TwinCheck 成功）、harm（actor 成功而 TwinCheck 失败）。目标不是单纯最大化检测召回，而是"救援多于伤害"，并保持干预集合足够选择性。

### 2.3 证据账本与三个证据条件（certificate）
- **证据账本（evidence ledger）**：把最新用户请求之后的轨迹后缀称为"当轮轨迹"，记录所有已解析记录（含输出缺失的调用）、位置与推断结果。固定启发式把账本与当前提案映射为 $d_{j,t}$：重复调用、观测到的工具错误、schema 违规会提高分数，并纳入最强匹配规则。检测分数**不被解释为失败概率，也不能单独授权修复**——检测与干预选择性被刻意分离。
- 仅识别三类证据条件（severity ≥ 0.90 才可干预）：
  1. **词法逆动作条件（1.00）**：提案与此前成功工具名共享同一分词对象后缀、动词在固定表中互为反义，且最新用户消息不含固定的"请求逆转"短语；也识别同一状态改变工具内、其余共享参数完全不变时的布尔翻转。
  2. **错误后重复条件（1.00）**：提案在失败结果之后重复相同工具与参数；若当轮后续出现任何成功工具记录则抑制该条件。
  3. **唯一过期参数条件（0.95）**：目标相关参数键下恰好一个标量与更早值匹配，而最新用户消息中恰好包含一个同类型、且与旧值不同的当前值。
- actor 提出的最终回复与澄清请求可被打分，但**永不修改**。

### 2.4 孪生的构造与结构校验
- 证据条件定义局部失败假设，并**要么决定确定性修复，要么约束模型生成的替代方案**：
  - 唯一过期参数：仅用当前值替换过期值，其余参数不变。
  - 词法逆动作：删除所有匹配调用；若删除后无调用且账本中至少有一个成功、且无未解决的后续失败，则输出固定回复 "The requested operation is complete."；若删除会使动作变空但不满足完成条件，可回落到唯一过期参数规则的确定性编辑。
  - 无确定性候选时，用**低算力调用同一底层模型**生成替代（也处理错误后重复情形），输入完整可用消息轨迹、最多 8 个工具 schema、以及包含证据条件理由与证据的指令；**不接收序列化后的 actor 动作**（但证据可能泄露相关工具或取值）。
- **结构校验**（非同一孪生必须通过）：满足当前 JSON schema；除非证据条件授权结构性变化，否则保持动作类型与调用数量；未获授权时模型生成孪生与 actor 动作的距离须 ≤ 0.35（1 减去规范化 JSON 序列化的 Python `SequenceMatcher` 比率）；同类型模型生成工具孪生中每个新引入的非布尔标量必须出现在"从最新用户消息开始"的序列化证据中。校验失败则保留 actor 动作。

### 2.5 反平衡对比验证
- 验证器接收紧凑近期轨迹、最多 8 个工具 schema、证据条件及其支持证据；A/B 标签**不含显式 actor/twin 标记**；同一对候选在**两种顺序**下各评一次。
- 每次取向 $v$ 输出：偏好、置信度 $c_v\in[0,1]$、每个候选的致命错误标签 $f_v(u)\in\{0,1\}$，以及目标对齐、状态落地、工具选择、参数有效性、完成安全性五个维度上的 0–4 分 $s_{v,k}(u)$。
- 归一化质量：
  $$q_v(u)=\mathrm{clip}_{[0,1]}\Big(\sum_k w_k \frac{s_{v,k}(u)}{4}-0.45 f_v(u)\Big),\quad w=(0.25,0.25,0.20,0.20,0.10)$$
- 差值 $\Delta_v = q_v(\tilde a_{j,t}) - q_v(a_{j,t})$；若 $E_{j,t}\in\{0,1\}$ 表示证据与结构门是否满足，则
  $$g_{j,t}=\begin{cases}\min_v \min\{c_v,\Delta_v\}, & E_{j,t}=1,\ \text{两个取向均偏好孪生、均标记 actor 为致命且孪生为非致命，且 } c_v\ge0.98,\ \Delta_v\ge0.50\\ 0, & \text{否则}\end{cases}$$
- **关键细节**：顺序反转只是**顺序敏感性检查，不是独立模型投票**。可解析响应若遗漏或重复某个取向则 $g_{j,t}=0$；schema 非法或空的结构化响应会触发一次额外验证查询，若仍解析失败则保留 actor 动作并记录运行异常。

### 2.6 校准、干预与精确重放
- 校准使用**任务 ID 不相交的 shadow run**（不做动作替换）：对每个校准任务取 $G_j=\max_t g_{j,t}$ 并记录 $Y_j^{\text{actor}}$；当至少一条 actor 轨迹成功时，
  $$\gamma=\max\Big(0.50,\ \mathrm{nextafter}\big(\max_{j:Y_j^{\text{actor}}=1}G_j,\ +\infty\big)\Big)$$
  若无成功轨迹则校准中止。在报告的 32 任务校准中，17 条成功且其 $\max G_j=0$，故预设定下限 $\gamma=0.50$ 保留——**校准起"核验"而非"调参"作用**。
- 不匹配会在验证器/孪生生成推理前停止审计，防止干预。
- 测试时**每条轨迹至多接受一次替换**；运行异常保留 actor 动作并记录；每条轨迹最多两个合格决策点可到达验证器。
- **精确重放（exact replay）**：actor 轨迹只生成一次；wrapper 重放相同的评估器可见解析响应与动作，直到接受一次替换后下游行为才可发散；未接受替换的轨迹必须完整保持该序列不变。这分离了干预效应与重采样效应。

## 3. 实验设计

- **Benchmark**：BFCL V4 的四个有状态多轮类别——`multi_turn_base`、`multi_turn_miss_func`、`multi_turn_miss_param`、`multi_turn_long_context`；固定 `bfcl-eval==2026.3.23`，该版本每类 200 任务。每轮后由 BFCL 官方评估器做状态与响应检查，**评估器从不接收 TwinCheck 的判断**。
- **划分**：排除工程/方法开发中触及的全部 401 个任务 ID；类别分层抽样得到 32 个校准任务（每类 8 个）与计划 160 任务主集（每类 40 个）。补齐缺失对后按预设条件启动规则（替换前或无干预轨迹上均需精确重放且无评估器可见不匹配、且无 wrapper 异常）通过，脚本再抽 160 任务"条件扩展集"（conditional extension），排除所有开发、shadow 与主集 ID。
- **模型**：actor、成对验证器、模型孪生生成器均使用 GPT-5.6 Sol（`gpt-5.6` API 别名，OpenAI Python SDK 2.53.0），2026 年 8 月运行；actor 推理强度 high，验证器 medium，孪生生成 low。
- **对比基线（触发器匹配控制）**：
  1. 未包装的 actor；
  2. **选择性自我修订**：相同证据条件与重放协议，请求一次直接动作修订，接受改变且 schema 合法、通过结构检查的动作；
  3. **选择性绝对验证器**：用式(4) 的加权评分，健康度 $h=(2q-1)c$（schema 违规时为 −1），$h<0.60$ 时触发，仅当修复后不再触发且健康度提升 ≥0.02 才接受。
- **指标与不确定性**：主要结果是类别级任务成功的**非加权均值**；百分点差由配对二值结果计算；95% CI 来自 20,000 次类别分层百分位自助法（类内独立抽任务对）；报告精确双侧 McNemar 检验；依赖敏感性用"数字后缀簇"（任务 ID 最后一个下划线后的整数）重抽样；伤害上界用 Clopper–Pearson。
