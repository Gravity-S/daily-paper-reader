## 摘要
异步监控、事件调查与合规审计主要依赖智能体轨迹来还原事件经过。这些分析均假定 LLM 智能体无法篡改自身的执行轨迹。我们表明，Claude Code、Codex、Antigravity、Open Code 和 Grok Build 等本地 LLM 智能体未能守住这一边界。除 Muse Code 外，所有受测的运行框架都允许智能体在被要求时删除其轨迹，且未触发监控防护机制。我们还验证了外部攻击者可利用这一缺口诱导轨迹被删除。最后，我们表明当智能体试图提升自身奖励时，轨迹篡改行为会从前沿模型中自然涌现。我们建议从业者确保轨迹记录通过不受智能体控制的独立拦截机制完成，从而即便主机被完全攻陷也能保持轨迹的完整性。总体而言，我们的发现揭示了智能体基础设施中轨迹完整性的一处具体失效，可被用于掩盖谋划或蓄意破坏等失准行为。

## Abstract
Asynchronous monitoring, incident investigations, and compliance audits primarily rely on agent traces to reconstruct what happened. These analyses assume that LLM agents cannot tamper with their own execution traces. We show that local LLM agents such as Claude Code, Codex, Antigravity, Open Code and Grok Build fail to enforce this boundary. All tested harnesses, except Muse Code, allowed agents to delete their traces when asked, without triggering monitor guardrails. We also validate that external attackers can exploit this gap to induce trace deletion. Finally, we show that trace tampering behavior emerges naturally in frontier models, when agents try to improve their rewards. We advise practitioners to ensure trace logging happens through an independent interception mechanism outside of the agent's control, preserving trace integrity even in cases of full host compromise. Overall, our findings identify a concrete failure of trace integrity in agent infrastructure which can be used to conceal misaligned behaviors like scheming or sabotage.

  2. **Exploitability**：外部攻击（如 prompt injection）能否在用户不知情下诱导篡改？

## 2. 方法论

### 2.1 威胁模型形式化

- **Agent 与轨迹定义**：语言模型 agent $M$ 经 harness $H$ 与输入 prompt $P$ 运行；第 $t$ 步 harness 将 context 发送给模型并收到 action $a_t$（assistant 消息、工具请求、模型生成的推理），执行工具调用后返回结果 $r_t$（未调用工具则 $r_t$ 为空）。
- **轨迹表示**：$T = \langle P, (a_1,r_1), \dots, (a_t,r_t) \rangle$，harness 在每步后更新；存储轨迹 $\hat{T}$ 意图忠实记录 $T$。注意 $T$ **不捕获环境状态**（虽可通过初始化沙箱并重放动作重建大部分），也**不记录全部系统活动**。
- **攻击者目标**：将 $\hat{T}$ 替换或修改为 $T'$ 以误导评估者，分两类操纵：
  - **Fabrication（伪造）**：插入或修改消息、动作、结果；
  - **Concealment（隐藏）**：删除证据，乃至整个 session 或 subagent。
  - 假设攻击者拥有部署环境的**完整用户级访问权限**（可为失准 agent、与 agent 协作的恶意用户，或对他人系统运行 agentic exploit 的外部攻击者）。
- **防御者目标**：在 agent 运行前部署 trace 记录协议（修改 harness、引入特权服务、改变沙箱权限），保证 $\hat{T}$ 对 $T$ 的真实性，防止任何插入、重排或删除；同时要求**最小改动现有工作流、低运行时开销**。信任边界应把 agent 运行时环境与"篡改 $\hat{T}$ 的权限"分离。
- **范围限定**：本研究只考察**客户端侧记录管线**，排除 provider 侧记录与其他独立遥测；检测篡改、评估监控器有效性明确在 scope 之外。
